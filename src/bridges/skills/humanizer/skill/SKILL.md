# bridges-humanizer SKILL

这是随 BridGes 发布的只读内置能力。它处理两条路径：改写用户提供的文本，或
按主题、受众、体裁、渠道与硬约束生成新文章。方法规则只改变表达组织方式，
不能越过事实锁、证据合同、体裁合同或用户任务边界。

## 边界

- 不规避 AI 检测，不冒充真人、名人或特定作者，不伪造个人经历，也不把模型
  猜测写成用户经历。
- 不虚构事实、论文、引用、数据、天气、时间或现场细节。缺少依据时保留缺口，
  需要时标记为需人工核实。
- 不用流畅度换取科学事实：数值、单位、对象关系、限定条件、公式、引用与
  结论强度由事实锁保护。
- 不复制未获许可的参考项目文本、提示词、目录结构、示例或测试语料；本文件的
  方法、例句和规则 ID 均为本项目独立表述。

## 证据边界

事实锁覆盖六个信息面：数值与单位、限定条件、结论强度、公式、引用、对象关系。

- **数值与单位**：原文出现的数字和单位保持不变；等价换算必须在修改明细中说明。
- **限定条件**：约、可能、仅、部分、在某条件下等限定词及其作用对象必须保留。
- **结论强度**：证明、表明、推测、可能等强度不得被升级；证据不足时只能降级。
- **公式**：公式、变量、系数和方向原样保留。
- **引用**：已有作者年份、编号和网址保持；新增引用必须来自证据合同，否则标为
  需人工核实或虚构风险。
- **对象关系**：影响、导致、相关、促进、抑制等关系的方向与范围保持，不把相关
  改成因果，也不扩大适用范围。

## 方法体系

方法块的运行时单一事实源是
`src/bridges/skills/humanizer/method_rules.py`；本文的规则 ID 必须与该模块
双向一致。运行时提示词使用场景筛选，但文章改写和文章生成共享同一套方法。

### 检测面：先找到模板痕迹，再决定是否需要改

下面的“检测锚点”是复核线索，不是逐条拦截器。判断要看语境、频率和信息增量；
每条都配一组自拟对照，避免把正常中文误判为问题。

- **清除协作痕迹**：检测“希望这对你有帮助”“如有需要请继续提问”等交付后尾声；
  对照：“希望这对你有帮助。”→“结论是：温度升高后速率下降。”。规则标识：
  `detect.collaboration-trace`
- **收敛谄媚开场**：检测“好问题”“你问得非常好”等没有任务增量的开场；对照：
  “这是个非常好的问题。先看定义。”→“先看定义：……” 。规则标识：
  `detect.flattery-opening`
- **压缩填充短语**：检测“需要指出的是”“在这个问题上”等垫话；对照：
  “需要指出的是，样本只有三组。”→“样本只有三组。”。规则标识：
  `detect.filler-phrase`
- **避免通用积极结论**：检测“这无疑很重要”“具有重要意义”等没有对象和依据的
  赞许；对照：“这项工作意义重大。”→“这项工作把测量误差降到了可比较的范围。”。
  规则标识：`detect.generic-positive`
- **检查高频模板词**：关注“此外”“至关重要”“深入探讨”等连续模板词；对照：
  “此外，至关重要的是深入探讨机制。”→“还要看机制是否能解释这个差异。”。
  规则标识：`detect.ai-frequency-words`
- **识别翻案式否定排比**：检测“不是 A 而是 B”“看似 A 实则 B”及换皮表达；对照：
  “不是温度变了，而是仪器错了。”→“这次差异更可能来自仪器误差。”。规则标识：
  `detect.negation-parallel`
- **控制三项排比**：检测连续三项同构短语的装饰性堆叠；对照：“准确、清晰、
  高效地完成工作。”→“把关键数据和限制写清楚。”。规则标识：
  `detect.three-part-overuse`
- **停止同义词循环**：检测为避免重复而轮换近义词；对照：“该结果……这一发现……
  该现象……”→“该结果……该结果……”。规则标识：`detect.synonym-loop`
- **核对虚假范围**：检测没有真实边界却写“从 X 到 Y”的包装；对照：“从实验室到
  全社会都将受益。”→“本结果目前只在实验室条件下成立。”。规则标识：
  `detect.false-range`
- **降下夸大意义**：检测“标志着”“见证了”“开启新篇章”等时代化结论；对照：
  “这标志着研究进入新纪元。”→“这组数据为后续比较提供了一个起点。”。规则标识：
  `detect.significance-hype`
- **拒绝模糊归因**：检测“专家认为”“研究显示”却没有可定位依据；对照：
  “专家认为方法有效。”→“在这组样本中，误差比基线低；外推仍需核实。”。规则标识：
  `detect.vague-attribution`
- **清理过度限定**：检测“可能、或许、在一定程度上、从某种意义上”的叠加；对照：
  “可能或许在一定程度上改善。”→“初步结果提示可能改善。”。规则标识：
  `detect.overqualification`
- **去掉宣传腔**：检测“全面赋能”“引领未来”“值得期待”等广告式承诺；对照：
  “全面赋能科研创新。”→“它减少了整理数据所需的手工步骤。”。规则标识：
  `detect.promo-tone`

英文标题的大写规则、单纯标点偏好等只适用于其他语言或其他体裁的项目，不纳入
中文人味化检测面；中文规则也不把偶发一个词当成自动失败。

### 改写面：让中文句法和节奏承担信息

- **主干先行**：先说谁做了什么，再补条件、范围和原因，不让背景把动作藏到句末。
  规则标识：`rewrite.main-clause-first`
- **顺势接话**：让前句对象或结果成为后句起点，避免每句重新铺设“这一现象/该问题”。
  规则标识：`rewrite.tail-connection`
- **拆开长定语**：一个句子塞入多个条件时拆成短句，每句只承担一个主要动作。规则标识：
  `rewrite.split-attributive`
- **把名词化还原成动词**：把“进行了优化/实现了提升”改成“改顺了/提高了”等可见
  动作，但不改变事实强度。规则标识：`rewrite.restore-verbs`
- **删去半数连词**：删掉不承担逻辑的“因此、同时、此外、从而”，再确认因果和转折
  关系仍然清楚。规则标识：`rewrite.trim-connectors`
- **允许必要重复**：同一术语可以自然重复，不为了变化强行换同义词。规则标识：
  `rewrite.allow-natural-repeat`
- **拉开句子节奏**：长句承载完整论证，短句落到判断或动作，不把所有句子切成口号。
  规则标识：`rewrite.rhythm-contrast`
- **分清逗号和句号**：逗号连接同一动作的补充，句号结束一个判断；跨越两个判断时
  不用逗号硬串。规则标识：`rewrite.punctuation-roles`
- **用正面判断**：禁用“不是 A 而是 B”“看似 A 实则 B”等翻案动作，换皮表达同样
  命中；直接说 B 成立到什么程度。规则标识：`rewrite.direct-judgment`
- **用具体动词**：不把抽象名词配具体动词写成抒情，优先写测量、比较、解释、限制和选择。
  规则标识：`rewrite.concrete-verbs`

### 事实护栏面：先判断证据能说到哪一步

现有事实锁引擎不因本方法体系改变；新增规则只约束 claim 强度和论证顺序。

- **相关不等于因果**：只有相关证据时写“提示/可能有关”，不能升级为“证明/导致”。
  规则标识：`fact.relevance-not-causality`
- **没有统计检验不写显著**：没有对应检验或明确证据时，改为“有差异/观察到变化”。
  规则标识：`fact.no-significance-without-test`
- **预测准确不等于因果成立**：预测命中只能说明预测表现，不能单独证明机制。规则标识：
  `fact.prediction-not-causality`
- **指标提升不等于场景有效**：单项指标变好不自动推出真实场景有效，要写清指标、
  场景和仍缺的验证。规则标识：`fact.metric-not-real-world`
- **样本内不等于外推成立**：样本、受控条件或单一群体中的结果不能直接推广。规则标识：
  `fact.sample-not-extrapolation`
- **强词证据不足就降级**：“关键因子/首次证明/系统揭示”等证据不够时改为“可能相关/
  初步支持/观察到”，不能补造证据。规则标识：`fact.downgrade-unsupported-claim`
- **按顺序回读**：先锁事实，再改论证顺序（做了什么→看到什么→能说明什么→还不能
  说明什么），再改句子，最后回读核查。规则标识：`fact.review-order`

### 个性与分寸：让表达像在完成任务，而不是表演助手身份

- **观点与依据相邻**：可以有明确判断，但把观察、数据或来源放在附近。规则标识：
  `voice.evidence-near-opinion`
- **承认复杂性**：遇到证据不足、条件依赖或争议时说清不确定性，不用整段免责声明，
  也不装作已经确定。规则标识：`voice.admit-uncertainty`
- **不谄媚**：不靠夸奖用户或拔高问题制造亲近感，亲近来自准确接住语境。规则标识：
  `voice.no-flattery`
- **不替用户编经历**：不把“你最近/你一定/你应该经历过”当事实；没有授权的个人信息
  保持中性。规则标识：`voice.no-fabricated-experience`
- **清零协作话术**：不输出“我来帮你一步步”“让我们一起探索”等流程表演；只说明
  必要步骤。规则标识：`voice.no-collaboration-trace`
- **一次说明知识边界**：需要说明缺口时，用一次自然、具体的短句交代缺口和下一步，
  不套免责声明模板。规则标识：`voice.knowledge-boundary`
- **保持讲者位置**：讲稿场景默认由讲者本人讲述，避免“本文将为您”“本助手认为”等
  旁观式助手腔。规则标识：`voice.speaker-position`
- **不造假细节**：不凭空补精确时间、天气、神态、现场动作或个人记忆；缺少依据就保持
  概括或待确认。规则标识：`voice.no-fake-detail`

### 创新规则

- **人味分档**：识别“快点/直接说/赶时间”等求快信号，以及已授权的相应偏好；命中
  时收敛修饰，只留事实护栏和清晰直答。没有求快信号时才展开节奏与个性。规则标识：
  `innovation.human-pace`
- **教学落到例子**：学习模式每次讲解至少落到一个具体例子或一道题，杜绝连续发送
  只有抽象名词的解释。规则标识：`innovation.teaching-example`

## 输出合同

每次成功结果固定包含以下五项，缺一项不标记完成：

1. **最终文本**（`final_text`）。
2. **逐项修改细节**（`edits`），每项含原文片段、新文片段和理由。
3. **每项理由**，说明触发的体裁规则或方法规则。
4. **事实核查结果**（`fact_check`），逐项给出已核实、需人工确认或存在虚构风险。
5. **尚未解决的问题**（`open_questions`）。

模型必须严格返回结构化 JSON；输出合同由运行时代码的 Schema 和确定性完整性检查
共同约束，方法规则不能新增或删除字段。

## 体裁合同

四类体裁各自有独立的表达 profile（任务目标、风险、可选表达方式与禁止
模式），方法规则不能把它们合并为泛化模板（人味化改造 Issue 04 起不再
有「必现元素」正则完成条件，可选表达一律按需使用）：

- `popular_science.md`：科普文案——向非专业读者解释科学主题；定义、类比、
  关联、设问均按需使用。
- `lecture_script.md`：课程讲稿——让听众跟上并完成一次检查或练习；学习
  目标、先备提醒、举例、理解检查、练习停顿均按需使用。
- `research_report.md`：科研汇报——让同行看清做了什么、看到什么、能说明
  什么、还不能说明什么；方法、局限、下一步均按需使用。
- `paper_assist.md`：论文写作——辅助结构、语言、引用与论证建议；AI 披露
  按需使用。

体裁复核只判断任务完成（正文非空）与禁止模式；风格发现由表达审稿器按
场景软审稿（只报警，不做机械替换）。高风险建议、数据真实性和作者责任
仍需要人工确认。

## 编排

1. **解析任务契约**：确认改写或生成路径、主题/原文、受众、体裁、渠道、长度和
   硬约束；改写原文只能来自用户粘贴或当前账户已授权材料。
2. **建立事实锁**：改写路径从原文确定性提取事实锁；生成路径把硬约束编译为事实锁。
3. **组装一次模型调用**：按路径选择文章改写档或文章生成档方法块，并与体裁合同、
   事实锁、证据合同和输出 Schema 一起组成 system/user prompt。
4. **立即交付草稿事件**：模型产出正文后先下发 `DRAFT` 事件；聊天服务持久化草稿，
   后续复核、修复或软门警告不得清空这份正文。
5. **确定性复核与质量门**：
   - **硬门**：事实锁出现阻断冲突、输出合同缺失或产生不可交付错误时停止交付违规
     结果，并给出可操作的重试或人工确认说明。
   - **软门**：体裁规则未完全满足时，不扣留当前正文；方法规则是生成时约束，不作为
      逐条回复拦截器。在明确的预算允许时，最多执行一次定向修复。修复失败、预算不足
      或修复后仍不通过，都交付当前最佳正文，质量状态为 `WARN`，结果终态为 `needs_human`
      并列出具体警告。
   - **通过**：事实锁、输出合同和体裁复核通过时，结果状态为 `done`，质量状态为 `OK`。
6. **恢复语义**：自然语言路由只做一次结构化生成，不进入第二次修复；显式任务保留
   一次定向修复兼容行为。过程卡继续使用 loading、empty、error、permission、recovery
   五态，SSE 事件合同不因方法体系改变。

### 表达任务契约新流程（人味化改造 Issue 04）

带版本化表达任务契约的任务（自然语言路由入口）走以下新流程：

1. **契约校验**：契约 Schema 版本未知或快照哈希不一致时，在模型调用前稳定拒绝。
2. **首稿编译**：只编译当前 profile（轻度/标准/深度）的 6—10 条高优先级正向规则；
   提示携带说话位置、读者下一问、材料边界与第一人称/假设权限，不包含内部方法 ID、
   全量检测清单或体裁必现短语。
3. **一次正文生成**：模型只产出候选正文（`final_text`），不再同时生产修改明细、
   事实核查与开放问题。
4. **保真硬门**：来源账本检查失败（Issue 02）停止交付。
5. **表达审稿**：对候选正文做软审稿（Issue 04），输出带稳定 code、位置、证据与
   定向建议的 `ExpressionReviewReport`；自然稿报告 `no_change_recommended`，系统
   不为满足规则强行改写。
6. **程序审计**：修改清单、保真结果、模式命中与可确定性差异全部由程序生成，不
   伪装成模型自证；旧投影字段在 Issue 08 前保持兼容。

## 失败恢复

过程卡提供中文 `loading`、`empty`、`error`、`permission`、`recovery` 五种状态。
失败后可从原任务重试；用户输入、任务契约、授权范围、事实锁边界和证据合同在重试
中保持不变。软门的 `WARN` 是诚实交付，不等同于事实冲突；事实冲突必须停下并说明
哪一项锁发生了变化。

## 设计取舍与净室说明

- 长文创作的材料数量门槛不直接套到聊天；聊天改用“每次讲解至少落到一个具体例子
  或一道题”的教学规则。
- 破折号、冒号和三项排比不做全局命中即失败；聊天档按频率告警，文章档交给体裁合同。
- 粗体、emoji 和标题不做全局清零，学习场景可按扫读需要适量结构化。
- 不引入允许跑题、半成型想法或混乱的个性开关；赶时间信号出现时关闭多余修饰。
- 不把离线评分器、逐条回复拦截脚本或“通过 AI 检测”作为运行时目标。
- 方法、例句、提示词与测试资产由本项目独立撰写；外部材料只用于研究方向和净室审计，
  具体来源与零文本复用记录见 `CLEAN_ROOM.md`。
