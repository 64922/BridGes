# 共同规则归属：生成终态与原子画像提交

## 来源和目标

本任务集固化 2026-09-27 架构报告的两个改进候选，避免实施依赖系统临时目录里的 HTML。用户要求把所有候选拆成详细本地票据，留待后续执行；本次不实施重构。

目标是增加 module 的 depth：调用者通过较小的 interface 获得完整行为，跨记录顺序、幂等和失败恢复集中在 implementation 内部，从而获得 locality 与 leverage。不是按文件长度拆分，也不是引入通用事务框架。

## 已观察到的结构摩擦

### 生成终态：强推荐

日常父图的 `converge_stopped`、`converge_error` 自行构造终态投影；回合编排暴露的 `finalize_message` 主要收尾消息；后台执行器的 `_reap_message`、`_ensure_terminal_event`、`_converge`、`_finalize_run` 分别处理失联、事件、停止和运行记录。消息条件更新有其自身保护，但调用者仍共同掌握跨对象顺序。

已有测试覆盖断连重连、刷新不重复调用、执行器竞争、失联恢复和停止保留内容。尚未在已检查测试中确认完整覆盖“消息终态已写入，事件或运行终态尚未写入”时的跨入口故障恢复，因此要先核查现有测试，再补缺口，不能宣称该处已存在生产缺陷。

删除检验：仅删除现有消息收尾函数会把规则散回调用者。应将其加深，使图、回合和执行器不再独立拼装共同的终态不变量。

### 原子画像提交：值得深入

自动提取的 `_commit_transaction` 按具体 SQLite 仓库类型决定事务安排；自动写入先调用 `upsert_automatic_record` 再调用 `mirror_record`；用户更正也显式协调这两类记录。删除与忘掉先提交墓碑，再撤回四维来源。

墓碑先写是已有安全策略，不应直接当成缺陷。需要保留用户编辑优先、删除防复活和账户隔离，同时把提交与恢复知识藏进 module。`InMemoryAtomicProfileRepository` 与 `SqliteAtomicProfileRepository` 是两个真实 adapter，可作为共同合同的验证面。

删除检验：直接删除镜像逻辑会迫使各调用者重学去重、编辑优先和墓碑规则。应集中提交职责，保留必要 implementation，而非只减少文件数量。

## 共同约束

- 使用中文描述、注释及用户文案；开发和验证使用 Conda `agent` 环境。
- 领域命名遵守现行 CONTEXT。ADR-0013 的 SQLite 和受监督后台原则、ADR-0026 的历史保留与迁移门、ADR-0030 的 V2 主对话及原子画像合同继续有效。
- 模型运行锁沿用 ADR-0031：在途轮次不因设置变化而切换模型，历史标识不改写。
- 工作流运行状态与产物可信状态保持独立；不得把生成完成解释为质量门已通过。
- 不改变用户界面、外部请求和事件合同来迁就内部重构；若现有合同存在矛盾，应先记录证据，不能静默改成新产品行为。
- 不引入远程执行平台、通用事务框架、新画像分类或已退役的教学计划/扩展入口。
- 保留历史读取、导出、迁移报告与回滚能力，不因内部调用迁移删除历史数据或兼容合同。
- interface 具体形状尚未设计。执行各链首票时，先写出责任与不变量，再选择最小实现并接入真实调用路径；不把臆测的方法签名固化为需求。
- 现有 seam 够用时直接复用。只有真实行为变化需要不同 adapter 时才增加 seam。

## 分批实施规则

两条链分别按扩展、调用迁移、内部收口推进。首票建立共同规则并迁移一条完整路径；中间票接入其他场景；末票闭合恢复路径并移除本次产生的无用兼容转发。

任何中间票都必须可单独验证并保持相关回归通过。暂时保留的内部兼容入口必须委托给共同实现，不能形成两份规则。外部历史兼容入口是否删除仍受既有迁移门约束。

测试通过用户可观察行为或 module 的 interface 验证。优先复用现有确定性模型与存储 adapter；不使用真实模型调用、真实密钥或外部网络验证本次重构。

## 完成定义

六张票据各自满足验收条件；所有迁移入口使用同一职责归属；两个候选对应的故障与回归场景有可复现证据；项目文档与实际责任一致。最终交付记录改动范围、验证命令/结果、残余风险，以及必要的迁移或恢复说明，不以“减少若干行代码”作为成功标准。
