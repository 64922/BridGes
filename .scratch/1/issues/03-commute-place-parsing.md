# 03 — 正确解析带口语前缀的校园通勤请求

**What to build:** 用户输入“我现在想从42栋步行到南区25栋”时，系统准确使用 42 栋和南区 25 栋查询步行路线；地点含糊时沿用现有澄清流程，不把意图前缀发送给地点服务。

**Blocked by:** None — 可立即开始；真实界面的配置后路线链路由 07 等待 02 一并验收。

**Status:** ready-for-agent

## 问题与证据

真实解析函数已复现起点为“现在想从42栋”，终点和步行方式正确。截图中的地点查询也包含错误前缀。缺少高德凭据是当次首先暴露的失败，但配置完成后仍可能因错误地点短语无法定位。

## 任务内容

1. 用原始句子建立确定性失败测试，断言起点、终点、出行方式以及实际送入地点查询端口的词。不能只断言解析函数不抛异常。
2. 检查出行方式剥离、句首意图处理、起终点识别的顺序，最小修改使“我现在想从”等口语前缀在位置明确时被识别，而不是对全句任意删字。
3. 覆盖“从42栋步行到南区25栋”“我想从42栋到南区25栋，步行”“42栋到南区25栋”等等价表达；保留南北区、数字、建筑名和用户原始地点信息。
4. 回归只有终点、缺少方式、多个地点候选、上一轮澄清恢复和不同出行方式。缺失信息应询问，不得从错误前缀或未经确认的上下文生成坐标。
5. 通过模块服务验证解析结果确实传入起终点查询与路线请求。学校范围限定可以继续使用现有规则，但不应把“现在想从”等意图词拼进地点。
6. 有效凭据下使用原句查询真实路线，保留来源、时间、路线及多候选选择过程；若具体楼栋无法唯一定位，证明澄清流程正确，不以伪造坐标强行完成。

## 验收标准

- [ ] 原句输出起点“42栋”、终点“南区25栋”、方式“步行”。
- [ ] 服务端口收到的地点查询不含意图前缀，起终点顺序不颠倒。
- [ ] 等价表达通过；地名中合法文字、校区信息和数字不被误删。
- [ ] 缺失信息、多候选及澄清恢复仍可用，账户和会话上下文不混用。
- [ ] 地点服务失败与解析失败可区分，不用解析成功掩盖外部调用失败。
- [ ] 独立模块测试通过；真实路线或需要澄清的真实响应证据交给 07 复核。

## 范围与协作

不修改高德凭据存储，不重建路线规划器，不增加校园坐标硬编码。与 02 共享通勤卡片时先协调；本票优先修改解析、模块调用和相应回归测试。
