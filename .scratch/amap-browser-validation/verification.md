# 高德浏览器地图验证：SDK 路由参数修复

日期：2026-10-07

## 原因

保存时主动构造的地理编码请求缺少 JS SDK 路由标识。仅追加安全码或
`platform=JS` 仍走普通 Web 服务校验，导致正确的 JS API Key 返回
`USERKEY_PLAT_NOMATCH`（10009）。官方 SDK 同时携带 `platform=JS` 和
`s=rsv3`，设置页探测必须保持该协议。运行期代理原样保留 SDK 查询参数。

## 真实请求验证

经用户明确授权，使用其提供的凭据向高德官方服务发送固定公开地址的请求。
凭据只经隐藏输入进入进程内存，没有写入源码、测试或此报告。

| 请求条件 | 结果 |
| --- | --- |
| Key、安全码，无 SDK 参数 | 10009，平台不符 |
| 仅补 platform=JS | 10009，平台不符 |
| 同时补 platform=JS、s=rsv3 | 10000，成功，地点数量 1 |
| 成功请求改成错误安全码 | 10008，安全码不匹配 |

修复后用真实 HTTP 客户端注入隔离的内存测试应用：实际探测函数通过，
`PUT /settings/credentials/amap/browser-map` 返回 200，内存凭据成对保存；
`GET /commute/amap-proxy/v3/geocode/geo` 返回 10000、地点数量 1；
设置卡片已配置、无错误、有运行期成功证据。保存与状态响应均不含凭据。
该测试没有修改用户正在运行的应用或持久化凭据库，也未验证浏览器瓦片渲染。

## 回归检查

保存接口测试按上述真实请求条件构造上游响应：修复前 422，修复后 200。
相关凭据、保存、运行期生效测试共 105 项通过；修改文件 Ruff、探测模块 mypy
和 git diff --check 通过。Web 服务探测不携带上述 JS SDK 参数。

上一轮全量检查结果为 5660 通过、205 失败、37 跳过；本轮未重复该完整套件。
此次复验以真实供应商响应与相关回归为依据，不能宣称全仓库检查通过。
