# BridGes 改进 PRD

Status: approved

## Objective

在当前仓库中保留可复用工程骨架，纵向替换旧 Science Companion 工作台，将产品改造成仅面向电脑端部署和使用的 BridGes：一个融合证据化数字分身与原创有人味科学表达能力的聊天优先本地 Web 应用。

完整规范以根目录 [`BridGes项目改进计划书.md`](../../BridGes项目改进计划书.md)、[`CONTEXT.md`](../../CONTEXT.md) 与 [`docs/adr/`](../../docs/adr/) 为准。本文件只为本地 Issue 跟踪提供稳定需求编号，不复制另一份可能漂移的实现计划。

## Legacy boundary

- `.scratch/science-companion-plan/` 与根目录 `tickets.md` 是旧 Wayfinder 产物，只读保留。
- 旧数据库没有真实账户、用户上传材料或有效画像，封存后以全新 `bridges.db` 开始。
- 本 effort 的唯一任务目录是 `.scratch/bridges-improvement/issues/`。

## Requirement identifiers

### 页面与视觉

- `UI-01`：以 `https://chatgpt.com/` 的电脑端页面作为整体布局和交互模板。
- `UI-02`：产品统一命名 BridGes，设计表达“用户与知识之桥”的原创 Logo 全套资产。
- `UI-03`：采用 Claude-inspired 的温暖、克制、高可读性美术风格，但不复制品牌资产。
- `UI-04`：为侧栏、工具、建议卡、消息操作、媒体状态和账户菜单设计语义一致的原创图标。
- `UI-05`：登录、注册和全部内容页均为完整成品，包含加载、空、错、权限、成功与恢复状态，不得保留空壳或假按钮。

### 导航

- `NAV-01`：Logo 点击或键盘激活后进入新聊天。
- `NAV-02`：统一搜索最近聊天、图片、文档和学习项目并精确跳转。
- `NAV-03`：电脑端侧边栏支持折叠和重新展开。
- `NAV-04`：取消“更多”模块。
- `NAV-05`：最近对话同时包含日常陪伴与学习模式并显示模式标识。

### 聊天

- `CHAT-01`：登录后默认进入新聊天，并在持续交流中形成受治理的用户画像。
- `CHAT-02`：同一聊天系统支持对话级“日常陪伴/学习模式”切换。
- `CHAT-03`：取消临时聊天模式。
- `CHAT-04`：新聊天按参考机制轮换恰好五条经过核查的简短学习名言。
- `CHAT-05`：取消模型选择器与实时语音，只保留 Qwen 听写、文本输入和发送；单条回答可按需朗读。
- `CHAT-06`：日常陪伴自然、有分寸，识别会话级情境信号而不形成心理诊断。
- `CHAT-07`：两种模式共用“上传文件/图片、论文搜索、文章人味化、生涯规划助手、选择项目、选择插件”的“+”菜单。
- `CHAT-08`：空白对话显示论文搜索、文章人味化和生涯规划三张带原创图标的建议卡。
- `CHAT-09`：学习模式因材施教、规划步骤、适当测验；本地教学材料缺失或不足时必须自动联网补充。
- `CHAT-10`：聊天保留学习项目与已启用插件选择，并显示当前选择状态。
- `CHAT-11`：生成时展开思考摘要，完成后折叠为“已思考（用时 X 秒）”，不展示原始思维链。

### 内容与服务

- `KNOW-01`：本地知识库保存当前账户的全局学习材料，可被授权对话检索。
- `PROJ-01`：学习项目仅作为对话与项目文件的文件夹，不恢复项目制教学工作台。
- `TASK-01`：用户以自己的 QQ SMTP 授权码向同一邮箱发送简练、可按画像适配的本地提醒。
- `EXT-01`：插件页安装、展示和治理 MCP 与 SKILL。
- `EXT-02`：默认安装 PDF、Documents 与原创 `bridges-humanizer` 等必要能力。
- `EXT-03`：支持安全上传声明式本地 SKILL。
- `PROFILE-01`：基本情况、阶段目标、兴趣偏好、表达习惯、知识状态、情绪变化、重要经历、当前问题和授权范围分开存储，记录何时写入、更新和用于回答，并支持查看、修改与撤回。

### 账户与身份

- `ACCOUNT-01`：侧栏底部上拉菜单包含切换账号、密钥设置、个人资料和退出登录；账户密钥不共享，头像和用户名可修改。
- `AUTH-01`：注册必须填写用户名、严格数字 QQ 邮箱和密码。
- `AUTH-02`：登录接受用户名或 QQ 邮箱其中之一加密码。
- `AUTH-03`：密钥、头像和用户名修改仅允许登录账户执行。

### 改造、部署与模型

- `IMP-01`：A 数字分身与 B 有人味表达必须融合为一个科普科教产品。
- `IMP-02`：原创人性化 SKILL 只借鉴合法通用方法，保留许可证和来源清洁记录。
- `IMP-03`：修复空壳页面、缺失退出路径、无法联网、假成功、硬编码状态和重启丢数据等现有缺陷。
- `DEPLOY-01`：下载源码后可在 Conda 或 `.venv` 环境安装前后端依赖并执行 `BridGes start`。
- `DEPLOY-02`：支持 Docker/Podman Compose 部署。
- `DEPLOY-03`：用户不创建 `.env`，删除无用环境变量并通过受保护账户设置配置秘密。
- `MODEL-01`：每类能力固定一个模型，用户不可更改、不可隐式降级。
- `MODEL-02`：普通联网搜索固定 DuckDuckGo，无需用户配置搜索 Key；论文使用 arXiv 公开能力。
- `MODEL-03`：同一账户百炼 Key 调用固定文本、Embedding、ASR、TTS、图片与 Wan 视频能力，并分别真实探测。
- `DESKTOP-01`：只允许电脑端部署与桌面浏览器使用，不适配手机、平板、移动浏览器、PWA 或原生移动应用。

### 比赛 A/B 与加分项

- `A-01`：形成“记录画像—调用画像—生成回答—用户反馈—修正画像或回答”的可回放闭环。
- `A-02`：用量化方式验证系统是否越来越懂用户，并保持自然、有分寸和事实可靠。
- `B-01`：在科普文案、课程讲稿、科研汇报和论文写作中验证中文模板腔、机翻感与 AI 味改善，同时保持事实。
- `BONUS-01`：展示多轮画像与回答修正效果。
- `BONUS-02`：提供降低幻觉、保持事实准确和识别风险信号的可复现证据。
- `BONUS-03`：与基础 Qwen 和合法开源参考方法对比画像更新、人味对话和低幻觉回答。
- `SCORE-01`：覆盖科学事实准确、解释清晰和主题完整一致。
- `SCORE-02`：覆盖模型/智能体/SKILL、多模态和稳定性技术深度。
- `SCORE-03`：覆盖真实使用价值、完整电脑端交付和可复现部署。

## Publication rules

- 每个 Issue 必须引用至少一个上面的需求编号和适用 ADR。
- Issue 必须是端到端可演示的纵向切片，不按前端、后端、测试分成长期不可用的孤岛。
- 页面类 Issue 必须交付电脑端完整状态与真实行为，不允许占位文案、无 handler 按钮或生产 Stub 假成功。
- 只有 Issue 01 需要人工处理真实密钥；其余 Issue 默认 `ready-for-agent`。
