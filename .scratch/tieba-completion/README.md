# 贴吧模块：按批次并行执行指南

本目录用于指导开发智能体完成贴吧模块的故障修复与完整可用闭环。15 张工单已获用户确认；本 README 提供执行排程建议，不代表工单已经实现或验收。

先阅读 [执行方案](PRD.md)，再领取下表中的具体工单。**能否开始，以工单的 `Blocked by` 和前置验收证据为准；`ready-for-agent` 不等于没有阻塞。**

建议配置一名协调者，按批次分配最多三个开发智能体。单任务批次只安排一个开发智能体，其余容量可用于审查和验证，不为凑并行数拆改同一条关键链路。该人数是调度建议，不是项目运行并发配置。

## 流水推进：无需等待无关工单

批次是排程参考，不增加工单原有依赖。协调者可以按以下规则缩短空等：

- 01 通过后，03 可以与尚未完成的 02 并行；04 仍必须等 01、02、03 全部通过。
- 06 通过后，07 可以与尚未完成的 05、12 并行；08 只等待 05、07，不等待 12。
- 08 通过后，09、11 可以启动；若 12 仍在执行，可形成三条并行工作线。
- 09 通过后，10 可与尚未完成的 11、12 并行。
- 10 通过后，14 可立即启动；13 必须再检查 11、12 是否已通过。
- 15 必须等待自身全部前置验收及其传递依赖，不能用“已写完代码”或“等待实测”代替通过。

某条分支被外部条件阻塞时，继续处理其他已具备前提的工单；不得通过跳过真实认证、分页身份或生产模型验收来提前解除依赖。

## 并行开发边界

建议每张工单使用独立分支与工作树，从已集成的前置成果开始。开发环境使用 conda 的 `agent`，测试前确认加载的是当前工作树代码。多智能体不要同时编辑同一个工作目录。

每批启动前，协调者记录各票负责人、基线版本、计划修改的共享接口及验证资源。一个智能体拥有一张票的完整行为交付；前端状态、公开投影和必要测试仍属于该票，不能全部推迟给 13。

| 并行组合 | 需要协调的交叉区域 | 建议分工 |
| --- | --- | --- |
| 01 与 02 | 搜索适配器、错误与查询记录 | 01 负责请求许可、排队与终止语义；02 负责话题与最终查询编译。共同文件由一方负责编辑，另一方提交明确接口需求。 |
| 05、06 与 12 | 浏览器适配、证据转换、共享预算和结果投影 | 05 拥有候选与搜索进度；06 拥有普通楼层与逐页证据；12 复用预算能力完成官网核验，不另改并发调度。共享字段先协调，再集成。 |
| 09 与 11 | 模型调用预算、收尾预留及部分结果语义 | 09 负责采集调度和截止，11 负责总结载荷、调用与支持核验；共同遵守既有五分钟及交付预留合同，不各自重定义额度。 |
| 10 与尚未结束的 11 | 证据复用、模型失败与恢复范围 | 10 负责恢复资格和任务版本，11 负责总结结果与失败分类；确认恢复输入及失效条件后再集成。 |
| 13 与 14 | 账户状态、恢复入口与任务终态 | 13 消费真实服务端状态，14 验证隔离与清理；不并行修改同一套公共状态定义。 |

这些是预期冲突区域，实施时需按实际差异复核。共享文件冲突通过负责人和顺序合并解决，不擅自增加业务依赖，也不为并行新增长期兼容层或双写路径。

## 真实验证资源也需要排程

代码可以并行开发，真实浏览器和模型验收不一定适合同时运行：

- 同一专用账户的真实浏览器旅程建议串行安排，避免登录、页面导航、退出和删除测试互相干扰。只有明确的并发验收场景才同时操作，并记录预期行为。
- 不同工作树的测试使用隔离数据库、临时目录和服务端口；不能让一票的清理删除另一票的会话或夹具。
- 删除与故障注入使用独立临时账户和测试数据，不能对用户主账户实施破坏性验收。
- 外部验证按当前有效授权和额度执行，记录调用范围及实际次数；历史单次授权不当作持续额度。不要由多个智能体重复提交同一真实验收。
- 03、04 及后续分页票在各自阶段取得真实证据，不等到 15 才首次尝试上游。脱敏夹具与替身测试必须明确标识。

## 每批执行流程

1. **领取前核对。** 阅读执行方案、工单与前置交接；确认验收结论和集成版本。当前状态以工单记录为准，不能依赖本 README 的发布时快照。
2. **记录认领。** 在工单 Comments 中追加负责人、开始时间、工作树及基线，避免重复领取；沿用现有分诊状态，不自行新增 `claimed` 或 `done`。
3. **建立验证。** 先复现本票问题或建立行为测试，再最小范围实现。协议能力必须实际验证，不按参考源码猜测。
4. **票内验证。** 完成该票端到端验收、必要静态检查与回归；前端变更必须构建，协议变化同步生成，实际涉及 schema 或存量数据时执行对应迁移。
5. **逐票集成。** 协调者按共享边界顺序合入已验收成果。后合入的票基于最新结果复验受影响链路，不能把各分支单独通过当作组合后通过。
6. **解除阻塞。** 记录集成版本、命令与退出码、真实/模拟证据、未通过项及回滚办法。只有行为验收合格，才能启动依赖它的下一票。

提交前仍须执行项目规定的完整检查；批次安排不豁免单票工程要求。完整检查发生既有失败时，按当前基线逐项比较；相关关键路径失败不能以“历史也失败”免验。

`ready-for-human` 表示等待人工复核，不自动代表验收成功。外部环境阻塞须留下具体原因、已尝试方法和恢复步骤；没有返回结果、被中断或缺少构建产物的命令不记为通过。

## 给执行智能体的任务模板

将下面的编号替换为实际待领取工单，附上对应工单链接即可：

> 执行贴吧模块工单 NN。先阅读本目录执行方案、本 README 和该票全部内容，核对 Blocked by 对应的验收证据与集成版本。仅实施本票，使用 conda agent 环境，在独立工作树记录认领和基线；先建立行为验证，再完成必要的代码、公开投影、中文状态和测试。共享接口改动先与协调者对齐；真实浏览器与模型验收按资源安排执行。已有能力优先复用，不修改原父工单。完成后交接测试命令及结果、真实与模拟证据、剩余限制、版本变化和回滚办法；前置未通过或关键外部能力无法验证时如实保持未完成，不擅自缩减验收范围。

## 完整交付标准

最终应有真实专用会话、真实贴吧上游和生产模型贯通的证据，以及认证、搜索、两层分页、时间/校区筛选、总结、引用、截止、停止恢复和账户隔离的场景记录。所有声明以 [15 的验收条件](issues/15-release-acceptance.md) 和 [执行方案](PRD.md) 为准。

本指南只安排开发工作，不授权自动部署或推送，也不改变原父工单状态。当前编写工作不启动任何开发智能体。
