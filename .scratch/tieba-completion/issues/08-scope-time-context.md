# 08 — 多帖证据遵守话题、校区和发言时间条件

**What to build:** 用户获得与指定话题、校区和时间范围匹配的讨论，近期、历史和未知时间清楚区分，相关纠正不会因措辞不同被误删。

**Blocked by:** 05 — 发现多页候选和仅在回复中出现的话题；07 — 楼中楼分页保留稳定身份和纠正上下文

**Status:** ready-for-agent

## 实施边界与关键决策

在当前筛选和时间逻辑上补齐跨页、回复命中和嵌套上下文场景。明确可用于观点的证据与仅供理解的历史父上下文。复用现有模型网关；若语义判断需要模型，调用纳入同轮预算。

## 验收条件

- [ ] 默认近十二个月优先；不足时明确补充历史，明确时间范围时不擅自补入范围外证据。
- [ ] 按发言时间筛选，老帖近期回复可纳入；只有月日、不可信年份或未知时区的情况不猜成近期。
- [ ] 明确校区冲突和仅同校区但无关话题被排除；无冲突且必要的上下文可保留，引用限制可验证。
- [ ] 标题无关但回复相关可进入证据；反驳、否定、纠正及常用别称不被简单关键词筛选抹掉。
- [ ] 历史父上下文标为仅上下文，不成为近期观点的引用；不同时间说法变化在总结中有依据。
- [ ] 候选数、已读数、合格证据数与排除原因分别记录；无合格证据不能表达成吧内不存在讨论。

## 验证方式

固定日期的时间边界矩阵 + 校区/反驳样例 + 真实默认时间与明确时间各一条旅程。

## 不在本票范围

不重写已通过的来源策略，不以检索日期补年份，不把未经核验的网友说法当规定。

## 通用执行与交接要求

- 执行前阅读本工作流执行方案及领域合同；复核当前实现，已有通过能力优先复用，不能依据历史问题描述重建已完成模块。
- 使用 conda agent 环境。先建立能捕获本票缺陷/行为的测试，再实现；每票包括所需公开投影、中文界面状态和端到端验证，不以单层完成替代行为交付。
- 外部协议须由真实响应验证；若主路径不能满足合同，说明验证过的备选与剩余差距，不静默缩减范围。不得搬运参考项目源码或引入其业务客户端。
- 共享预算、账户、任务版本、租约与证据边界保持一致；内部旧路径直接移除，不新增长期双实现。稳定API及历史数据按外部合同评估。
- 提交前执行项目完整检查，前端变更额外构建，协议变更同步生成；schema/存量数据变化才执行对应迁移。变更源码及测试单文件不超过500行，必要拆分只限本票职责。
- 交接记录实际行为、测试命令及退出码、真实/模拟证据、未验证项、回滚方法、公开契约与版本变化。完成实现但待人工复核可转 ready-for-human；只有验收证据合格才解除下游阻塞。
