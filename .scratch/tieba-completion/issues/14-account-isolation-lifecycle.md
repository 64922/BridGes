# 14 — 账户隔离与浏览器生命周期闭环验收

**What to build:** 两个账户搜集互不影响，退出、删除账户或服务关闭后不会残留可续跑的任务和可被别的账户访问的贴吧证据。

**Blocked by:** 10 — 停止、登录等待和故障后从有效证据续接

**Status:** ready-for-human

## 实施边界与关键决策

在现有账户目录、OS锁、删除fence与worker池基础上验证新排队/认证/分页恢复链路，修复确有缺口的行为。浏览器进程、请求队列、会话文件和证据仓储的所有权保持清晰。

## 验收条件

- [x] 双账户并发和同账户多聊天分别验证会话隔离、任务数据隔离和账户内串行/受控调度，无跨账户缓存或引用。（自动化：双账户 worker、同账户串行、同账户两会话顺序任务隔离）
- [x] 删除发生在锁等待、浏览器启动、认证等待、分页和恢复前时，fence均阻止旧任务；不能绕过删除标记重建profile。（自动化故障注入）
- [x] 删除失败保留可重试状态，不能假报清理成功；再次清理不删除其他账户目录，不引入跨进程锁竞态。（自动化故障注入）
- [x] 服务关闭、worker崩溃、池容量淘汰及任务终态后，资源按现有合同有界回收；成功后保留会话与保留任务执行权分开。（自动化与既有回归）
- [ ] 日志、模型输入、公开投影、导出和验收材料不含Cookie、令牌、认证响应秘密或其他账户原文。（已覆盖错误载荷、读取投影、搜索命中与导出隔离；日志/模型输入/验收材料未单独验证）
- [ ] 账户隔离自动化和真实专用会话生命周期证据分别记录；真实账户缺失时明确未验收项目。（真实专用账户证据缺失，见下方未验收项）

## 验证方式

独立临时账户/目录故障注入 + 并发删除回归 + 实际专用worker退出检查；不对用户主账户做破坏性验收。

## 不在本票范围

不新增多租户基础设施，不顺便改造全应用账户系统，不读取个人浏览器秘密。
