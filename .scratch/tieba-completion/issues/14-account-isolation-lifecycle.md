# 14 — 账户隔离与浏览器生命周期闭环验收

**What to build:** 两个账户搜集互不影响，退出、删除账户或服务关闭后不会残留可续跑的任务和可被别的账户访问的贴吧证据。

**Blocked by:** 10 — 停止、登录等待和故障后从有效证据续接

**Status:** ready-for-agent

## 实施边界与关键决策

在现有账户目录、OS锁、删除fence与worker池基础上验证新排队/认证/分页恢复链路，修复确有缺口的行为。浏览器进程、请求队列、会话文件和证据仓储的所有权保持清晰。

## 验收条件

- [ ] 双账户并发和同账户多聊天分别验证会话隔离、任务数据隔离和账户内串行/受控调度，无跨账户缓存或引用。
- [ ] 删除发生在锁等待、浏览器启动、认证等待、分页和恢复前时，fence均阻止旧任务；不能绕过删除标记重建profile。
- [ ] 删除失败保留可重试状态，不能假报清理成功；再次清理不删除其他账户目录，不引入跨进程锁竞态。
- [ ] 服务关闭、worker崩溃、池容量淘汰及任务终态后，资源按现有合同有界回收；成功后保留会话与保留任务执行权分开。
- [ ] 日志、模型输入、公开投影、导出和验收材料不含Cookie、令牌、认证响应秘密或其他账户原文。
- [ ] 账户隔离自动化和真实专用会话生命周期证据分别记录；真实账户缺失时明确未验收项目。

## 验证方式

独立临时账户/目录故障注入 + 并发删除回归 + 实际专用worker退出检查；不对用户主账户做破坏性验收。

## 不在本票范围

不新增多租户基础设施，不顺便改造全应用账户系统，不读取个人浏览器秘密。

## 通用执行与交接要求

- 执行前阅读本工作流执行方案及领域合同；复核当前实现，已有通过能力优先复用，不能依据历史问题描述重建已完成模块。
- 使用 conda agent 环境。先建立能捕获本票缺陷/行为的测试，再实现；每票包括所需公开投影、中文界面状态和端到端验证，不以单层完成替代行为交付。
- 外部协议须由真实响应验证；若主路径不能满足合同，说明验证过的备选与剩余差距，不静默缩减范围。不得搬运参考项目源码或引入其业务客户端。
- 共享预算、账户、任务版本、租约与证据边界保持一致；内部旧路径直接移除，不新增长期双实现。稳定API及历史数据按外部合同评估。
- 提交前执行项目完整检查，前端变更额外构建，协议变更同步生成；schema/存量数据变化才执行对应迁移。变更源码及测试单文件不超过500行，必要拆分只限本票职责。
- 交接记录实际行为、测试命令及退出码、真实/模拟证据、未验证项、回滚方法、公开契约与版本变化。完成实现但待人工复核可转 ready-for-human；只有验收证据合格才解除下游阻塞。
