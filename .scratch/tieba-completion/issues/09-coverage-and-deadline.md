# 09 — 五分钟内优先覆盖多帖并准时收尾

**What to build:** 系统先给多个相关帖子读取机会，再深入重点讨论；在五分钟累计工作预算内留下总结与核验空间，慢请求不会让页面无限生成。

**Blocked by:** 08 — 多帖证据遵守话题、校区和发言时间条件

**Status:** ready-for-agent

## 实施边界与关键决策

基于现有预算账本、阶段调度与逐页产物安排搜索/读取/总结。实测请求节奏，串行页面导航与可并发数据请求分别调度。处理持续传输和未完成响应的墙钟截止，不只设置连接或单次read超时。

## 验收条件

- [ ] 一个超长帖不会独占全部读取时间；受控多帖样例在深入前获得跨帖首轮证据。
- [ ] 保留现有五分钟与交付预留合同，所有模型/检索调用均在同一累计预算中；人工等待以外的排队和退避计入工作时间。
- [ ] 慢响应、持续小块传输和worker无响应均在截止后有界终止；事先定义并测量清理容差，不能无上限等待。
- [ ] 真实限流/临时错误按分类有界退避，鉴权失败或终止状态不盲目重试，不引入规避限制手段。
- [ ] 截止或证据足够时停止新采集；有原文则部分总结，无原文则明确未取得，成功页不因最后一次失败消失。
- [ ] 记录请求类型、排队/网络耗时、阶段耗时、剩余预算和收尾原因，以实测校准节奏，不预先承诺固定采集数量。

## 验证方式

可控时钟与慢流服务器测试 + 多帖覆盖旅程 + 专用会话节奏实测；测试中的加速截止不替代真实耗时记录。

## 不在本票范围

不延长五分钟掩盖性能问题，不为页面静态资源统一套用业务分页频率；所有真实业务请求仍计量。

## 通用执行与交接要求

- 执行前阅读本工作流执行方案及领域合同；复核当前实现，已有通过能力优先复用，不能依据历史问题描述重建已完成模块。
- 使用 conda agent 环境。先建立能捕获本票缺陷/行为的测试，再实现；每票包括所需公开投影、中文界面状态和端到端验证，不以单层完成替代行为交付。
- 外部协议须由真实响应验证；若主路径不能满足合同，说明验证过的备选与剩余差距，不静默缩减范围。不得搬运参考项目源码或引入其业务客户端。
- 共享预算、账户、任务版本、租约与证据边界保持一致；内部旧路径直接移除，不新增长期双实现。稳定API及历史数据按外部合同评估。
- 提交前执行项目完整检查，前端变更额外构建，协议变更同步生成；schema/存量数据变化才执行对应迁移。变更源码及测试单文件不超过500行，必要拆分只限本票职责。
- 交接记录实际行为、测试命令及退出码、真实/模拟证据、未验证项、回滚方法、公开契约与版本变化。完成实现但待人工复核可转 ready-for-human；只有验收证据合格才解除下游阻塞。
