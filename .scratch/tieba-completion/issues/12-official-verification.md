# 12 — 明确核实时追加学校官网并区分两类结论

**What to build:** 只搜集讨论时仅使用贴吧；用户明确要求核实规定时追加学校官网，并清楚区分吧友说法、官方确认及未能核实的部分。

**Blocked by:** 04 — 打通单话题单帖的真实采集与引用总结

**Status:** ready-for-agent

## 实施边界与关键决策

沿用已有来源意图与官方读取链路，对新浏览器证据及预算分类做端到端补齐。官网请求、跳转、原文读取与模型引用遵守同一任务边界。

## 验收条件

- [ ] 同一话题“搜集住宿费讨论”不自动访问官网；“核实住宿费规定”才追加允许的官方来源。
- [ ] 官方确认必须来自实际读取且适用的官方原文，核对发布日期/生效范围；标题和搜索摘要不足以确认。
- [ ] 官网失败、过期或规定冲突时保留贴吧结果并明确未核实，不让局部失败抹掉已取得讨论。
- [ ] 官方跳转不越允许来源域，正文中的链接或指令不扩大来源；每次请求和重试进入共享预算。
- [ ] 正文与引用详情分别显示网友说法和官方依据；真实公开官方页面与受控过期/失败场景均有记录。

## 验证方式

来源意图成对旅程 + 官方读取失败夹具 + 至少一个真实适用官方来源核对。

## 不在本票范围

不扩展全网核验，不默认将规定类词语判为官方核验请求。

## 通用执行与交接要求

- 执行前阅读本工作流执行方案及领域合同；复核当前实现，已有通过能力优先复用，不能依据历史问题描述重建已完成模块。
- 使用 conda agent 环境。先建立能捕获本票缺陷/行为的测试，再实现；每票包括所需公开投影、中文界面状态和端到端验证，不以单层完成替代行为交付。
- 外部协议须由真实响应验证；若主路径不能满足合同，说明验证过的备选与剩余差距，不静默缩减范围。不得搬运参考项目源码或引入其业务客户端。
- 共享预算、账户、任务版本、租约与证据边界保持一致；内部旧路径直接移除，不新增长期双实现。稳定API及历史数据按外部合同评估。
- 提交前执行项目完整检查，前端变更额外构建，协议变更同步生成；schema/存量数据变化才执行对应迁移。变更源码及测试单文件不超过500行，必要拆分只限本票职责。
