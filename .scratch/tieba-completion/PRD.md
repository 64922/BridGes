# 贴吧信息搜集完整可用：执行方案（已确认）

日期：2026-10-18（Asia/Shanghai）。状态：用户已确认拆分，15张工单正式发布；未开始业务开发。

## 目标与范围

本工作流同时修复本次预算误报故障，并完成 ADR-0040 已确认、当前仍未验收的完整用户旅程。完成不是“测试全绿”或“返回一些链接”，而是用户从聊天提出华东交通大学吧的话题后，能经必要的自动登录、真实检索、分页读取、筛选、模型总结与支持核验，得到可追溯、有真实覆盖说明的中文回答。

完整可用不等于全吧穷尽采集。维持五分钟累计工作上限、人工登录/安全验证等待除外、默认近十二个月优先、显式条件优先、多帖覆盖优先，以及按需官网核验。明确标注部分范围是正常结果；缺少主要采集、认证或总结能力却仅显示降级文案，不能算完整交付。

不扩大到其他贴吧、持续全吧爬取、新工作台或额外平台。复用现有模型网关、运行内核、预算账本、账户隔离、节点产物和连续正文交互，不另造通用采集框架。

## 职责与数据流

聊天输入 → 当前任务条件与查询计划 → 专用会话认证及采集可用性 → 受控真实请求 → 经校验的候选与分页证据 → 话题/校区/发言时间筛选 → 模型分批归纳 → 引用及支持核验 → 连续正文与按需证据详情。

- 任务编排拥有当前账户、任务版本、运行租约、累计工作预算与停止状态。
- 浏览器适配器拥有专用上下文、认证信号、固定只读协议与请求调度；不拥有总结或聊天UI。
- 请求预算许可区分暂时容量不足与终止原因。排队必须有界、可取消，不阻塞完成事件；所有实际业务请求均可计量。
- 外部响应在边界校验，再转为候选或证据；协议字段不直接渗透到视图。搜索摘要只用于发现候选。
- 逐页证据与进度一致保存；真实身份、父子关系、时间、读取范围及未知字段独立表达。不得用文本哈希冒充上游身份。
- 总结与核验只消费当前任务可用证据；已读但未送模型、仅上下文、未核实、未读取分别说明。
- 公开投影只暴露可解释状态与合法恢复动作，凭据及不可信指令不进入执行权限。

不会先做横向大重构。01在修复页面加载的纵向路径中完成最小必要预算接口整理；后续每票沿用户可验收行为推进。若实施时发现更大的前置重构，先说明具体阻塞及小范围方案，不私自扩成全仓改造。

## 正式工单与依赖

1. [页面并发加载不再误报预算耗尽](issues/01-browser-concurrency.md) — 阻塞：无。用户发起贴吧搜集时，正常页面产生多个请求可以受控排队完成；只有真正时间耗尽才结束本轮，失败信息与真实原因一致。

2. [自然语言话题生成有效且不重复的检索计划](issues/02-topic-query-plan.md) — 阻塞：无。“我想获取关于宿舍的讨论”以宿舍、寝室等真实话题检索，指令词不进入查询，校区与时间条件保持有效。

3. [专用会话认证成功后自动续接原话题](issues/03-verified-auto-login.md) — 阻塞：01。明确未登录时自动打开官方登录页；用户完成登录后，系统独立确认认证和采集能力，自动继续有效任务，无需再发送话题。

4. [打通单话题单帖的真实采集与引用总结](issues/04-first-real-journey.md) — 阻塞：01、02、03。用户在应用内提出一个明确话题，系统从真实吧内候选读取至少一条相关原文，经生产模型生成有可核对引用的短总结。

5. [发现多页候选和仅在回复中出现的话题](issues/05-search-pagination.md) — 阻塞：04。标题不含话题、但回复确实讨论该话题的帖子也能被发现；候选不再局限于每个搜索标签的第一页。

6. [普通回复逐页读取并保存可恢复证据](issues/06-post-reply-pagination.md) — 阻塞：04。系统能读取首批可见楼层之外的普通回复，每页成功后保留证据，后续页面失败也能交付已有材料。

7. [楼中楼分页保留稳定身份和纠正上下文](issues/07-nested-reply-pagination.md) — 阻塞：06。楼中楼首批预览之外的反驳、纠正与补充可以被读取，并与正确父楼层一起呈现在总结依据中。

8. [多帖证据遵守话题、校区和发言时间条件](issues/08-scope-time-context.md) — 阻塞：05、07。用户获得与指定话题、校区和时间范围匹配的讨论，近期、历史和未知时间清楚区分，相关纠正不会因措辞不同被误删。

9. [五分钟内优先覆盖多帖并准时收尾](issues/09-coverage-and-deadline.md) — 阻塞：08。系统先给多个相关帖子读取机会，再深入重点讨论；在五分钟累计工作预算内留下总结与核验空间，慢请求不会让页面无限生成。

10. [停止、登录等待和故障后从有效证据续接](issues/10-stop-resume-recovery.md) — 阻塞：09。用户停止后没有新的后台请求；等待登录、进程中断或暂时失败后可从有效进度恢复，改了话题不会收到旧任务结果。

11. [多批次总结保留分歧、时间与可核对引用](issues/11-grounded-summary.md) — 阻塞：08。多帖和长讨论生成连贯中文总结，保留不同意见及时间变化，每个关键观点能回溯已读证据；部分模型失败仍诚实交付。

12. [明确核实时追加学校官网并区分两类结论](issues/12-official-verification.md) — 阻塞：04。只搜集讨论时仅使用贴吧；用户明确要求核实规定时追加学校官网，并清楚区分吧友说法、官方确认及未能核实的部分。

13. [完整旅程的进度、引用和历史结果可用](issues/13-delivery-and-history.md) — 阻塞：10、11、12。用户在连续正文中得到总结，生成期间看到真实阶段；引用在按需详情中可核对，失败能恢复，刷新或历史重开仍能理解原结果。

14. [账户隔离与浏览器生命周期闭环验收](issues/14-account-isolation-lifecycle.md) — 阻塞：10。两个账户搜集互不影响，退出、删除账户或服务关闭后不会残留可续跑的任务和可被别的账户访问的贴吧证据。

15. [完整模块真实验收与发布准入](issues/15-release-acceptance.md) — 阻塞：09、13、14。给出能证明模块完整可用的真实旅程与回归记录；未达到产品合同的缺口明确阻断“完成”，后续智能体可据同一证据复验。

依赖只表达行为前提；共享文件冲突是实施协调事项，不自动新增业务阻塞。编号不是全部串行顺序。当前可从01、02开始；每次选择所有前置票已验收的任务。04是第一个真实最小闭环，不能等15才首次碰真实上游。05与06分别扩大候选和普通回复；08统一新证据的条件语义；09/11分别推进采集时限与总结，12可在04后独立推进。

## 尚需实测的事实与阻塞处理

认证响应、搜索及两层回复的当前可用协议、稳定身份/时间字段和分页终止信号，必须由03—07在真实专用会话内逐票确认。历史源码中的接口名和参数不是当前可用性证明。结构化响应优先、页面补充；若两者均不能满足必要能力，记录尝试、样本和影响，保留该票未完成，提交具体调整方案，不静默换成参考项目客户端。

生产模型与上游验收按当前会话实际授权、工具和费用限制执行；历史一次性验收授权已经使用，不视为长期额度。此规划不发起任何外部请求或付费模型调用。实施者先准备可审阅的测试范围和预期调用数，仅在确有权限/额度门时请求补充；不因猜测风险重复确认已获授权的动作。

安全验证不应刻意制造风控。真实可观察场景记录真实证据；无法主动触发的分支用明确标识的故障注入覆盖。认证成功与正常采集/生产模型主路径必须有真实证据。

使用conda agent，核实实际加载的工作区代码和运行服务版本。提交前运行项目完整检查；后端包括pytest、Ruff和严格类型检查，前端包括typecheck、lint、单测与生产构建，公开协议变更同步生成并检查。schema和存量数据变更才执行相应迁移。历史失败按当前基线逐项比较，不能沿用旧日期的失败数量充当免责；本模块关键路径失败即阻断完成。无结果、中断或未生成构建产物不能记通过。
