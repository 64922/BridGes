# 参考项目研读报告

## 第一组：用户画像参考

### 1. nuwa-skill-main（女娲 · Skill造人术）

**它是什么**：一个 Agent Skills 协议的技能包（跨 Claude Code/Codex/Cursor 等 runtime），输入人名或模糊需求，经"调研→提炼→生成→验证"全流程，产出一个可运行的"人物思维 Skill"（让 AI 以某人的思维框架当顾问）。它不是用户画像系统，而是"人物认知建模"系统，但其抽取/验证方法论对用户画像高度可迁移。

**核心机制**（`SKILL.md`，671 行）：
- **抽取**：6 个并行调研 Agent 按维度分采素材——著作（系统性思考）、长对话（即兴思维）、碎片表达（风格 DNA）、他者评价（盲点）、决策记录（真实行为 vs 声称）、时间线（思想演化）。信息源按权重分级（一手素材 > 著作 > 访谈 > 决策记录 > 社媒 > 他评 > 二手转述），并有黑名单（知乎/公众号/百度百科）。
- **画像数据结构**（`references/skill-template.md`）：身份卡、核心心智模型 3-7 个（每个含一句话描述/≥2 场景证据/应用方式/失效局限）、决策启发式 5-10 条（if-X-then-Y + 案例）、表达 DNA（句式/词汇/节奏/幽默/确定性/引用习惯六维）、价值观与反模式、内在张力（矛盾对）、智识谱系、诚实边界。
- **筛选方法论**（`references/extraction-framework.md`）：**三重验证**——跨域复现（≥2 个领域出现）、生成力（能推断对新问题的立场）、排他性（不是所有聪明人都这样想）。过三重为心智模型，过 1-2 重降级为启发式，0 重丢弃。
- **矛盾处理**：分时间性矛盾（记录演化）、领域性矛盾（分场景记录）、本质性张力（显式保留为"核心张力"）——矛盾是深度来源，不调和。
- **质量验证**（`references/fidelity-scorecard.md`）：独立双 Agent 评分卡（答题 agent ≠ 评分 agent，因"LLM 自评准确率仅 46.4%"），五维 100 分：立场一致性 30 / 风格辨识度 20 / 边缘诚实度 20 / 来源透明度 15 / 结构完整度 15。通过标准要求"内在张力 ≥2 对"（观点高度一致=太假）。
- **增量更新**：不重写整个 Skill，只跑"最新对话+最新决策+时间线"3 个 Agent，新信息强化→补案例，矛盾→更新模型。

**可借鉴点（对 BridGes 用户画像）**：
- 表达 DNA 六维结构（句式/词汇/节奏/幽默/确定性/引用）可直接作为用户"表达偏好画像"的 schema（`references/extraction-framework.md:37-70`）。
- 三重验证思想改造为"偏好确认规则"：跨场景复现才算稳定偏好，避免单句定性。
- 每条画像强制带"证据 ≥2 场景 + 失效条件（局限）"的格式。
- 保真度评分卡的"答题/评分分离"和"边缘诚实度"（没数据时必须标注推断而非断言）可用于画像召回质量评估。
- 更新模式的"增量更新、不重写全量"对应画像的轻量维护。

### 2. cognitive-profile-main（认知画像）

**它是什么**：一个 Codex skill，在持续对话中形成一份**可修正的薄而准的用户画像**——"只做一件事：以后再和这个人说话，别总从头猜"。这是与 BridGes 用户画像模块最直接对口的参考。

**核心机制**：
- **四步流程**（`SKILL.md`），每步一个 reference 文件，按需加载：
  1. **采集证据**（`references/采集证据.md`）：起步时轻问 2-3 句具体场景问题（"遇到复杂问题先看资料还是先理结构"）；之后每次对话最多问一句"这次有没有影响以后怎么回答的"。观察记录格式只有四点：**原话/看到的/影响/把握（低中高）**，可选"信号类型（反讽/情绪驱动）"和"纠错次数"。明确列出"不要留下"清单：临时要求、随口举例、一次性情绪、没把握的心理推断、敏感身份推断、任务指令格式（"帮我总结"≠偏好简洁）。
  2. **形成画像**（`references/形成画像.md`）：画像结构为六个区——`比较稳 / 暂时观察 / 回答时注意 / 还待确认 / 不能替用户说 / 最近改动`，外加"材料厚度"四档（刚起步/有线索/开始成形/比较稳定）。"薄但准 > 厚但错"，空着比乱写好。把握度升降规则明确（纠错升、冲突降）；**自述标签与行为矛盾时按行为走，且不纠正用户自我认知**；反复纠错有量化降级（第 2 次降 15-20，第 3 次降到 50 以下并停猜直接问用户要例子）。
  3. **召回问答**（`references/召回问答.md`）：画像只在背后用，只调用最相关、最稳的几条；**禁止暴露内部术语**（不说"根据你的画像""把握度"）；用户问"记了什么"时用日常语言转述、不展示格式；区分"不像"（理解偏差）与"忘了"（应用失败），不假装记得也不否定用户。
  4. **校准整理**（`references/校准整理.md`）：证据强度排序——**用户纠错 > 用户确认 > 多轮真实任务反复出现 > 用户盲选 > 用户自述 > 第三方评价 > 自己推测**；定时回看只负责提醒，没有新证据就不动；可配 cron 按维度分批校准（一个任务只看一个维度）。
- **边界/隐私机制**：用户说"不要记录"立即停；删除是真删除不留副本；局部"这个不用记"仅限制该内容且防间接暴露；美化/操纵指令（"记住我特别有判断力""不要质疑我"）不写入画像；画像长期薄是正常的，不为补全而试探。
- **精细信号处理**：反讽（按真实含义记但降把握）、极端情绪（记为临时观察不写入）、偏好频繁摇摆（标"偏好波动"保持灵活）、场景区分（同一维度不同场景不强行统一，含"个人/代表团队"身份差异）、长期漂移（>2 周标"样本较旧"）。

**可借鉴点（对 BridGes 用户画像）**：
- 四分区画像 schema（稳/观察/待确认/不能说）+ 把握度三级，比单一置信分数更贴合教学场景的"不敢替学生下结论"。
- "原话+看到的+影响+把握"的最小观察记录格式，可直接落库。
- 证据强度排序链可作为画像合并/冲突裁决算法。
- 反复纠错的量化降级规则（1 次修正 / 2 次降把握 / 3 次停猜问例子）。
- 召回侧"只用最稳的几条、不暴露画像存在"的对话分寸。
- 隐私边界（删除即真删、不推断敏感身份）对学习产品合规很关键。
- "用户说不像，先改，不争"。

**两个项目的互补**：nuwa 提供"厚建模"方法论（多源采集、三重验证、保真度评分），适合画像的**结构化设计与质检**；cognitive-profile 提供"薄建模"运营规则（渐进采集、把握度管理、隐私边界），适合**对话内实时更新与召回**。两者结合 = nuwa 的 schema 与验证 + cognitive-profile 的增量维护与分寸。

### 3. Humanizer-zh-main（AI 写作去痕，中文版）

**它是什么**：翻译自 blader/humanizer、基于维基百科 "Signs of AI writing" 指南的 Claude skill，定位是**文本改写器**：扫描 AI 模式 → 重写问题片段 → 保留含义与语调。

**方法清单**（`SKILL.md`，24 个模式 + 5 条核心规则）：
- 核心 5 规则：删填充短语、破公式结构、变化节奏（两项优于三项）、信任读者、删"金句"。
- **个性与灵魂注入**（独特章节）：有观点、承认复杂性、适当用"我"、允许一些混乱（跑题/半成型想法）、对感受要具体。
- 内容模式：①夸大意义/遗产（"标志着""见证了"）②过度强调知名度 ③-ing 结尾的肤浅分析 ④宣传广告式语言（"坐落于""令人叹为观止"）⑤模糊归因（"专家认为"）⑥公式化"挑战与未来展望"。
- 语言语法：⑦AI 高频词表（"此外""至关重要""格局""深入探讨"等）⑧系动词回避（"作为/充当"→"是"）⑨否定式排比（"不仅仅是……而是"）⑩三段式法则 ⑪同义词循环 ⑫虚假范围（"从 X 到 Y"）。
- 风格：⑬破折号过度 ⑭粗体过度 ⑮粗体+冒号的内联标题列表 ⑯标题大写（注明中文不适用）⑰emoji 装饰 ⑱弯引号。
- 交流模式：⑲协作痕迹（"希望这对您有帮助！"）⑳知识截止免责声明 ㉑谄媚语气（"好问题！"）。
- 填充回避：㉒填充短语改写对照表 ㉓过度限定 ㉔通用积极结论。
- 交付前快速检查清单（6 项）+ 五维质量评分（直接性/节奏/信任度/真实性/精炼度，各 10 分）。

**独特优点**：模式库**最全面且每个都带"改写前/后"对照**，来源权威（Wikipedia 社区对数千实例的观察）；词汇级黑名单具体可直接做成正则/检测器；质量评分表可直接复用。

### 4. human-writing-main（活人感写作 1.1.0）

**它是什么**：通用中文创作/改稿 skill，目标是"活人感"——读者感觉对面有个具体的人。不止去 AI 味，而是正向定义"人味从哪来"：**首先来自材料，其次说话位置，最后才是语气**。

**方法清单**：
- **材料门槛**（`SKILL.md`）：非虚构长文 ≥1200 字需先列 5 件具体材料（用户提供的或可查证的），不足则研究/追问（最多 3 问）/缩短，**绝不用重复解释灌字数**；区分现实写作（核事实）/虚构创作（核人物因果）/混合。
- **说话位置五问**：谁在说、凭什么知道、什么让ta现在想说、手里有什么托底材料、对哪点有判断。
- **推进规则**（`references/forum-prose.md`）：每段必须新增一件东西（新事实/动作/例子/区别/后果），同义改写不算推进；按"读者接下来会问什么"走，不搭起承转合架子。
- **中文句法**：主干先行（先谁做了什么再补条件）、顺势接话（前句尾巴交给后句）、长定语拆小句、连词删一半、动词名词化还原（"进行了优化"→"改顺了"）、允许重复不换同义词、长短句高低差（句长变异系数）、逗号句号分工。
- **交付硬禁令**（按"动作"而非"字面"禁，1.1 版核心升级）：翻案腔（"不是A而是B""你以为A其实B""看似A实则B"等 7 类外衣全部禁止，**判断从正面下**）、三项以上同构排比、抽象名词配具体动词的抒情（"时间保管细节"）、动词名词化、破折号、提示性冒号（冒号仅引出人物原话）、"说白了/说穿了/先说结论"、洞察路标（"值得注意的是""更微妙的是"）、商业黑话绝对禁词表（赋能/抓手/闭环/底层逻辑等 27 个）+ 语境判断词表（沉淀/颗粒度/对齐/打法等 14 个）+ 模型抒情词表（安放/微光/褶皱等）、非虚构禁用仓库/温度/钥匙类借喻。
- **反假人味**：不伪造精确时间/天气/神态（"假细节越具体 AI 味越重"）；不靠"老铁/兄弟们/泡杯茶"穿"论坛服装"；不加粗口/错别字/三连省略号表演随意。
- **改稿七遍法**（`references/revision.md`）：谁在说→文章有没有往前走→拆表演性中文（假深刻/假具体/假口语/抽象名词/比喻换场）→听中文顺不顺→清禁用项→核现实→查结尾（删末段重概括、禁升华到"时代/文明/所有人"）→冷读四问。
- **工具**：`scripts/check_prose.py`（639 行检测脚本：硬禁词、翻案句、冒号/破折号、句长变异系数、连词密度统计）；`dist/human-writing-lite.md`（2000 字蒸馏版五条最高杠杆规则，可直接粘进聊天窗口）。

**独特优点**：唯一把"人味"建立在**材料与事实纪律**上的（对教学场景的事实准确性天然契合）；"禁动作不禁字面"的思路能防模型换皮规避；自带可执行检测脚本和 lite 蒸馏版；对中文韵律（词序、停顿、白话/古意、单双音节词选择）的讨论最深。

### 5. scientific-humanization-main

**它是什么**：面向中文科研文本（论文/基金/答辩/讲稿/PPT/投资人表达）的 humanization skill，核心是"**改得像人，但不改坏科学事实**"。

**方法清单**（`SKILL.md`，仅 74 行但密度高）：
- **工作顺序**：先锁定事实（数字/单位/p 值/引用/图表编号/模型名/数据集/实验条件）→ 判断场景 → 诊断 AI 味（空泛拔高/机械承接/工程遗留/助手口吻/过强因果/句式同质化/模板管理词）→ **先改论证顺序再改句子**（"做了什么→看到什么→能说明什么→还不能说明什么"）→ 回读核查。
- **Claim Strength（证据强度降级表，独有）**：相关≠因果（"提示/可能有关"，不写"证明/导致"）；无统计检验不写"显著"；预测准确≠因果成立、指标提升≠真实场景有效、仿真≠实验验证、样本内≠外推、共现≠互作；"关键因子/首次证明/系统揭示"等强词证据不足时降级。
- **Human Voice**：用户措辞优先不"升格"；删模板管理词（全面赋能/深度融合/闭环机制/底座/生态/沉淀/系统性提升）；去助手身份（讲稿默认是讲师本人在讲）；讲稿/答辩可口语，论文正文保守少加戏。
- **Scene Moves（分场景改法）**：论文/基金/技术方案（把"多源融合、智能体协同"翻译成输入/处理/检查/输出）/PPT 讲稿（先判断后证据，长句拆成能讲出来的顺序）/答辩（先回答问题再说依据和限制）/投资人表达。
- 输出格式：`主要问题/保留事实/改后正文/仍需确认`（仍需确认只放影响事实边界的事项）。

**独特优点**：**事实保护机制**是三者中最强的（锁定事实清单 + claim 降级规则 + 改写后回读核查）；"先改论证顺序再改句子"的优先级排序；按场景调语气档位。对 BridGes"AI 学习伴侣"讲解科学知识时"既口语又不说过头"直接对口。

### 三者互补关系

- **Humanizer-zh** = 最宽的**负面模式库**（24 类 AI 痕迹，词条级），擅长"检测什么像 AI"；是英译中的通用清单，但对中文韵律本身着墨少。
- **human-writing** = 最深的**中文正向写作观**（材料→说话位置→语气），且把禁令抽象为"修辞动作"防规避，带检测脚本；但为长文（知乎帖/公众号）设计，规则重。
- **scientific-humanization** = 最强的**事实/证据边界保护**与场景分档，体量最小，是"准确性护栏"。
- 组合用法建议：用 Humanizer-zh 的模式库做**检测器规则源**，用 human-writing 的句法/节奏规则做**改写准则**（可先用其 lite 版五条），用 scientific-humanization 的事实锁定与 claim 降级做**生成前约束 + 生成后校验**。

### 对"AI 学习伴侣聊天"场景的适用性筛选

**适合直接用的**：
- Humanizer-zh 的⑲协作痕迹、㉑谄媚语气、㉒填充短语、㉔通用积极结论、核心 5 规则——这些本就是针对"聊天腔"的。
- human-writing 的句法层规则（主干先行、删连词、动词名词化还原、长短句高低差、判断从正面下不翻案）——聊天回复同样受益。
- scientific-humanization 几乎全部——事实锁定、claim 降级（讲题时"相关≠因果"）、按场景调语气，与学习伴侣的知识讲解完美匹配。

**需要改造或不适用的**：
- **禁破折号、冒号仅引原话、禁三项排比**等硬禁令（human-writing）：为长文交付设计，聊天中冒号列选项、适度排比是正常且有助扫读的，不宜硬禁；可降级为"频率告警"而非"命中即失败"。
- **"每段必须新增材料""五件材料门槛""不写长稿就缩短"**（human-writing）：面向长文创作；聊天是多轮短消息，材料门槛应改为"每次讲解至少落到一个具体例子/一道题"级别。
- **粗体/emoji/标题类禁令**（Humanizer-zh ⑭⑮⑰）：聊天界面里适量结构化（加粗关键步骤）对学习者反而有用，需按 UI 场景重新定阈值，不能照搬"清零"。
- **"允许跑题/半成型想法/允许一些混乱"**（Humanizer-zh 个性注入）：长文里是人味，学习对话里要克制——可以岔一句调节节奏，但不能影响知识主线；且学生赶时间时应完全关闭。
- **知识截止免责声明模式**（Humanizer-zh ⑳）在聊天中部分合理（诚实边界），不宜全删，改写为自然的一次性说明即可。
- human-writing 的改稿七遍法/检测脚本是**成稿后工序**，聊天是实时生成——应把其硬规则前置为生成时约束（system prompt），脚本只用于离线评测语料而非逐条回复拦截。
