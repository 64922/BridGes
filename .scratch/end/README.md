## 目标

关闭以下四个用户现场发现的问题，全部修到根因，不得只修截图表象：

1. 画像闭环断裂：聊天中用户明确表示"改主意了，把这条画像内容修改成我喜欢学习卷积神经网络相关知识"，助手口头承诺"已经帮你把关注点换成 CNN"，但四维画像记录从始至终停留在"Transformer的相关基础知识"——"记录画像—调用画像—生成回答—用户反馈—修正画像"的闭环断在最后一环。
2. 学习模式误报"本轮未联网核实"：输入"我想学习卷积神经网络的相关基础知识"，DuckDuckGo 实际返回 5 条已抓取核验来源，教学卡却显示"已降级为模型知识回答（本轮未联网核实）"，回复正文被自动加上"本轮未联网核实：已搜索但未覆盖本轮目标"声明。
3. 输入框占位文案未体现真实能力：现文案"向 BridGes 提问，或描述你的学习目标"未覆盖论文搜索、文章人味化、生涯规划、生成图片/视频等自然语言可调用的功能。
4. 新聊天首页排版：聊天框上方格言字号偏小；输入框下方"BridGes 的回答会标注依据与来源；重要内容请核对引用。"需下移到屏幕底部。

本执行图采用已经讨论批准的方案：画像修正走**确定性纠正管道**（不引入模型工具调用、不做确认卡）；证据门走**目标词修正 + CJK 归一化 + 别名表**（不引入 embedding/模型语义判定）。

## 用户故事

- **US-01**：作为聊天用户，当我明确要求修改某条画像内容时，系统应真实地更新对应画像记录，回复措辞与真实写入结果一致；系统做不到时不得口头承诺已修改。
- **US-02**：作为学习模式用户，当联网搜索返回了覆盖本轮学习目标的已抓取来源时，我应获得标注来源的可靠教学，不被误报"未联网核实"；当来源真的不覆盖目标时，我仍看到诚实的缺口说明。
- **US-03**：作为新用户，输入框占位文案应直接告诉我可以搜论文、人味化文章、生涯规划、生成图片或视频。
- **US-04**：作为访客，新聊天首页的格言应清晰易读，免责声明应位于屏幕底部而非紧贴输入框。

## 已冻结决策

- 画像写入继续保持确定性、fail-open：**不引入模型工具调用，不做确认卡**；纠正意图识别、维度映射、原地 UPDATE 全部在抽取管道内完成。
- 助手回复必须与真实写入结果挂钩：只有系统确认写入成功，回复才可确认修改；未识别或写入被保护规则拒绝时，回复不得声称已修改，并引导用户到画像页手动操作。
- `correction_count >= 3` 的防抖动保护对聊天纠正同样生效，不得绕过。
- "本轮未联网核实"在来源真实不覆盖目标时仍是正确安全状态（沿袭上轮冻结决策），本轮只修**误判**，不得通过放宽门或删除提示掩盖真实缺口。
- 覆盖判定保持字面匹配本质与"≥1 条已接受来源"的二元门槛：不引入 embedding/模型语义判定，不引入新搜索提供方，不动公网 8 秒预算。
- 覆盖规则变更必须版本化（`EVIDENCE_COVERAGE_RULES_VERSION` 升版）并保留回归反例（如电力变压器干扰页对 AI Transformer 目标仍判不覆盖）。
- 占位文案、格言字号、免责声明位置只改用户指定内容，不夹带其他文案或排版变更；开发模板页（`app/templates/`）不在范围内。
- 日志、指标和审计不得包含画像正文、用户消息原文、账户标识或凭据。
