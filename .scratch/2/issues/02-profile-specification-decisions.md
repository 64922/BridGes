# 02 — 补齐画像剩余规格与验收决策

**What to build:** 形成可供后续画像票实施的完整规格，保留已确认原则，向用户呈现少量具体未决取舍并记录回答。

**Blocked by:** 无 — 可立即开始

**Status:** ready-for-agent

**验收：** 规格交付已完成（2026-09-30）；业务实现由后续画像票验收。

**优先级：** P0

## 任务内容

1. 汇总 D01–D09 已确认边界：明确事实/偏好/目标/约束、范围与明确有效期、目标并存、明确重新记住才恢复、当前要求优先、记录/使用分别控制、本地指令加语义候选、简洁列表按需展开、回答后异步。
2. 给出完整事实、主体/关系/对象/范围身份、精确证据、活动/被替代/过期/删除状态的最小合同方案。用户编辑权威与自动可靠度分开；自述基础与答题知识状态分开，不建设人格或全局能力标签。
3. 逐项提供具体选项：无明确期限如何使用；暂停/完成/替代信号及续期；失败或停止的回答是否触发提取；必要邻近上下文和可跳过消息；冲突未解决时如何保留；显式恢复范围与不确定近义的处理。
4. 明确删除画像、关闭长期使用、本轮不使用、停止记录与删除聊天原文的区别。重点决定被忘事实是否也在原文回补/摘要中受抑制；保留原历史可读不等于仍允许其用于个性化，不能默认宣称彻底遗忘。
5. 提出有/无/错误或过期画像的行为量表与成本基线方案。数值限额由实测决定；记录实际回答改善，避免以画像条数或套话作成功依据。用户确认后更新讨论、应用流程、相关 ADR/交互合同。

## 跨票接缝与责任

07、16–20、22、29、41 的画像实现依赖本票；这是用户对拆票方式的最新确认。本票只编写规格，不实施待定行为。

开发与验证使用 conda `agent`。保持现有账户隔离、首条消息后的模式固定、会话附件与全局知识库分域及历史可读/导出。新增持久状态须在本票内完成适用的版本化迁移、备份/导出、删除、审计和失败恢复，不留给最终集成票补做。仅修改本票必要接缝；不恢复退役创作、提醒、用户插件或项目工作台。
