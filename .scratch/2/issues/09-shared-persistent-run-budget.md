# 09 — 持久化整次运行预算与有限调整额度

**What to build:** 同次运行的节点、并行、重试和恢复共享截止时间与调用额度；预算耗尽时交付已核实部分或明确阻塞。

**Blocked by:** 03 — 锁定完整模型额度与每次调用版本；08 — 保存有来源的跨轮任务、有效条件与澄清

**Status:** ready-for-agent

**优先级：** P0

## 背景与需求

父聊天与模块各起计时，重试和恢复容易绕过整次运行上限；新模型核验和分支必须留出交付预算。

## 任务内容

1. 运行创建时冻结截止时间、调用/token 上限、已耗额度与核验/交付预留；计数持久化并由内核唯一修改，模型不能延时或扩容。
2. 按已确认初值方案试行：普通检索 60 秒、深入/书页最多 120 秒；核验交付先预留 15/30 秒；外部独立并行初期最多 2，初筛 20、普通重点深读 3、深入 5。作为待校准初值，不宣称性能承诺。
3. 整次运行最多一轮自动补证/调整，结构和内容修复共用此轮；每个登记的临时传输失败最多重试 1 次，检查错误类型、冷却和剩余额度。
4. 配方从必要节点、候选读取上限和有限修复计算调用数/token 上限。明确深入需求在创建时获更高预算，不由主智能体临时无限增加。
5. 恢复保留原截止和消耗；用户明确继续/修改建立新运行、复用有效产物。限流等待超过剩余预算就结束，有真实恢复时刻才按 Asia/Shanghai 显示。
6. 普通轻量交流沿用已验证超时；摘要、提取后台任务各有独立有界运行，调用目的分别计量。先贯通普通调用的停止/重试/恢复，10 贯通首个确定性模块。

7. 在共同上下文边界给出可核验分批计划时，执行登记的有界分批，冻结批次数/耗时和中间来源引用；不能保持原任务含义时返回受限结果，不自动缩小任务。

## 跨票接缝与责任

拥有运行预算账本；04 检查每次输入额度；各节点领取而非重建预算，38 展示实际受限原因，40/42 校准参数。

开发与验证使用 conda `agent`。保持现有账户隔离、首条消息后的模式固定、会话附件与全局知识库分域及历史可读/导出。新增持久状态须在本票内完成适用的版本化迁移、备份/导出、删除、审计和失败恢复，不留给最终集成票补做。仅修改本票必要接缝；不恢复退役创作、提醒、用户插件或项目工作台。

## 验收标准

- [ ] 并行和串行消耗同一账本，租约恢复、结构修复及供应商重试均不重置额度。
- [ ] 第二轮自动补证、超额调用或超时等待被代码拒绝；仍保留必要核验/交付空间。
- [ ] 用户停止后没有新调用，明确继续才创建新预算运行；等待输入不消耗后台执行资源。
- [ ] 初值/真实实测/调整结果分别记录；消耗与诊断脱敏，不记录凭据。
- [ ] 持久计数、取消竞争和进程恢复的幂等/版本守卫可测试，新增账本生命周期完整。

## 验证与交付证据

用可控时钟与调用适配器验证并行、冷却、重试、自动调整和重启，不依赖真实睡眠测上限。

记录实际代码/合同版本、运行环境、测试及其限制。确定性模型/工具响应只能证明机制，真实模型体验和外部可得性分别按评测票验证。本票完成时补充实现说明、接口/迁移变化与验证结果，维护阻塞消费者可用的接缝；设计文档和历史基线通过数不能充当本次实施通过证据。
