# 08 — 保存有来源的跨轮任务、有效条件与澄清

**What to build:** 同会话任务跨轮延续，最新纠正及时替代旧值；话题切换后只恢复仍有效条件，澄清不占执行资源。

**Blocked by:** 01 — 记录已确认合同替代与增量迁移接缝

**Status:** ready-for-human

## 任务内容

1. 在现有 SQLite/会话底座增加小规模任务、不可变任务版本、当前指针与等待记录；普通聊天轻量，不为每句话创建复杂持久任务。
2. 记录目标、明确条件、确认决定、开放问题和结果引用及原话 ID/范围。用户明示直接生效；助手未获接受的方案是草案，模型推测只作线索。
3. 条件默认绑定目标/对象对应任务，用户明示才扩展到会话。模块切换不必然换任务；切换无关话题暂停旧条件，回原任务恢复最新值，撤销/纠正不复活。
4. 澄清绑定账户/会话/任务/预期版本/缺失字段/问题/来源消息。只接收匹配答复；新话题、画像命令或学习动作不填旧等待。等待不保留工作租约。
5. 任务、运行和产物可信状态分开：消息 DONE 可以是澄清成功而任务仍待输入；部分完成、阻塞、暂停、取消各有含义。
6. 用普通任务的等待→答复→完成端到端贯通持久版本、API 投影、恢复与旧消息兼容；领域仓库拥有写模型，图只存引用。

7. 同一会话初期只允许一个前台可写运行，多个模块在该运行内并行；暂停/等待释放资源。条件明确修订生成新版本，完成目标可继续修订，已取消目标不悄悄恢复旧等待。

## 跨票接缝与责任

拥有共同任务/条件/等待权威合同；11 定位对象，12 产生任务关系，10 与模块票提交产物依赖。学习阶段继续由学习领域服务拥有。

开发与验证使用 conda `agent`。保持现有账户隔离、首条消息后的模式固定、会话附件与全局知识库分域及历史可读/导出。新增持久状态须在本票内完成适用的版本化迁移、备份/导出、删除、审计和失败恢复，不留给最终集成票补做。仅修改本票必要接缝；不恢复退役创作、提醒、用户插件或项目工作台。

## 验收标准

- [ ] 长消息末尾预算有来源；5,000 改 3,000 本轮即有效，话题往返不复活旧值。
- [ ] 选购→通勤→返回选购只携带各自相关条件；明确全会话限制正确保留。
- [ ] 旧澄清后换话题再说“好的”不误填等待，等待终态释放租约。
- [ ] 助手提议与摘要推测不能直接变成用户约束；工具事实保留自身证据来源。
- [ ] 新增状态有版本化迁移、导出、删除、审计及重建/恢复；账户隔离和乐观版本冲突可验证。
