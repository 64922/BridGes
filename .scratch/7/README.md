# BridGes 第七轮：意图路由、联网搜索与可靠性修复方案

Decision status: approved

Last updated: 2026-08-14

## 目标

把用户《七次改进》中实际遇到的四个生产问题修到可验证：自然语言请求精准路由到对应功能、论文搜索在超时/限流下可靠、学习模式真正能联网并在联网失败时完整降级、人味化/生涯不再 120 秒空等。

- 用户发送「帮我人味化这篇文章」「给我规划一下……」「给我找几篇关于……的论文」时，必须精准调用「文章人味化」「生涯规划」「论文搜索」；人味化轮次要查询并披露用户画像。
- 论文搜索（arXiv）在「先超时、手动重试、再吃 429」场景下不再失效：结果缓存、请求节流、限流冷却与准确的重试引导。
- 学习模式的通用网页搜索提供方由 DuckDuckGo 更换为 Tavily（用户已提供 Key，本机实测可达）；联网失败时的降级链覆盖「本地材料不足」组合，不再只剩一句拒绝，且画像参与回答。
- 人味化/生涯规划的结构化模型调用按剩余预算截断，预算不足不重试，人味化支持首稿部分交付，真实上游错误不再被 `budget_exceeded` 文案掩盖。

本方案的可靠性定位是：

> **路由精准、联网真实、降级完整、失败有准确边界、等待有硬上限。**

## 用户故事

- `US-01`：作为用户，我说「帮我人味化这篇文章」「给我规划一下我的学习任务」「给我找几篇关于 Transformer 的论文」时，系统必须调用对应功能模块，而不是落入普通陪伴聊天。
- `US-02`：作为人味化用户，我希望系统参考我已授权的用户画像（如身份、风格偏好），并在「本次上下文说明」中如实披露。
- `US-03`：作为论文搜索用户，搜索超时后我重试时不会立刻再吃限流；相同主题的重复搜索命中缓存；被限流时我能看到准确的剩余等待时间。
- `US-04`：作为学习模式用户，系统能通过 Tavily 真实搜索网页并抓取内容形成教学内容；联网成功时给出可核验来源。
- `US-05`：作为学习模式用户，联网失败且本地材料不足时，我仍能获得由真实 Qwen 提供、明确标注「本轮未联网核实」的背景回答，而不是只有一句拒绝。
- `US-06`：作为人味化/生涯用户，模型调用慢时系统在预算内有界等待；实在放不下时给我已完成的草稿而不是两分钟空等后的一句报错；失败时告诉我真实原因。
- `US-07`：作为部署者，我在终端输入「BridGes」启动项目时，按提示依次输入 Qwen Key 和 Tavily Key 即可完成安装，Key 不进入仓库、日志或任何票据。
- `US-08`：作为发布负责人，我有一条失败关闭的发布门证明：生产搜索提供方只有 Tavily、降级语义正确、路由金标全过、密钥零泄漏。

## 已验证现状

### 意图路由与画像注入

全部意图路由为确定性关键词规则，无模型分类器。已在当前 HEAD 实测：

- 「帮我人味化这篇文章」「给我人味化润色这篇文章：<长文>」能命中人味化路由（`route_humanizer_message`，`src/bridges/skills/humanizer/intent.py:63`）；「给我找几篇关于 Transformer 的论文」能命中 `paper_search`（`src/bridges/routing/service.py:255-304`）。这两套路由均为 2026-08-10 才合入（f7cabd8、2756448），生产截图中的漏路由最可能是生产构建早于该版本。
- 「给我规划一下我的学习任务」**在 HEAD 实测仍落入普通聊天**：`routing/service.py:344-372` 的兜底组合要求「规划」与方向/职业/就业/工作同现，「学习任务」不在词表；`src/bridges/career/intent.py:43-74` 的弱关键词路径同样不覆盖。前端生涯建议卡文案「帮我排一下研究生三年的学习优先级」（`apps/web/src/components/bridges/chat-template.tsx:285`）实测也不触发。
- 人味化链路从不编译画像：`_stream_humanizer`（`src/bridges/chat/turn.py:3869-4344`）无 `use_profile` 参数、不调 `_compile_profile_slice`（`turn.py:5483-5684`）；生涯规划有画像编译（`turn.py:4613-4693`）；论文搜索刻意排除画像（`turn.py:3043-3050`）。
- 说法变体存在静默漏路由：「把这篇文章改得有人味一点」不命中（`REWRITE_ACTION_RE` 有「人味化」无「人味」，`src/bridges/skills/humanizer/contract_compiler.py:65-71`）；无命中即普通聊天，无任何兜底提示。
- 前端从不发送 `skill_id` 载荷，从聊天框触发能力完全依赖后端 NL 路由。

### arXiv 论文搜索超时与限流

生产观测：第 1 次尝试「arXiv 搜索超时」，用户手动重试后「arXiv 请求过于频繁（429）」。代码事实：

- 阶段预算 10 秒（`src/bridges/chat/budget.py:33-36`），Windows 上 worker 子进程 spawn + httpx 导入即消耗数秒；HTTP 超时被压成剩余预算（`src/bridges/arxiv_mcp/client.py:136-137`）。
- 客户端层无重试、无缓存、无任何针对上游的节流/最小间隔（全库 grep 无命中）；429 分类在 `client.py:163-168`。
- 手动重试路径（`retry_generation`，`src/bridges/chat/service.py:1636`）在前次 ERROR 后可立即重建 run 并再次打上游；第一次超时的请求已真实到达 export.arxiv.org，上游速率计数不撤销，立即重试必然落入限流窗口。
- 本机实测 `export.arxiv.org` 2.2 秒返回 200，上游非永久不可达；arXiv 官方建议请求间隔 ≥3 秒。

### 学习模式：DDG 不可达与降级空档

- 本机实测 DuckDuckGo 完全不可达（`html.duckduckgo.com`、`duckduckgo.com` 连接超时，无代理环境变量），第 6 轮冻结的 DDG-only 在该网络环境下永远无法成功。Tavily API 实测可达且返回真实结果（`api.tavily.com/search` 200）。
- 降级空档（确定性代码证据）：`src/bridges/learning/teaching_gate.py:363-373` 的 `allow_model_knowledge = not local and …`。本地知识库 docx 有命中但覆盖不足（`insufficient_coverage`）时 `local` 非空 → 禁止降级 → gap 取 `teaching_gate.py:430` 的拒绝文案 → `_turn` 拼出用户看到的拒绝句（`teaching_gate.py:1227-1231`）→ `turn.py:2647-2687` 短路返回，不调 Qwen、不推进进度。
- 画像编译点（`turn.py:3037+`）位于上述短路之后，拒绝路径不编译、不注入、不披露画像——用户抱怨的「没有调用用户画像」由此产生。
- 「暂按初学者处理」是硬编码字符串（`teaching_gate.py:1235`、`686`），不是画像兜底。

### 人味化/生涯 120 秒超时

- 整轮硬上限 120 秒（`src/bridges/chat/budget.py:30`）；两条链路均走非流式 `gateway.invoke("qwen_structured_output")`。
- 耗时算术与观测吻合：单次调用慢到静默被 httpx 60 秒掐断（`src/bridges/ai/qwen_client.py:146`）→ 网关重试第 2 次（`src/bridges/ai/production.py:79,94`）≈ 121 秒 + 前置检索 ≈ 观测到的 123/124 秒。
- 预算只在事件边界检查（`turn.py:4181-4209`、`4723-4749`），进行中的阻塞调用不可中断；`budget_exceeded` 检查排在 result 事件处理之前，会掩盖真实上游错误（`turn.py:524`）。
- 两条链路不下发 delta，用户全程只看到「已思考」；156 秒成功案例是「调用在预算外完成」的形态。

## 已冻结的 grilling 决策

1. **通用网页搜索提供方由 DuckDuckGo 更换为 Tavily**（用户已申请 Key）。安装流程在输入 Qwen Key 之后增加一步输入 Tavily Key，经系统凭据库保存；运行合同为 `BRIDGES_TAVILY_API_KEY` / `BRIDGES_TAVILY_API_KEY_FILE`。Key 值不进入仓库、票据、日志、运行锁或发布报告。本轮决策取代第 6 轮冻结决策 #2（DDG-only），对应 ADR 由 Issue 07 更新。产品后端直连 Tavily REST API，不引入 MCP 形态。
2. **学习模式降级范围扩大**：本地材料覆盖不足（`insufficient_coverage`）+ 联网失败时，允许真实 Qwen 基于本地材料与模型知识给出谨慎回答，显著标注「本轮未联网核实」，本地引用照常展示，不推进教学进度；仅本地材料冲突（CONFLICT）时保持拒绝。拒绝/降级路径也必须编译并披露画像。
3. **人味化轮次注入已授权画像切片**并在「本次上下文说明」披露；论文搜索维持「模型上下文只允许公开 arXiv 结果、不注入画像」的边界不变。
4. **意图路由只扩确定性词表 + 金标契约测试**，不引入模型分类器，不加前端显式入口。金标集必须包含用户点名的三类语句及其近似变体与负例。
5. **arXiv 可靠性全包**：相同规范化查询短 TTL 结果缓存；上游请求进程级最小间隔 3 秒；429/超时后进入短冷却，冷却期内重试直接返回准确错误与剩余等待秒数，前端重试按钮倒计时；阶段预算 10s→15s。
6. **时延修复全包**：每次模型调用的超时按「剩余预算 − 交接预留」截断；网关重试前检查剩余预算；人味化首稿完成但修订放不下时交付带标注的首稿而非报错；模型调用本身失败时透传真实错误码，不再被 `budget_exceeded` 掩盖；120 秒总预算不变。
7. **按 7 张 ticket 两波执行**：波次 A 为 01–06 并行，波次 B 为 07 收口。

## 全局完成定义

- 7 张 Issue 的验收标准、测试计划和依赖全部完成。
- 「帮我人味化这篇文章」「给我规划一下我的学习任务」「给我找几篇关于 Transformer 的论文」及其金标变体全部路由到对应模块，负例不被误劫持；金标契约测试进入常规回归。
- 人味化轮次编译、注入并披露画像；论文搜索模型上下文仍然只有公开 arXiv 结果。
- 生产通用网页搜索提供方只有 Tavily；安装流程在 Qwen Key 之后提示并安全保存 Tavily Key；缺 Key 时联网入口如实标注不可用，不伪装成功。
- 学习模式联网成功时给出经核验的真实来源；失败且本地不足时给出带「本轮未联网核实」标注的模型知识回答并注入画像；本地冲突时保持拒绝；三条路径都不推进教学进度（除可靠回答路径）。
- arXiv 相同查询命中缓存；上游请求间隔 ≥3 秒；429/超时冷却期内重试返回准确错误与剩余秒数，前端按钮有倒计时；阶段预算 15 秒。
- 人味化/生涯单次模型调用不再可能吃光 120 秒总预算；预算不足时不重试；人味化可交付带标注首稿；真实上游错误以自身错误码呈现。
- 发布门证明：提供方清单只有 Tavily、降级语义正确、金标路由通过、Tavily/Qwen Key 在锁、日志、投影与发布报告中零泄漏。

## 风险与处理

- **Tavily 同样是第三方，可能限流、欠费或变更接口**：不承诺永远可用；保留第 6 轮建立的有界重试、错误保真与降级语义，401 配置错误与 429 限流语义分离，发布门含 opt-in 真实 smoke。
- **Key 泄漏**：凭据库保存、环境变量注入、日志与锁字段允许列表、`scripts/artifact_secret_scan.py` 增加 `tvly-` 形态扫描；票据与文档只描述机制不记录 Key 值。
- **路由词表扩张误伤普通聊天**：金标集含负例（如「这篇论文讲了什么」保持普通聊天）；每条新词必须有对应测试。
- **arXiv 缓存导致结果陈旧**：短 TTL（10 分钟）、以规范化查询为键、仅缓存成功结果，失败与空结果不缓存。
- **预算截断导致长文人味化输出变短**：优先交付带标注首稿；截断与部分交付都在消息中如实披露，不冒充完整完成。
- **DDG 代码去留**：生产组合即刻只注册 Tavily；DDG 实现是否保留为测试夹具由 Issue 07 按 ADR 决定，生产路径不得再出现静默 fallback。
