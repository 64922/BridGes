# BridGes 严重缺陷收尾执行图

Status: `ready-for-agent`  
Approved: `2026-08-12`  
Source: `四次改进.txt`  
Contract authority: `CONTEXT.md`、ADR-0020、ADR-0025、ADR-0026

## 目标

彻底关闭以下三个用户可见缺陷簇，而不是隐藏错误提示或只修截图表象：

1. 学习模式对正常知识请求错误显示“本轮未联网核实”。
2. 中文论文请求约 8 秒后稳定返回 arXiv 超时。
3. 多轮对话已出现明确画像信号，但四维画像页面仍为空。

本执行图采用已经批准的方案：DuckDuckGo 继续作为主公开搜索提供方，同时允许一个经过 ADR 登记、显式配置、返回结构化结果的备用提供方；任何切换都必须可见、可审计，不能静默更换来源。

## 用户故事

- **US-01**：作为学习模式用户，我希望获得带可核实来源的回答；如果公开来源不可用，我应看到准确且只出现一次的可重试说明，系统不得伪造来源或推进正式课时。
- **US-02**：作为论文检索用户，我希望中文自然语言请求能在约定预算内返回主题相关论文；真正超时后应安全终止并允许立即重试。
- **US-03**：作为长期使用者，我明确表达的学业情况、知识兴趣和阶段目标应自动进入四维画像并在重启后保留。
- **US-04**：作为重视隐私的用户，历史回放不得复活已删除、已撤回、禁止记录或跨账户的数据。
- **US-05**：作为维护者，我希望发布门能在上线前发现提供方挑战页、协议变化、结构化抽取失效和后台任务泄漏。

## 已验证的失败基线

| 缺陷簇 | 确定性反馈回路 | 当前失败证据 | 修复后的关键断言 |
| --- | --- | --- | --- |
| 学习联网 | 精确输入“我想学习Transformer架构的相关知识”；公开搜索返回固定挑战页 | HTTP 202 挑战页被投影成 `empty`，四次同提供方请求，教学门降级 | 挑战页必须是提供方错误；备用源成功时有相关来源且无未核实提示；全失败时只提示一次且不推进学习进度 |
| 论文搜索 | 精确输入“给我找几篇Transformer方向相关的论文”；arXiv 替身在预算内延迟成功 | arXiv-only 被未参与的 web 8 秒预算截断；查询还携带中文指令噪声 | 相关论文可返回；web-only/arXiv-only/双来源预算分别为 8/10/10 秒；超时任务被有界回收 |
| 四维画像 | 将用户原句送入生产同构聊天、SQLite 和自动画像链路 | 跳过被记作成功但记录数为零；运行记录另有结构化合同失败和耗尽 | 三个有证据维度生成并持久化；兴趣爱好保持合法空态；历史失败可安全、幂等回放 |

这些反馈回路必须先固化成测试，再进入修复；不能用只验证理想 HTML、零延迟假客户端或手工播种画像的测试替代。

## 已冻结决策

- “本轮未联网核实”是证据不足时的正确安全状态，不得通过删除提示掩盖检索失败。
- DuckDuckGo 挑战页、异常 HTML 和真实零结果是三种不同状态，健康检查与业务搜索必须复用同一分类合同。
- DuckDuckGo 主用，备用公开搜索提供方必须结构化、显式配置、记录实际来源，并先更新供应商与预算 ADR。
- 独立提供方可以并行；同一 HTML 提供方的查询变体不得并发制造挑战风暴。
- 公共搜索查询只能包含完成当前任务所需的最小关键词，不能携带账户、画像、原始私有材料或无关对话。
- arXiv 阶段预算由实际活跃来源决定；聊天层、worker 和 HTTP 使用同一个绝对截止时间。
- 四维画像只覆盖学业情况、知识兴趣、兴趣爱好和阶段目标；敏感推断、第三方陈述、否定内容和单次行为不得被误升格为稳定画像。
- 历史修复必须先识别权威运行数据库并通过 schema、备份、墓碑、隐私阻止和账户归属门。

## 推荐执行波次

1. **第一波，可并行**：01、04、05、06。先固定三个红色反馈回路并修复无依赖根因。
2. **第二波，可并行**：02、03、07。公开搜索架构、学习合同和画像网关分别建立在第一波稳定合同上。
3. **第三波**：08。代码合同稳定后，才允许对存量画像运行 dry-run、迁移和回放。
4. **第四波**：09。通过真实 API、持久化、浏览器和联网探针执行最终发布门。

同一 Issue 只能在其所有 `Blocked by` 完成后认领；并行 Issue 不得通过复制公共逻辑形成新的分叉实现。

## 全局完成定义

- 所有 Issue 的验收清单均有自动化或可重复的人工证据，且不存在只靠截图判定通过的条目。
- 三条精确用户输入旅程在新账户、现有账户、服务重启和立即重试场景下均符合合同。
- Python 单元/集成测试、静态检查、Web 单元测试、类型检查及指定 Playwright 收尾测试全部通过。
- 联网能力通过预发布探针验证；无外网环境中的确定性测试不依赖实时第三方服务。
- 日志、指标和审计不得包含密钥、账户标识、完整用户原文、画像正文或私有材料。
- 数据修复有 dry-run、备份、幂等证明和回滚报告；未经确认不得修改用户权威数据库。
- ADR、运行说明、错误码和 UI 文案与最终行为一致，不再把挑战、超时、真实空结果混为一类。
