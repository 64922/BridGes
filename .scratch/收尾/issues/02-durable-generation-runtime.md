# 02 将回复生成从页面/SSE 生命周期迁移到持久化后台运行

Status: completed
Priority: P0
Type: architecture-enabling defect
Blocked by: 01
Blocks: 03, 06, 07, 08, 09, 11

## 用户价值

用户离开、刷新或稍后重开会话时，回复应继续生成并可恢复查看；“停止生成”必须只由显式操作触发。该切片同时消除生涯规划和人味化中大量伪装成“连接中断”的失败。

## 已确认根因

- 聊天页面卸载时主动调用停止消息并 abort 当前流。
- 服务端在 SSE 请求协程内执行完整生成；客户端断开会触发生成器退出并把消息终态写为 `stream_interrupted`。
- 数据库中人味化改写约 297 秒、生涯规划约 95 秒的失败均为 `stream_interrupted`，不是对应技能的领域错误。
- ADR-0013 已要求长生成运行在独立、受监督的本地后台执行器中。

## 要实现的纵向切片

复用现有本地后台执行器，把“生成运行”作为持久化作业。HTTP/SSE 只负责创建运行、订阅事件和显式停止，不再拥有运行生命周期。

最小运行状态：`queued → running → done | failed | stopped`。每次运行保存 run ID、会话/消息归属、当前阶段、事件游标、租约、尝试号、终态原因和脱敏耗时；部分内容按可恢复粒度持久化。

## 实施步骤

1. 先为普通聊天建立一条后台运行纵向切片：同一事务创建用户消息、助手占位与 queued run。
2. 后台执行器以租约原子领取运行；重复领取、进程重启和超时恢复必须幂等，最多一个尝试可提交终态。
3. SSE 改为按 run ID/游标订阅已持久化事件；断开只移除订阅者，不改变运行状态。
4. 页面重开时读取消息投影与 run 状态，从最后游标恢复，不重复发送用户消息、不重复调用模型。
5. 显式“停止”写入 stop requested，由 worker 在安全检查点终止并提交 `stopped`；页面卸载不得调用它。
6. 账户切换只断开当前视图；账户删除、会话删除等已有敏感生命周期操作仍需按领域规则取消相关运行。
7. 迁移现有技能分支走同一运行外壳，技能内部阶段由各专项 issue 收紧。

## 验收标准

- [ ] 发送消息后立即切到另一会话，原运行继续；返回时能看到阶段/部分内容，最终正常完成。
- [ ] 刷新页面、关闭并重开同一浏览器标签，不会产生第二条用户消息或第二个模型调用。
- [ ] 模拟 SSE 在首个 token 前、生成中途、完成前断开，运行状态均不变为 `stream_interrupted`。
- [ ] 只有点击“停止生成”才产生 `stopped`；停止操作在 2 秒内可见，且完成后不会被迟到事件改写成 done。
- [ ] worker 在持有运行时被强制退出：租约到期后最多恢复一次，或以明确可重试终态结束；不得永久 `running`。
- [ ] 同一 run 被两个 worker 竞争时，只有一个执行模型调用和提交终态。
- [ ] 跨账户无法订阅、读取或停止他人的 run。
- [ ] 普通聊天、人味化、生涯规划、学习模式均不再因路由切换写出 `stream_interrupted`。

## 反馈环

先写一个真实 HTTP + SQLite + 可控慢模型测试：模型分三次输出，每次由测试闸门放行。依次验证发送、断开、打开另一会话、重连、完成；在修复前它应稳定得到 `stream_interrupted`，修复后应得到单一 done 运行。

再增加租约竞争、进程重启、显式停止和跨账户测试。最后用 Playwright 在生成中切换会话 20 次。

## 约束与非目标

- 不引入 Redis、云队列或多机分布式调度。
- 不用无限内存缓存作为事件真相源；重启后仍应可恢复。
- 不以忽略客户端断开异常代替后台迁移；生成必须真正脱离请求栈。
- 不改变用户主动停止、账户删除等明确取消语义。
