## 用户价值

前置 issue 分别修复局部后，还需要证明它们组合起来不会重现用户截图中的严重问题，且新增后台任务、附件事务和安全状态机没有引入跨账户、重复执行、秘密泄漏等新故障。

## 要实现的纵向切片

建立并执行一套以用户九组场景为中心的发布候选验收。自动化使用 issue 01 的 Windows 真实链路测试入口；人工验收使用桌面浏览器和测试账户。最终产出 `.scratch/收尾/closeout-acceptance-report.md`，逐项记录命令、版本、结果、脱敏证据和遗留风险。

## 自动化验收矩阵

| 场景 | 正常路径 | 必做故障注入 |
|---|---|---|
| 新会话首轮 | 普通消息、技能入口均立即可见且进入最近列表 | started 延迟、响应重放、双击、刷新、返回/前进 |
| Shell/Logo | 路由后 Logo 正常，鼠标不显示 skip link | 键盘 Tab 仍可见且正确跳转 |
| 附件 | 新/旧会话上传图片和 DOCX，消息原子绑定 | 上传慢、绑定事务失败、跨会话 ID、发送重试 |
| arXiv | 中文/英文/Unicode 结果可解析 | worker 崩溃、非法 JSON、启动超时、网络超时、取消 |
| 人味化 | 生成正文；DOCX 改写只用当前附件 | 软门失败、硬事实冲突、模型超时、切会话 |
| 学习模式 | 五轮对话式教学闭环 | 无本地命中、公开搜索空/失败、跳过、追问、刷新 |
| 生涯规划 | intake 后生成可执行规划 | 结构非法、慢模型、辅助检索失败、切会话 |
| 后台生成 | 离开/刷新后继续并恢复 | SSE 断开、worker 重启、双 worker、显式停止 |
| QQ 验证 | 原页再认证、延迟邮件后 verified | 密码错误、60 秒邮件延迟、A/B 竞争、删除时迟到、超时 |

## 人工桌面验收脚本

1. 新建会话，从 `+` 上传一张图片和一个 DOCX；确认附件 chip 后发送，立即切换到旧会话，再返回。
2. 从首页调用论文搜索，搜索包含中英文的主题；检查进度、结果、错误恢复和最近列表。
3. 运行文章人味化“生成文章”，确认即使软风格门未完全通过也有正文；再用指定 DOCX 运行“改写文章”，确认没有无关知识库图片。
4. 输入“我想学习 Transformer”，选择初学者路径，完成至少五轮：目标确认、讲解、部分正确回答、追问、跳过。
5. 启动生涯规划，在生成中离开并返回，确认同一 run 继续且有最终计划。
6. 使用测试 QQ 账户验证 SMTP：触发近期认证过期，确认原页密码弹窗自动续交；收到验证邮件后等待 UI 显示已验证，再新建一条提醒。
7. 全程检查 Logo、主内容焦点、最近列表、阶段状态、停止按钮和中文错误文案。

## 验收标准

- [ ] 所有前置 issue 状态为完成并有对应测试提交；本 issue 不代替前置缺陷修复。
- [ ] 收尾自动化套件在 Windows 串行连续运行 3 次全部通过，无残留进程/端口/数据锁。
- [ ] 新会话首轮压力测试 100 次：空白、重复消息、遗漏最近列表、skip link 误显示均为 0。
- [ ] 生成期间随机执行 50 次会话切换/刷新：除显式停止外，`stream_interrupted` 为 0。
- [ ] 附件故障注入后，数据库不存在已成功消息却未绑定声明附件的状态；无跨账户可见性。
- [ ] 所有前台 run 在规定总预算内进入终态；没有 300 秒无反馈或永久 running。
- [ ] 人味化、学习、生涯规划分别通过正常、软失败/外部失败和离开恢复路径。
- [ ] QQ 60 秒延迟邮件最终 verified；旧 attempt 不能覆盖新设置；提醒仅在 verified 后可创建。
- [ ] 自动秘密扫描确认日志、trace、截图元数据和报告不含凭据/消息正文/附件正文。
- [ ] `closeout-acceptance-report.md` 对用户 1—9 每项标为通过，或列出明确未通过项、复现步骤与阻断发布决定。

## 发布门

以下任一项失败即不得宣称“彻底解决”：

- 新会话仍可能空白或丢失；
- 附件仍可能未绑定或回退到无关知识库；
- 离开页面仍会停止生成；
- arXiv 子进程 Unicode/退出错误仍统一误报；
- 人味化软门仍清空正文；
- 学习目标建立仍受事实证据门阻断；
- 任一技能可无反馈等待超过总预算；
- QQ 收件已到却在有效窗口内仍无法收敛，或为改善体验而取消了敏感操作保护；
- 发现跨账户读取、秘密落盘/落日志或旧后台任务覆盖新状态。

## 反馈环

先让验收矩阵中的每个场景在对应专项 issue 合入前至少失败一次，并保存脱敏失败证据；专项修复后使用完全相同的输入和故障注入转绿。本 issue 最后只组合运行既有测试、压力循环与人工脚本，不另造宽松替代断言。

若三轮 Windows 串行套件中任一轮失败，先按 run/attempt ID 定位到具体阶段，修复后重新从第 1 轮计数；不得只重跑失败用例后宣布通过。

## 报告要求

验收报告应包含：代码版本/提交、系统与浏览器版本、执行命令、自动化汇总、九组人工结果、耗时 p50/p95、故障注入结果、秘密扫描结果、未解决风险和发布结论。只引用脱敏 run/message/attempt ID，不复制用户正文或附件内容。

## 约束与非目标

- 不以人工“看起来好了”替代自动回归。
- 不用线上服务偶发失败否定本地确定性测试；线上 smoke 单独记录环境与时间。
- 不顺手扩展新功能或重做视觉设计。
- 不覆盖用户已有的历史验收报告文件；使用本 issue 指定的新报告名。
