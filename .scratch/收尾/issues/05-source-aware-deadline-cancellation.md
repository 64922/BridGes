# Issue 05：按活跃来源统一截止时间并有界回收超时搜索

Status: ready-for-agent  
Type: task  
Priority: P0  
User stories: US-02, US-05

## What to build

交付一条来源感知、可取消且可并发隔离的公开搜索纵向路径。用户提交“给我找几篇Transformer方向相关的论文”后，编排器只根据本轮实际启动的来源计算等待预算：web-only 为 8 秒、arXiv-only 为 10 秒、web 与 arXiv 并行为 10 秒，并始终受当前前台 run 剩余预算约束。聊天编排、搜索服务、受限 worker 与 HTTP 请求必须共享同一个绝对截止时间，不能各自重新起算或让较短的未参与来源截断较长来源。

截止时间到期或用户取消时，系统必须主动传播停止信号并有界回收 future、线程、管道和 worker；用户收到终态后不得还有会继续写审计或占用共享响应队列的旧搜索。共享 worker 必须通过互斥隔离或请求关联保证并发响应归属正确，一个请求的超时、取消、崩溃或立即重试不得污染另一请求。成功路径继续返回论文/网页结果和紧凑引用；真正超时则 fail closed，返回稳定中文可重试状态，不调用模型伪造证据。

## 已验证复现与根因摘要

- 无外网确定性复现使用精确用户输入和一个 9 秒后成功的 arXiv 替身。arXiv 合同为 10 秒，但当前聊天在约 8.02 秒返回 `arxiv_timeout`；把诊断进程中的网页预算临时调到 10 秒后，同一请求约 9.02 秒成功。
- 根因是公开搜索阶段无论实际启动哪些来源，都取 web 8 秒与 arXiv 10 秒的最小值。论文路由只提交 arXiv，却被未参与的 web 预算提前截断；相同预算计算在多个编排路径重复存在。
- 当前阶段等待超时后只执行非等待式线程池关闭，不设置取消信号，也不回收正在运行的 future。探针确认主流程返回超时终态时任务尚未完成，之后仍在后台继续执行。
- HTTP、worker 响应兜底、worker 重启和聊天阶段分别持有独立时限；它们没有共享绝对截止时间。应用又复用同一个无请求关联的 worker 客户端，因此超时后的后台调用会放大立即重试和并发响应串线风险。
- 正确虚拟环境下现有 arXiv worker、UTF-8、聊天和自然语言路由测试全部通过，说明现有覆盖停留在单层：慢搜索测试只覆盖 web，worker 超时测试不经过聊天预算，浏览器论文测试模拟了后端终态。

## 非目标

- 不改变前台 run 120 秒硬上限，不把 web-only 预算放宽到 10 秒，也不靠统一增加所有超时掩盖预算错误。
- 不把真正的网络超时改成成功，不缓存或伪造 arXiv 结果，不绕过引用和教学证据门。
- 不引入远程遥测平台、用户可管理 worker/MCP 或无限 worker 池。
- 不在本 issue 重写中文查询净化和 Transformer 相关性；该纵向行为由独立 issue 04 负责。
- 不保留“用户已收到超时、后台任务稍后自行结束”的最终一致性语义；终态必须与资源生命周期一致。

## Acceptance criteria

- [ ] 对精确输入“给我找几篇Transformer方向相关的论文”，只启动 arXiv 来源时使用 10 秒来源预算；一个 9 秒后返回固定论文的确定性替身必须成功并展示引用，不得在约 8 秒误报超时。
- [ ] 活跃来源预算矩阵固定为：web-only 8 秒、arXiv-only 10 秒、web 与 arXiv 并行 10 秒；未启动的来源不得参与计算，并行总耗时接近较慢的活跃来源而非两者之和。
- [ ] 来源预算还必须与 `RunBudget` 剩余时间取更严格者；剩余 run 预算不足时不得新开超出剩余时间的搜索或重试。
- [ ] 聊天编排、搜索服务、worker 握手/响应、HTTP 请求、重试门和清理路径消费同一个绝对截止时间；各层不得重新起算完整超时，也不得在相等的内外层超时边界制造竞态。
- [ ] web-only 永不返回的请求在 8.5 秒内进入稳定可重试终态，arXiv-only 永不返回的请求在 10.5 秒内进入稳定可重试终态；两者均不得保持 loading/running。
- [ ] 截止时间或用户取消触发后，未完成 future、线程、管道和 worker 在 2 秒内全部停止并回收；终态后不得继续产生成功审计、写入搜索投影或占用共享响应队列。
- [ ] 用户主动取消后 2 秒内得到 stopped/cancelled 终态，而不是 `arxiv_timeout`；取消一个并发请求不得取消另一个账户或另一个会话的请求。
- [ ] 一个 arXiv 请求超时后，用户立即点击重试可以在干净执行上下文中成功；重试不等待旧请求自然结束，不复用旧响应，不增加重复终态或矛盾审计。
- [ ] 两个并发请求返回不同固定论文时，每条响应都通过稳定请求关联回到原账户、会话和消息；不得交换论文、错误、取消信号或 worker 重启状态。
- [ ] 一个并发请求挂起或 worker 崩溃时，另一个正常请求仍能得到自己的结果；任何共享 worker 策略都必须有明确容量上限和背压终态，不得无限创建线程或进程。
- [ ] 真正的 arXiv/web 超时、网络不可达、限流、权限失败、worker 启动失败和协议损坏继续映射到各自稳定错误；证据不足时不调用模型、不生成虚假引用、不推进学习课时。
- [ ] 阶段事件、持久化消息和本地性能摘要对同一请求给出一致终态和耗时；超时来源、活跃来源、取消清理与重试次数可由脱敏指标解释。
- [ ] 既有 worker UTF-8、错误分类、崩溃后有限重启、取消、论文路由、聊天预算和浏览器恢复入口测试继续通过，且测试进程结束后无本套件遗留的搜索线程、worker 或数据锁。

## Test plan

- 新增来源预算纯函数/策略的表驱动单元测试，覆盖空来源、web-only、arXiv-only、both、较短剩余 run 预算和已耗尽预算。
- 将已验证的快速红灯固化为聊天集成测试：精确输入、缩放时钟、arXiv 响应落在自身预算内但晚于 web 预算，修复前稳定红、修复后稳定绿。
- 增加真实 8/10 秒尺度的收尾测试：9 秒 arXiv 固定成功必须成功；web 与 arXiv 并行时总耗时接近较慢来源；超出截止时间的挂起替身必须按 SLA 失败。
- 在 worker 边界注入可观察取消的挂起客户端，断言停止信号、future 完成、线程退出、管道关闭、worker 回收和终态审计均在有界时间内完成。
- 增加立即重试测试：首请求超时，第二请求立即返回不同固定论文；断言没有旧响应、重复投影、矛盾审计或额外 worker 重启污染。
- 增加多账户并发压力测试，使用查询特定响应、随机完成顺序、单请求超时/取消/崩溃，循环验证请求关联、隔离、容量上限和无残留资源。
- 增加真实 API 的确定性浏览器纵向测试，覆盖加载、9 秒内成功、超时中文恢复入口、取消和立即重试；不能只用页面路由直接注入最终状态。
- 使用仓库虚拟环境运行聊天预算、arXiv worker、自然语言论文路由、API、浏览器和收尾组合套件，并执行至少三轮串行压力验收。

## Observability & rollback

- 为每次公开搜索记录脱敏的活跃来源集合、预算来源、绝对截止时间相对值、阶段耗时、超时起源、取消清理耗时、worker 重启次数、请求关联 ID 和终态；不得记录查询、论文标题/摘要、消息正文或凭据。
- 区分聊天阶段截止、worker 响应截止、HTTP 超时、用户取消和背压拒绝，避免所有内部故障只表现为无法定位的 `arxiv_timeout`；用户侧继续保持稳定中文提示。
- 监控本地超时率、取消后残留任务数、终态后迟到写入数、请求关联错误数和立即重试成功率；残留任务、迟到写入和关联错误的验收值均为零。
- 来源感知预算与统一截止时间应通过版本化编排开关渐进启用，不需要破坏性数据迁移；旧持久化事件保持可读。
- 若新路径上线异常，可关闭新编排开关并临时将 arXiv 搜索收敛为明确可重试不可用状态。不得回滚到非等待式遗留后台任务或无请求关联的共享响应队列；资源回收与 fail-closed 门必须始终保留。
