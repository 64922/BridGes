# 03 原子创建新会话首轮并修复空白主区、最近列表和焦点异常

Status: completed
Priority: P0
Type: defect
Blocked by: 01, 02
Blocks: 04, 08, 11

## 用户价值

从首页发送第一条消息或调用任一功能后，应立即看到自己的消息、运行状态和新会话；不应出现中央空白、需要点别的会话才能找回，或左上角出现蓝色块。

## 已确认根因

- 首页先创建空会话，把首条提示与附件暂存在 `sessionStorage`，跳转到会话页后再真正发送，形成跨页面竞态。
- 最近对话接口有意过滤“无标题且消息数为 0”的草稿；侧栏在首条消息完成前没有收到可靠更新。
- 会话页直到服务端发出 started 才加入用户消息，首事件前主区为空。
- “跳转到主内容”无障碍链接在客户端导航后偶发获得焦点，触发其蓝色可见样式，覆盖 Logo 区域。

## 要实现的纵向切片

建立一个“准备并开始首轮”的原子命令：服务端在同一事务内创建会话、用户消息、助手占位和后台 run，然后返回完整投影；前端收到成功响应后再导航。`sessionStorage` 不再承担业务真相。

## 实施步骤

1. 新增或扩展首轮命令，允许带普通消息/技能意图创建会话并启动 run，使用幂等键抵御双击和导航重试。
2. 返回值至少包含 conversation、user message、assistant placeholder、run ID；前端立即渲染这些投影。
3. 侧栏在事务成功后立即插入/更新该会话；服务端列表对已存在用户消息的会话必须可见，不等待助手完成。
4. 路由直达、返回/前进、刷新均从服务端投影恢复，不消费一次性浏览器存储。
5. 梳理 App Shell 的焦点管理：客户端导航后将焦点放到稳定的主区标题/消息区；跳转链接只在真实键盘 `focus-visible` 时显示，鼠标点击/程序化路由不显示。
6. 失败时保留首页输入并显示明确错误；不得留下用户无法发现的空草稿。

## 验收标准

- [ ] 首页发送普通消息后 500ms 内可见用户气泡和“排队/生成中”状态，不出现空白主区。
- [ ] 会话在首轮事务成功后 1 秒内出现在最近列表，不依赖助手输出完成或点击其他会话。
- [ ] 连续双击发送、网络响应重放和浏览器返回/前进均只创建一个会话、一条用户消息和一个 run。
- [ ] 首轮命令失败时仍停留在可编辑首页，输入不丢失；没有不可见空草稿。
- [ ] 直接刷新新会话 URL 可以恢复相同消息和 run，不再依赖 `sessionStorage`。
- [ ] 鼠标发送、功能入口跳转和程序化导航不会显示蓝色“跳转到主内容”；按 Tab 时该链接仍可见且可用。
- [ ] Logo 在以上路径始终可见，且不是通过提高 z-index 掩盖焦点错误。
- [ ] 串行运行 100 次首轮场景，空白、重复和最近列表遗漏均为 0。

## 反馈环

先写真实 API 的事务测试和 Playwright 循环测试。测试在服务端 started 事件前设置 2 秒闸门，以稳定复现空白窗口；修复后在闸门未放行时也必须看到首轮投影。

增加键盘与鼠标两条焦点测试：鼠标发送后跳转链接不可见；从地址栏进入后按 Tab，跳转链接可见并能把焦点移到主内容。

## 约束与非目标

- 不通过让空草稿全部出现在最近列表来掩盖竞态。
- 不把最近列表刷新推迟到生成完成。
- 不删除跳转链接或牺牲键盘无障碍。
- 不在前端复制一套会话状态机；服务端事务投影是事实源。
