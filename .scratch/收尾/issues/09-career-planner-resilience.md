# 09 让生涯规划助手具备快速入题、后台执行和可恢复降级

Status: ready-for-agent
Priority: P0
Type: defect / reliability
Blocked by: 02, 06
Blocks: 11

## 用户价值

生涯规划不应在等待 95 秒后只显示“连接中断”。信息不足时应先问一个关键问题；信息足够时应持续显示阶段并交付结构清楚、可执行的规划，即使某个辅助来源失败也有明确恢复路径。

## 已确认根因

- 截图对应最近运行约 95 秒后以“连接中断，已保留已接收内容”结束。
- 数据库中两次相关助手消息分别约 48 秒和 95 秒，终态均为 `stream_interrupted`，没有生涯规划投影/正文。
- 生涯服务使用非流式结构化模型调用；当前运行仍绑定 SSE/页面生命周期，故 transport 故障被误认为领域失败。
- 尚无阶段耗时证据证明是模型、检索还是校验占用大头，需依赖 issue 06 埋点。

## 要实现的纵向切片

把生涯助手迁移到持久化 run，并明确两条路径：

- 信息不足：快速返回 intake，只问一个最影响方案的问题，例如目标方向、当前阶段或时间范围。
- 信息足够：后台生成“现状假设、目标、差距、近期行动、里程碑、风险/备选、待确认项”的最小可执行规划。

## 实施步骤

1. 定义最小必需输入与确定性缺口判断，避免在明显缺信息时先做长模型调用。
2. 迁移到 issue 02 的后台运行外壳，页面断开/切换不停止任务。
3. 使用 issue 06 的阶段与预算；模型结构化输出超时/格式错误时只做一次有界修复。
4. 可选资料检索失败时，不伪造事实；若仍能基于用户自述给出规划框架，则交付并标记待核实项。
5. 严格校验输出结构、日期/里程碑顺序和不可证实的承诺；校验失败给出可操作错误，而不是连接中断。
6. UI 显示“收集信息/形成路径/校验计划/完成”，返回会话后恢复当前阶段与结果。

## 验收标准

- [ ] 仅输入模糊请求时 2 秒内出现一个关键澄清问题，不启动完整规划生成。
- [ ] 提供足够信息时生成完整结构化计划，至少包含未来 7 天行动和一个可检查里程碑。
- [ ] 生成中切换会话、刷新或重开页面，运行继续且不会重复模型调用。
- [ ] 注入 95 秒慢模型时，run 仍保持可恢复阶段；到预算后明确超时/降级，不写 `stream_interrupted`。
- [ ] 结构化输出第一次非法、第二次合法时只修复一次并成功；连续非法时在总预算内失败。
- [ ] 辅助检索失败但用户信息足够时交付不依赖外部事实的规划骨架，并列出待核实项。
- [ ] 不生成保证录取、保证就业等不可验证承诺。
- [ ] 重试创建新 attempt 并保留旧失败记录，不覆盖历史证据。

## 反馈环

使用可控结构化模型覆盖四条用例：信息不足、正常成功、首轮非法后修复、慢调用超预算。Playwright 在“形成路径”阶段切到另一会话再返回，断言同一 run 完成。

## 约束与非目标

- 不在此 issue 构建完整职业测评系统。
- 不用虚构行业数据填补检索失败。
- 不通过无限提高模型 timeout 解决问题。
- 不把 transport 断开映射成生涯规划错误。
