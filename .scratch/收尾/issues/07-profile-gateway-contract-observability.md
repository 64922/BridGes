# Issue 07：固化画像网关契约、失败语义与用户可见状态

Status: ready-for-agent
Type: task
Priority: P0
User stories: US-03, US-05

## What to build

在 Issue 06 的统一信号分类基础上，交付从歧义画像候选进入 GatewayAutomaticProfileExtractor，经 ModelGateway 和真实结构化输出适配器，到本地合同校验、持久运行状态、受监督重试、画像 API 状态及 /account/profile 用户反馈的完整纵向路径。

为选定的生产模型声明并验证实际支持的结构化输出格式。供应商只保证 JSON object 时，应使用该格式并在本地执行严格 ProfileExtractionOutput 校验；若使用 JSON Schema，必须有真实适配器级证据证明选定模型和区域支持该合同。测试不能只伪造 Gateway 成功结果。

建立明确的错误分类：HTTP 400、认证/授权、安全拒绝、未绑定适配器、未验证能力和确定性合同错误属于永久失败，不进入盲目重试；限流、网络中断和受支持的 5xx 属于瞬态失败，进入有界、可恢复重试。聊天回答继续 fail-open，但画像失败必须持久化、可观测并在画像页面与合法空态区分。

## 已验证复现与根因摘要

- 只读检查样本数据库发现三条画像抽取运行以 client_error_400 重试三次后 exhausted；相关消息包含已报告的学业、考研和 Transformer 信号，但最终 observation 和四维记录均为零。
- 三条 400 均早于现有“提示中明确包含 JSON”修复；仓库已有针对历史 400 的重排队脚本，但样本数据库中的失败仍未收敛。
- 当前运行记录还捕获到模型返回顶层数组和中文语义键，而内部 `ModelCallResult.output` 与 `ProfileExtractionOutput` 要求顶层对象及固定字段；该响应被判为 `profile_extraction_contract_invalid`，相同确定性请求随后被盲重试。
- 当前 test 环境使用规则抽取器，生产使用 Gateway；现有 Gateway 测试只校验伪造结果和提示内容，没有驱动真实 QwenStructuredOutputAdapter 请求。
- ChatService 对画像异常整体 suppress；前端只能看到四维空态，无法判断没有信息、等待重试还是永久失败。

## 非目标

- 不在本任务中扩展 Issue 06 已冻结的信号语义或四维范围。
- 不在本任务中执行 profile-auto-v1 存量数据回放；由 Issue 08 处理。
- 不让画像失败阻断聊天消息持久化、回答生成或其他受控能力。
- 不向普通用户暴露供应商原始错误体、模型提示、账户标识或消息正文。

## Acceptance criteria

- [ ] GatewayAutomaticProfileExtractor、ModelGateway、结构化输出适配器和 ProfileExtractionOutput 形成一条经过真实请求体与响应体的端到端合同测试路径。
- [ ] 选定结构化输出格式有明确能力声明；不受支持的 JSON Schema 不得发送到生产模型，本地严格校验始终是最终写入门。
- [ ] 永久失败首轮即进入明确终态，不创建重复重试任务；瞬态失败只按固定版本、固定消息快照和既定上限重试，重启后可继续收敛。
- [ ] 顶层数组、缺少 `items`、使用中文别名键或字段类型错误等确定性合同违例在适配器边界被识别并脱敏分类，不得重复发送相同请求；只有结构兼容且规则明确的响应才能规范化后进入本地严格校验。
- [ ] 同一错误不能同时被标记为成功和失败；无信号跳过、成功无条目、成功写入、等待重试、永久失败具有可区分的内部结果。
- [ ] ChatService 不再无痕吞掉画像异常；聊天仍可继续，但运行、任务、脱敏指标和必要审计能够定位失败类别。
- [ ] /account/profile 在无记录且存在 pending 时显示“正在整理/等待重试”，存在永久失败时显示可重试或服务不可用状态，只有没有相关信号且没有失败时显示正常空态。
- [ ] 页面状态和画像 API 只返回当前账户的聚合状态，不包含其他账户的计数、运行 ID、消息 ID、错误原文或证据正文。
- [ ] 第三方、否定、假设、角色扮演和敏感内容由 US-03 分类器在网关前拒绝；这些负例不得产生计费调用、重试任务或带正文的错误指标。
- [ ] 生产能力未绑定、认证失败或启动 canary 失败时，健康/就绪状态至少报告画像能力 degraded，不得继续宣称画像链路正常。

## Test plan

- [ ] 使用真实 QwenStructuredOutputAdapter 与 HTTP MockTransport 验证当前能力的完整请求格式、合法 JSON 响应、本地 schema 校验和持久写入。
- [ ] 分别模拟 400、未绑定适配器、认证、安全拒绝、schema 无效、限流、网络失败和 5xx，断言永久/瞬态分类、重试次数和终态。
- [ ] 增加进程重启测试，证明瞬态任务恢复后成功收敛，永久失败不会重新入队。
- [ ] 增加 ChatService/API 纵向测试：画像失败不阻断聊天，但状态 API 和页面可准确显示 pending、failed、empty 与 ready。
- [ ] 增加账户隔离测试，覆盖状态汇总、任务队列、审计指标和页面请求，不允许通过聚合计数推断其他账户是否存在。
- [ ] 增加第三方、否定和敏感负例，断言适配器调用次数为零且日志、指标无正文。
- [ ] 在具备受控凭据的发布门中运行不含私人数据的结构化输出 canary；CI 中使用固定 cassette 或供应商沙箱验证合同漂移。

## Observability & rollback

- 发布以下脱敏指标：按 outcome/reason 分类的抽取总数、永久失败数、瞬态重试数、队列深度、重试耗尽数和页面状态请求数；标签不得包含账户、消息、主题或自由文本。
- 记录结构化能力版本、适配器版本、供应商状态码类别和重试次数；供应商错误正文仅按现有安全策略受控保存，普通日志和 API 不得复制。
- 对永久失败率、队列积压和 probable signal 长期零写入设置阈值告警，并提供不含用户内容的诊断快照。
- 回滚时可停用歧义候选的网关调用并保留 US-03 高置信确定性路径；不得删除已成功画像记录或重放消息。
- 若新状态投影影响页面，可回退页面展示但继续保留后台失败状态和指标，避免再次把故障伪装成正常空态。
