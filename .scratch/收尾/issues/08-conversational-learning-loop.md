# 08 重构学习模式为有状态、循序渐进的对话式教学循环

Status: ready-for-agent
Priority: P0
Type: product-defect / domain-model
Blocked by: 02, 03, 04, 05, 06
Blocks: 11

## 用户价值

输入“我想学习 Transformer”后，系统应先了解目标和当前水平，再一次讲一个小单元、问一道理解题、根据回答调整。它不应立即用“证据不足”结束，也不应把无关知识库图片当成学习材料。

## 已确认根因

- 当前学习分支对每条消息先执行本地检索，再按关键词选择公开来源；无本地命中时，“我想学习 X”也会被送去 DuckDuckGo。
- 公开搜索为空/失败后，证据门直接生成固定缺口响应并结束，本轮不调用教学模型。
- 代码虽然生成目标、步骤和 quiz 投影，但没有把“建立学习任务”和“讲授事实”区分为不同阶段。
- 主题提取会把用户原句直接变成教学 topic，先验假设统一为初学者，缺少对用户目标/已有知识的真实采集。
- 数据库中截图对应轮次的 teaching evidence 为 `insufficient`，回复只有几十个字符的通用失败文本。

## 要实现的纵向切片

建立持久化教学状态机：

1. `mission_setup`：确认学习目标、用途、已有水平；这一阶段不需要先通过事实证据门。
2. `micro_lesson`：基于合格来源一次讲一个概念，包含解释、例子和边界。
3. `understanding_check`：每轮最多一道低负担问题，可回答、跳过或追问。
4. `adaptation`：依据本轮回答证据选择补讲、换例子、迁移练习或下一概念。

会话中持久化 mission、当前概念、水平假设及依据、已讲步骤、理解证据和下一动作；刷新/离开后继续同一教学进度。

## 实施步骤

1. 先分类“建立目标/修改目标/事实提问/作答/追问/跳过/切换模式”，不要用单一关键词正则决定全部行为。
2. 对“我想学习 Transformer”先回复一个简短目标确认，并只问一个最能影响下一步的问题；用户未回答也可选择“按初学者开始”。
3. mission 确认后才为首个微课构造检索查询；查询使用规范主题与本轮概念，不直接拿整句意图搜索。
4. 当前附件优先；知识库只接受达到相关阈值且可支持本轮概念的命中。图片没有可用 OCR/文本证据时不能成为教学引用。
5. 事实教学仍遵守证据门和 ADR-0020：本地不足自动搜索。所有来源不可用时保留 mission，明确说明当前阶段受阻，并提供重试/上传材料；不得回退成无关回答。
6. 有充分来源时生成一小段教学、一个例子和一道题；答案评价只形成候选理解状态，不一次作答即宣称掌握。
7. 追问优先回答追问并保持当前概念；“跳过”不判错；连续困难时自动缩小概念或换例子。
8. UI 显示当前目标、进度、依据和下一步，但聊天正文仍自然，不把内部状态机表格塞给用户。

## 验收标准

- [ ] 第一轮输入“我想学习 Transformer”不会先显示证据不足；系统确认目标/水平，并允许一键“按初学者开始”。
- [ ] 完成确认后，每轮只推进一个清晰概念，正文包含解释、例子和最多一道理解检查题。
- [ ] 用户回答正确、部分正确、不理解、追问、跳过时分别走预期分支，且不会把追问误判为答题证据。
- [ ] 刷新或切换会话后，mission、当前概念和已产生的理解证据保持一致。
- [ ] 知识库只有“巴巴博一.jpg”且与主题无关时，不出现在引用、原文或教学依据中。
- [ ] 本地无材料但公开来源成功时，自动补充来源并继续微课；搜索失败时保留学习任务和恢复动作，不输出与学习无关内容。
- [ ] arXiv/网页搜索各自失败时显示准确来源状态，不统一误报证据不足。
- [ ] 任一教学事实可追溯到当前附件、项目文件、授权知识库或本轮公开来源。
- [ ] 连续 5 轮脚本化对话符合“目标 → 讲解 → 检查 → 调整”顺序，且每轮受 issue 06 时延预算控制。

## 反馈环

先写一个五轮契约测试，固定对话为：建立 Transformer 目标 → 初学者开始 → 部分正确 → 追问 → 跳过。当前实现应在第一轮被证据门截断；修复后断言状态转移、每轮题目数量和证据绑定。

再用 Playwright 验证切会话/刷新恢复，以及“不相关图片 + 无当前附件”不会污染教学来源。

## 约束与非目标

- 不取消事实教学的证据门，也不用模型记忆冒充来源。
- 不要求用户先填写长表单；一次只问一个关键问题。
- 不因一次回答就写入“已掌握”。
- 不把独立课程管理系统塞进聊天；只实现本次对话式最小闭环。
