# 10 重做 QQ 授权码原页再认证与延迟收件验证状态机

Status: completed
Priority: P0
Type: defect / security UX / concurrency
Blocked by: 01
Blocks: 11

## 用户价值

用户输入 QQ 邮箱 16 位授权码后，应在当前页面完成必要的安全确认并自动继续验证；邮件稍晚到达时，状态应最终显示“已验证”，然后可以新建提醒。不得跳到整页“重新登录”，也不得在邮件实际到达后永久显示失败。

## 已确认根因与约束

- 保存授权码接口按 ADR-0018 要求近期密码确认，过期时返回 `reauth_required`；前端把它转换成整页 `permissionDenied`，原表单和操作上下文丢失。
- 产品已有 `/auth/reauthenticate` 能在当前会话确认密码，无需完整重新登录。
- SMTP 发信后，IMAP 只做 4 次轮询、间隔 2 秒，整体收件等待约 6 秒；用户收到晚到邮件时后台已写 `verification_failed`。
- 后台使用 daemon thread，验证 attempt 没有持久 ID/版本；更换/删除授权码后，旧线程可能迟到并覆盖新状态。
- 前端最多轮询约 90 秒，但后台通常在约 6 秒就已不可逆失败。
- ADR-0017 要求自发自收验证；仅 SMTP 接受邮件不能直接标记控制权已验证。

## 要实现的纵向切片

### 原页再认证

保存收到 `reauth_required` 时，在 SMTP 卡片内/模态框询问当前 BridGes 账户密码；授权码只保留在组件内存。密码确认成功后自动重试原保存命令，随后立即清空密码和授权码。最近认证仍有效时直接保存，不额外提示。

### 持久化验证 attempt

每次保存/重新验证创建唯一 attempt，状态至少包括 `smtp_connecting`、`mail_sent`、`waiting_receipt`、`verified`、`failed`、`cancelled/superseded`，并保存不含秘密的截止时间、更新时间和错误码。后台执行器负责轮询；只有当前 attempt 可以提交账户 SMTP 终态。

## 实施步骤

1. 用现有 reauthenticate API 实现原页密码确认与自动续交；错误时聚焦密码字段，不跳转、不刷新整页。
2. 认证/保存期间避免把授权码写入 URL、日志、storage、错误对象或分析事件；成功/取消后清空内存状态。
3. 把 daemon thread 迁移到受监督后台执行器或等价可恢复作业；数据库持久化 attempt/version。
4. SMTP 成功后显示“验证邮件已发送，正在确认收件”，不要立即称已验证。
5. 收件窗口改为可配置且足够覆盖正常延迟（默认 120 秒），使用有界退避和同一 IMAP 会话/NOOP；以不可变 token 的 Message-ID/自定义头为主，主题为兼容回退。
6. 每次状态提交检查 attempt 仍为当前；新授权码、重新验证、删除凭据会 supersede 旧 attempt。
7. UI 按服务端状态持续轮询/订阅；离开页面不停止验证，返回后从权威状态恢复。
8. 区分 SMTP 认证失败、IMAP 认证失败、邮件已发送但等待超时、网络临时失败、旧 attempt 失效，并提供对应动作。

## 验收标准

- [ ] 近期认证有效时，输入授权码并点击“保存并验证”直接进入验证状态。
- [ ] 近期认证过期时，原页面弹出密码确认；正确密码后自动续交一次，授权码无需重输，页面不跳转。
- [ ] 密码错误只显示局部错误，不清空授权码；取消时清空敏感内存并保持服务器原设置不变。
- [ ] 假邮件 0 秒、10 秒、60 秒到达时最终均为 verified；超过 120 秒才以 receipt timeout 失败。
- [ ] 用户在等待中离开/刷新，后台继续；返回后能看到 mail_sent/waiting_receipt/verified 的当前状态。
- [ ] 先保存 A、立即保存 B，A 的迟到成功/失败不能覆盖 B；删除凭据后任何旧 attempt 都不能恢复 verified。
- [ ] SMTP 接受但 IMAP 未确认时不得启用新提醒；确认成功后无需刷新整页即可新建。
- [ ] API、日志、审计、测试 trace 均不含密码和授权码正文。
- [ ] 真实 QQ 人工 smoke：测试邮件实际到达后，在有效窗口内 UI 收敛为“已验证”。

## 反馈环

先写两个必红测试：

1. reauth_required → 原页输入密码 → 自动重试 save，断言只创建一个有效 verification attempt。
2. 假邮件延迟 10 秒到达，现状会在约 6 秒失败；修复后最终 verified。

再增加 A/B attempt 竞争、删除期间迟到回调、IMAP 临时断线恢复、120 秒超时（使用虚拟时钟）和秘密扫描测试。

## 约束与非目标

- 不取消 ADR-0018 的近期密码确认。
- 不把“SMTP 已发送”当作邮箱控制权验证成功。
- 不在浏览器持久化授权码或密码。
- 不使用无限轮询；截止时间到达必须有终态和重新验证路径。
