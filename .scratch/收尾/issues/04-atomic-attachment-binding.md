# 04 统一新旧会话附件管线并保证附件与消息原子绑定

Status: ready-for-agent
Priority: P0
Type: defect / data-integrity
Blocked by: 01, 03
Blocks: 07, 08, 11

## 用户价值

从 `+ → 上传文件/图片` 选择的材料必须明确显示在当前待发送消息中，并在发送后只服务于这条消息/会话。文章改写必须读取用户刚上传的 DOCX，不得把全局知识库图片冒充原文。

## 已确认根因

- 普通编辑器、新会话首页、技能弹窗各自维护附件状态，提交契约不一致。
- 文章人味化弹窗会提交第三个参数 `attachmentIds`，首页包装回调只转发前两个参数，附件 ID 被静默丢弃。
- 首页跳转后的自动发送只从另一条 session key 取附件，因此技能合同中虽有 ID，聊天消息仍以空附件列表发送。
- 只读数据库显示目标 DOCX 已上传到对应会话，但 `message_id` 为空；相关人味化消息绑定附件数为 0。
- 路由卸载会 abort 上传并尝试取消，上传完成、绑定未完成之间存在孤儿窗口。

## 要实现的纵向切片

定义一个统一 `PreparedTurn`（概念名可调整）：消息文本、会话、技能输入、附件 ID、知识库开关和幂等键由同一对象提交。服务端在创建用户消息时验证附件归属，并在同一事务完成绑定；技能与检索只读取消息已绑定附件。

## 实施步骤

1. 统一普通聊天、新会话和所有技能弹窗的附件选择/上传状态，不再用位置参数转发关键 ID。
2. 上传完成后在编辑器展示文件名、类型、大小、状态、移除操作；发送按钮在上传未完成时给出明确状态，不能静默发送空附件。
3. 首轮/续轮发送命令在事务内校验 attachment 属于当前账户与会话、状态可用、未绑定其他消息，然后绑定到新用户消息。
4. 技能合同引用的附件 ID必须与消息绑定集合一致；不一致直接返回可理解错误，不得回退到知识库。
5. “改写文章”默认只检索当前消息附件，`use_knowledge_base=false`；只有用户明确开启知识库时才能补充，且仍不能把补充材料称为“原文”。
6. 为已上传未绑定对象定义恢复/清理规则：用户仍在草稿时可恢复；超过安全期限且无活跃草稿时清理。不得误删已绑定对象。
7. 文件解析失败时指出具体文件和支持格式，保留附件供重试，不自动改用另一材料。

## 验收标准

- [ ] 在现有会话通过 `+` 上传 PNG/JPG/DOCX/PDF/TXT，上传完成后均可见并随下一条消息绑定。
- [ ] 在首页先上传再发送，路由跳转后附件 chip、消息绑定和检索披露保持一致。
- [ ] 文章改写上传《Transformer：AI 大模型的核心基石.docx》后，消息投影中恰有该附件，回复不得出现“本轮未附加文件”。
- [ ] 全局知识库存在“巴巴博一.jpg”时，默认改写链路既不检索它，也不把它展示/描述为原文。
- [ ] 上传中点击发送不会创建空附件消息；可等待完成或明确取消。
- [ ] 双击发送、网络重试不会把同一附件绑定到两条消息。
- [ ] 跨账户、跨会话伪造 attachment ID 返回 404/领域拒绝，不泄漏文件名和存在性。
- [ ] 上传成功后关闭页面再返回，未发送草稿可恢复；超过清理期限的真正孤儿被安全清理。
- [ ] 数据库约束/事务测试证明不存在“消息提交成功但附件仍未绑定”的中间成功态。

## 反馈环

先新增两个必红 E2E：

1. 首页人味化改写上传真实小型 DOCX，发送后从 API 读取消息投影并断言附件 ID 相同。
2. 知识库预置一张不相关图片，改写时断言检索请求禁用知识库、回复披露只含 DOCX。

同时增加事务故障注入：在绑定前/后抛错，断言消息与绑定要么同时提交，要么同时回滚。

## 约束与非目标

- 不把浏览器 session/local storage 作为附件绑定事实源。
- 不允许“找不到当前附件就试试知识库”的静默降级。
- 不在此 issue 扩展新的文件格式；只保证已宣称支持的格式可靠。
- 不记录文件正文到日志和测试报告。
