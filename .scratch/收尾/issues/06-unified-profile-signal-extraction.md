# Issue 06：统一四维画像信号分类并贯通聊天到画像

Status: ready-for-agent
Type: task
Priority: P0
User stories: US-03

## What to build

交付一条从已认证用户的聊天原句开始，经过唯一画像信号分类、确定性抽取、证据校验和四维记录持久化，最终可由当前账户在 /account/profile 查看结果的完整纵向路径。

引入唯一权威的 ProfileSignalClassifier（名称可调整），让候选预检、确定性抽取、网关边界、提交校验和晋升策略共享同一份分类结果。分类至少明确区分无信号、明确自述、符合中文主语省略习惯的高置信自述、行为观察和禁止内容，消除当前多组正则独立判断造成的矛盾。

高置信、低风险且可确定判断的四维信息优先在本地完成，不依赖生产网关是否可用；只有歧义候选才进入后续结构化模型路径。生产与测试环境必须执行同一分类策略。知识主题不能依赖封闭中文词表，应支持 Transformer 等中英文技术主题。

用户依次在多个对话中表达“大三人工智能专业”“目标考211相关专业/考研”“想学习Transformer”“找Transformer论文”后，学业情况、阶段目标和感兴趣的知识应形成可审计记录并在画像页面展示；兴趣爱好保持空白是正确结果。“找 Transformer 论文”单独出现时只能作为行为观察，不得单独晋升为稳定兴趣；它可与明确的学习表达共同构成证据。

## 已验证复现与根因摘要

- 已用 ChatService、真实 SQLite 仓储和四维画像读取服务构造无文件写入的确定性反馈环：四条原句产生四条 succeeded、attempts 为零的抽取运行，但 observation、record 和页面读取投影全部为零。
- 同一反馈环把前三句补成完整的“我现在是……”“我的目标是……”“我想学习……”后，立即生成学业、目标和知识兴趣三类记录，证明聊天接线、账户 ID、仓储和读取投影不是主因。
- 当前 probable-signal 预检把未命中词法模板的消息直接记作 succeeded；规则抽取器、预检与提交校验又分别维护不同的自述判断。仅放宽预检仍会被提交校验拒绝，因此必须建立唯一分类结果。
- 当前测试正例集中在完整“我……”模板，未覆盖中文主语省略、通用英文技术主题和搜索观察语义。

## 非目标

- 不在本任务中修改生产模型的 HTTP/结构化输出合同或重试分类；由 Issue 07 处理。
- 不在本任务中回放或改写任何存量 profile-auto-v1 运行；由 Issue 08 处理。
- 不把单次搜索、普通课程问题、点击行为或模型猜测直接升级为长期画像。
- 不扩展四维范围，不加入敏感身份、健康、情绪、人格或心理推断。

## Acceptance criteria

- [ ] 候选预检、确定性抽取、网关输入边界、提交校验和晋升只消费同一个画像信号分类结果，不再各自重新推断“是否为用户自述”。
- [ ] 高置信确定性信号在生产与测试环境都先走同一路径；网关不可用时仍能完成本任务列出的三类低风险记录。
- [ ] 四条已验证原句跨多个学习对话发送后，当前账户的画像 API 和 /account/profile 都展示学业情况、阶段目标、感兴趣的知识三类记录，兴趣爱好合法为空。
- [ ] Transformer、CNN 等中英文技术主题无需加入固定白名单即可被“想学习/正在学习/研究”等明确表达提取。
- [ ] “找 Transformer 论文”单独出现只形成内部观察；与“想学习 Transformer”等明确自述结合时去重到同一知识主题，不制造重复记录。
- [ ] 每条写入都保留当前账户、来源消息、有限证据原话、分类/抽取版本和可靠程度；不同账户的消息、观察和画像记录不可互读或互相晋升。
- [ ] “我朋友是大三人工智能专业”“假设我是大三学生”“我不想学习 Transformer”、角色扮演、引用文本、健康/情绪/人格/政治/宗教等敏感内容均不得进入 observation 或稳定画像。
- [ ] 否定、第三方和敏感负例不会因省略主语支持而被放宽；现有墓碑、撤回和停止记录边界继续生效。
- [ ] 重复提交同一消息保持幂等，同一主题在多对话出现按证据更新可靠程度，不生成无界副本。

## Test plan

- [ ] 为四条原句、完整主语对照、常见中文主语省略、标点变体和中英文技术主题增加表驱动单元测试。
- [ ] 增加分类器契约测试，证明预检、抽取、校验和晋升观察到同一分类与原因码。
- [ ] 增加否定、第三方、引用、假设、角色扮演和全部敏感类别的负例矩阵。
- [ ] 用同一 SQLite 数据库执行多对话服务测试，断言 observation 去重、三类记录持久化、重启后读取一致及跨账户隔离。
- [ ] 增加聊天 API 纵向测试：注册账户、创建多个对话、发送四条原句、读取四维画像 API，并验证另一账户仍为空。
- [ ] 增加画像页面测试，数据必须由聊天自动产生，禁止通过手工播种四维记录绕过抽取链路。
- [ ] 将诊断阶段的红色反馈环固化为快速确定性回归命令，并在修复后运行至绿色。

## Observability & rollback

- 为分类结果记录脱敏计数和稳定原因码，只记录类别、策略版本、是否产生 observation/record，不记录消息正文、证据原话、账户标识或模型提示。
- 对 probable signal 被判为无信号的比例建立可查询基线，便于发现新的词法漏判；正式失败指标和用户可见失败状态由 US-04 补齐。
- 分类策略应带内部版本，发布后可只回退新消息的分类策略；已生成记录不得在回退时物理删除，继续通过现有修改、撤回和审计能力治理。
- 若负例误写率或跨账户测试失败，立即停止新自动写入并回退分类策略，不回放历史消息，保留运行和审计证据供修复后处理。
