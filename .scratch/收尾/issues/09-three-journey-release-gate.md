# Issue 09：建立三条现场旅程的收尾发布门

Status: `ready-for-agent`  
Priority: `P0`  
Type: `task`  
User stories: `US-01`、`US-02`、`US-03`、`US-04`、`US-05`

## What to build

建立一个可重复执行的收尾发布门，通过真实 BridGes API、流式聊天、SQLite 持久化和浏览器界面验证三条用户现场旅程。发布门同时包含不联网的确定性回归和显式启用的真实提供方探针；它必须能区分产品缺陷、外部服务不可用和测试环境配置错误，并产出不包含私人正文的证据摘要。

这条纵向切片完成后，维护者可以用一次有记录的执行回答：学习联网是否可靠、论文搜索是否相关且遵守预算、画像是否在聊天后自动形成并安全恢复。单元测试全绿或使用浏览器路由模拟后端，不能单独视为发布通过。

## 已验证的复现与根因摘要

- 学习旅程曾把公开搜索挑战页当成真实零结果，最终回答出现重复的未核实提示；安全降级本身正确，错误在上游可用性和状态投影。
- 论文旅程曾在约 8 秒误报 arXiv 超时，并在用户收到终态后继续运行后台任务；中文查询还会混入无意义指令词。
- 画像旅程曾留下抽取运行记录却没有任何画像记录，原因包括信号预检漏判、结构化合同失败和历史数据未回放；前端只是在忠实展示后端空投影。

## 非目标

- 不新增与三个缺陷簇无关的聊天、画像或搜索功能。
- 不把实时第三方联网结果做成普通 CI 的硬依赖。
- 不用手工播种搜索结果或画像记录证明生产链路正确。
- 不在发布门中直接修改、删除或重置真实用户数据库。
- 不将“偶尔一次联网成功”解释为供应商长期可靠性证明。

## Acceptance criteria

### 学习联网旅程

- [ ] 使用全新学习模式对话输入“我想学习Transformer架构的相关知识”，从浏览器提交到持久化回复的完整路径可重复执行。
- [ ] 主提供方成功时，回答至少绑定一个与 Transformer 教学目标相关、可访问且通过来源抓取门的公开来源；教学卡显示证据充分，正文没有“本轮未联网核实”。
- [ ] 主提供方进入挑战而备用提供方成功时，用户仍获得可核实回答；能力详情准确显示实际使用的提供方，不伪装成 DuckDuckGo 成功。
- [ ] 所有提供方失败时，只出现一次统一的未核实说明和准确的可重试原因；不伪造引用，不创建或推进正式教学计划、课时和已覆盖进度。
- [ ] 挑战、真实零结果、限流、网络超时和解析异常在 API 投影、能力详情与指标中保持可区分。

### 论文搜索旅程

- [ ] 在日常陪伴模式输入“给我找几篇Transformer方向相关的论文”，路由到论文搜索并返回与 Transformer 主题相关的论文，而不是因中文指令噪声得到零结果。
- [ ] 正常响应在统一前台 120 秒上限内结束；web-only、arXiv-only 和双来源阶段分别遵守 8、10、10 秒活跃来源预算合同。
- [ ] 超过截止时间时返回稳定、可重试的来源级错误；终态返回后的限定清理窗口内没有继续运行的 future、失配响应或孤儿 worker。
- [ ] 超时后立即重试以及两个结果不同的并发请求都返回各自正确的论文，不发生协议串线。

### 四维画像旅程

- [ ] 同一账户跨不同对话依次输入“我想学习Transformer架构的相关知识”“我是一名人工智能专业的大三学生，目标是考一个211院校的相关专业，给我规划一下考研”“给我找几篇Transformer方向相关的论文”。
- [ ] 画像页最终显示有证据的知识兴趣、学业情况和阶段目标；没有长期爱好证据时，兴趣爱好保持明确的合法空态。
- [ ] 刷新页面和重启服务后记录仍存在，首次稳定记录时间不会因重复抽取或回放被改写。
- [ ] 另一个账户无法读取、影响或通过回放获得该账户的画像。
- [ ] 删除、撤回、停止记录和隐私阻止场景在重复运行回放后仍然有效。
- [ ] 页面能区分“确实没有信息”“正在处理”和“抽取失败待重试”，不再把处理失败展示成普通空白画像。

### 发布与证据

- [ ] 确定性回归在断网环境可运行，使用协议固件、受控时钟和临时 SQLite，且能在旧实现上稳定跑红。
- [ ] 真实联网探针必须由显式开关启用，分别记录提供方、语义健康结果、耗时和脱敏错误分类；探针失败会阻止发布但不会污染普通 CI。
- [ ] Python 测试与静态检查、Web 单元测试、TypeScript 类型检查和指定的 Playwright 收尾项目全部通过。
- [ ] 发布证据记录代码版本、配置类别、数据库 schema 版本、测试结果和未解决风险，不保存密钥、完整用户消息或画像正文。
- [ ] 三个缺陷簇的运行手册包含复现、健康判断、重试、回滚和数据恢复步骤，并与 ADR 和实际错误码一致。

## Test plan

1. 先在旧实现上运行三个精确输入的确定性测试，保存失败类型和耗时范围；修复后用同一测试转绿。
2. 运行搜索、教学、arXiv、自动画像、治理和数据库迁移相关的 Python 单元与集成测试。
3. 运行 Web 单元测试、类型检查和收尾 Playwright 项目；浏览器测试必须调用真实本地 API，不得通过路由桩绕过待验收后端。
4. 在临时数据目录完成注册、三段聊天、画像读取、重启、账户切换、删除/撤回和重复回放。
5. 在明确允许联网的预发布环境执行 DDG、备用搜索提供方和 arXiv 探针，记录 p50/p95、错误分类及 worker 清理结果。
6. 模拟主源挑战、备用源成功、全部来源失败、慢但预算内成功、真正超时、结构化合同失败及历史回放中断。

## Observability & rollback

- 发布门汇总公开搜索结果分类、实际提供方、教学证据裁决、来源级截止时间、取消结果、画像抽取决策和回放统计；所有字段必须脱敏。
- 为公开搜索挑战率、超时率、孤儿任务数、画像永久失败数、跳过原因和回放拒绝原因设置可判定阈值。
- 搜索侧回滚通过显式提供方开关恢复到上一个已登记配置；回滚后证据不足路径仍必须安全降级。
- 画像侧在任何正式回放前生成可验证备份和 dry-run 报告；异常时停止批次、恢复备份，并保留已处理范围和审计 ID。
- 任一 P0 验收失败都阻止发布，不允许以隐藏提示、放宽断言或关闭隐私门作为临时放行方式。
