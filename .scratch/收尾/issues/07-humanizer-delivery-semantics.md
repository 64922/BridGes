# 07 让文章人味化可靠交付正文并区分硬事实门与软风格门

Status: ready-for-agent
Priority: P0
Type: defect / product-semantics
Blocked by: 02, 04, 06
Blocks: 11

## 用户价值

“生成文章”应直接交付符合内置要求的人味化文章；“改写文章”应基于用户当前附件交付改写稿。风格评分不完美不能把已生成正文全部扣留，只允许在科学事实可能被篡改等硬风险下阻止发布。

## 已确认根因

- 人味化服务已经构造 `final_text`、编辑说明与事实检查，但体裁检查失败会把整个 output 置空并返回错误卡，只剩“重新生成”。
- 最近一次生成在约 27.9 秒后以 `genre_check_failed` 结束，没有正文。
- 改写入口附件 ID 丢失，导致当前消息没有绑定 DOCX；检索随后显示“当前附件未启用”并暴露无关知识库图片。
- 部分人味化调用使用非流式结构化生成并可能重试，长时间没有可见产物。
- ADR-0011 要求输出最终文本、编辑说明、事实检查和未解决项，同时禁止把功能包装为 AI 检测规避器。

## 要实现的纵向切片

把质量门分成两级：

- 硬门：事实锁冲突、关键科学结论被改变、来源/引文伪造、输入不可解析。硬门可以阻止把文本标为最终稿，但必须说明具体冲突和恢复方式。
- 软门：句式、节奏、体裁、重复、口吻等风格指标。软门最多触发一次有预算的修复；仍未完全通过时交付当前最佳正文并附“未完全满足项”，不得清空正文。

## 实施步骤

1. 统一生成与改写输出契约：`final_text`、`edits`、`fact_check`、`unresolved`、`quality_status`、`source_attachment_ids`。
2. 改写开始前验证恰有可解析的当前消息附件；默认禁用全局知识库，并在界面明确列出原文文件名。
3. 生成路径在模型产出正文后立即持久化草稿；软质量检查只更新状态，不删除草稿。
4. 软门失败且预算允许时只做一次定向修复；修复失败/超时则交付原草稿和具体警告。
5. 硬门只针对可定位的事实/来源问题；错误投影包含冲突项，不泄漏内部 prompt，不把普通风格失败升级为硬门。
6. UI 始终以文章正文为主，编辑说明、事实检查和未解决项可展开；“重新生成”是可选操作，不是唯一出口。
7. 文案保持“可读性/风格改写”定位，不声称逃避 AI 检测或保证“不可检测”。

## 验收标准

- [ ] “生成文章”在模型返回合法正文、但体裁分数未达阈值时仍显示完整正文和具体软警告。
- [ ] 软门最多触发一次修复，且受 issue 06 总预算约束；没有循环重生成。
- [ ] 上传目标 DOCX 的“改写文章”只把该 DOCX 作为原文，输出中 source attachment ID 与消息绑定一致。
- [ ] 知识库存在不相关图片时，默认路径不检索、不展示、不引用该图片。
- [ ] 科学事实锁被改写时，硬门阻止将错误版本标记为最终稿，并列出冲突字段与可操作恢复路径。
- [ ] 解析失败时显示“无法解析某文件”的明确错误，保留附件和用户参数供重试。
- [ ] 切换会话/刷新后运行继续，返回可看到草稿、阶段和最终结果。
- [ ] 任何成功/软失败结果都包含正文；只有硬门或无正文的模型错误可以没有 final text。
- [ ] E2E 覆盖生成、DOCX 改写、软门失败、硬门失败、模型超时和离开后返回。

## 反馈环

先固定一个返回合格正文但故意未过 genre check 的模型适配器；现状应复现“正文被清空”，修复后断言正文存在、警告存在且修复次数 ≤ 1。

再用真实小型 DOCX 与不相关知识库图片跑无 route mock 的 E2E，检查附件绑定、检索披露和最终输出。

## 约束与非目标

- 不取消事实锁和科学诚信硬门。
- 不以反复调用模型直到评分通过作为修复方案。
- 不静默使用未绑定材料或全局知识库替代原文。
- 不承诺 AI 检测器结果。
