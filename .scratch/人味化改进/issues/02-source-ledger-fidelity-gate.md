# Issue 02：建立来源账本与保真硬门

Status: completed

Type: task

Priority: P0

Parent: [BridGes 有人味表达改进方案](../README.md)

User stories: US-02、US-03、US-04、US-06

## What to build

把现有只检查“原事实是否还在”的事实锁加深为版本化来源账本与双向保真硬门。每个文章任务在生成前都必须明确哪些事实、专名、数字、引语、经历、保护区和外部材料可以使用；生成后既检查原有信息是否被破坏，也检查候选新增的可核查 claim 是否有授权来源。

来源账本是文章生成、表达审稿、证据安全修订和评测共同使用的深模块。调用方只能提交来源与权限，不能各自维护另一套事实词表。保真检查缺失、版本不匹配或无法判定关键 claim 时失败关闭。

## 已验证现状与根因摘要

- 现有事实锁覆盖数字、单位、部分关系、公式、引用、限定词和结论强度，但没有完整保护专名、精确引语、个人经历和用户指定措辞。
- 当前比较重点是“源内容是否还在”，不能可靠识别候选凭空添加的朋友对话、生活场景、产品功能、样本方法或下一步计划。
- 现有 scripted “好答案”本身出现过无来源的实验方法、样本局限、生活例子和解释性事实，说明 additive hallucination 没有进入质量硬门。
- `Humanizer-zh` 示例会通过新增具体经历和数据提高自然感；若不先建立来源边界，系统会得到方向错误的高分。

## 非目标

- 不构建开放域事实核查搜索引擎。
- 不把所有普通词语和标点设为不可修改。
- 不要求纯风格句子逐字对应原文。
- 不允许生成模型仅凭自报“事实已核查”绕过确定性检查。
- 不静默把无法判定的高风险 claim 当作正确。

## Acceptance criteria

- [ ] 定义版本化 `SourceLedger`（名称可按现有领域模型调整），至少表达：来源条目、内容哈希、来源类型、允许用途、保护 span、事实/claim、专名、数字单位、日期、公式代码、URL、精确引语、否定与因果方向、限定词、结论强度、个人经历及第一人称权限。
- [ ] 来源类型能区分用户原文、用户补充材料、账户作用域授权材料、明确允许的外部来源、普通常识和显式假设；纯改写默认只允许消费用户原文，不自动扩大事实范围。
- [ ] 明确假设必须在候选正文中以“比如、假设、设想”等不会冒充亲历的方式标注，并且契约允许使用；假设不得承载高风险事实或作者/用户经历。
- [ ] 第一人称经历只有在原文已有或用户明确授权代写作者口吻时可绑定；“我认为/我更倾向于”这类当下判断与“我以前/我亲自做过”亲历分开建模。
- [ ] 候选中的新增数字、日期、专名、引语、功能、研究方法、样本、事件、时间地点和亲历必须绑定到账本来源；绑定引用的 span/hash 不存在时视为无来源。
- [ ] 对原有锁执行保留检查，对新增 claim 执行来源检查；关键项失败返回稳定硬失败，非关键但无法判定的项返回 `needs_user_confirmation` 或稳定风险状态，不进入人工评审队列，两者都不能被自然度分数覆盖。
- [ ] 每次成功文章结果携带来源账本版本、检查器版本、账本哈希和检查摘要；任一字段缺失、检查异常或版本不支持时不得标记成功。
- [ ] 引语、代码、公式、URL、引用和用户指定措辞作为 protected spans；后续表达 lint 只检查作者新增正文，不改写这些区域。
- [ ] 账本与检查报告不把私人正文写入普通日志；审计使用 ID、类型、哈希、计数、位置和失败码。
- [ ] 旧人味化任务仍可读取；新任务使用新账本版本。迁移和回滚不把旧任务伪装成已经通过新增来源检查。

## Test plan

1. 为每一种来源类型和保护项建立表驱动单元测试，覆盖中文标点、全半角单位、日期、引用编号和多段精确引语。
2. 构造删除否定、反转因果、放大结论、改变数字单位、替换专名和改写引语的候选，断言硬门失败。
3. 构造“我以前也这样”“上周朋友告诉我”“2019—2023 年收集 5000 例”“新增离线模式”等无来源内容，断言 additive claim 失败。
4. 构造明确“比如每周五统一回邮件”的低风险假设，分别验证契约允许时通过、未允许或伪装成亲历时失败。
5. 验证专业语境中的合法术语、原文已有的比喻和被保护引语不会被误判为新增作者事实。
6. 模拟检查器异常、空结果、版本不匹配和账本哈希变化，验证全部失败关闭。
7. 运行现有人味化事实锁、服务状态机和评测回归，证明旧读取与错误语义没有被破坏。

## Observability & rollback

- 指标至少包含账本编译失败率、各类保护项数量、新增 claim 数、无来源 claim 数、第一人称经历拦截数、硬失败与 `needs_user_confirmation` 比例。
- 日志只记录任务 ID、版本、哈希、位置与错误码；不得记录完整原文、引语或个人经历正文。
- 以版本和能力开关灰度启用。回滚时新任务恢复旧流程但不得把旧检查标成新硬门通过；已存账本和报告保持只读可审计。
