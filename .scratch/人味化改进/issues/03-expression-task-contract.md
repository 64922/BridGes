# Issue 03：重构表达任务契约

Status: ready-for-agent

Type: task

Priority: P0

Parent: [BridGes 有人味表达改进方案](../README.md)

User stories: US-01、US-02、US-03、US-04

## What to build

把当前零散的自然语言意图、体裁默认值、模式提示和文章参数收敛为一个版本化表达任务契约。契约在生成前回答：这是聊天还是文章、现实承诺是什么、谁在说、允许知道什么、改写多深、材料是否足够、是否允许第一人称或假设、用户期望的受众/渠道/长度是什么，以及是否进入证据安全修订。

契约编译器只做确定性解析和最小澄清决策，不生成正文。普通聊天和文章共用任务边界词汇，但分别编译自己的轻量策略和完整文章流程，不能重新合并成同一块总提示词。

## 已验证现状与根因摘要

- 当前文章意图默认受众为普通读者、渠道为聊天回复，无法可靠表达说话位置、现实/虚构、第一人称权限、来源权限或改写强度。
- 未命中少量类型词时会落入科普默认值，普通邮件、观点文、报告或教程可能被强迫使用科普定义与类比。
- 普通聊天的模式合同、画像片段和全局写作策略分别拼装，优先级与本轮表达目标不够清楚。
- 当前材料不足没有统一结果：模型可能为了长度补细节，也可能反复表达同一观点。
- 现有重试依赖策略快照；新契约必须继续提供不可变版本，避免同一任务重试时规则漂移。

## 非目标

- 不在契约编译器里调用模型写正文。
- 不推断用户人格、心理、未表达的情绪或亲密关系。
- 不新增超出冻结四维画像的敏感或隐式画像字段。
- 不把渠道、体裁或改写强度转换为必现句型。
- 不一次追问多个材料问题。

## Acceptance criteria

- [ ] 定义版本化 `ExpressionTaskContract`（名称可适配现有合同），至少包含：surface、operation、conversation mode、reality mode、rewrite intensity、speaker position、first-person permission、hypothetical permission、audience、channel、length、genre/profile、material sufficiency、source scope、evidence revision mode、user constraints 和版本哈希。
- [ ] `surface` 明确区分普通聊天与文章；`operation` 区分改写、扩写和按主题生成；文章结果仍跳过普通聊天全局策略。
- [ ] `reality mode` 区分现实、虚构和混合。现实模式禁止补亲历；虚构或混合模式也必须标明哪些内容允许创作，不能把虚构部分投影为用户事实。
- [ ] `rewrite intensity` 支持轻度、标准、深度，默认标准；用户显式选择优先于自动推荐。三个档位都带不伤害规则和同一来源保真边界。
- [ ] 材料充分度至少有 `sufficient`、`ask_one_question`、`shorten`、`use_placeholders`；扩写或生成不足时返回一个最高价值问题，纯改写不得因材料不足扩大事实范围。
- [ ] `evidence revision mode` 默认保留原结论；只有用户明确选择时为证据安全修订，且该选择进入不可变任务快照。
- [ ] 普通聊天只读取当前轮上下文和允许的最小画像切片；称呼、篇幅、专业程度和明确表达偏好可影响表达，事实判断和证据标准不受画像影响。
- [ ] 规则优先级固定为：用户显式要求与安全边界 → 来源/现实承诺 → 表面与模式合同 → 场景表达规则 → 软风格检查。冲突时返回可解释的稳定裁决。
- [ ] 旧路由快照可读取和重试；新任务绑定新契约版本。同一任务重试复用原契约，不因规则热更新改变强度、来源或第一人称权限。
- [ ] 未识别体裁时使用通用文章 profile，不再默认强制科普；低置信且会实质改变结果时只追问一个必要问题。
- [ ] 合同编译结果可序列化、可哈希、可审计，日志不保存画像正文或完整私人材料。

## Test plan

1. 建立 surface × operation × reality × intensity × evidence mode 的表驱动合同测试，覆盖用户显式选择和默认行为。
2. 用邮件、报告、教程、观点文、演讲、科普、科研段落和未声明体裁的请求验证不会误落入科普必现模板。
3. 用“扩写到 3000 字但只有一句观点”验证只返回一个高价值问题；模拟用户不补材料后验证 `shorten` 或 `use_placeholders`。
4. 用原文已自然案例验证三个强度都携带不伤害约束，轻度不会自动升级。
5. 用允许和禁止的第一人称、显式虚构、混合文本、假设例子建立权限回归。
6. 用同一任务跨规则版本重试，验证快照和哈希不变；用未知版本验证执行前稳定拒绝。
7. 验证画像缺失、撤回、版本不可用和安全基线场景，不会推测用户或改变事实标准。

## Observability & rollback

- 记录合同版本、surface、operation、强度、材料裁决、是否追问、profile ID、最小画像条目数和降级原因，不记录画像正文。
- 统计未识别路由、材料不足、追问后继续率、强度分布和现实模式冲突。
- 通过契约版本双读和路由能力开关灰度。回滚后旧任务继续用旧快照，新合同记录保留只读，不做破坏性降级。
