# Issue 10：建立隔离的多模型自动盲评

Status: ready-for-agent

Type: task

Priority: P0

Parent: [BridGes 有人味表达改进方案](../README.md)

User stories: US-01、US-02、US-04、US-06、US-07

## What to build

把现有 A/B 对比升级为不泄漏候选身份、完全由系统执行的多模型匿名裁判。评测必须分离 judge-facing packet 与 evaluator-private sealed mapping：裁判只看到不透明 ID、固定 A/B 标签、任务上下文、来源边界和候选正文；SUT、生成模型、策略、peer、真实映射和匿名种子只在评测器私有侧保存。

每个正式比较项至少由三个隔离、版本固定的系统裁判独立评价。每个裁判都对 A/B 与 B/A 两种顺序作答，输出偏好、七维结构化评分、候选原文证据 span 和无法判断原因。系统通过预注册聚合规则产生结论；裁判分歧、位置偏差、校准失败或模型多样性不足时直接返回 `inconclusive`，不创建人工评审或仲裁队列。

## 已验证现状与根因摘要

- 当前 blind review 的 `label_a/label_b` 与 `item_id` 可能携带 SUT/peer 映射，CLI 又直接展示这些字段，匿名化可能失效。
- 现有测试主要检查正文不含 SUT 字符串，没有扫描元数据、ID、标签、文件名和排序泄漏。
- 当前评审项只有两段输出，缺少原文、用户要求、受众、渠道、长度和来源边界，系统无法判断具体场景是否有来源或结论是否保真。
- 单个裁判模型容易偏爱更长、更多第一人称和更具体的文本；若与候选生成模型同源，还可能奖励熟悉句式。
- “哪版更像真人”会奖励假经历。自动裁判的主问题必须聚焦“是否适合直接发送或发布”，并且保真硬门先于模型偏好。

## 非目标

- 不接入任何人工评分、抽查、校准或仲裁流程。
- 不向系统裁判展示策略提示、SUT 名、生成模型名或内部映射。
- 不让候选生成会话同时充当裁判，或把单个模型自评分当作结论。
- 不把自然度与事实忠实平均成可相互抵消的总分。
- 不使用“规避 AI 检测”或“更像真人”作为目标或量表。

## Acceptance criteria

- [ ] 定义 judge-facing packet 与 evaluator-private sealed mapping 两个不同合同；packet ID 随机且不透明，显示标签永远只是 A/B，不复用 case、SUT、模型、策略、peer 或左右映射信息。
- [ ] sealed mapping 记录 packet ID、case/run、候选来源、生成模型、左右映射、匿名种子、内容哈希和创建版本；只有聚合器可读取，裁判适配器拿不到该对象。
- [ ] 导出器递归扫描 judge packet 的字段名、字段值和路径，禁止出现已登记的 SUT、model、strategy、skill、peer、git/build 和 mapping 标识；泄漏检查失败时不调用裁判。
- [ ] judge packet 提供判断所需的最小上下文：用户请求、原文或前序对话、模式、受众、渠道、长度、改写强度、现实承诺、允许材料、保护项和匿名候选；不包含账户或评测内部身份。
- [ ] 建立版本化 judge registry。正式 panel 至少三个裁判，优先来自不同模型家族或提供方，并且不得全部与候选生成模型相同；不满足预注册多样性时结论为 `inconclusive`。
- [ ] 每个裁判调用使用独立、全新、无工具的会话，不继承候选生成的消息、缓存、隐藏状态或输出来源；temperature、seed、系统提示、schema 和模型快照进入运行锁。
- [ ] 主偏好问题固定为“哪一版更适合直接发送/发布”，输出 A、B、平局或无法判断；同时输出自然度、可信/有根据、具体落地、分寸/非说教、任务与声音适配、可读性和事实忠实的 1—5 行为锚点评分。
- [ ] 每个非平局裁决必须引用候选中的有效 span，并关联稳定 reason code；span 不存在、引用来自任务说明而非候选、理由与选择矛盾时判为无效。
- [ ] 同一裁判对每一配对执行 A/B 与 B/A 两次判断。映射还原后偏好或关键维度矛盾且无有效理由时标记位置偏差；该裁判对该 case 的票无效。
- [ ] 裁判上线前必须通过冻结 canary：事实破坏、虚构第一人称、来源缺失、协议泄漏、明显模板注入、不伤害样例、左右顺序和提示注入对抗；存在硬门已知正确答案的 canary 必须 100% 通过。
- [ ] 裁判模型、提示、schema 或参数变化后自动重跑 canary；相对冻结基线的偏好/评分漂移超过预注册阈值时禁止进入正式 panel。
- [ ] 聚合器使用预注册规则处理有效裁决，报告每个裁判的双向结果、证据、分歧和可靠性；分歧超过阈值时返回 `inconclusive`，不得调用第四个“仲裁模型”临时改判。
- [ ] 确定性保真硬门优先于所有裁判：任一关键事实、保护区或虚构亲历失败直接判失败，多数票不能放行。
- [ ] 全流程可无人值守运行；任何异常只产生 `fail` 或 `inconclusive` 及机器可读原因，不产生等待人工评审的状态。
- [ ] 报告明确标注“系统自动裁判结果，未经真实用户或人工验证”，不得把通过写成真实中文用户偏好事实。

## Test plan

1. 构造含 `current_production/candidate/humanizer_zh` 名称的私有对象，递归断言 judge packet、文件名和裁判请求完全不存在这些标识。
2. 使用固定匿名种子验证 sealed mapping 可复现；改变种子验证左右顺序变化，而裁判仍只看到 A/B。
3. 用窃取映射、复用候选会话、提示注入、额外工具和缓存命中的假适配器验证隔离边界会拒绝运行。
4. 用可控假裁判验证 A/B 与 B/A 一致、位置偏差、无效 span、理由矛盾、分歧超阈值和 `inconclusive`。
5. 为七个维度做 schema、范围和行为锚点测试；事实忠实失败不能被其他维度 5 分覆盖。
6. 运行冻结 canary，验证每个硬门题 100% 通过；修改裁判版本或提示后必须重跑，漂移超阈值自动停用。
7. 用三个、两个、同一模型家族、一个失效和全部分歧的 panel 验证多样性与可用性门。
8. 运行旧 blind review CLI/API 兼容测试；旧人工评审集只读标为 legacy，不进入新统计，也不阻塞全自动流程。

## Observability & rollback

- 指标包含裁判包数、泄漏失败、隔离失败、裁判可用性、模型家族分布、双向一致率、canary 通过率、漂移、无效 span、panel 分歧和 `inconclusive` 原因；不记录候选正文或自由文本理由。
- sealed mapping 的读取有机器审计；任何裁判侧身份泄漏都作为 P0 评测完整性事件阻止发布。
- 裁判 registry 和聚合规则版本化。回滚选择上一套冻结 panel；已经泄漏、漂移或校准失败的运行标记无效，不进入正式统计。
