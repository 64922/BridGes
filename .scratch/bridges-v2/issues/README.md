# BridGes V2 issues：智能体并行执行建议

本目录的 `01`–`21` 是独立验收的纵向切片。`Blocked by` 表示硬前置：只有阻塞票完成并验收后，后续票才可开始。文件中的 `ready-for-agent` 表示票据描述已可领取，不表示前置工作已完成。本文是执行说明，不是第 22 张 ticket；目前不包含任何 V2 生产实现。

## 启动一张 ticket 前

1. 完整阅读该票、[ADR-0030](../../../docs/adr/0030-v2-campus-assistant-and-approved-desktop-interaction.md)、[V2 设计索引](../../../docs/v2/README.md)及索引所列的产品契约、桌面交互、工作流、可行性、技术架构和交付计划；正式界面还要对照已获批原型。V2 决策优先于旧 ADR-0026 中相冲突的产品行为。
2. 检查 `Blocked by` 中每张票的实现及验收确已完成，并阅读其落地后的接口或迁移说明。只给智能体一个 issue 文件时，不能假定它已看过其他任务的上下文。
3. 在 conda `agent` 环境开发。涉及供应商的票分别记录可控测试与少量真实可得性验证；模拟返回不能证明高德路线、贴吧回复、岗位或模型能力可用。
4. 每张票交付用户可操作的正式界面、服务行为、持久化和必要验证。未实现或未验收的模块不得在生产界面显示为可用。迁移保持旧历史可读、可导出、可恢复。

`/implement` 技能本身只说按传入规范或 tickets 实现、尽可能使用 `/tdd`、定期类型检查和单文件测试、末尾跑全套测试、使用 `/code-review`，并在当前分支提交。它**没有**自动读取 ADR 或 V2 文档的规定。因此每张 issue 都写了“实施前必读”；调用 `/implement` 时仍应把具体 issue 文件交给智能体，并检查它确已阅读这些依据。提交时只暂存本票改动，不带入工作区原有的未提交内容。

## 共用验收门

- 新增数据、图检查点、附件、画像与事件恢复均需账户隔离；密钥不得进入响应、日志、浏览器存储或截图。
- 写入新持久状态的切片须在同一票内落实适用的版本化迁移、备份、导出、删除、审计和失败恢复；`21` 只复核整体结果，不承接前面票遗漏的数据生命周期工作。
- 澄清与学习逐题状态必须持久化；停止、断线和重试不能重复用户消息、附件绑定或题目判定。
- 外部工具只取得最小必要查询，返回结果经来源与正文匹配检查后才能作为证据；不可得内容按各模块降级合同呈现。
- 高德校内路线、贴吧回复或岗位样本若未通过真实可得性门，只交付文档允许的降级；若需进一步收缩已确认范围，先记录实测证据并请用户审查产品合同。
- 每个切片对照自己的 UI、API、数据和端到端场景验收。`21` 再执行跨模块、旧数据、导出及三个目标桌面尺寸的整体回归。
