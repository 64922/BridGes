# 03 — 长对话上下文

**What to build:** 用户在长对话中引用早先说过的内容时，助手能在实际模型预算内找回相关原文，并说明回答依据。

**Blocked by:** 02 — 可恢复的对话运行

**Status:** ready-for-human

**实施前必读：** [ADR-0030](../../../docs/adr/0030-v2-campus-assistant-and-approved-desktop-interaction.md)、[V2 设计索引](../../../docs/v2/README.md)及索引所列六份设计文档；先核对阻塞票已验收。

**跨票接缝：** 编译器以原始消息为权威源，统一接收带来源的当前附件、最小画像、知识库片段和经核验的工具结果；本票先以普通聊天贯通近期及旧消息，`05`、`07`、`08` 和模块票分别接入其真实输入，不能另造互不兼容的上下文拼装链。

- [x] 每轮按锁定模型的已验证窗口编译当前请求、近期消息、旧消息摘要及必要原文，保留输出与工具预算；原始消息完整保存。
- [x] 动态预算明确预留系统规则、输出、工具及图片成本；编译记录模型 ID、预算版本、摘要版本和实际采用的原文消息 ID。
- [x] 摘要记录其来源消息范围；用户引用早先实体或约定时，能补回相关原文并记录本轮使用的消息 ID。
- [x] 预算不足时先裁掉低相关材料，不丢当前请求或已取得的关键证据；找不到旧原文时承认不确定并询问。
- [x] 私人会话材料不会整体发送到公开检索服务，跨账户历史不可召回；模型切换后下一轮重新计算预算。

## Comments

- 实现：新增 `src/bridges/chat/context_compiler.py`（上下文编译器，纯函数）。按锁定模型已验证窗口（`fixed_models.MODEL_CONTEXT_WINDOWS`，未知模型回退保守 32k）计算动态输入预算：预留输出（1024+256 余量）与工具（512），系统规则文本与当前回合图片按实际估算计入。编译产物为「模式合同 → 较早摘要块（带摘要版本与来源消息 ID 范围）→ 补回原文块（完整原文 + 消息 ID）→ 近期原文（当前请求逐字保留在最后）」。
- 补回线索：当前请求中的引号原文（「」『』“”"）优先，出现回指词（之前/上次/说好的/约定的等）时用名词性连续串作线索（过滤在较早消息中出现过于频繁的词），按线索在本会话较早消息中确定性检索并补回原文（单轮上限 4 条）；找不到时附「承认不确定并询问、不得编造」规则块并记录 `unresolved_reference`。预算不足按合同顺序裁剪：先缩较旧原文（移入摘要），再加重摘要压缩（160→60 字符）；当前请求与补回的关键证据绝不裁，触底如实记录 `budget_floor_exceeded`。补回在每轮裁剪后重算——预算收缩把被引用原文降级进摘要时仍能补回。
- 接线：`graph.py` 的 `compile_context` 节点产出 `compiled_messages` 进图状态（纯字符串/数字，检查点可序列化；租约恢复随检查点复用，不重复编译/落审计），`invoke_subgraph_or_chat` 经 `stream_generation`/`stream_turn` 以其驱动模型历史（未传入时回退既有 `_model_history`，旧编排路径不受影响）；`assemble_payload` 各 system 块注入顺序不变。
- 审计与配对：每轮落一条 `CONTEXT_COMPILED` 审计（`object_refs=[assistant_message_id]`；details 只含模型 ID、预算/摘要/估算版本、窗口与预留、采用的原文消息 ID，不含任何正文）；历史配对语义（用户原文总是纳入、助手只取最近一条 done、按轮次截断）抽取为 `turn.history_items` 共享函数，`_model_history` 与编译器共用同一实现。
- 测试：`tests/chat/test_v2_03_conversation_context.py` 14 用例覆盖五项 AC（含小窗口摘要化、预算触底保证据、不确定规则、审计无正文泄漏、跨账户隔离、双窗口重算、父图整链集成 + 审计断言）。全量 pytest 与 main 失败名称级比对无新增（258 failed / 2 errors 同 main，唯二差异：本票修复了字面量扫描违规；`humanize_eval/test_holdout` 为 main 全量跑中的顺序性波动，单测通过）；mypy strict 与 main 同口径 21 错完全一致；ruff 新文件全绿。
- 已知边界（后续票处理）：① 模型锁定已与 issue 09 对齐（合并整合）：编译器按 `run.config["run_model_id"]` 的运行锁定模型编译，窗口优先取运行配置快照的 `min(context_window, max_input_tokens)` 已验证值，未装配提供者/快照不一致时回退 `fixed_models.MODEL_CONTEXT_WINDOWS` 登记表与保守缺省窗口——换模型后下一轮按新窗口重算预算已是运行时行为；② 编译预算覆盖模式合同与编译材料，`assemble_payload` 后注入的检索/公网/教学/画像/表达策略块不受其约束（`TOOL_RESERVE_TOKENS=512` 为静态预留）——`07`、`08` 与模块票把真实输入接入编译器时收敛为单一预算口径；③ 补回线索为确定性启发式（引号 + 回指词），语义级指代消解不在本票范围。
- Code review（两轴）结论与修复：消除与 `_model_history` 的配对语义重复（共享 `history_items`）；`mode_system_contract` 收敛为单一公开访问器；删除无消费方的 `verified_model_ids`；补回重算移入裁剪循环闭合"被引用原文被降级后无法补回"边界；补齐中文弯引号识别；模型窗口登记表按架构测试合同移入 `fixed_models.py`（本票曾引入生产路径模型字面量违规，已修复）；去掉服务与回合编排间的双重防御拷贝。
