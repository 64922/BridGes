# 01 — 冻结新版产品契约并建立迁移门

Status: ready-for-agent
Type: task

## What to build

在改动运行时代码前，建立一套无矛盾、可供后续代理直接执行的权威产品合同。使用新的 superseding ADR 记录本轮已经确认的决策，并同步领域词汇、产品说明和迁移策略。

新决策必须明确取代以下旧方向：画像需预授权和逐条通知、用户管理 SKILL/MCP、项目与附件分层检索、画像中心显示复杂治理信息、对话可中途切换模式。

同时定义 expand–migrate–contract 顺序：先加入新合同和迁移读能力，再切换写路径与用户旅程，最后在兼容窗口结束后删除旧接口、表约束和页面。

## Acceptance criteria

- [ ] 新 ADR 明确声明被取代的旧 ADR，并逐项写出替代原因、行为合同、兼容期和回滚边界。
- [ ] 领域词汇新增并统一日常陪伴、学习模式、对话固定模式、全局知识库、四维画像、能力路由、教学计划、课时、内置 SKILL 和紧凑引用；把局部知识库、学习项目、任务安排、用户插件/MCP、聊天附件、会话内模式切换及旧九维画像明确标为退役，不删除账户、会话、证据和迁移审计等仍有效术语。
- [ ] 文档明确：第一条用户消息提交后模式不可变，任何客户端均不能绕过。
- [ ] 文档明确：用户扩展和 MCP 管理退出，内置 SKILL 与内部论文搜索适配器保留。
- [ ] 文档明确：知识库是唯一上传与本地检索来源，聊天附件和项目文件退出。
- [ ] 文档明确：画像默认自动提取；首次启用时只有一次非交互、不阻断聊天的隐私说明，不是授权弹窗或逐条写入通知；同时禁止敏感推断、限制为最小注入，并支持修改和撤回。
- [ ] 文档明确：人味化分为全局轻量策略和显式完整改写流程，确定性文本不改写。
- [ ] 文档明确：学习证据不足时自动联网；外网失败不得伪造资料或推进计划。
- [ ] 文档明确旧项目、提醒、凭据、扩展包和九维画像的数据迁移及回滚策略。
- [ ] 根级旧计划或历史任务若仍陈述相反规则，必须被标为历史或已由本计划取代，不让代理面对两个“当前真相”。
- [ ] 文档链接、ADR 编号和领域术语检查通过，没有断链或同词异义。

## Verification

- 对领域文档和 ADR 做全文冲突扫描，确认旧规范只出现在历史说明或“被取代”上下文中。
- 人工逐项对照 PRD 的最终产品合同、数据迁移合同和二十三项确认决策。
- 运行仓库已有的文档链接或格式检查；若仓库没有自动检查，记录人工检查清单。

## Blocked by

None - can start immediately.

## Out of scope

- 不在本 Issue 修改数据库、API、页面或运行时行为。
- 不重新设计本轮已确认的产品决策。
- 不删除历史 ADR；历史决策必须保留可审计性。

## Agent notes

这是全部后续 Issue 的规范门。若发现代码与新合同冲突，只记录到对应后续 Issue，不在这里顺手改代码。任何无法由现有决策唯一回答的新问题，应停止并在 Comments 中请求产品裁决。
