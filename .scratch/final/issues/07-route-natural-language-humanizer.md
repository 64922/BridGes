# 07 — 让自然语言自动进入文章人味化能力

Status: ready-for-agent
Type: task

## What to build

在统一聊天入口中识别“润色、改写、去模板腔、让文章更自然”等自然语言意图，并自动调用现有的文章人味化能力。用户不再先打开工具选择器，也不需要组装 SKILL 载荷；一句包含任务要求和原文的普通消息即可完成路由、事实锁检查、改写和结构化结果展示。

该切片只处理显式文章改写意图。路由命中后，把用户粘贴的原文或明确引用的当前账户知识库文档、目标受众、体裁、渠道、长度和必须保留项编译成版本化任务合同；未提供的可选字段采用稳定默认值，缺少原文这一必需输入时在聊天中给出一次简短补充提示。文章润色默认不做通用知识库检索，也不联网；只有用户明确引用知识库文档，或要求补充、核验外部事实时，才允许进入对应的精确文件解析或证据流程。聊天消息不得上传附件。

旧的显式 SKILL 消息及既有结果继续可读，新消息只走自然语言路由。历史任务只有在原文仍为消息内文本或已迁入当前账户知识库时才可重试；若唯一输入是历史聊天附件，则拒绝重新执行并引导用户先把原文件上传到知识库，不能把只读历史附件重新作为模型输入。

本 Issue 还负责把现有低质量完整改写流程升级为新的净室版本，而不只是接上路由。新版本至少包含：明确任务合同、受保护事实区、体裁与受众适配、结构和节奏修订、模板腔软检测、一次结构化生成后的确定性完整性检查，以及可追踪的未决问题。规则、示例、提示和评测语料必须由 BridGes 原创，不能把外部参考仓库的文字或资产直接复制进产品。参考项目："C:\Users\33755\Desktop\参考资料\Humanizer-zh-main"、"C:\Users\33755\Desktop\参考资料\human-writing-main"、"C:\Users\33755\Desktop\参考资料\scientific-humanization-main"

## Acceptance criteria

- [ ] **成功路径**：发送“给我润色这篇文章：……”等消息时，系统自动识别人味化意图，保存路由决策和任务合同，并在原对话中返回最终文本、修改明细、理由、改写前后事实保持检查和未决问题；只有实际执行外部证据核验时才可标为“事实核查”。
- [ ] **成功路径**：同一句消息中的受众、体裁、长度和“数字、引用、术语不能改”等约束能进入任务合同；没有给出的可选项使用有版本的默认值，不额外追问。
- [ ] **失败路径**：只有改写要求却没有原文或可用材料时，不调用人味化生成模型，不把请求降级成普通聊天；消息内给出一次明确、可操作的补充提示。
- [ ] **失败路径**：模型不可用、事实锁冲突、被引用的知识库文档不可读或输出合同不完整时，返回稳定中文错误或需人工确认状态，保留原始任务以便重试，不展示内部异常和提示词。
- [ ] **幂等**：同一用户消息、同一尝试重复投递或页面重连时只形成一个路由快照和一个人味化运行；重试沿用原任务合同，已完成结果不重复生成。
- [ ] **账户隔离**：粘贴原文、知识库文档、检索证据、运行记录和结果只能由所属账户读取；伪造或引用其他账户的知识库对象时在模型调用前拒绝。
- [ ] **迁移**：历史显式 SKILL 消息和结果保持可读；新合同在扩展期兼容旧投影，不批量改写历史消息，也不把旧消息重新路由。依赖历史聊天附件的任务重试返回稳定拒绝与“先上传到知识库”的中文操作指引，不复用附件对象。
- [ ] **模型调用次数**：每个新消息最多复用 Issue 06 的一次路由模型调用；命中且输入完整后最多执行一次人味化生成调用。事实锁、合同校验和完成度检查为确定性逻辑，不再调用模型；缺原文时人味化生成调用为零。
- [ ] **事实安全**：数字、单位、对象关系、限定条件、公式、引用和结论强度必须通过事实锁；不得新增无来源事实、伪造引用、冒充用户亲历或以“更自然”为由删除风险限定。
- [ ] **质量门**：建立至少 30 个原创中文评测样例，覆盖说明文、科普、邮件、报告、演讲稿和长短文本。新版本在预先冻结的盲评量表中至少 80% 样例达到“自然、具体、无模板腔”的通过线，且不得低于旧基线；所有样例的受保护数字、单位、专名、公式、引用和限定条件保持率为 100%，任何新增无来源事实均阻断发布。
- [ ] **净室记录**：同步更新 `src/bridges/skills/humanizer/skill/CLEAN_ROOM.md` 与现有净室 ADR，逐项登记研究仓库、许可证判断、未复制内容、原创规则/语料及审阅证据；实现或测试中不存在来源不明的逐字片段。
- [ ] **前后端**：前端以普通聊天发送消息并显示过程/结果卡，不要求打开“+”号工具；后端以同一持久化、流式、停止和重试生命周期执行，不建立旁路接口。
- [ ] **合同**：路由结果、任务输入、事实锁结果和人味化输出均有可验证的版本化结构；未知路由版本或缺少必填字段必须显式失败。
- [ ] **测试**：覆盖中文典型表达、口语化表达、否定意图、普通聊天近似词、超长原文、提示注入、事实锁冲突、旧消息兼容、历史附件拒绝重试、断线重连、重复投递、账户越权，以及与论文/图片/视频/生涯路由的共享互斥矩阵。

## Verification

1. 用表驱动用例验证至少十种自然语言改写表达和十种不应命中的近似表达。
2. 记录一次成功、一次缺原文、一次事实锁冲突和一次模型失败的事件流，确认终态、调用计数和重试合同。
3. 通过两个账户分别创建同名知识库文档并交叉请求，确认服务端在模型调用前拒绝越权。
4. 打开历史显式 SKILL 会话，确认结果仍可读取；分别验证内联原文可按合同重试、历史聊天附件被拒绝且不进入模型。
5. 冻结评测集和旧基线，执行盲评、事实保持与调用次数门禁，再运行相关后端、前端和端到端测试及仓库全量回归。

## Out of scope

- 普通回答的全局人味化表达策略，由 Issue 17 交付。
- 图片、视频、生涯规划或论文搜索的自然语言路由。
- 增加评测集未覆盖的新文章体裁；本 Issue 必须升级已有体裁的改写规则与事实保持质量。
- 复制或安装外部人味化 SKILL。

## Agent notes

- 复用现有的人味化领域服务和消息生命周期，不再实现第二套改写器。
- 路由只决定能力和输入合同，不得让路由模型直接生成最终文章。
- 默认不做通用知识库检索是本 Issue 的产品规则；只有明确引用知识库文档或要求外部事实核验时才携带最小证据切片。
- 任何外部参考只能提供通用方法灵感，具体规则、提示、示例和测试必须净室重写并进入来源清洁记录。
