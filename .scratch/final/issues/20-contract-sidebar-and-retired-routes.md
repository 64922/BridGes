# 20 — 收敛侧栏契约并退役学习项目、任务安排与插件管理页面

Status: ready-for-agent
Type: task

## What to build

把登录后的全局导航收敛为产品仍然存在的能力，并完整退役已经取消的学习项目、任务安排和插件管理入口。完成后，侧栏自上而下只包含品牌入口、搜索、收起侧栏、新聊天、知识库、用户画像、最近对话和账户菜单；“新聊天”不再使用与侧栏割裂的白色大色块，最近对话自动占用释放出的纵向空间。

这是一次端到端合同收缩，不是只把三个链接设为不可见：

- 删除学习项目、任务安排、插件管理及 MCP 管理的用户可达页面；直接访问旧地址时由集中兼容规则重定向到新聊天，且不得加载旧模块数据。该兼容边至少跨过一个可观测的迁移版本，并在旧地址调用清零后才由 Issue 24 删除并进入标准 404。
- 删除侧栏为学习项目名称、移动/移出项目、插件或任务状态发起的后台请求、缓存、事件监听、选择器和对话框。
- 最近对话项只保留模式、更新时间、置顶状态及仍有效的会话操作，不再显示项目徽标，也不再提供移动到项目或移出项目。
- 将所有用户可见的“本地知识库”统一改称“知识库”；知识库仍是当前账户的全局材料入口。
- 从统一搜索、数据隐私/导出清单、前端完整性检查以及其他全局导航衍生面中移除学习项目、任务和插件管理的残留入口与旧文案。
- 清理因此失去调用方的前端组件、数据 hook、API 客户端封装、生成类型引用和测试夹具；不得留下页面虽消失但登录首页仍请求退役接口的情况。

## Acceptance criteria

- [ ] 登录成功后，展开侧栏的可见顺序严格为：品牌、搜索、收起侧栏、新聊天、知识库、用户画像、最近对话、账户菜单；页面中不存在“学习项目”“任务安排”“插件”导航项。
- [ ] “新聊天”入口背景与侧栏表面连续，不再出现截图中的突兀白色卡片；当前页仍有不依赖大色块的清晰可访问状态。
- [ ] 删除三个模块后，最近对话区域使用剩余高度并保持自身可滚动，账户菜单始终固定在侧栏底部且可操作。
- [ ] 在兼容版本中，直接访问旧的学习项目列表/详情、任务安排和插件管理地址时重定向到新聊天；重定向无循环、不创建空会话、不加载旧模块数据，也不出现旧模块的 loading、empty 或 error 组件。
- [ ] 每个退役地址重定向都按稳定路由标识、服务版本和流量类别计数；自动探针与真实用户流量分离，指标不含账户、URL 参数或请求正文。部署后按 `COMPATIBILITY-GATE.md` 生成至少跨一个完整迁移版本的观察报告。
- [ ] 登录首页、普通聊天、搜索、知识库、画像页之间导航时，不会发出学习项目列表/详情、提醒列表、插件列表或 MCP 列表请求；测试以网络拦截将任何此类请求视为失败。
- [ ] 最近对话不显示项目名称或项目占位，操作菜单中不存在“移动到学习项目”与“移出学习项目”；置顶、改名和删除仍保持原有成功语义。
- [ ] 知识库入口、页面标题、页面元数据、空态、搜索范围和辅助文本统一使用“知识库”，不再出现会让用户误以为还存在局部库的“本地知识库”。
- [ ] 搜索输入提示、结果分类和无结果状态不再承诺搜索学习项目；隐私、导出、删除和备份说明不再列出已经退役的数据类别。
- [ ] 最近对话加载成功时展示真实列表；加载失败、无权限或会话过期时仍展示中文错误/权限状态与可用的重试或重新登录动作，退役模块不得因错误分支重新出现。
- [ ] 在 1280×720、1440×900、1920×1080 三个桌面视口以及每个视口 200% 页面缩放下，侧栏没有水平溢出，所有保留入口和底部账户菜单可达。
- [ ] 几何断言验证：侧栏上下边界在视口内；账户菜单底边不越过视口；最近对话区域顶部位于“用户画像”下方、底部位于账户菜单上方；播种超长会话列表后 `scrollHeight > clientHeight` 且改变 `scrollTop` 能滚动，无对话时该区域仍占满可用空间。
- [ ] 纯键盘从品牌入口开始 Tab 遍历时只经过保留入口，焦点顺序与视觉顺序一致，焦点环清晰；收起后可用键盘重新展开，并把焦点归还到收起前约定的恢复入口。
- [ ] 旧的“固定五模块侧栏”、学习项目页面、任务页面、插件/MCP 页面、相关视觉/无障碍/缩放测试被删除或替换为新合同测试；不得通过 skip、弱化断言或同时保留新旧两套期望来过关。
- [ ] 新的端到端测试至少覆盖：正常导航、退役地址兼容重定向、退役接口零请求、最近对话加载错误恢复、三视口、200% 缩放、键盘路径和上述几何断言。
- [ ] 类型检查、前端单元测试、相关端到端测试和前端完整性检查全部通过，且不存在因本任务产生的未使用导入、不可达组件或孤立路由。

## Verification

1. 在 Web 应用目录运行类型检查和单元测试。
2. 运行侧栏、认证落点、最近对话、搜索、数据隐私、无障碍、缩放和视觉回归的相关 Playwright 用例。
3. 对三个桌面视口分别执行正常缩放与 200% 缩放矩阵，并保存新基线截图。
4. 在测试中拦截所有退役模块接口，访问首页、聊天、搜索、知识库和画像页，确认拦截计数始终为零。
5. 分别直接访问所有退役地址，确认只发生一次到新聊天的兼容重定向、无旧数据请求且浏览器控制台无运行时错误。
6. 验证重定向探针计数与真实流量计数可区分，并输出 `COMPATIBILITY-GATE.md` 所需的路由级指标摘要。
7. 运行仓库的前端完整性检查，确认它只要求当前产品合同中的页面和组件。

- 保留既有最近对话的置顶、改名、删除、账户隔离和错误恢复语义；这里只移除项目归属能力。
