# 23 — 修复最近对话操作菜单的裁剪与碰撞定位

Status: ready-for-agent
Type: task

## What to build

修复最近对话每一项右侧“…”操作菜单只能显示一小部分的问题，使置顶/取消置顶、改名和删除在最近对话滚动区的任意位置都完整可见、可点击且键盘可用。

菜单浮层必须脱离会裁剪它的滚动祖先，依据触发器和视口实时定位，并在右侧、底部或顶部空间不足时自动翻转/收缩。修复应落在可复用菜单边界或等价的统一浮层机制中，而不是只给这一处堆叠更高 `z-index`、关闭最近对话滚动或把祖先 overflow 改成 visible。

Issue 20 完成后，该菜单的最终业务项只有置顶/取消置顶、改名和删除；本任务保留这些操作现有的请求、确认、账户隔离和错误恢复语义，只修复展示、定位与交互可靠性。

## Acceptance criteria

- [ ] 最近对话列表顶部、中部和底部的任意“…”按钮打开后，菜单所有内容完整可见，不被侧栏、最近对话滚动容器、账户菜单或视口边缘裁剪。
- [ ] 菜单只显示置顶/取消置顶、改名和删除；不存在已退役的项目移动操作。
- [ ] 空间足够时菜单与触发器保持稳定的端对齐；右侧空间不足时向左对齐，底部空间不足时向上展开，顶部也不足时限制最大高度并让菜单自身可滚动。
- [ ] 菜单打开期间滚动最近对话、滚动页面、改变窗口大小或改变缩放时，浮层持续跟随仍在视口内的触发器；触发器卸载或离开有效上下文时安全关闭，不残留孤立浮层。
- [ ] 点击菜单外部、按 Escape、激活菜单项、切换路由或触发器卸载都会关闭菜单；关闭后按既有约定把焦点归还原触发按钮，打开会话框的操作则把焦点正确交给对话框。
- [ ] Enter、Space 或 ArrowDown 打开并聚焦第一项，ArrowUp 从触发器打开时聚焦最后一项；菜单内上下箭头循环，Home/End 跳转首尾，Tab 关闭且不困住焦点。
- [ ] 置顶成功后列表顺序/标识真实更新；改名成功后菜单关闭、对话框完成保存且触发点可重新定位；删除仍经过确认并在成功后移除会话。
- [ ] 置顶、改名或删除请求失败时显示中文可恢复错误，不伪装成功；菜单可再次打开，最近对话列表和焦点仍可操作。
- [ ] 在 1280×720、1440×900、1920×1080 三个桌面视口以及每个视口 200% 页面缩放下，对最近对话第一条、中间条和最后一条执行同一组定位与键盘测试。
- [ ] 几何断言验证：菜单 `left >= 0`、`top >= 0`、`right <= viewportWidth`、`bottom <= viewportHeight`（1px 容差）；菜单与触发器至少一边按设计对齐；菜单中心点及每个菜单项中心点的 `elementFromPoint` 命中菜单自身而非裁剪层或侧栏遮罩。
- [ ] 最近对话区域仍保持独立滚动，账户菜单底部位置不变；修复后页面和侧栏均无新增水平滚动。
- [ ] 通用菜单的其他现有调用点至少通过一组回归测试，确认 portal/浮层定位没有破坏账户菜单、知识库行菜单或对话框焦点归还。
- [ ] 替换仅验证“菜单功能能调用”却不验证可见几何的旧最近对话测试；新增顶部/中部/底部、三视口、200% 缩放、键盘、成功/错误态和几何命中断言，不得仅更新截图掩盖裁剪。
- [ ] 类型检查、单元测试和相关端到端测试全部通过，事件监听、观察器和 portal 容器在关闭或卸载后均已清理。

## Verification

1. 在 Web 应用目录运行类型检查和单元测试。
2. 运行最近对话生命周期、通用菜单键盘、账户菜单、无障碍、缩放和视觉回归用例。
3. 播种足够多的最近对话使侧栏产生内部滚动，对第一条、中间条和最后一条分别执行菜单 bounding-box 与 `elementFromPoint` 断言。
4. 在三个桌面视口及 200% 缩放下重复定位矩阵，并覆盖打开菜单后滚动、调整窗口和路由切换。
5. 模拟置顶、改名和删除的成功与失败响应，确认列表、错误提示和焦点恢复。
6. 检查关闭菜单和卸载侧栏后的 DOM 与监听器，确认没有孤立浮层、重复菜单 ID 或控制台错误。

## Agent notes

- 已定位的根因是绝对定位菜单仍位于最近对话的 overflow 滚动祖先中；提高 `z-index` 无法穿透祖先裁剪。
- 推荐使用 portal 加视口坐标和碰撞检测；若选择其他实现，必须满足同样的滚动、缩放、卸载和焦点验收。
- 不要把最近对话容器改成 `overflow: visible`，这会破坏长列表滚动和底部账户菜单。
- 浮层定位需要考虑设备缩放后的 CSS 像素、菜单实际测量尺寸和触发器在打开后的移动；避免用固定宽高猜测。
- 通用菜单的 WAI-ARIA 行为已经存在，迁移渲染宿主时应保持同一个可访问名称、控制关系和唯一 ID。
