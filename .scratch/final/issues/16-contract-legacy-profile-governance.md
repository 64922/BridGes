# 16 — 收缩旧画像治理合同与页面

Status: ready-for-agent
Type: task

## What to build

完成四维画像改造的 contract 阶段：在 Issue 15 的自动抽取与注入链路稳定后，停止并移除旧九维画像的新增入口、自动更新许可、候选确认、写入通知、来源/范围/历史的用户界面、画像页静态头像区和手动新增记录。画像页最终只呈现学业情况、感兴趣的知识、兴趣爱好、阶段目标四组记录，以及首次稳定记录时间、修改和撤回操作；头像只在个人资料页面维护。

公共合同应收缩为四维列表、修改和撤回。已迁移的 legacy 记录按 Issue 14 的结果进入四维或安全封存；没有确定映射的旧记录不得重新注入回答。为了数据完整性、回滚和安全审计，内部最小来源引用、版本与撤回账本可以保留，但不再作为普通用户页面或普通聊天合同返回。

## Acceptance criteria

- [ ] **成功路径**：最终画像页只有四维记录、首次稳定记录时间、修改和撤回；编辑不会重置展示时间。页面没有新增、许可、通知、候选、冻结、回滚历史、来源、范围或头像管理入口。
- [ ] **成功路径**：修改立即影响后续合法切片，撤回立即阻止后续使用；用户无法通过旧页面、旧 API 或构造旧请求新增画像。
- [ ] **成功路径**：不存在单条画像硬删除按钮或公开 API；旧删除请求在兼容期按退役合同返回 410。账户删除仍会依照账户生命周期物理清除画像及其墓碑。
- [ ] **失败路径**：兼容窗口内调用已退役的写入、权限、通知、候选或历史端点时统一返回 HTTP 410、稳定错误码和替代说明，不静默成功，也不触发任何画像副作用；最终 404 由 Issue 24 收缩。
- [ ] **观测门**：每个旧画像 410 端点按稳定端点标识、服务版本和真实/探针流量分类计数，不记录账户、画像 ID 或请求正文，并向 `COMPATIBILITY-GATE.md` 输出观察数据。
- [ ] **失败路径**：legacy 记录未确定迁移目标时保持封存且不进入模型；收缩预检发现仍有新写调用方或未处理记录时必须阻止删除阶段。
- [ ] **幂等**：重复执行合同收缩和数据清理不会重复撤回、丢失用户修改或产生新的审计事件；修改/撤回继续使用版本校验。
- [ ] **账户隔离**：四维列表、修改、撤回和封存迁移均按账户执行；旧端点退役后也不能因错误回退暴露跨账户数据。
- [ ] **迁移**：收缩前运行调用方扫描、legacy 记录清点和可回滚备份；先停写、再迁移读取、最后删除公共合同。失败时可恢复只读旧合同，不恢复旧自动写入。
- [ ] **模型调用次数**：合同收缩、数据封存、修改和撤回均不调用语言模型；自动抽取调用仍只由 Issue 15 所有。
- [ ] **事实安全**：不确定的 legacy 内容不得硬映射或重新注入；撤回记录不能以缓存、旧切片或生成重试重新进入回答。
- [ ] **前后端**：前端移除旧控件和页面状态，后端移除对应公共写合同与事件投影；个人资料页面继续拥有头像，画像页面不复制头像状态。
- [ ] **合同**：公开画像合同只保留四维读取、修改和撤回，退役端点有明确错误码与兼容窗口；内部审计结构不出现在普通响应 Schema。
- [ ] **测试**：覆盖旧入口不可用、四维修改/撤回、撤回后切片失效、旧缓存失效、legacy 封存、重复收缩、回滚预检、个人资料头像和跨账户访问。

## Verification

1. 扫描前后端调用面，确认没有生产路径继续调用旧许可、通知、候选、历史或手动新增合同。
2. 从旧版数据库升级后逐条核对 migrated、sealed 和 withdrawn 数量，确保无静默丢失。
3. 修改并撤回一条四维记录，重试旧消息生成，确认旧切片不再复活。
4. 直接请求每个退役端点，确认稳定失败且数据库无副作用。
5. 运行画像、数据库迁移、聊天切片、前端和全量回归测试。

## Out of scope

- 删除为安全审计和迁移回滚保留的最小内部账本。
- 扩展新的画像维度或恢复用户手动新增。
- 修改个人资料页面除头像归属之外的功能。
- 回放历史聊天生成新画像。

## Agent notes

- 收缩必须以“没有旧写调用方、所有 legacy 记录有明确处置”为硬门。
- 用户界面简化不等于破坏账户隔离、乐观锁和真实撤回语义。
- 不要顺手删除与本收缩无关的存储或审计能力。
