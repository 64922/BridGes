# 06 — 从聊天自然语言路由论文搜索

Status: ready-for-agent
Type: task

## What to build

让用户在任一会话模式中直接用自然语言提出论文检索需求，由聊天能力路由器识别意图、形成受约束的检索计划并复用现有受控 arXiv worker、内部 API 与任务生命周期。用户不需要选择插件、MCP 或功能按钮；路由结果和规范化查询必须先持久化，再启动外部请求，使恢复生成、重复提交和并发重试复用同一次决定。不得另建第二套论文抓取服务，也不得把现有 arXiv 适配器误当成用户 MCP 删除。

本 Issue 同时建立后续能力共用的版本化路由注册表和互斥合同：能力定义只能通过可加性注册合并，不能让某个后续 Issue 覆盖整份枚举、分类提示或分支表。单条消息只选择并执行一个主能力；若用户同时提出多个独立任务，则只询问一个问题让用户决定先执行哪一个，不创建复合计划，也不触发任何副作用。其他歧义同样只问一个能决定主能力的问题。

该能力只处理真正的论文查找、筛选或核对请求。普通讨论中提到“论文”、请求改写论文段落、针对知识库中已有论文提问或图片生成提示均不得误触发。结果在原聊天流中返回，保持当前 `companion` 或 `study` 角色，并提供可核验的标题、作者、时间、标识符和来源链接；提供方失败时明确说明未完成搜索，绝不编造论文、引用或搜索成功状态。

## Acceptance criteria

- [ ] 明确包含查找动作及论文对象的中文或英文请求可触发论文搜索，并能提取主题、作者、标题、标识符、年份范围和数量等已表达约束。
- [ ] 仅提到论文、要求润色现有论文文本、讨论写作方法、针对知识库中已有论文的内容问答和非论文网页搜索会被确定性识别为其他意图而不误触发；真正低置信度时只询问一个最小澄清问题，澄清前不进入普通回答或任何能力副作用。
- [ ] 能力路由发生在知识库和普通联网检索决策之前；命中论文搜索后不再重复执行全局知识库检索或通用网页搜索。同一消息还有独立任务时先让用户选择本轮主任务。
- [ ] 路由注册表、能力枚举、优先级和单主能力合同均版本化并支持可加性扩展；新增 Humanizer、图片、视频或生涯能力时不能覆盖已登记能力。
- [ ] 单消息只持久化一个主能力路由并进入一个副作用分支；明确多任务或能力冲突时只提出一个“先执行哪一个”的澄清问题，澄清前不生成普通回答、不创建任务。付费图片/视频不得成为模糊请求的默认分支。
- [ ] 路由类型、规范化查询、约束、判定原因和版本在任何外部副作用前持久化；相同消息或幂等键重放复用原计划，不重复创建结果卡或并发请求。
- [ ] 路由分类每条新消息最多调用一次语言模型，确定性预检命中或明确跳过时可为零次；论文搜索、参数验证、去重、恢复和结果投影本身不得再调用语言模型。
- [ ] 发往 arXiv 的查询只含完成检索所需的主题词、作者、标识符、年份和数量约束；只有用户明确把某姓名作为“论文作者检索条件”时才能保留该作者名，用户本人姓名、画像推断姓名及其他身份、邮箱、账号、精确位置、画像私人信息、知识库原文和凭据一律剔除。审计脱敏规则版本但不记录敏感原文。
- [ ] 请求参数有明确上限和验证；非法年份、过大数量、空查询及无法支持的筛选得到可理解的聊天反馈，不把验证失败伪装成“没有论文”。
- [ ] 搜索结果去重并保留提供方原始标识；每条结果至少包含可用的标题、作者、发布日期或年份、摘要可用性、稳定标识符和来源链接，缺失字段如实标记。
- [ ] 论文卡和最终回答中的引用能回溯到同一结果快照；模型不得生成快照之外的题名、作者、年份或链接。
- [ ] 超时、限流、网络断开、提供方返回畸形数据和零结果具有不同、可审计的状态；失败或未验证时明确告诉用户，绝不生成虚假引用。
- [ ] 可安全重试的网络错误采用有界重试；恢复生成复用已成功的搜索快照，不因模型重试再次访问外部提供方。
- [ ] 会话、路由记录、搜索快照和结果卡严格归属当前账户；猜测其他账户的会话、运行或结果标识不能读取其查询和论文记录。
- [ ] 前端无需任何工具选择器即可展示搜索中、部分结果、完成、零结果和失败状态；刷新或恢复后不会丢卡、重复卡或把失败显示为成功。
- [ ] 合同明确自然语言路由结果、论文搜索状态、结果字段、错误类型和流式事件；生成客户端、接口说明和运行时校验保持同步，不要求新的客户端提交内部 MCP 载荷。
- [ ] 测试覆盖正向意图、负向提及、歧义、参数边界、显式作者名保留、用户本人/画像姓名剔除、查询脱敏、零结果、去重、超时、限流、畸形响应、幂等重试、生成恢复、模式角色和账户隔离；提供参数化的跨能力互斥测试入口，后续能力注册后必须加入同一矩阵。
- [ ] 除可重复的模拟提供方测试外，存在显式标记的真实联网冒烟测试，实际访问固定论文提供方并验证响应来源、最小元数据和失败报告；该测试不得用静态 fixture 冒充联网成功。

## Verification

- 运行能力路由、聊天生成、论文搜索、流式事件、合同及账户隔离的单元和集成测试。
- 使用中英文正例、仅提及“论文”的反例、论文段落改写和多任务请求执行端到端桌面测试，确认多任务只澄清且零副作用。
- 注入超时、限流、畸形数据、零结果和恢复生成，核对只产生一个持久化计划与一个结果快照。
- 重新生成并校验 API 合同，运行前端类型检查和论文结果卡组件测试。
- 在允许联网的发布候选环境运行真实论文提供方冒烟测试，保存访问时间、目标主机和成功/失败证据；网络不可用时测试必须显式失败或跳过并说明原因，不能回退 fixture 后仍报通过。

## Out of scope

- 通用网页事实检索；该工作属于 Issue 13。
- 用户安装或管理论文 MCP。
- 下载付费全文、绕过登录或自动获取受限版权内容。
- 用知识库文件冒充线上论文搜索结果。

## Agent notes

- 固定内部论文提供方是受控产品能力，不是用户可管理 MCP。
- 优先使用确定性规则与结构化分类结果组合；无论实现方式如何，决定必须可版本化、可解释并在副作用前落盘。
- 路由快照是幂等边界。不要在每次 worker 重试或流恢复时重新判断意图。
- Issue 07–10 必须向本注册表追加能力并复用同一个分类结果；禁止各自在编排器中增加会覆盖其他能力的独立 if/else 顶层分支。

## Comments

- 已确认：论文搜索由自然语言自动触发，聊天中不再要求用户选择工具。
- 已确认：真实联网失败必须如实呈现，不得以缓存、模型记忆或伪造条目宣称搜索成功。
