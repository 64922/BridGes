# 04 — 退役用户 SKILL、插件与 MCP 管理

Status: ready-for-agent
Type: task

## What to build

把能力系统收敛为由产品维护的内置 SKILL 和固定内部能力：用户不再安装、上传、启停、卸载或选择 SKILL、插件和通用 MCP，也不再授予 MCP 权限或确认任意 MCP 调用。聊天和知识库摄取按产品策略自动应用适用的内置 SKILL。固定的论文搜索能力仍作为内部受控提供方存在，不得因目录或历史命名中包含 MCP 而被删除。

采用 expand-contract 安全退役：先禁止新安装和新启用、把既有外部能力标记为禁用并阻止执行，保留必要审计和导出；同步发布不含选择器与管理模型的新合同和界面；兼容窗口内，旧管理和调用接口统一返回结构化 410；确认没有执行流量后，再考虑物理清理旧包、状态和密钥引用。本 Issue 不直接破坏性删除历史记录。

## Acceptance criteria

- [ ] 桌面端移除插件中心、MCP 管理、权限确认、SKILL 上传及聊天能力选择器；旧深链显示退役说明并引导回聊天或知识库。
- [ ] 新用户和升级用户都不能安装、上传、启用、禁用、卸载或直接调用用户提供的 SKILL/MCP；旧接口在兼容窗口内返回 HTTP 410 和稳定错误码。
- [ ] 410 响应不得伪造安装、启用或调用成功；重复请求幂等且不改变状态、不下载包、不启动进程、不访问网络。
- [ ] 每个管理或调用 410 端点按稳定端点标识、服务版本和真实/探针流量分类计数，不记录账户、包/服务器 ID 或请求正文，并向 `COMPATIBILITY-GATE.md` 输出观察数据。
- [ ] 升级时先把全部非内置能力置为不可执行，再迁移客户端；迁移失败时系统保持“禁止执行”的安全状态，不回退为继续运行未知代码。
- [ ] 已安装包、账户启用状态、MCP 调用历史和确认记录在兼容期只读保留并可审计；任何密钥或令牌均不出现在日志、导出页面或错误体中。
- [ ] 旧的进行中或待确认 MCP 调用被幂等终止，重启、重试或恢复旧备份都不能重新执行。
- [ ] 内置 SKILL 注册由应用版本控制，自动适用于声明支持的聊天或知识库阶段；用户无需也不能管理其启用状态。
- [ ] 知识库上传阶段的内置能力只可解析、规范化和提取元数据，不得用 Humanizer 改写源文件、改变事实或替换原始对象。
- [ ] Humanizer 作为内置写作策略可作用于助手正文和显式文章改写，但不处理系统错误、工具状态或用户上传原文；其具体质量升级不在本 Issue 中实现。
- [ ] 固定内部论文搜索仍可由自然语言路由调用，并受超时、来源限制和审计约束；它不出现在用户 MCP 列表中，也不依赖账户安装状态。
- [ ] 所有管理、调用、审计和遗留读取都执行账户隔离；账户 A 不能通过包 ID、服务器 ID、调用 ID 或确认 ID 获取账户 B 的数据。
- [ ] 新合同移除插件选择、MCP 选择、权限和调用载荷；兼容合同准确描述 410，生成客户端、接口文档和运行时校验一致。
- [ ] 备份、恢复、账户导出和删除能识别遗留记录，但恢复不得重新启用外部能力；账户删除不会遗留可用凭据或可执行状态。
- [ ] 安全测试证明任意旧客户端、篡改请求、并发启用、待确认重放和直接服务调用均无法执行用户 SKILL 或通用 MCP。

## Verification

- 运行内置技能注册、插件、MCP、聊天选择、论文搜索、安全、生命周期及账户隔离测试。
- 从包含已启用插件、MCP 凭据和待确认调用的旧数据库快照升级，验证全部变为不可执行且审计仍可读取。
- 对旧安装、启停、卸载、权限、调用和确认接口执行合同及幂等测试，核对统一 410 行为。
- 运行前端导航、旧深链、聊天编辑器、知识库上传、类型检查及桌面端端到端测试。
- 做一次内部论文搜索回归，证明保留的固定提供方不依赖用户 MCP 管理表或选择器。

## Out of scope

- 删除固定内部论文搜索能力。
- 重写 Humanizer 的语言规则和质量评测。
- 改写用户上传的知识库材料。
- 在本次兼容窗口内物理清除所有历史包、调用与审计数据。

## Agent notes

- 以“可执行能力”而不是目录名判断保留范围；内部论文搜索和用户可配置 MCP 是两个不同边界。
- 收缩顺序必须是先断执行、再移除界面和合同、最后清理数据。不要让升级中的旧账户继续运行外部命令。
- 对旧字段采用先停止写入、再观测读取量、最后移除的策略；每个阶段保持 CI 和旧数据启动测试为绿。
