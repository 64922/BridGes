# 14 — 扩展四维画像模型并迁移现有记录

Status: ready-for-agent
Type: task

## What to build

按 expand–migrate–contract 的前两阶段，在旧画像合同旁新增用户确认的四个产品维度：学业情况、感兴趣的知识、兴趣爱好、阶段目标。新维度拥有稳定标识、中文标签、首次稳定记录时间、内部更新时间、编辑版本和撤回状态，并贯穿存储、领域合同、账户 API、画像页面和测试。用户不能手动新增记录；页面只展示四类分组、记录内容和首次稳定记录时间，并提供修改与撤回。

迁移必须保守且可回滚。旧阶段目标可直接映射到新阶段目标；只有证据明确指向教育阶段的旧基本情况才映射到学业情况；只有能确定是知识主题或爱好的旧兴趣记录才分别迁移。旧知识状态转入教学域的内部学习记录，不能伪装成兴趣或学业画像；表达习惯、情绪、重要经历、当前问题、授权范围和所有语义含糊记录不得靠模型猜测，保留为不可新增且不可注入的 legacy 封存记录，等待 Issue 16 收口。

默认页面不显示来源、适用范围、画像历史、授权状态和内部置信度；为了迁移可回退、账户隔离和误写撤销，后端仍保留最小来源引用、版本和审计信息，不把这些内部字段注入普通页面或普通模型上下文。

## Acceptance criteria

- [ ] **成功路径**：四个维度可独立保存、读取、修改和撤回；默认画像页只显示分组、内容、首次稳定记录时间及修改/撤回操作，没有新增按钮。修改内容不会重置展示时间，更新时间和版本只留在内部审计。
- [ ] **治理**：公开合同不提供单条画像硬删除；撤回保留墓碑并停止使用。只有账户删除生命周期可按数据保留合同物理清除画像内容、内部证据和墓碑。
- [ ] **成功路径**：迁移报告逐账户列出四维迁移、教学记录迁移、保持 legacy、跳过和失败数量，不包含画像正文；可从报告追踪到稳定记录标识。
- [ ] **失败路径**：无法确定目标维度、内容不合法、版本冲突或迁移中断时保留旧记录，不产生猜测性新记录，并给出可重试状态。
- [ ] **失败路径**：修改或撤回不存在、已撤回或版本过期的记录时返回稳定冲突，不覆盖较新的用户操作。
- [ ] **幂等**：迁移以旧记录稳定标识和目标版本为幂等键；重复执行不重复创建四维记录，不改变已由用户修改或撤回的结果。
- [ ] **账户隔离**：迁移、列表、修改和撤回全部按账户作用域执行；相同记录标识也不能跨账户读取或操作，迁移报告不能聚合泄露正文。
- [ ] **迁移**：采用先扩展、再按确定性规则搬迁、最后由 Issue 16 收缩的顺序；升级前有备份/预检，失败可回滚到旧读路径，成功后新旧读路径在过渡期一致。
- [ ] **模型调用次数**：Schema 扩展、分类迁移、去重和报告生成全部为确定性逻辑，迁移期间语言模型调用次数为零。
- [ ] **事实安全**：知识掌握程度只能进入教学域内部学习记录，不得自动改成兴趣；不得从年龄、学校名或一次提问推断学业阶段，不得把第三方、假设、角色扮演或情绪材料迁移成用户画像。
- [ ] **前后端**：后端提供四维读取、修改和撤回合同；前端仅呈现四类与首次稳定记录时间，头像移交个人资料页面，旧治理面在过渡期只读且不新增。
- [ ] **合同**：四维枚举、记录投影、乐观锁版本、撤回语义和迁移状态有版本化定义；教学域接收旧知识状态的最小内部合同有稳定来源标识且不出现在画像 API；旧画像枚举在扩展期仍可解码，但不得成为新写入目标。
- [ ] **测试**：覆盖四维 CRUD 限定操作、无新增入口、直接映射、旧知识状态转教学记录、含糊记录封存、重复迁移、部分失败回滚、用户修改优先、跨账户隔离和旧客户端读取。

## Verification

1. 在旧结构夹具上执行迁移两次，比较记录数量、内容哈希和迁移报告，确认第二次无新增副作用。
2. 对每个旧维度准备明确、含糊和冲突样例，确认只有确定性映射成功，旧知识状态只进入教学域而不出现在四维画像页。
3. 在迁移前后修改或撤回同一条记录，验证乐观锁、用户操作优先级及修改不重置首次稳定记录时间。
4. 用两个账户执行列表和变更，确认结果完全隔离。
5. 运行数据库迁移、画像领域、API、前端和全量回归测试。
