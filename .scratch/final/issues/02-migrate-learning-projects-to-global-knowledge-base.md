# 02 — 将学习项目资料安全迁移到全局知识库

Status: ready-for-agent
Type: task

## What to build

用 expand-contract 完成一次可审计、可重入、非破坏性的资料迁移：把每个账户现有学习项目中的文件及其可检索内容迁入该账户唯一的全局知识库，同时在收缩阶段到来前维持旧数据可读。迁移期间不得覆盖同名文件、串用其他账户对象、重写原始内容或让新增项目文件落在迁移快照之外。

本 Issue 是“单一全局知识库”的数据准备阶段，不立即删除旧表和历史引用。先扩展全局知识库记录，使其能够保存旧项目文件的稳定来源标识、原始文件名、所属项目名称、对象校验值、摄取版本和迁移状态；再冻结旧项目文件入口的新建与修改能力，并明确引导到知识库上传，不采用双写；随后分账户回填、校验并切换展示；最后把旧项目入口置为只读并进入明确的兼容窗口。兼容窗口结束后的 410 收缩由后续 Issue 11 完成。

迁移后的文件必须像普通知识库文件一样能够被列出、下载、重新索引、删除和导出。项目文件迁移并校验成功后，已有项目对话解除运行时项目归属，保留原会话标识、锁定模式、完整消息顺序和生成历史；旧项目名称及关联只进入迁移审计。历史对话仍应能展示旧的项目引用；不得为了统一新模型而改写历史消息或伪造新的引用来源。

## Acceptance criteria

- [ ] 扩展阶段先增加迁移身份与状态，再进行回填；部署任一中间版本时，旧数据和新数据都可读，且应用不会因新旧记录并存而启动失败。
- [ ] 每个旧项目文件最多生成一条对应的全局知识库源记录；幂等键不依赖可变文件名，重复执行、进程重启和任务重投不会生成重复文档或重复对象。
- [ ] 同一账户内内容哈希相同的旧文件只生成一个知识库文档、原始对象和索引，多个旧来源以审计映射指向它；跨账户记录仍保持独立授权边界，不因物理去重泄露对象存在性。
- [ ] 同名但内容不同的文件分别保留，界面使用项目名、时间或稳定后缀帮助区分，不覆盖已有全局知识库文件。
- [ ] 原始对象在目标记录、索引和校验全部通过前不得删除或移动；失败时保留原文件并把该项标记为可重试失败，不把部分索引标记为成功。
- [ ] 迁移前后逐账户核对文件数、字节数、内容校验值、可下载性、索引版本和失败数；提供机器可读的迁移摘要及可追踪的失败原因。
- [ ] 迁移只读取当前账户拥有的项目、文件和对象，目标知识库记录继续归属同一账户；使用猜测 ID、其他账户会话或对象键均不能观察、下载或迁移他人资料。
- [ ] 迁移运行期间，旧项目文件的新建与修改被明确拒绝并提示改到知识库上传；不得保留双写分支，也不得出现无提示的迁移后增量遗漏。
- [ ] 项目文件关联的摄取任务处于排队、处理中、失败或已完成时均有确定迁移语义；旧任务晚到完成不能覆盖新索引或制造第二份来源。
- [ ] 已撤回、已删除或对象缺失的旧记录不被“复活”；其迁移状态可审计，用户界面不把它们显示为成功文件。
- [ ] 用户在迁移后删除知识库目标时写入迁移删除墓碑；即使旧源仍因兼容期保留，重跑、恢复或旧任务迟到也不得重新创建文档、对象或索引。只有一次新的知识库上传可产生新记录。
- [ ] 每个旧项目对话在其所需文件迁移通过闸门后幂等解除项目归属，原会话 ID、账户、模式、消息、运行状态和时间顺序完全保留；新消息不再写项目外键，项目名和旧关联仅存于迁移审计。
- [ ] 前端把旧学习项目资料页改为只读迁移视图，展示完成、处理中和失败状态，并把后续上传入口指向全局知识库；刷新和重复点击不会重复启动同一迁移。
- [ ] 后端提供受账户鉴权保护的迁移状态与安全重试能力；批量任务支持断点续跑、限速和单项失败隔离。
- [ ] 新合同增加迁移状态和目标知识库文件标识，但在兼容期继续解析旧项目来源与旧引用；生成的客户端类型、接口说明和运行时校验保持一致。
- [ ] 备份、恢复、账户导出与账户删除覆盖迁移台账和新知识库记录；恢复后重跑迁移仍幂等，删除账户不会遗留其迁移对象。
- [ ] 自动化测试覆盖成功迁移、同名冲突、同账户相同内容哈希去重、多来源审计映射、删除目标后的墓碑防复活、重复执行、中途崩溃、对象缺失、索引失败、并发写入、对话解除项目归属、账户越权、备份恢复和历史引用兼容。

## Verification

- 运行数据库迁移的升级、重复升级、从真实旧版本快照升级及备份恢复测试。
- 运行知识库、摄取、对象存储、学习项目、生命周期和账户隔离的服务级与 API 集成测试。
- 使用至少两个账户、同名异内容文件、同内容异来源文件、项目对话和一个故意失败的对象执行端到端迁移，核对哈希去重、审计映射、下载内容、索引命中、会话身份/模式/消息不变及重试结果；随后删除一个迁移目标并重跑，确认墓碑阻止复活。
- 运行前端类型检查、迁移视图组件测试和“旧页只读、上传跳转知识库”的桌面端流程测试。
- 重新生成并校验 API 合同；运行全量回归，确认历史项目引用仍可渲染。

## Out of scope

- 删除旧项目表、旧来源枚举或历史引用。
- 决定普通聊天是否发起检索。
- 改写、摘要或 Humanizer 处理用户上传的原始资料。
- 迁移历史聊天附件；聊天附件入口退役与历史兼容由后续合同收缩处理。
- 删除通用后台任务基础设施。

## Agent notes

- 这是 expand-contract 的扩展与迁移阶段。不要用一次破坏性表重建同时完成复制和删除。
- 优先保留稳定来源 ID 与对象校验值；文件名不是可靠幂等键。
- 新记录只允许产生 `knowledge_base` 来源，旧 `project` / `project_file` 值仅用于历史兼容。
- 在收缩前提供至少一个明确版本的只读兼容窗口，并记录可观测的旧入口调用量，供 Issue 11 判断何时返回 410。
