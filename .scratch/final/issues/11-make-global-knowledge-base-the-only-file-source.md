# 11 — 将全局知识库收缩为唯一可检索文件来源

Status: ready-for-agent
Type: task

## What to build

在 Issue 02 已完成项目资料回填和校验的基础上，完成 expand-contract 的收缩阶段：所有供聊天使用的文档和用户图片只能通过全局知识库进入系统，新建聊天和新检索记录只产生 `knowledge_base` 来源。删除学习项目资料管理、聊天附件上传和其他文件入口，并在兼容窗口内让旧项目文件及聊天附件写 API 返回明确的 410。

历史消息、历史 citation 和旧备份中的项目或附件来源继续只读兼容；历史聊天附件不会被暗中迁入知识库，也不能作为新请求的输入。系统不得为追求新合同一致而篡改历史证据。需要使用文件的 Humanizer、图片编辑或问答请求，必须引用当前账户知识库中已经存在且有权访问的文件。

每次知识库上传先保存不可变原件及内容校验值，再自动运行由产品登记的受信任内置能力：类型/安全校验、文档解析或图片视觉理解、元数据提取、分块和索引。用户不选择或启停这些能力；流水线与各阶段版本可审计，重新索引只更新派生物，不改写原件。Humanizer 不参与摄取，也不能润色、覆盖或替换源文件。

## Acceptance criteria

- [ ] 只有全局知识库页面提供文档和用户图片的上传、列表、下载、重新索引和删除能力；导航、学习项目页和聊天编辑器不再提供文件选择、隐藏文件输入或“加入项目资料库”等第二入口。
- [ ] 所有新摄取、索引、检索文档和新 citation 的持久来源均为 `knowledge_base`；任何新代码路径都不能写入项目文件或可检索聊天附件来源。
- [ ] 文档与图片上传均先持久化不可变原件和内容哈希，再自动执行适用的受信任解析/视觉理解、元数据、分块和索引阶段；无需用户选择 SKILL，各阶段保存能力版本、输入/输出身份和明确终态。
- [ ] 重新解析、重新分块和重新索引只产生版本化派生物，不改变原件字节或哈希；Humanizer 和其他写作策略不进入摄取链路，任何原件变化均阻断验收。
- [ ] 新消息合同不再接受聊天附件上传、绑定或摄取字段；需要文件的自然语言任务只能解析当前账户知识库中的授权文件，不能通过遗留对象 ID 复用历史聊天附件。
- [ ] 项目创建、项目文件写入与关联、聊天附件上传与绑定接口在兼容窗口内返回 HTTP 410、稳定错误码和全局知识库替代入口；重复旧请求无副作用且不返回假成功。
- [ ] 每个项目/附件 410 端点按稳定端点标识、服务版本和真实/探针流量分类计数，不记录账户、项目/对象 ID 或请求正文，并向 `COMPATIBILITY-GATE.md` 输出观察数据。
- [ ] 收缩前设置迁移闸门：只要任一账户存在未迁移、校验失败或迁移期间新增但未纳管的项目文件，部署就拒绝进入收缩状态并给出可操作摘要。
- [ ] 成功收缩后重复运行迁移检查幂等；不得重复摄取、重复复制对象、改变文档版本或删除已验证的全局知识库记录。
- [ ] 旧项目对象至少保留到兼容窗口结束且备份恢复验证通过；物理清理必须单独审计，不能夹带在普通 schema 升级中。
- [ ] 历史项目/附件 citation、导出文件和备份恢复后仍可渲染其原始来源标签；新客户端不会把历史来源误显示成新全局知识库命中。
- [ ] 每次知识库上传、下载、重新索引、删除、能力输入解析和历史引用解析都执行账户授权；账户 A 无法通过文件名、摘要、对象键、索引命中或历史 ID 推断账户 B 的资料。
- [ ] 同名文件以稳定文档身份区分；删除或重新索引一个文件不会影响同账户的另一同名文件，更不会影响其他账户。
- [ ] 摄取失败、视觉理解失败、格式不支持、对象损坏或索引不可用时返回阶段化真实状态并允许安全重试；重试复用同一原件且不重复创建文档或索引，文件未可检索前不得显示“已完成”。
- [ ] 前端对知识库上传、摄取进度、失败重试、下载、删除和旧链接兼容均有明确状态；聊天编辑器没有附件按钮或隐藏上传路径，刷新和断线恢复不产生重复上传。
- [ ] 新合同移除项目来源、聊天附件请求字段和相关写事件，只对历史投影保留兼容枚举；生成客户端、接口文档、运行时校验和导出格式同步更新。
- [ ] 搜索目录、账户导出、备份、恢复和账户删除不再依赖活跃学习项目，但能处理历史数据；全量测试证明没有孤立对象或不可删除记录。

## Out of scope

- 决定每个聊天回合是否需要检索；该工作属于 Issue 12。
- 把历史聊天附件迁入知识库；它们保持历史只读，后续物理清理由最终收缩门控制。
- 改写历史消息或把历史来源批量伪装成知识库来源。
- 退役学习复习调度；该工作属于 Issue 03。
