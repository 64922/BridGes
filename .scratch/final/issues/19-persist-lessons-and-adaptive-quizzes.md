# 19 — 持久化课时进度与自适应测验

Status: ready-for-agent
Type: task

## What to build

在 Issue 18 的计划与第一课基础上，把学习对话变成可恢复的课时序列。每个成功完成的正式教学回答对应且只对应一个课时；澄清问题、错误、加载和工具状态不计课时。计划在知识边界或每完成 2–4 个课时安排一次短测验，读取用户答案后评估当前理解，再生成下一课、复习课或补救课。

课时进度属于当前学习对话，不建立学习项目。持久化对象应覆盖计划版本、课时编号、教学目标、证据快照、测验、用户作答、评分依据、掌握观察和下一步决策。测验掌握度是课程进度状态，不新增第五个长期画像维度；只有符合 Issue 15 四维规则的稳定兴趣或目标信号才可进入画像。

用户明确反馈“太快、太难、想多练习”等，或相关画像被修改、撤回时，只调整尚未交付的课时。每次调整创建幂等的计划调整记录，保存触发消息或画像版本、原因、旧计划版本、新计划版本和受影响的未来课时；已经交付的课程、评分和证据快照不倒改。

为控制成本和一致性，含测验作答的一个用户回合使用一次结构化教学生成，同时产出“对上次作答的判定 + 下一课内容”；后端先验证判定与证据，再原子提交评分和新课时。公开检索只在下一课证据不足时发生，不因评分自动联网。

## Acceptance criteria

- [ ] **成功路径**：计划、课时和测验可在刷新、重启和重新登录后恢复；每个成功正式教学回答编号递增一次，当前进度和下一检查点在聊天中可见。
- [ ] **成功路径**：到达知识边界或完成 2–4 个课时时生成与已教内容对应的短测验；除等待补答等非教学状态外，连续正式课时不得超过 4 个而没有测验。用户作答后，下一课根据错误点选择继续、复习或补救，并给出简短可解释反馈。
- [ ] **成功路径**：用户节奏/难度反馈或相关画像修改、撤回会生成一个版本化计划调整，并从下一课生效；调整记录包含原因及新旧计划版本，历史课时不变。
- [ ] **失败路径**：无效作答、评分合同不完整、证据不足或模型失败时不递增课时、不提交部分评分，保留原测验等待补答或重试。
- [ ] **失败路径**：普通澄清、停止、错误消息和工具状态不得消耗课时；用户偏离主题时可生成同编号内的澄清，不伪造已完成课程。
- [ ] **幂等**：对话、计划版本、用户消息和课时编号形成唯一边界；同一作答重复投递只评分一次，同一生成重试只创建一个下一课，同一反馈或画像版本只创建一条计划调整，已提交评分和调整不可被迟到结果覆盖。
- [ ] **账户隔离**：计划、课时、测验、作答、评分和证据均绑定账户与对话；切换账户后不能读取或推进其他账户的课程。
- [ ] **迁移**：Issue 18 生成的计划与第一课可直接升级为持久序列；没有新状态的旧学习对话在下一次有效学习消息时惰性初始化，不重写历史消息或依赖学习项目。
- [ ] **模型调用次数**：每个有效学习回合最多一次结构化教学生成；有测验作答时同一次调用同时返回判定与下一课，不另启评分模型。画像抽取、统一路由和外部搜索分别计量，教学服务不得重复调用它们。
- [ ] **事实安全**：测验题、参考答案和评分依据必须来自本计划已教内容及其证据；不得把开放问题强判为唯一答案，不得把模型自评分当作科学正确证明，证据变化时旧题可标记失效。
- [ ] **前后端**：前端在消息流中展示课时编号、计划进度、测验、作答反馈和下一步，不新增课程工作台；后端原子持久化作答、判定、下一课和消息终态。
- [ ] **合同**：计划、Lesson、Quiz、Attempt、Assessment、NextAction 和 PlanAdjustment 有版本化状态及允许转换；运行成功与课时可信/完成状态分开，未知转换必须拒绝。
- [ ] **测试**：覆盖连续多课时、2/3/4 课时检查点、全对/部分错/无效作答、补救课、难度反馈、画像修改/撤回、调整记录幂等、证据失效、重复投递、迟到结果、进程重启、旧对话惰性初始化和跨账户推进。

## Verification

1. 使用固定模型夹具完成“第一课→作答→第二课→测验→补救课”的完整链路，并分别覆盖 2、3、4 课时检查点，核对状态转换和编号。
2. 对同一测验答案并发提交两次并重放后台任务，确认只产生一份评分和一个下一课。
3. 在评分生成、数据库提交和下一课流式输出的不同阶段注入失败，确认原子回滚与可恢复状态。
4. 修改/撤回画像并提交“太难”反馈，确认只产生一个计划调整版本、下一课生效、历史课时不变；重放事件不重复调整。
5. 使某条教学证据失效，确认受影响测验和后续课时被标记并重新取证，而不是继续沿用错误答案。
6. 运行教学状态、持久化、检索失效、聊天、前端和全量端到端测试。

## Out of scope

- 学习项目、独立课程后台、证书、排行榜或多人课堂。
- 把测验分数写成新的长期画像维度。
- 高风险考试的正式评分、监考或录取预测。
- 邮件提醒和任务安排。

## Agent notes

- “每次回复一个课时”仅指成功的正式教学回复；错误和澄清不应制造虚假进度。
- 下一课与评分一次生成、一次原子提交，能同时控制调用数和状态一致性。
- 自适应只能依据当前课程的作答与合法四维切片，不得推断智力、人格或永久能力标签。
