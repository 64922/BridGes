# 10 — 让自然语言自动进入生涯规划

Status: ready-for-agent
Type: task

## What to build

让用户直接说“帮我规划考研后的职业方向”“我该不该转行”等话，系统即可从普通聊天进入现有生涯规划能力。路由应区分可执行的生涯规划请求、一般职业闲聊和学习计划请求，把目标、时间范围、约束、当前消息中的文字材料及当前可用的最小画像切片编译成规划合同，并在同一对话中输出可解释的规划结果。聊天消息不接收附件；若用户明确要求依据知识库材料，统一检索链路只能读取当前账户授权的知识库文件。

画像只用于调整建议的层次、例子和约束，不能把推断当成用户事实。遇到职位、考试政策、行业趋势等时效性信息时沿用已登记搜索能力；没有证据时明确不确定性，不给出保证录取、保证就业或确定收入的承诺。

## Acceptance criteria

- [ ] **成功路径**：典型生涯规划自然语言被自动路由，输出目标澄清、当前条件、可选路径、取舍依据、近期行动和风险/待确认项，并作为当前消息的结构化结果持久化。
- [ ] **成功路径**：已有且与任务相关的画像切片可用于调整建议；没有画像时仍能按当前消息完成，不主动盘问画像或装作了解用户。
- [ ] **失败路径**：目标过于含糊且会改变方案时只问一个最关键问题；证据不足、搜索失败或规划服务不可用时返回范围受限的说明，不伪造市场数据和成功概率。
- [ ] **失败路径**：一般职业话题、简历文本润色和学习课程规划被确定性识别为其他意图，不得误触发生涯规划；真正低置信度时只提出一个最小澄清问题，澄清前不生成规划或普通替代回答。
- [ ] **幂等**：同一消息的路由合同和规划运行只创建一次；重试复用输入、画像快照和证据快照，已完成结果不重复生成。
- [ ] **账户隔离**：画像、当前消息、授权知识库证据、搜索披露、规划结果和历史只属于当前账户；跨账户对象在任何模型或搜索调用前拒绝。
- [ ] **迁移**：历史显式生涯规划结果保持可读；新自然语言合同与旧结果投影并存，旧消息不重新路由、不重新抓取时效数据。
- [ ] **模型调用次数**：每个新消息最多复用 Issue 06 的一次路由调用；命中且输入充分后最多一次规划生成调用。公开搜索和确定性合同校验不额外调用语言模型；缺关键目标时规划生成调用为零。
- [ ] **事实安全**：所有时效性结论标注来源和访问时间，画像推断不得冒充事实；输出必须保留不确定性、备选方案和用户最终决定权，不承诺就业、录取、薪酬或投资回报。
- [ ] **前后端**：普通聊天输入即可触发，结果以内嵌可展开卡和正文呈现；后端复用统一消息、搜索披露、停止、重试和审计生命周期。
- [ ] **合同**：路由与规划合同明确目标、期限、约束、证据、画像使用类别、版本及未决问题；缺字段、未知版本和证据过期有稳定失败语义。
- [ ] **测试**：覆盖考研、转行、求职和长期方向请求，普通闲聊近似词，缺目标，聊天附件拒绝、授权知识库证据、搜索失败，画像为空/冲突，提示注入，重复投递，旧消息兼容、跨账户访问及共享路由互斥矩阵。

## Verification

1. 用四类典型生涯请求和一组近似非意图消息验证路由边界。
2. 对同一请求分别在无画像、有相关画像和有冲突画像下运行，确认建议变化可解释且不泄露内部画像术语。
3. 固定搜索结果后重复运行，确认调用计数、证据快照和幂等结果。
4. 模拟搜索失败与模型失败，检查未决项、错误状态和重试行为。
5. 运行生涯规划、聊天、搜索、前端和端到端回归测试。

## Out of scope

- 个性化课程编排，由 Issue 18 和 19 交付。
- 简历全文人味化，由 Issue 07 负责路由。
- 替用户投递职位、报名考试或联系第三方。
- 医疗、法律、投资等专业决定。

## Agent notes

- 生涯规划是建议与取舍工具，不是预测器。
- 画像只允许通过当前任务的最小切片进入模型；路由模型不得读取完整画像。
- 时效性事实必须先取证再生成，搜索失败不能用训练记忆补成最新事实。
