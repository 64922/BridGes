# 05 — 在首轮消息提交时锁定会话模式

Status: ready-for-agent
Type: task

## What to build

把 `companion` 与 `study` 变成会话级不可变约束。用户可以在空白新会话发送第一条消息前选择模式；首条用户消息、所选模式和首个生成任务必须在同一原子操作中提交，此后前端不再提供切换，后端也拒绝任何试图改变模式的请求。所有回复、恢复生成和重试都从持久化会话读取模式，不信任客户端重复传入的值。

用 expand-contract 处理旧切换接口与历史事件：先增加锁定状态和服务端校验，旧客户端对相同模式的重复提交保持幂等，对不同模式返回冲突；随后移除新客户端的切换合同和界面；兼容窗口内，专用切换接口返回结构化 410。历史模式事件只读保留，不能改写已有对话内容。

## Acceptance criteria

- [ ] 新会话在没有用户消息时可选择 `companion` 或 `study`；首条用户消息成功提交后，持久化模式立即锁定且不可更改。
- [ ] 首条消息、会话模式、用户消息记录和生成任务原子提交；任一环节失败时不留下“消息已写入但模式未锁定”或“模式已锁定但没有首轮”的半状态。
- [ ] 两个并发首轮请求只能有一个决定模式；相同幂等键重放返回同一首轮结果，不重复生成；不同模式竞争时失败方收到稳定的 `409 conversation_mode_locked`。
- [ ] 已锁定会话再次提交相同模式可作为幂等兼容处理，不创建模式事件；提交不同模式无论来自 API、恢复任务、旧客户端还是内部服务都被拒绝。
- [ ] 旧的模式切换接口在兼容窗口内返回 HTTP 410、稳定错误码和“新建另一会话以使用其他模式”的中文提示，不返回假成功。
- [ ] 模式切换 410 按稳定端点标识、服务版本和真实/探针流量分类计数，不记录账户、会话 ID 或请求正文，并向 `COMPATIBILITY-GATE.md` 输出观察数据。
- [ ] 所有助手回合、工具路由、画像装配、检索和学习状态都使用持久化模式；客户端省略、篡改或伪造模式不能改变行为。
- [ ] `companion` 始终使用陪伴角色合同，`study` 始终使用教师角色合同；模式锁定不削弱安全提示、事实约束或引用规则。
- [ ] 升级迁移为所有已有会话保留当前有效模式并标记已锁定；历史切换事件仍可读取，但迁移不新增事件、不重新解释旧回复。
- [ ] 遇到缺失或非法历史模式时，迁移显式失败并列入审计，不静默猜测导致人格改变；修复后重复迁移幂等。
- [ ] 模式的读取、锁定、冲突和历史事件严格按账户隔离；使用其他账户的会话 ID 不得泄露其模式或是否存在。
- [ ] 前端在首轮前显示模式选择，在首轮提交成功后固定展示当前模式并移除切换动作；冲突或网络重试不会清空已输入内容或开启第二个会话。
- [ ] 新合同把模式定义为创建/首轮属性并移除切换能力；兼容合同包含 409 与 410，生成客户端、接口说明和运行时验证同步。
- [ ] 自动化测试覆盖两种模式、空会话选择、原子失败、并发首轮、幂等重试、生成恢复、旧接口 410、历史迁移和跨账户访问。

## Verification

- 运行聊天服务、首轮原子提交、生成恢复、教学状态、合同和账户隔离测试。
- 用并发测试同时向同一空会话提交相同及不同模式，核对唯一消息、唯一生成任务和确定的冲突结果。
- 从含多次历史模式事件的旧数据库升级并重跑迁移，确认当前模式保留、历史可读且没有新增事件。
- 运行前端模式选择、刷新、断网重试、旧深链和桌面端端到端测试。
- 重新生成 API 合同并运行全量回归，确认两种角色提示在各自模式中稳定生效。

## Agent notes

- 锁定时点是首条用户消息的原子提交，不是仅靠前端按钮状态，也不是会话草稿创建时。
- 服务层必须成为唯一不变量边界，避免某个内部调用绕开 HTTP 校验。
- 专用切换 API 使用 410；在正常发消息接口中携带冲突模式使用 409，两者语义不要混淆。
