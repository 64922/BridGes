# 15 — 默认启用画像抽取并在回答前注入

Status: ready-for-agent
Type: task

## What to build

对每一条持久化成功的用户消息执行画像预处理：识别其中可稳定复用的学业情况、感兴趣的知识、兴趣爱好和阶段目标，先以四维记录完成去重或更新，再编译与本轮任务相关的最小画像切片，最后开始能力路由或回答生成。整个过程不向用户直接询问画像，不要求开启许可，也不发送写入通知；并非每条消息都必须产出记录，无法可靠提取时应当零写入。

抽取只处理用户关于自己的明确、稳定信号。第三方信息、引用文本、假设、否定句、角色扮演、一次性情绪、敏感身份、健康、政治、宗教、财务、精确位置、凭据和私人通信不得进入四维画像。用户明确说“我对 X 感兴趣”等自我陈述可立即形成稳定兴趣；普通提问只形成不进入模型上下文、也不显示在画像页的内部观察。初始晋升规则为同一规范化知识主题在 90 天内至少出现在两个不同消息/回合中，规则阈值和窗口必须版本化；消息重放不累计，过期观察不晋升。冲突记录保留最新用户明确陈述并降低内部可靠度，不静默拼成矛盾结论。

画像预处理失败不能拖垮聊天。正常路径同步只尝试一次；失败时不写部分结果、不注入未提交数据，回答按无新增画像继续，并创建以“消息 + 抽取器版本”为唯一键的持久重试任务。任务状态至少包含 pending、running、succeeded、exhausted，使用后台队列最多重试三次并按现有队列策略退避，进程重启后可恢复。成功重试只影响未来回答，不倒改已生成消息；它固定原消息快照和抽取器版本，且不能覆盖失败后发生的用户修改、撤回或墓碑。已存在且合法的画像仍可按相关性、模式和长度上限编译为切片；模型只能使用切片，不得直接查询完整画像库。

## Acceptance criteria

- [ ] **成功路径**：每条用户消息在生成开始前都有一个持久化的画像预处理终态；有效四维信号先提交，再能在同一轮最小切片中被使用。
- [ ] **成功路径**：明确的教育阶段、持续知识主题、爱好和阶段目标分别进入正确维度；重复同义表达去重，用户后来明确更正时更新而非新增冲突副本。
- [ ] **首次说明**：账户第一次启用画像能力时只展示一次非交互式隐私说明，并持久化账户级、跨设备的 `ever_shown` 标记；说明版本只用于审计，版本升级不会自动再次展示，除非未来另有明确产品决策。说明不要求同意、不阻断本轮聊天、不提供关闭开关，后续消息和每条写入均不重复提示。升级账户已有可证明的历史告知时标为已展示，否则只补展示一次。
- [ ] **失败路径**：抽取模型不可用、超时、输出不合约或数据库提交失败时整批零写入，聊天继续生成，且本轮上下文不包含未提交候选；同一失败只创建一个持久重试任务，后台三次有界尝试后进入可审计终态，重启不会丢失或无限重试。
- [ ] **失败路径**：第三方、假设、引用、角色扮演、敏感信息和单次情绪均为零写入；系统不得为了“更懂用户”而追问画像或扩大推断。
- [ ] **幂等**：消息标识、抽取器版本、维度和规范化内容共同构成幂等边界；同一消息重放、生成重试或后台重新领取不重复写画像、观察或重试任务，也不重复累计兴趣晋升证据。
- [ ] **账户隔离**：抽取输入、写入记录和注入切片均绑定消息所属账户；后台任务必须携带账户上下文，任何跨账户候选在模型调用前失败。
- [ ] **迁移**：新抽取只写 Issue 14 的四维合同；旧画像继续按迁移结果读取但不接受新写入。上线不回放全部历史聊天，除非另有一次性、显式批准的迁移任务；升级账户只按 `ever_shown` 或可证明的历史告知决定是否补展示，不因说明版本变化重复提示。
- [ ] **模型调用次数**：同步路径每条可分析的自然语言消息最多一次结构化画像抽取调用，不在聊天请求内循环；每次后台重试最多一次调用且总计最多三次，已成功或 exhausted 后不再调用。明显无画像信号的机器命令或空载荷可由确定性预检以零次调用结束。普通文本回答仍最多一次主生成调用，画像注入本身不增加生成调用。
- [ ] **事实安全**：画像值被标记为用户信号而非外部事实；回答不得声称用户未明确提供的信息，不得从画像推导诊断、身份或高风险结论，观察、冲突和低可靠记录不进入切片。撤回墓碑阻止旧证据重放或普通观察重新晋升；只有撤回后的全新、明确自我陈述才可建立新记录。
- [ ] **前后端**：后端在消息持久化与生成之间完成预处理，前端不展示权限开关或写入通知；画像页在回答后可刷新看到新记录，但不弹窗打断对话。
- [ ] **合同**：抽取输出只能包含四维枚举、规范化值、内部证据引用、可靠度和动作类型；额外字段、未知维度或超长内容整批拒绝。切片包含用途、版本和长度预算，但不暴露完整来源正文。
- [ ] **测试**：覆盖四维正例、零写入反例、明确兴趣立即写入、普通提问仅观察、兴趣阈值前后、90 天过期、否定/引用/第三方/角色扮演、重复与冲突、抽取超时、坏 JSON、事务失败、三次后台重试、重启恢复、exhausted 终态、消息重放、墓碑、生成重试、切片预算和跨账户污染。

## Verification

1. 对固定语料逐条运行抽取，人工核对四维精确率、零写入率和敏感信息拦截率。
2. 发送一条含有效目标的消息，断言写入提交时间早于主生成开始，且本轮切片能使用该目标。
3. 注入抽取超时、解析失败和数据库失败，确认回答继续、无部分写入，并观察持久任务完成三次有界后台尝试及重启恢复。
4. 重放同一消息、推进观察时钟并重试生成，确认画像、观察、重试任务和版本不异常增长；撤回后旧证据不能复活。
5. 在两个设备会话验证首次说明只展示一次，再运行画像、聊天生命周期、模型网关、前端刷新和账户隔离的全量回归。

## Out of scope

- 重新开放画像许可、候选确认或写入通知。
- 从全部历史聊天批量构建画像。
- 情绪、人格、健康、政治、宗教、财务和敏感身份画像。
- 让模型直接读取完整画像中心。

## Agent notes

- “每条消息抽取”表示每条消息都经过判定，不表示每条消息必须落一条画像。
- 保留内部最小证据、抽取器版本和可靠度是去重、纠错与撤回所需，不在简化 UI 展示。
- 画像参考项目只能提供通用方法灵感；规则、提示、示例和测试需净室重写，并在来源清洁记录中登记研究边界。
