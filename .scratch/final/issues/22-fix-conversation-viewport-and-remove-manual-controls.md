# 22 — 固定会话输入区并移除模式切换与手动工具控件

Status: ready-for-agent
Type: task

## What to build

把已创建会话改成单视口聊天工作区：消息只在会话线程内部滚动，输入区始终停靠在主内容底部，输入区周围使用与会话页面连续的背景，不再出现截图中的白色割裂带。会话模式在首轮创建时已经确定，进入会话后只能读取、不能切换。

同时把会话输入区收敛为自然语言入口，只保留消息输入、听写、发送/停止和必要状态：

- 删除模式切换按钮和切换模式请求、事件与客户端状态。
- 删除附件/项目/知识库/画像来源条、“+”菜单、聊天附件上传、学习项目选择、插件选择、MCP 调用和所有手动功能对话框。
- 删除请求中的人工知识库/画像开关、项目/插件选择、MCP 和手动技能选择等退役字段；知识库检索时机、画像注入和技能路由由服务端决定。
- 删除冗长的“本地检索”过程卡、来源层状态、无命中说明和手动重试按钮。若回答带知识库证据，保留紧凑、可访问的引用链接，但不得重新包成“本地检索”模块。
- 保留自然语言路由后的真实结果展示，包括论文搜索、人味化、生涯规划、图片和视频结果；删除已取消的 MCP 结果与确认 UI。
- 清理不再可达的组件状态、请求封装、事件处理、恢复逻辑、缓存和旧契约引用，不能只用 CSS 隐藏。

## Acceptance criteria

- [ ] 打开已有日常陪伴或学习模式会话时，不存在可点击的模式切换控件，也不会调用切换模式接口；会话投影中的模式在刷新、继续发送和错误重试后保持不变。
- [ ] 会话页保留唯一、语义正确的一级标题；模式需要展示时只能是只读文本，不得伪装成按钮、开关或可聚焦控件。
- [ ] 输入区中只保留消息输入、听写、发送或生成中的停止动作及必要状态信息；不存在来源状态条、“更多功能”、隐藏文件输入、项目/插件 chip、MCP 调用、手动工具对话框或人工知识库/画像开关。
- [ ] 普通消息请求不再提交附件、学习项目、插件/MCP、模式切换、手动技能选择、`use_knowledge_base` 或 `use_profile` 等退役字段；测试断言字段不存在，而不是被固定为默认值。
- [ ] 用户以自然语言请求论文搜索、人味化、生涯规划、图片或视频能力时，消息像普通文本一样发送；服务端返回对应过程/结果投影后，既有结果卡正常显示、刷新后仍可恢复。
- [ ] 页面不再出现“本地检索”“正在检索本地材料”、附件→项目→知识库来源层、检索充足性、无命中说明或“重试检索”。
- [ ] 当回答包含知识库引用时，以紧凑引用列表保留文件名及可用定位信息，键盘可打开证据；无引用时不渲染空引用容器。引用详情失败时显示局部中文错误并允许重试，不恢复冗长检索卡。
- [ ] MCP 选择、调用、敏感确认和结果卡从当前会话合同中消失；系统默认技能不提供用户级启停、选择或调用控件。
- [ ] 消息较少时输入区位于主内容底部；消息超过一屏时浏览器 body 不承担聊天滚动，只有会话线程滚动，输入区在整个滚动过程中位置不变。
- [ ] 输入区外层背景与会话页计算后的背景色一致，不出现独立白色横带；输入卡本身仍满足边界和对比度要求。
- [ ] 会话加载成功、加载失败、发送失败、流式生成、停止、断流恢复和重试均有真实中文状态；任何失败都不得改变会话模式、清空未发送文本或显示假成功。
- [ ] 在 1280×720、1440×900、1920×1080 三个桌面视口以及每个视口 200% 页面缩放下，输入区始终完整位于主内容视口内，消息线程可到达最后一条消息且没有水平滚动。
- [ ] 几何断言验证：页面根滚动高度不超过视口 1px 容差；线程 `scrollHeight > clientHeight` 时可独立改变 `scrollTop`；滚动前后输入区的 x/y/width/height 在 1px 容差内不变；输入区底边不越过视口，且不与侧栏或展开恢复按钮相交。
- [ ] 纯键盘可以进入消息线程、输入框、听写和发送；Enter 发送、Shift+Enter 换行、生成时 Escape/停止动作保持既有语义；滚动、失败和重试后焦点不丢到 body，也不会落到已删除控件。
- [ ] 替换所有锁定“会话内可切模式”、来源条、知识库/画像开关、“+”菜单、聊天附件、项目/插件选择、MCP 调用和完整本地检索卡的旧测试；自然语言能力测试迁移为直接输入意图，不得 skip。
- [ ] 新端到端测试覆盖两种只读模式、长会话内部滚动、短会话底部停靠、自然语言能力成功、加载/发送/引用错误、停止恢复、三视口、200% 缩放、键盘路径和上述几何断言；更新会话页视觉快照。
- [ ] 类型检查、单元测试和相关端到端测试全部通过，不存在因本任务产生的未使用导入、不可达弹窗、孤立 API 客户端函数或旧事件渲染分支。

## Verification

1. 在 Web 应用目录运行类型检查和单元测试。
2. 运行会话模式、流式消息、停止/恢复、自然语言能力、引用、听写、无障碍、缩放和视觉回归用例。
3. 捕获普通消息和各自然语言能力消息的请求体，断言只包含新合同字段且服务端投影能够恢复。
4. 构造短会话与超过三屏的长会话，分别在三个桌面视口和 200% 缩放下执行根页面、线程和输入区的几何断言。
5. 模拟会话加载失败、发送失败、断流、引用详情失败和重试成功，确认错误局部化、文本保留、焦点恢复及模式不变。
6. 检索页面文本与可访问树，确认退役控件、“本地检索”和 MCP 交互均不存在；重新生成会话页视觉基线。

## Agent notes

- 当前问题的根因是聊天外壳只有最小高度、没有受限高度；线程虽声明可滚动，父级仍会随内容增长。应建立明确的视口高布局和 `min-height: 0` flex 链，而不是仅给输入区加 `position: fixed`。
- 使用 `fixed` 直接钉在窗口容易覆盖侧栏、缩放后的内容和错误横幅；优先让会话主列成为一屏高布局，线程滚动、输入区作为固定 flex 子项。
- 输入区白带来自外层表面色，而非消息正文。以计算背景色和视觉快照验收，不要写死某个十六进制颜色。
- 自然语言能力的过程/结果卡是保留项；删除的是手动选择入口及 MCP。不要在清理“+”菜单时误删论文、人味化、生涯、图片和视频的结果投影。
- “本地检索”整块删除，但科学依据仍以紧凑引用保留，这是已确认的取舍。
