# 13 — 强化自动联网证据搜索与失败诚实性

Status: resolved
Type: task

## What to build

在能力路由和知识库检索决策之后，强化现有 `src/bridges/web_search` DuckDuckGo 客户端与服务，建立自动联网证据搜索的可靠闭环。用户明确要求联网、核查事实，问题涉及近期变化的信息，或学习问题在全局知识库中没有足够证据时，系统形成持久化的联网计划，访问产品固定的无用户密钥 DuckDuckGo 提供方，筛选可核验来源，并让回答中的事实引用绑定到实际抓取结果。不得另建只在 mock 中可用的搜索旁路，也不得把联网能力改成用户 MCP。

不需要联网的闲聊、创作、Humanizer、图片任务和已有充分本地证据的稳定问题应跳过。论文意图继续交给固定论文搜索，不能同时走通用网页搜索。网络失败、来源不足或内容无法验证时，系统必须清楚区分并告知用户，不能用模型记忆、旧缓存或虚构链接冒充本次联网结果。

## Acceptance criteria

- [ ] 明确“搜索/查证/最新”等请求、具有明显时效性的事实问题和知识库证据不足的学习问题可触发联网；普通闲聊、纯创作、Humanizer、图片任务及稳定且已有充分证据的问题跳过。
- [ ] 论文搜索作为主能力命中时不再启动通用网页搜索；用户同时提出论文搜索和另一个独立任务时沿用 Issue 06 的单主能力澄清合同，不生成分步复合计划。教学证据门内部按需组合公开网页与论文来源不视为用户多能力路由。
- [ ] 联网决定、规范化查询、触发原因、时效判断、提供方、规则版本和预算在网络请求前持久化；幂等重试和生成恢复复用计划及已成功结果。
- [ ] 联网决策、查询编译、来源筛选、抓取、缓存和引用投影均使用确定性逻辑，语言模型调用次数为零；不得为搜索计划或来源评分另启模型。
- [ ] 统一外发边界只发送完成搜索所需的去身份化主题词，强制剔除姓名、邮箱、账号、精确位置、画像私人信息、知识库原文、凭据和私人通信；分别审计原始查询引用与外发查询哈希、脱敏规则版本和删除类别，但日志不保存敏感正文。
- [ ] 查询数、结果数、重试次数、总时限、响应大小和重定向次数均有上限；只允许受控协议和目标，拒绝本地地址、私有网络、凭据 URL 及危险重定向。
- [ ] 搜索结果保留真实标题、来源域名、链接、发布时间可用性、抓取时间和内容摘要；最终引用必须能映射到同一持久化结果，模型不得补造 URL 或来源。
- [ ] 对时效性结论优先使用权威一手来源，并在可能时用独立来源交叉验证；只有搜索摘要、聚合转载或无法打开的页面不得被包装成已核实一手证据。
- [ ] 外部页面中的提示注入、指令、要求泄露系统信息或触发工具的文本始终作为不可信资料处理，不改变系统策略、账户范围或后续工具调用。
- [ ] 零结果、DNS/连接失败、超时、限流、提供方错误、页面抓取失败、来源冲突和证据不足具有不同状态及用户提示；不得把任何失败显示为“已联网核实”。
- [ ] 当联网是回答时效性事实的必要条件而搜索失败时，助手明确说明无法完成核验，并避免给出确定性最新结论；能提供稳定背景时要清楚区分背景知识与未核验部分。
- [ ] 缓存必须按规范化查询、时间窗口和提供方版本隔离，并标出缓存时间；过期缓存不能冒充当前搜索。相同回合重试不重复生成搜索卡或引用。
- [ ] 查询、结果快照、缓存和引用严格按账户与会话授权；日志和指标不得记录完整敏感查询、页面凭据或其他账户数据。
- [ ] 前端在同一聊天流中准确展示计划中、搜索中、部分成功、已核验、零结果和失败状态；引用可打开真实来源，刷新恢复后状态不倒退、不重复。
- [ ] 合同明确联网决策、状态机、来源元数据、引用、缓存时间和结构化失败；生成客户端、接口文档和运行时校验同步。
- [ ] 自动化测试覆盖触发/跳过决策、论文去重、权威来源优先、时效缓存、超时、限流、冲突来源、提示注入、危险 URL、幂等恢复及账户隔离。
- [ ] 建立显式标记的真实联网冒烟测试，通过现有 DuckDuckGo 客户端访问真实提供方并验证 DNS/HTTP 确实发生、来源域名和抓取时间真实、回答引用可打开；不得用 mock 或 fixture 冒充真实联网通过。
- [ ] 每个受控搜索提供方都有不含用户查询的健康检查，能区分 DNS、连接、认证、限流和上游故障；健康状态不替代真实搜索冒烟，故障注入能验证切换/失败状态与有界恢复。
- [ ] 发布门禁分别报告确定性测试和真实联网冒烟结果；因环境禁止联网而跳过时必须标记“未验证”，不能把发布候选描述为已通过联网验收。

## Verification

- 运行联网决策、搜索提供方、抓取安全、提示注入防护、聊天生成、流式状态、citation、合同和账户隔离测试。
- 用受控故障注入覆盖 DNS 失败、超时、限流、畸形响应、来源冲突、过期缓存和生成恢复，核对状态与用户措辞。
- 运行 SSRF/重定向/私有地址、恶意网页指令、超大响应和敏感日志检查等安全测试。
- 执行前端状态卡、引用打开、刷新恢复、类型检查和桌面端端到端测试。
- 在允许联网的发布候选环境运行真实网络冒烟，保存目标域名、请求时间、响应状态和引用可达性证据；关闭 mock，并让失败真实反映在门禁结果中。

## Out of scope

- 登录网站、绕过付费墙、验证码或访问用户私人浏览器会话。
- 取代专用论文搜索或把论文结果混入通用网页来源。
- 为所有普通聊天强制联网。
- 在来源不足时由模型自行补全“可能存在”的链接或事实。

## Agent notes

- 判断顺序应保持“能力路由 → 本地检索决策/结果 → 联网决策”，防止三条证据路径互相重复。
- “搜索成功”必须以真实提供方结果和持久化证据为准，不以模型是否写出流畅答案为准。
- 真实联网测试可单独标记以控制日常 CI 波动，但必须是发布候选门禁的可见项目。

## Comments

- 已确认：需要时自动联网，不要求用户手动选择搜索工具；不需要时不增加延迟和噪声。
- 已确认：网络不可用、证据不足或来源冲突时必须如实说明，禁止伪造检索、引用或“已核实”结论。

## Answer

已在 `codex/issue-13-harden-online-evidence-search` 实现并提交：

- 联网计划在请求前持久化，包含触发原因、脱敏查询、提供方/规则版本、预算、哈希和删除类别；重试、刷新恢复和账户缓存复用成功结果。
- DuckDuckGo 客户端使用固定探针、查询/结果/重试/总时限/响应大小/重定向边界，拒绝凭据 URL、本地/私有地址和危险重定向，并保留真实来源元数据。
- 新增空结果、页面抓取失败、证据不足、部分成功、来源冲突、限流、DNS/连接/超时和提供方健康状态；外部标题/摘要按不可信资料注入，回答引用和 URL 必须绑定持久化结果。
- SQLite 缓存按账户、规范化查询、提供方版本和时效窗口隔离；前端、OpenAPI 和 TypeScript 生成契约同步。

验证：搜索、聊天、学习、存储迁移、契约和延迟预算定向测试通过；真实 DuckDuckGo 冒烟仅在显式 `BRIDGES_DDG_SMOKE=1` 时运行，未设置时标记为 skipped/未验证。完整套件默认收集仍受仓库既有同名测试模块冲突阻塞。
