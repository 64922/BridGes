决策依据：本轮 grilling 逐项讨论及用户最终回复「定稿」。合同替代关系见 [ADR-0042](../../docs/adr/0042-adaptive-learning-mode.md)。当前使用行为仍以实际代码及根目录 README 为准；本文件描述替代目标。

## 1. 产品目标与范围

将学习模式重新实现为个人自适应学习导师，以学习问题和具体理解障碍为中心，通过启发、讲解、验证、诊断与后续教学形成持续反馈。

首要验收场景是「突破理解难点」：能够找到具体误解，帮助用户独立解释和应用。系统性领域学习与围绕资料学习也属于范围。

沿用 BridGes 的聊天入口、桌面视觉语言和现有模型配置。学习诊断、路线与进展属于当前账户，支持跨学习对话延续。日常陪伴及三个保留模块的合同继续适用。

不增加真人教师端、师生管理、独立课程工作台、提醒调度或用户插件。学习路线也不恢复已退出的日常「学习资料推荐」模块。

参考约束 C01（用户补充确认）：只借鉴参考项目的教学逻辑，不直接复制、搬运或改名移植其代码。导师、诊断和规划的提示词、数据合同与实现均根据本项目定稿重新设计，优先复用 BridGes 自身已有模块；不迁入参考项目的配置、学生档案或文件数据库。

## 4. 教学流程

### 4.1 启动与恢复

1. 识别本次请求属于具体问题、题目、系统性目标、资料学习、续学或临时岔题。
2. 具体问题直接开始必要的探查或讲解，保存会话进展；无需创建长期课程目标。
3. 系统性目标读取相关已核验记录与用户明确自述，提出简短可调整路线；缺少会改变教法的信息时只问一个必要问题，不统一先做入门测验。
4. 「继续上次的线性代数」按本人目标和进展恢复；多个候选确有歧义时先澄清目标，不从最近话题强行选择。
5. 路线是导师方案，用户明确接受的目标和条件保持权威；方案不能反向改写用户的学习目的。

### 4.2 每轮教学

读取当前目标与路线、当前知识点、必要前文、待回答问题、相关学习档案、相关明确偏好和实际采用的资料。只注入本轮需要的内容。

导师根据当前理解选择主要教学动作：探查理解、逐步提示、反例引导、补充前置知识、直接解释、应用验证或阶段小结。一次聚焦一个问题，按实际困难调整方式，不机械地每轮出题或连续重复同类追问。

需要给出完整解释、演示推导或参考解法时允许直接交付。解释保持条件与假设，计算题可使用已登记工具复算；模型知识不得冒充教材原文或已取得的外部来源。

提问、请求再讲、临时岔题和明确跳过不是对待答题的作答，不能被自动判错。明确跳过时解除当前等待，记录未验证，允许继续。

### 4.3 验证与诊断

在关键概念处，通过复述理由、辨别例子或小应用获得作答证据。正式题目在展示前形成评价依据，保留等价表述和关键误解；作答后不根据学生答案临时改标准。开放探查记录理解线索，不伪装成有唯一标准答案的考试。

导师可针对本轮回答及时反馈。学习档案中的正式判断由独立后台诊断核对实际题目、回答、提示程度、评价依据和必要知识来源后形成；待核验的观察不作为已确认的长期判断。

区分尚未验证、在提示后完成、本次独立完成、观察到的具体误解及尚无法判断。它们是证据的含义，不是固定能力等级或掌握百分比。单次独立答对不等于长期掌握；没有作答不等于存在知识缺口。

### 4.4 调整、切换与收尾

已提交的诊断按目标相关性影响后续例子、提示和前置知识安排。教学可以降低粒度或补讲，用户可以随时跳过、修改路线或直接要求下一步。

临时问题获得局部回答，原目标继续保留；明确改学时保存原进展，暂停原目标，激活新目标。待答问题同时记录暂停或跳过，不把新话题回答写入旧题。

问题解决或小目标完成后，自然概括本次验证内容、尚未确认之处与可选下一步。用户说「今天先到这里」即可暂停，不要求额外考试。小结使用实际记录，后台未完成项如实保持待确认。

## 5. 职责与现有基础的接入

| 职责 | 输入 | 输出与边界 |
| --- | --- | --- |
| 导师 | 当前请求、必要前文、目标、相关档案与资料 | 流式教学回复；本轮即时反馈不直接改写正式学情。 |
| 学情诊断 | 实际作答与提示记录、题目及评价依据、知识上下文 | 可追溯诊断与知识判断，独立核验后由领域服务提交。 |
| 学习规划 | 用户目标、相关已核验诊断、已有路线与约束 | 路线草案或修订建议；新目标及必要调整时调用。 |
| 学习领域服务 | 用户动作、模型结构化结果、版本和权限 | 目标、会话进展、证据、档案及任务状态的权威写入。 |
| 共享执行底座 | 登记能力、节点输入、预算和停止信号 | 调用、事件、完成收据、恢复与终态提交，不持有学习业务规则。 |

实时导师使用现有流式聊天能力；诊断与规划使用现有结构化输出。角色不要求不同模型，也不要求每轮串行调用全部角色。沿用当前主模型配置、运行快照和额度规则。

优先接缝：

- `chat/service_context.py`：已有上下文编译与模式运行入口。
- `ai/qwen_adapters.py`：已有流式回复与结构化输出能力。
- `runtime/queue.py`：已有事务入队、租约、重试和崩溃恢复。
- `kernel/`：已有节点、产物、收据和提交守卫。
- `chat/attachments*.py`：已有照片与文件账户草稿、会话绑定和解析边界。
- `profiles/automatic.py`：异步任务的现有接线范例；学习诊断使用自身业务记录，不复用画像提取提示词或把两类记录混写。

保持学习模块职责清晰，按目标管理、导师、诊断、档案、规划、材料、历史承接等实际职责拆分；通过类型化端口接入现有服务。避免新模块直接依赖大型 ChatService 的私有状态，代码单文件控制在 500 行以内。

## 6. 逻辑数据合同

| 对象 | 必需含义 | 所有权与生命周期 |
| --- | --- | --- |
| 学习目标 | 稳定目标 ID、本人目标及原话来源、路线版本、进展、活动或暂停状态 | 学习领域；长期目标独立于会话 ID，多次对话可关联同一目标。 |
| 学习路线 | 目标对应的知识点顺序、前置关系、当前节点、修订原因和版本 | 学习领域；保留修订前版本，不能静默改变目标。 |
| 学习会话进展 | 当前目标或局部问题、当前知识点、待答问题、本轮约束、暂停位置 | 学习领域；同一对话只绑定一个当前目标，局部问题不强制创建长期目标。 |
| 学习证据 | 题目与实际回答的消息定位、提示程度、知识上下文、评价依据、来源有效性 | 学习领域引用聊天/材料；不复制全部历史作无限期档案。 |
| 学习诊断 | 具体误解或表现、支持与反驳证据、不确定性、后续验证建议、诊断状态和版本 | 学习领域；未核验结果不晋升为正式知识判断。 |
| 学习档案 | 按知识点及其学科/目标上下文组织的当前知识判断、相关证据与修订记录 | 账户级学习领域；用户可查看、纠正和删除。 |
| 诊断任务 | 目标及证据引用、输入版本、处理状态、尝试次数、结果引用与失败原因 | 学习领域拥有业务状态，共享队列只负责领取和调度。 |
| 阶段小结 | 实际验证内容、尚未验证项、具体缺口、可选下一步及依据 | 绑定生成时进展和证据版本，不随后续状态重写历史。 |

现有跨轮任务带会话归属，不能直接将其会话 ID 改成跨会话学习目标。学习目标拥有独立身份，会话内任务与单次运行通过引用关联，复用已有版本和执行能力而不扩大日常任务语义。

知识点不得仅以标题作为跨目标身份；同名概念需要保留学科、用途与证据上下文，无法确认相同时分别保留。暂不建设全学科统一知识本体或通用课程平台。

学习档案和原子画像分别管理：画像中的明确目标、偏好可辅助教学；作答误解不自动变为人格、情绪、注意力或整体能力标签。学习档案的读取、记录与个人画像开关的具体接线在实施合同中明确，不扩大现有画像授权。

## 7. 异步、并发与失败合同

1. 学习回复的终态提交与诊断任务登记使用同一短事务；成功回复需要诊断时，不留下「回复已保存但任务丢失」的间隙。模型调用在事务外执行。
2. 诊断以账户、学习证据、输入版本和诊断协议版本构成幂等单位。重复事件或恢复不重复计数同一作答；已完成任务不因重复入队再次更新学情。
3. 页面关闭后，待执行任务留在数据库；应用进程仍运行时后台继续处理，应用退出后重启恢复，不声称程序关闭期间仍会调用模型。
4. 后台只读取仍有效且属于当前账户的来源。提交前校验目标、证据和档案版本；用户纠正、删除、撤回或目标切换后，迟到结果不能覆盖最新状态。
5. 不同作答的诊断按实际证据顺序归并，不能以任务完成先后决定当前知识判断。冲突保留并待进一步验证。
6. 停止或失败的教学回复不推进路线，也不生成成功作答诊断；已经完成并提交的独立证据不被页面停止抹除。
7. 诊断失败保留原档案，按既有有界重试恢复；不把服务失败记为学生答错。失败状态可在学习详情中查看与重试。
8. 用户删除的记录及其旧来源不得由历史扫描自动恢复；真正的新作答作为新证据处理。用户纠正保留主动来源，自动结果不能原地覆盖该纠正。
9. 多个会话继续同一目标时，通过目标/路线版本提交守卫处理并发；冲突时重新读取或要求用户选择，不悄悄覆盖进展。

## 8. 材料、查证与隐私边界

取消学习模式统一的书页照片首轮门禁。复用现有已支持的照片、PDF、DOCX、TXT、Markdown 与本人知识库能力，维持现有格式、体积及解析限制；不引入新的媒体类型承诺。

资料按目标和当前问题读取。照片、公式或图表不清时，只请求补充依赖它的部分；不把识别失败升级为整个学习模式不可用。长资料明确实际读取范围，不声称已读完整本书。

基础知识、常规方法和推导可以用模型知识直接教学。用户明确要求核实或引用、涉及具体论文、时效信息、精确外部数据或争议结论时，触发相关查证；用户不联网或关闭知识库的限制优先。查证失败可交付已经支持的内容，待核实结论保持缺口。

区分教材原文、知识库来源、公开检索、模型解释与推导。公式保留条件，引用指向实际取得的片段。公开查询只发必要术语，不发送完整私人材料、学习档案或完整会话。

目标、档案、任务与材料访问均校验账户。来源删除后的派生引用停止使用并如实显示不可用；导出、备份和账户删除应覆盖新学习对象及任务。用户管理入口不显示隐藏提示词或模型内部推理。

## 9. 界面合同

- 新聊天选择学习模式后，可直接输入问题或目标；资料上传为可选操作。
- 首条消息后沿用当前对话模式锁定规则。切换学习目标不等于切换学习/日常模式。
- 对话顶部简洁显示当前目标与知识点，局部问题只显示相关主题；取消固定五阶段条。
- 学习详情按需展开，展示路线与进展、具体缺口、验证状态、依据和下一步建议。
- 正式诊断尚未完成时显示真实状态，不先显示虚构的掌握结果；查看、纠正、删除操作可访问。
- 完成小目标时在聊天中自然小结，支持暂停、继续、直接讲解、跳过验证及明确切换目标的自然语言操作。
- 加载、无学习记录、部分材料不可读、诊断失败、停止及重试各有明确反馈；键盘操作、焦点和状态播报沿用现有桌面可访问性合同。

具体接口、按钮和布局在实施前形成与上述行为一致的交互合同，不新增独立工作台。

## 10. 旧模式退出与历史承接

实施切换后，所有新学习入口使用新流程，删除旧五阶段写入与执行路径，不以兼容层维持两套学习教学逻辑。历史合同及只读渲染所需类型按外部读取义务保留。

旧会话、附件、预习与复盘题、原始作答、判定和总结保持可读/可导出，不重新评分。历史停止、重试或恢复操作不得重新启动旧图。

用户主动选择「继续学习」后创建新模式对话，以本人选定的目标和材料开始。旧材料的沿用必须校验来源账户、可访问性与用户选择，生成新会话有权使用的引用；不得绕过现有附件会话边界。原材料位置和来源仍可追溯。

旧评分可以作为历史作答记录查看，不能直接转换成长期掌握。进入新模式后通过新的实际作答与核验形成学情。

上线前识别旧未完成运行并安全结束，按图和能力版本禁止旧检查点套用新节点。备份、导出与回滚需实测；新学习数据不能在回滚时被旧五阶段状态误解释或静默删除。

## 11. 实施顺序

| 阶段 | 交付内容 | 必须验证 |
| --- | --- | --- |
| P1 领域与存储 | 学习目标、会话进展、证据、档案及版本合同，账户仓库和生命周期 | 跨会话目标关联、单当前目标、来源有效性、导出/删除与版本冲突。 |
| P2 最小教学闭环 | 纯文字启动、实时导师、单个难点探查/讲解/验证、跳过与自然收尾 | 使用确定性替身复现误解纠正、停止/重试和未验证语义。 |
| P3 独立诊断 | 事务入队、后台核验、档案更新、提示程度区分、用户管理 | 幂等、重启恢复、乱序完成、失败、删除与迟到结果。 |
| P4 持续带学 | 简短路线、按档案调整、跨对话续学、岔题和明确切换 | 用户目标不漂移，进展可恢复，跳过验证不被门禁阻塞。 |
| P5 资料与界面 | 现有附件/知识库接入、按需查证、学习详情、真实状态投影 | 来源约束、解析边界、引用、键盘/状态反馈和前端构建。 |
| P6 历史与发布验收 | 旧写入退出、历史只读及主动续学、完整回归与真实模型评测 | 新入口唯一、旧图不复活、历史可读、三个日常模块无新增回归。 |

这些是设计阶段划分，不表示已经创建、执行或完成实现工单。后续实施在 conda `agent` 环境进行；沿用项目已有依赖，新增依赖须先核对现有能力。

## 12. 验收合同

| 编号 | 场景与可观察结果 |
| --- | --- |
| AC01 | 纯文字「互斥是不是独立」可启动；不要求书页，能探查并定位混淆。 |
| AC02 | 引导或讲解后使用不同情境检查；能记录是否需要提示，不能把被提示的复述算作独立完成。 |
| AC03 | 连续卡住或缺少前置知识时改变教法；不循环重复相同问题，不以无限追问阻塞用户。 |
| AC04 | 「直接完整讲解，我不想答题」得到完整说明并允许继续，档案保持未验证。 |
| AC05 | 提问、看完解释、「懂了」和未作答都不自动生成掌握或缺口结论。 |
| AC06 | 「带我学线性代数」形成简短路线，暂停并重开对话可恢复；单个问题不强制形成长期目标。 |
| AC07 | 概率学习中临时问 Python 不改目标；明确改学后原目标保存并暂停。 |
| AC08 | 诊断由实际证据触发，回复不等待所有后台任务；核验前不显示正式掌握判断。 |
| AC09 | 回复成功与诊断入队原子一致；关闭页面、执行器重启、重复调度不丢任务、不重复记账。 |
| AC10 | 诊断失败、乱序返回、并发续学或旧版本提交不会伪造学情或覆盖新状态。 |
| AC11 | 用户纠正/删除后，旧证据不再影响教学，历史扫描和迟到任务不能恢复记录；他人不能访问档案。 |
| AC12 | 无资料基础概念可直接教；需要查证时遵守来源限制，失败保留未核实项，引用不伪造。 |
| AC13 | 文件未解析或照片不清如实反馈，不能声称已读；无关材料不能改变用户学习目标。 |
| AC14 | 阶段小结只描述实际验证和未验证项，不宣称长期掌握，不要求额外考试；详情按需展开。 |
| AC15 | 旧记录可读，主动续学新建新模式对话；旧评分不转换成长期掌握，旧运行和重试不复活。 |
| AC16 | 模式锁定、附件分域、账户隔离、日常陪伴及 paper/commute/tieba 的既有行为无新增回归。 |

机制测试验证状态、权限、事务和恢复；真实模型评测单独验证误解定位、教学适应、解释正确性和用户控制。真实评测至少覆盖概率概念、函数/极限概念与编程理解难点，并保留一次失败、一次跳过和一次跨会话续学的完整旅程。

实施时先记录固定基线及当前失败，再运行项目定义的完整检查；前端修改额外构建，数据库变更执行生成/迁移，数据搬迁另执行数据迁移。不能用替身测试代替真实教学效果，也不能把基线问题声称为本票已修复。
