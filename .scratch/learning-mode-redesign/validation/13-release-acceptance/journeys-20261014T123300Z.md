互斥（Mutually Exclusive）和独立（Independent）是两个完全不同的概念，在概率均大于 0 的情况下，它们通常是**对立**的。

我们可以从定义上来区分：
*   **互斥**意味着两个事件不可能同时发生。如果事件 A 发生了，事件 B 就绝对不可能发生。即 $P(A \cap B) = 0$。
*   **独立**意味着一个事件的发生与否，完全不影响另一个事件发生的概率。即 $P(A \cap B) = P(A)P(B)$。

如果两个事件互斥且概率都大于 0，那么当你知道 A 发生时，B 发生的概率立刻变为 0。这意味着 A 的发生极大地“影响”了 B 的概率（从原来的正数变成了 0）。因此，它们不仅不独立，反而是高度相关的。

只有当其中一个事件的概率为 0 时，互斥才可能与独立共存，但在常规讨论中（概率 > 0），互斥绝不等于独立。

## programming-mutable-default
- 目标误解：认为默认参数每次调用都会重新求值，两次调用各自得到新列表。
- 会话：nj-TcxumwXeRsG_s5Qte6Q（55671 ms）

### 学员（c1-start）

这段 Python 代码两次 print 分别输出什么？为什么？
def add(item, bucket=[]):
    bucket.append(item)
    return bucket
print(add(1))
print(add(2))

**导师**（status=done，首段 7991 ms，完成 13479 ms，调用 2，输入/输出 token 1944/702）

这段代码展示了 Python 中一个非常经典且容易踩坑的特性：**默认参数只在函数定义时求值一次**，而不是在每次调用时重新创建。

### 1. 输出结果

*   第一次 `print(add(1))` 输出：`[1]`
*   第二次 `print(add(2))` 输出：`[1, 2]`

### 2. 核心概念解析

在 Python 中，函数的默认参数（这里是 `bucket=[]`）是在**定义函数时**就创建好的对象，并且这个对象会一直驻留在内存中，绑定在函数对象上。

*   **第一次调用 `add(1)`**：
    由于没有传入 `bucket` 参数，Python 使用定义时创建的那个空列表 `[]`。执行 `bucket.append(1)` 后，这个列表变成了 `[1]`。函数返回这个列表。

*   **第二次调用 `add(2)`**：
    同样没有传入 `bucket` 参数。关键点来了：Python **不会**重新创建一个新的空列表，而是继续使用**同一个**列表对象。此时，这个列表里已经存有上一次调用留下的 `1`。执行 `bucket.append(2)` 后，列表变成了 `[1, 2]`。

这就好比 `bucket` 是一个全局共享的“容器”，每次你不指定新容器时，它都往同一个旧容器里加东西。

### 为什么 bucket 没有重置？

1.  **“一次性”创建**：默认参数对象是在**定义函数时**（即执行 `def add(...)` 那一行时）创建一次的。
2.  **共享引用**：这个创建好的列表对象会一直存在内存中，并绑定在函数上。每次你调用 `add()` 且不传 `bucket` 参数时，Python 都会指向**同一个**列表对象。
3.  **累积效应**：
    *   第一次调用 `add(1)`：往这个共享列表里加了 `1`，列表变为 `[1]`。
    *   第二次调用 `add(2)`：还是指向那个已经变成 `[1]` 的列表，再加个 `2`，结果就是 `[1, 2]`。

你可以把默认参数想象成函数的一个“私有全局变量”，它记住了上一次的状态。

```python
def add(item, bucket=None):
    if bucket is None:

    bucket.append(item)
    return bucket
```
