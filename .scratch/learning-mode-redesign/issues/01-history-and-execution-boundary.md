# 01 — 分离学习历史读取与教学执行边界

**What to build:** 用户仍能完整查看和导出已有学习对话、书页、作答、判定与总结；历史读取拥有独立边界，不因打开页面启动或推进教学，为新模式替换旧执行提供可靠接缝。

**Blocked by:** None — can start immediately.

**Status:** ready-for-human

**发布状态：** 用户已确认拆分与依赖；本票已实施并完成验证，新学习模式尚未上线。

**对应合同：** D14；AC15、AC16；C01。

## 用户演示

1. 打开含预习、复盘作答和总结的旧学习对话，内容及原依据正常显示。
2. 刷新、展开历史详情、导出，消息、题目、判定和引用均保持原语义。
3. 捕获模型调用与数据库写入，证明纯读取没有启动识别、出题、诊断或进度更新。
4. 同一记录换成其他账户访问，接口拒绝，界面不泄露内容。

## 实施范围

1. 盘点当前学习读投影、历史状态升级、附件来源、消息终态与执行入口，明确读模型和写业务的所有权。
2. 将历史解码/投影/导出的边界与教学执行分离。模型能力、上下文编译、材料读取、进度事件和终态提交通过必要的类型化端口连接，避免新增业务依赖大型聊天服务私有状态。
3. 只整理支持新模式接入的必要接缝；不重写普通聊天、日常模块或通用内核，不先建设整套新数据平台。
4. 明确旧/新学习协议与运行版本的识别方式，未知版本如实报不可解释状态，不把旧检查点套成新流程。
5. 历史题目只向客户端提供原来允许展示的内容，未问问题和私有评价依据保持不可见。
6. 提供后续新执行、局部进展及历史承接可消费的边界说明，保持当前正式行为直到后续新模式接入。

## 接口、持久化与界面

- 读取投影与领域写模型独立转换；历史读取无隐式迁移写入。确需持久化迁移时另通过正式迁移完成。
- 原消息、原判定和原来源不重写。若新增版本标记，本票完成对应迁移、读取、导出和删除适配。
- 界面沿用原历史展示；材料已删除或原记录不可读时显示实际状态，不构造新引文。
- 对外读取合同的稳定性与内部执行接口重构分别评估，不以内部整理为由破坏已有历史响应。

## 范围边界与后续接缝

本票不实现新导师、长期目标或自动档案迁移，不将旧评分转换成学情。02 消费新教学执行接缝；12 消费历史来源与只读投影。整仓旧执行删除由替代各路径的票负责，本票不做无关清理。
