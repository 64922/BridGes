# 02 — 纯文字启动与流式局部辅导

**What to build:** 用户选择学习模式后，无需照片即可提出一个问题，获得保持必要前文的流式启发或讲解；局部学习进展保存，刷新后继续，不强制建立长期课程目标。

**Blocked by:** 01 — 分离学习历史读取与教学执行边界。

**Status:** ready-for-human

**发布状态：** 用户已确认拆分与依赖；本票已实施并完成验证，新学习模式尚未上线。

**对应合同：** D01、D02、D03、D06、D09；AC01、AC03、AC16；C01。

## 用户演示

1. 在新聊天选择学习模式，输入「互斥是不是独立」，不上传任何资料。
2. 导师直接进入必要探查或说明，保持一个主要关注点，正文流式呈现。
3. 用户接着解释自己的理解；导师能利用前文，不把本轮当作全新单句。
4. 刷新后仍可继续该问题；停止或重试不会多建会话、多存同一消息或虚增进展。

## 实施范围

1. 同时覆盖原子首轮入口、已有会话发送和服务端内部校验，移除新学习请求统一照片前置门禁，不能只改空白态文案。
2. 建立轻量局部学习进展：主题/知识上下文、当前关注点、来源消息、版本和运行关联。单个问题不写长期课程目标或整套路线。
3. 将导师接入现有流式模型能力、上下文编译、运行快照和预算。上下文包含当前请求与必要前文，资料可为空；相关明确偏好按已有授权使用。
4. 提示词按本项目合同重新编写：允许启发、解释、反例和补讲，避免严格永不回答、机械追问、长篇开场测验及原始内部推理展示。
5. 基础概念使用模型知识可直接教，不能声称查过资料。联网和长期档案消费分别由后续票补齐，本票不把它们设为开课条件。
6. 新模式回复与局部进展在正确终态提交，失败和停止保留可解释状态；重试复用幂等身份，迟到回复不能覆盖新运行。
7. 通过 01 的边界保留旧历史读取；删除本票替代的旧入口及孤儿执行代码，不新增长期双轨或业务兼容层。

## 接口、持久化与界面

- 新会话与已有会话的学习请求采用一致权限、模式锁定、空消息和并发生成规则。
- 局部进展拥有自己的权威版本；响应投影只包含可公开字段，不把整套模型上下文存到界面或日志。
- 空白态改为问题/目标均可开始，顶部简洁展示当前主题；新路径不再渲染书页五阶段条。
- 流式期间保留停止，失败提供真实错误及重试，键盘与状态播报沿用聊天合同。
- 新状态的迁移、导出、账户删除和恢复在本票完成。

## 范围边界与依赖理由

01 提供不受新生成影响的历史与执行边界，是真实前置。03 扩展理解验证；07 扩展长期目标。本票不做所有资料类型或完整学情面板，但不得用空壳界面代替实际流式生成链路。

## 验收标准

- [x] 纯文字首轮与后续发送均能生成学习回复，无照片门禁残留。
- [x] 局部问题未自动创建长期目标、固定课程或入门测验。
- [x] 真实模型请求中包含必要前文和已授权相关信息，保持统一预算与模型快照。
- [x] 基础概念未无条件联网，模型解释未冒充来源。
- [x] 提示词允许讲解与调整方式，未复制参考项目提示词定义或实现。
- [x] 进展、消息和终态原子一致，停止/失败不虚增学习成果。
- [x] 幂等重试与迟到响应不产生重复会话、消息或覆盖。
- [x] 新主题提示、流式、停止、错误与刷新恢复端到端可用。
- [x] 账户隔离、模式锁定和三个日常模块无新增回归。
- [x] 适用的数据迁移、生命周期和生成合同已同步。

## 验证与交付证据

- 覆盖两种发送入口及真实服务调用，不只测试单个提示词构造函数。
- 以概率概念、函数概念和编程理解三个确定性旅程验证前文、流式和局部进展。
- 覆盖网络中断、用户停止、重复首轮、不同请求并发、刷新和跨账户访问。
- 前端构建与对应检查按共同要求完成；真实教学效果由 13 单独验收。
