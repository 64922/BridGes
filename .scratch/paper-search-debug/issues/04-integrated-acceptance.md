# 04 — 原始用户旅程集成验收

**What to build:** 对“帮我找几篇机器学习入门论文”的完整用户旅程给出可复查的验收证据，确认有效论文能够交付、故障能如实收敛，且没有通过降低证据标准换取成功。

**Blocked by:** 01 — 有效语义证据可靠进入论文推荐；02 — 失败终态与检索来源如实呈现；03 — arXiv 请求失败可诊断并保持多来源交付。

**Status:** ready-for-human

## 验收目标

前置工单分别解决独立可验证的问题，此票检查它们组合后的实际用户体验、错误传播和合同一致性。不得以全部单元测试通过代替原始旅程验收，也不得因某次真实模型随机成功宣称稳健修复。

## 执行范围

- 检查前置票的完成证据与仍未确定事项；确认应用运行的是本次代码与构建产物，而非旧服务或旧前端。
- 使用合成账户和隔离数据目录建立可重放主路径：原始请求、研究意图、两个来源、有效稳定概念标识、逐字证据、最终推荐与资料面板。
- 验证成功推荐的每条需求证据可定位到本轮取得的标题/摘要；存在全文链接也不表示本轮读取过全文。
- 用失败矩阵覆盖 arXiv 单源失败但 OpenAlex 可交付、全部来源失败、所有语义证据无效、部分证据有效、模型返回未知概念标识、取消、失败后重试和重载恢复。
- 检查运行、消息、论文投影、搜索卡片、查询记录与 SSE 终态一致；保留失败来源事实，不混淆计划调用和实际调用。
- 使用真实供应商对原始请求做一次有界验证，记录查询、调用结果、候选/排除计数、交付数量、总耗时与预算消耗。无需重复大量请求来凑成功率，不能将固定返回篇数作为外部服务必达承诺。
- 使用桌面浏览器验证交互，至少覆盖原截图相近视口及项目要求的桌面尺寸。失败无持续转圈，重试入口与实际能力一致。
- 执行项目要求的完整检查与前端构建；对基线失败独立归因并留证。若发现前置缺陷，将明确失败场景回填对应票并修复后重验，不扩大为无关重构。

## 旧缺陷恢复（变异）证据

1. **显示名精确匹配**：临时把语义证据查找从稳定标识改回显示名称匹配后，`test_original_user_journey_delivers_verified_papers` 与 `test_display_name_case_does_not_break_identifier_mapping` 均失败；恢复代码后 10 个测试全部通过。该证据只确认显示名匹配这一已复现缺陷。
2. **失败投影来源为空**：单独把失败投影的 `selected_sources` 改为 `[]` 时测试仍通过，因为读取路径会从真实查询记录补回来源，说明存在纵深防御。随后同时移除失败投影派生和读取补回，`test_all_sources_failing_keeps_terminal_state_and_actual_sources` 失败，断言为 `[] == ['arxiv', 'openalex']`。
3. **全部证据无效仍标成功**：临时关闭“无已筛选候选且存在 `semantic_*` 排除时失败”的分支后，全部无效与未知标识两条测试均失败（`done` 取代 `error`）；恢复后通过。

## 根因判定与历史限制

- **已确认的本地根因**：01 的显示名精确匹配（已做红/绿与变异复现）；02 的失败终态未收敛及实际来源为空（已做变异复现）；03 的 arXiv `all:` 二次前缀导致真实 HTTP 400（见 03 工单修复前后请求对照）。这些是实验可复现的缺陷，不是根据结果倒推的猜测。
- **已修复**：稳定概念标识与逐字证据校验、部分证据保留、全部无效失败；失败/停止终态收敛、真实来源派生、旧尝试隔离；arXiv 表达式保留与错误细分；桌面端的失败停止转圈、来源展示和重试/继续入口。
- **历史仍不可证实**：没有取得历史 18 篇拒绝的原始模型裁决，因此不能把 18 篇全部归因于名称大小写，也不能声称本轮真实运行复现了那 18 篇的同一原因。本次真实运行的 15 篇排除原因是新的 `semantic_evaluation_unavailable`，与历史内容相关性判断不是同一证据。
- **真实运行的边界**：单次成功不是外部服务稳定性承诺；目标篇数不是供应商必达合同。批量裁决未覆盖全部候选时，系统选择少交付并说明原因，这是当前的安全行为；若要提高覆盖率，应在 01 的语义裁决范围内另行改进，不以放低证据标准换篇数。

## 风险与回滚

- 回滚 01–03 会恢复显示名精确匹配、失败终态残留和 arXiv 表达式缺陷；本票新增测试将随之变红，可作为回滚护栏。
- 本票只新增测试与本报告，不引入数据库 schema 迁移、兼容层或双写。01 的配方/能力版本升级使旧核验产物不会被新合同复用；历史消息仍可只读。回滚代码后，旧版本不会读取新配方产物。
- 跨来源部分交付、批量语义裁决覆盖率不足、外部供应商波动仍是运行风险；用户侧必须继续展示实际来源、未核验边界和可恢复性，不得用固定篇数承诺掩盖。
- 桌面 E2E 使用受控 API 替身；真实供应商行为与完整后端链路由确定性集成测试和本次隔离真实运行分别证明，二者不能互相替代。
