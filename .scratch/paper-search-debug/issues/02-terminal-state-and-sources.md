# 02 — 失败终态与检索来源如实呈现

**What to build:** 论文搜索失败后，用户立即看到一致的失败状态和正确恢复入口，页面停止转圈，不再允许取消已经结束的任务；资料面板如实展示实际调用过的来源。

**Blocked by:** 无 — 可独立开始；通过注入失败验证，不依赖 01 或 03 的修复。

**Status:** ready-for-agent

## 问题与目标

历史运行已持久化为失败，错误 SSE 仍携带旧搜索投影 `loading`、允许取消且不允许重试。可重试的筛选失败最终又表现为不可重试，需要定位其在模块交付、父图、终态提交和事件生成之间的传播错误。

失败论文投影没有填充实际来源，界面依据空列表显示“未实际调用来源”，与 OpenAlex 和 arXiv 调用记录冲突。此票同时修复失败旅程中用户能看到的状态和来源信息。

## 实施范围与设计约束

- 沿 PaperSearchService 交付、父图错误传播、消息持久化、生成运行终态和 SSE 消费检查实际链路，明确每个状态的权威来源。
- 在终态提交中收敛论文投影及仍被界面使用的搜索卡片状态；不要仅靠前端隐藏加载动画。数据库恢复、刷新与流式事件应得出相同结果。
- 失败后撤销取消能力；是否可重试由错误合同和恢复策略决定，不硬编码所有失败都可重试。停止、不可恢复条件与需要补充输入应保持区别。
- 复用现有重试入口，在账户/会话/任务边界内启动合法新尝试；避免重复点击产生并行重复运行。旧尝试的迟到事件不能覆盖新尝试，也不能把失败恢复为 loading。
- 从实际查询记录形成实际调用来源集合，包含已调用但失败或为空的来源；计划来源、实际调用来源、成功来源与最终推荐来源不得混淆。
- 检查 `selected_sources` 现有合同含义。如果它表示计划选择，不能静默改成实际来源，应通过已有查询记录或语义明确的投影表达。不要只为消除空文案填充猜测值。
- 搜索尚未调用任何来源时，保留真实“未执行”含义。候选全部未通过不应抹去已发生的查询。
- 修改固定提示使用项目文案登记机制。多来源任务的进度文字不应永远声称只在搜索 arXiv。
- 更新必要的 API/前端生成合同和历史缺省处理；不为旧内部路径新增兼容层。

## 测试与验证方式

用隔离账户和确定性失败注入运行真实父图/终态链路，分别验证可重试证据失败、不可重试请求错误、用户停止、分析失败前尚无来源调用以及单源失败其他来源成功。

在桌面浏览器验证实时 SSE、刷新重载、断线重连、重试和旧事件迟到。断言实际按钮行为、运行状态和查询来源，不只做截图比较或组件静态渲染。

## 验收标准

- [ ] 原有终态仍 loading 的行为具有先失败后通过的回归测试。
- [ ] 可重试筛选失败到达界面后停止转圈，取消按钮消失或禁用，恢复入口可用。
- [ ] 不可重试失败和用户停止不会错误展示与原因不符的恢复动作。
- [ ] 页面刷新与 SSE 实时状态一致，旧尝试的迟到事件不会覆盖当前终态或新尝试。
- [ ] 用户重试可以创建合法尝试，重复操作不产生无边界并发；账户隔离不受影响。
- [ ] 实际调用过 arXiv、OpenAlex 时，资料面板展示两者及各自结果，不再声称未调用来源。
- [ ] 计划但未调用的来源不伪装成已调用；全部候选被拒绝时仍保留检索事实。
- [ ] 桌面交互、相关后端和前端测试、类型检查及前端构建通过。

## 不在范围内

重新设计整个聊天 UI、改造所有模块的状态机、重做历史搜索记录、自动重跑用户历史失败任务。
