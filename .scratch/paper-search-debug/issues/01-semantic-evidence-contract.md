# 01 — 有效语义证据可靠进入论文推荐

**What to build:** 用户请求论文推荐后，模型能够用明确的研究概念标识提交证据；有效的标题或摘要证据可以进入后续推荐链路，错误证据仍被拒绝，失败时能区分具体原因。

**Blocked by:** 无 — 可独立开始。

**Status:** ready-for-human

## 问题与目标

真实运行最终 20 篇候选中 18 篇被标为 `semantic_evidence_unverified`，2 篇不相关。已复现需求名称仅大小写变化就导致相同有效引文被拒绝。当前证据输出允许任意字符串，消费端却对研究概念显示名做精确匹配，生产者与消费者合同不一致。

此票修复可证明的合同缺陷，同时补足拒绝分类。不得把“名称不匹配”当作历史 18 篇的唯一已确认根因。研究需求、原文引用和相关性判断必须分别校验。

## 实施范围与设计约束

- 从研究意图分析、批量证据角色到筛选结果检查实际数据流。为当前分析中的概念生成稳定且唯一的内部标识，由代码分配并验证，不让模型自由创造。
- 标识只服务当前需求映射，保持原有账户、运行和任务版本作用域；不引入全局概念注册表。补搜、同节点裁决缓存和最终筛选必须沿用同一映射。
- 在模型请求中清楚传递“标识—显示名称—需求”对应，结构化输出限定合法标识。模型供应商是否支持所选 schema 约束，应检查已有适配器；本地验证始终不可省略。
- 用户可见的需求说明继续展示可读名称。更新内部调用链，不保留以显示名模糊猜测归属的旁路。修改产物合同后检查配方/能力版本、输入键与缓存失效策略，不能复用不满足新合同的旧核验结果。
- 原文引用仍须在实际标题或摘要中定位；不通过翻译、模糊匹配或标点清洗将虚构引文变成“已验证”。来源字段限定到实际支持的读取范围。
- 区分至少：缺少裁决/结构错误、未知需求标识、来源字段非法、引文无法定位、明确不相关。对一篇有多条证据的论文，保留有效证据；无有效证据时才按现有安全合同拒绝。
- 经现有产物和诊断链记录脱敏原因计数；用户侧给出准确且可恢复的说明，不暴露内部 ID 或供应商原始载荷。此票不负责通用终态卡片同步，那由 02 处理。
- 保持预算上限和有限调用次数。不要为每篇候选增加一次模型调用，也不要无条件重试所有失败。

## 测试与验证方式

先构造具有两个研究概念及真实标题、摘要的合成候选，通过实际批量角色输出解析与筛选接缝测试。第一步保存旧行为的失败证据；修复后测试改为验证稳定标识合同，而不是要求消费者接受任意同义字符串。

覆盖名称大小写、显示名称翻译或改写但标识相同；标识未知/缺失；引文不存在；来源非法；一个有效证据加一个无效证据；模型明确不相关；部分候选合法、全部候选无效；补搜新增候选与已有缓存共存。再用确定性供应商夹具跑通从用户请求到已核验推荐的流程。

## 验收标准

- [x] 改动前测试能稳定捕获名称精确匹配造成的误拒，记录实际运行结果。
- [x] 合法稳定标识与有效原文证据可进入推荐链路，不受显示名称大小写或翻译影响。
- [x] 未知标识、错误来源、伪造引文和缺少裁决均不能成为已核验推荐。
- [x] 有效候选不会因其他候选核验失败被全部丢弃，未交付部分的原因如实保留。
- [x] 全部证据无效时诚实失败，诊断可区分原因；没有降级为未经核验推荐。
- [x] 补搜与缓存复用不串联不同研究概念或旧任务版本，模型调用未突破共享预算。
- [x] 历史结果仍可读取，新运行不会复用旧合同的核验产物。
- [x] 相关行为测试及仓库要求的检查通过；提交中说明历史根因仍存在的证据限制。

## 不在范围内

提升论文排名算法、扩大候选上限、增加全文抓取、重构所有模型结构化输出、修改其他业务模块。
