- 持久化运行状态为 `failed`，错误码为 `paper_semantic_evaluation_unavailable`。
- 首轮 arXiv 返回 `arxiv_request`，用户消息对应客户端 HTTP 错误响应分支。现有记录不足以区分具体 HTTP 状态及响应来源，不能擅自认定为 HTTP 400、查询语法错误、代理问题或断网。
- OpenAlex 首轮返回 10 条，补搜返回 10 条；引用扩展有一次返回 2 条，另两次为空。这些是调用计数，不等于去重后候选数量。
- 最终初筛 20 篇：18 篇 `semantic_evidence_unverified`、2 篇 `judge_not_relevant`，通过数为 0。18 篇对应相关性判断为真但证据未通过，不应描述为模型完全没有返回。

- 失败论文投影未填充 `selected_sources`，界面据其空值显示“未实际调用来源”，与实际查询记录冲突。

## 所有工单共同遵守

遵守仓库 AGENTS、领域词汇和 ADR-0039 的研究问题驱动、多来源、共享预算、逐字证据核验合同；界面遵守连续正文与按需资料预览合同。先检查当前实现，按职责和符号定位，不依赖本文固定源码行号。

开发使用 Conda `agent` 环境，先验证解释器确实来自该环境。原诊断中 `conda run` 启动失败，直接使用该环境解释器成功；这是诊断工具环境现象，不是产品根因。

每票先建立能捕获自身错误的行为测试，见红再修复。不得修改真实数据库来让测试通过；真实数据库仅只读取证，测试使用合成账户、独立数据库和伪造供应商响应。不得保存密钥、Cookie、完整私人会话或未脱敏模型载荷。需要观测时优先保存原因码和计数。

不关闭语义门、不用关键词匹配冒充语义核验、不把未经核验候选显示为正式推荐。不做全仓重构，不增加新供应商或独立执行系统；先复用现有能力、预算、状态注册表、投影和重试机制。内部合同变更直接更新调用方，不增加旧协议 shim。历史持久化产物和外部 API 的兼容义务单独评估。

每票记录修改理由、验证命令、结果、剩余限制和回滚影响。接口合同改变时按现有流程更新生成类型；若确需改数据库 schema，解释必要性并执行项目生成与迁移流程。本组任务默认不预设数据库迁移。

提交前执行仓库定义的完整检查；当前 README 列出 pip 依赖检查、pytest、ruff、mypy，前端还要求类型检查、单元测试和构建。不要把未经验证的脚本名写成已通过。前端变更额外覆盖桌面交互，Conda 执行浏览器测试时正确配置其 Python。已有基线失败必须单独举证，不能记为本次通过。
