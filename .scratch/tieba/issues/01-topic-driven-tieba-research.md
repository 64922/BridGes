# 01 — 话题驱动的贴吧信息搜集与自动登录续接

**What to build:** 用户在现有聊天入口提出“搜集华东交通大学吧关于宿舍条件的讨论”等自然语言请求后，系统理解话题、寻找相关帖子及回复、读取楼中楼与必要上下文，生成一段连贯的中文总结。总结概括本轮实际取得的主要讨论点、不同意见、不确定信息和时间变化，关键观点附少量可点击引用，用户可展开查看原文、发言时间、原帖链接与实际采集范围。

未登录时自动打开贴吧官方登录页面，用户完成登录后，系统检测、复验并自动继续原任务；正常流程无需点击登录引导或完成按钮，也无需重新提交话题。默认覆盖优先、近十二个月为主，单次任务累计执行用时最多五分钟，人工登录或验证的等待单独处理。

**Blocked by:** 无 — 可开始本票的真实接口验证与实现准备；接口验证是本票内的首个实施阶段。

**Status:** ready-for-human

**需求依据:** [ADR-0040：话题驱动的贴吧讨论采集与自动登录续接](../../../docs/adr/0040-topic-driven-tieba-collection-and-auto-login.md)。用户于 2026-10-11 明确确认完整方案。本票只登记已批准的改造，创建票据不表示功能已经实施。

**实现方式:** 两个参考项目仅用于理解架构、工作流、分页机制和数据建模思路。新增采集、解析、领域模型与编排衔接代码由 BridGes 独立设计和编写，符合本项目的职责边界、命名和工程规范；不得复制参考源码、搬运函数体或代码片段，也不得通过改名或逐行转写移植其实现。可以复用 BridGes 已有能力和通用依赖；参考项目的源码与业务客户端不作为本票的运行时实现引入。已核实的外部接口与字段语义作为协议事实使用，源码索引只用于解释设计依据。

## 当前问题

现有模块仅尝试读取前三个候选，浏览器采集依赖有限次滚动，主题判断主要依据关键词命中；“归纳”使用标记词分类摘录，没有模型语义总结。登录入口依靠用户点击按钮打开、保存会话，再通过后续搜索观察访问限制，没有独立、可靠的登录成功确认与自动续接流程。

## 实施顺序

本票覆盖完整用户旅程，按以下顺序推进；每个阶段都验证实际用户行为，而不是分别交付只有后端或只有界面的功能。

1. **验证并打通最小闭环。** 在本机专用浏览器会话中验证认证检测、吧内搜索、帖子正文、回复分页与楼中楼读取。先让一个具体话题从连接检测、必要的自动登录、真实采集到带引用的短总结完整跑通，并展示真实进度与失败状态。记录接口、字段、成功或失败和耗时；参考源码中的接口存在不等于当前环境可用。
2. **扩大话题覆盖与保持上下文。** 接入同义表达、常用说法、相关子问题和回复内话题检索，完成多帖去重、语义筛选、时间条件、回复层级及必要上下文的采集与交付。按真实结果调整检索计划，保持用户明确条件。
3. **完成有依据的语义总结。** 接入现有模型网关、输入额度与必要的分批归纳，保留观点和证据关联，完成引用及语义支持程度核验。聊天正文交付一段总结，证据详情按需展开。
4. **闭合预算、等待、取消与恢复。** 将贴吧专用五分钟预算接入现有执行内核和账本，预留总结、核验与交付时间；完成并发登录、会话过期、安全验证、关闭窗口、部分失败、模型失败、停止和续接的行为验收，并校准采集规模与请求节奏。

## 验收条件

### 自动登录与账户隔离

- [ ] 每次调用先检查当前 BridGes 账户的专用贴吧会话；BridGes 登录、个人日常浏览器登录与专用贴吧会话认证分别处理，不能混用其他账户的会话或数据。
- [ ] 缺少会话或明确未登录时，系统自动打开官方登录页面。用户自行完成登录后，系统取得真实已认证状态，再检查吧内搜索可用性，自动续接当前有效任务条件；正常流程无需登录引导或完成按钮。
- [ ] 会话目录存在、窗口打开、Cookie 存在或用户自述完成都不能作为唯一登录成功依据；认证有效与采集路径可用分别记录。凭据保留在受隔离的本机会话中，不进入公开响应、日志或模型材料。
- [ ] 已登录但需要安全验证时自动打开验证页面并等待；网络超时或认证状态未知时显示真实失败与重试说明，不误判成未登录。
- [ ] 一个登录或验证等待过程只自动打开一次窗口，同一账户并发请求复用该入口。用户关闭窗口而未完成时，保留任务并提示尚未开始采集，之后可在聊天中说“继续”恢复；用户明确停止或任务条件已失效时不自动执行旧任务。

### 检索范围、时间与采集深度

- [ ] 讨论搜集固定在华东交通大学吧。搜索摘要只用于发现候选，真实取得的内容用于确认归属与主题相关性；他吧内容不能混入确认结果。
- [ ] 自然语言话题可以扩展为原话题内的同义词、常用说法和相关子问题，分组检索并合并去重；标题没有命中但回复涉及话题的讨论也能进入候选。用户明确时间、校区和话题条件保持有效，检索调整不静默放宽这些条件。
- [ ] 未指定时间时优先近十二个月，相关讨论不足时补充历史信息。以实际发言时间判断时效，老帖中的近期回复可以纳入，旧正文可作必要上下文；近期、历史和未知时间分别表达，不能把未知时间标为近期。
- [ ] 优先覆盖更多相关帖子，再深入读取相关回复、楼中楼与必要上下文。长帖尚未读完时也可以在预算内交付，并明确实际覆盖范围；热门或高赞不是唯一采集依据。
- [ ] 帖子、回复与楼中楼按实际身份去重，保留父子关系、原文、发言时间、发现路径和读取范围。反驳、纠正、后续补充及其必要上下文被保留；重复内容不能计作多份独立证据，缺失字段不编造。
- [ ] 用户仅要求搜集讨论时默认只查贴吧；明确要求确认规定或核实真伪时才追加学校官网核验，分别呈现网友说法与已核实规定。

### 总结、引用与结果体验

- [ ] 默认正文是一段连贯的中文语义总结，覆盖主要讨论点、不同意见、不确定信息及必要的时间变化；分类摘录或链接清单不能代替总结。
- [ ] 总结通过现有模型网关生成，遵守本运行的模型、输入额度与调用预算。证据较少时直接归纳，超过输入额度时按帖子或讨论串分批处理后汇总，保留各阶段的证据关联；帖子内容中的指令不能改变任务、来源或权限。
- [ ] 关键观点带少量可点击引用，展开能定位已采集原文、发言时间及原帖链接。核验引用身份、引文匹配和总结是否得到原文支持；不依靠搜索摘要或模型记忆补写未取得的回复，不将本次采集样本写成全体学生共识。
- [ ] 完整原文、采集范围和审计详情默认折叠；采集不足、部分失败和未读范围用简洁中文明确呈现。检查连接、等待登录或验证、查找讨论、读取回复、整理总结等进度对应真实发生的阶段。

### 预算、失败、恢复与历史结果

- [ ] 贴吧任务具有专用五分钟累计执行上限，包含采集、模型总结、核验和交付，人工登录或验证等待不计入；证据充分时提前结束，达到上限时如实收尾。自动重试或自动续接不能通过重置预算无限延长同一任务。
- [ ] 所有真实外部请求与模型调用进入现有账本；请求频率、并发、分页、重试和取消由代码控制，采集数量与请求节奏根据真实验证校准，预先不承诺帖子或回复数量。
- [ ] 部分采集失败时，可以基于已取得的相关证据交付并说明不足；没有可用原文时说明本轮未取得讨论，不能写成吧内没有相关讨论。模型总结失败时保留真实证据并说明总结未生成，重试可复用仍有效的证据。
- [ ] 等待、恢复、停止和提交遵守当前账户、运行租约及任务版本守卫。停止后释放本任务占用的资源，不启动新的自动采集；任务条件变化后不提交旧条件结果。
- [ ] 解析、检索、采集和总结语义变化后升级对应配方及能力版本，防止旧语义产物被新运行或恢复复用；历史消息按其原证据合同读取与导出。

### 验证与交付检查

- [ ] 真实验收记录至少包含一个多帖话题、回复中才出现的话题、带反驳或纠正的楼中楼，以及默认时间范围与用户明确时间条件。真实接口结果与脱敏测试夹具明确区分，不能用模拟结果声称真实采集通过。
- [ ] 可重复的行为测试覆盖未登录自动打开与续接、认证失效、安全验证、网络失败、关闭窗口、同账户并发、跨账户隔离、达到预算、部分读取失败、总结失败、停止、任务条件变更和引用越界。
- [ ] 开发与验证使用 conda 的 `agent` 环境；沿用项目已有能力与依赖边界，代码职责清晰、单文件不超过 500 行，只修改本票必要范围。内部被替换实现直接移除，稳定外部契约和历史证据按现有合同评估兼容性。
- [ ] 代码审查确认新增业务实现由本项目独立完成，未复制、搬运或逐行转写两个参考项目的源码、函数体或代码片段，也未将其业务客户端作为运行时实现引入；调研记录能说明借鉴的设计思路及本项目独立落实的方式。
- [ ] 完成项目定义的完整检查及前端构建；公开协议变更时同步生成 API 与前端类型，只有实际涉及数据库结构或存量数据变化时才执行相应生成、迁移与数据迁移。实施完成后同步设计状态和验收记录，真实结果通过前不标记已实施。

## 参考调研结论与落实方法

以下内容基于 2026-10-11 对两个本地参考项目的源码阅读，说明具体借鉴对象、原有行为和 BridGes 的改造要求。源码路径与函数名用于定位这次调研依据，不是代码复制清单，也不要求本项目沿用这些类名或函数结构；参考接口的当前可用性尚未在真实环境验证。浏览器采集、自动登录、五分钟预算和总结交付仍以本票前述验收条件及 ADR-0040 为准。

调研发现的限制必须在接入时修正：

- [get_notes_by_keyword](D:/参考项目/MediaCrawler-main/media_platform/tieba/client.py:375) 调用 `/mo/q/search/multsearch`，本地请求参数没有固定吧名；`note_type` 虽然作为方法参数和枚举存在，但没有写入该请求参数，搜索解析器又只保留 thread 卡片。因此不能据此宣称已经具备“固定华东交通大学吧内的帖子、回复混合搜索”。本项目优先验证并使用真正的吧内搜索请求或页面，取得相关楼层定位信息后再扩展父帖。

- [pong](D:/参考项目/MediaCrawler-main/media_platform/tieba/client.py:320) 和 [check_login_state](D:/参考项目/MediaCrawler-main/media_platform/tieba/login.py:51) 主要依据登录 Cookie 是否存在判断。只借鉴“等待用户登录后继续”的生命周期，登录有效性仍按本票要求作实际认证复验。
- 参考编排共用一个 `playwright_page`，楼中楼读取又调用该页的 `goto`；批量任务不能未经控制地同时改变同一页面。部分方法捕获异常后返回空值或提前结束，也不能原样映射为“没有相关讨论”，本项目保留失败类别和成功范围。
- callback 的逐页保存有助于保留部分结果，但不能将 README 提及的 Pro 断点续爬能力视为这份源码已经实现。本项目的恢复仍由现有节点收据、任务版本与仓储承担。

数据层级应借鉴其真实字段含义：

| 参考字段 | 准确语义 | BridGes 的证据映射要求 |
| --- | --- | --- |
| `fid` / `fname` | 贴吧 ID / 吧名。 | 保存真实归属与确认依据；来源名称规范化不能把其他贴吧变成目标贴吧。 |

| `create_time` | 发言时间；参考 Comment 类注明为秒级时间戳。 | 保留原始值、已确认单位和规范化时间，落实近十二个月规则；浏览器接口的单位及相对时间另行验证，缺失或无效时间不转换成有效历史日期。 |

| `is_thread_author` | 发言者是否为该主题帖楼主。 | 帮助保存楼主补充与其他发言的上下文，不能仅据身份判断说法真实。 |
| `text` / `contents` | 可读文本 / 结构化内容片段。 | 提取实际取得的文字，保留非文字内容未读取的范围；图片、语音或链接的存在不表示其内容已被读取。 |
| `page` / `has_more` | 当前页、页大小、声明总页数、是否有后继页等。 | 记录实际请求和成功页，声明总量仅作辅助；是否完成由真实分页及预算共同判断。 |

分页实现以 [Page_fsch](D:/参考项目/aiotieba-master/src/aiotieba/api/search_in_forum/_classdef.py:67)、[Page_p](D:/参考项目/aiotieba-master/src/aiotieba/api/get_posts/_classdef.py:602) 和 [Page_c](D:/参考项目/aiotieba-master/src/aiotieba/api/get_comments/_classdef.py:380) 为参考：先保存本页成功证据，再根据 `has_more` 或当前页与声明总页数决定下一页，每次请求前复核取消和预算。若返回空页但仍声明有后继页、连续返回重复身份或没有可信分页信息，记录异常或部分范围并有界结束，不能推测已全量读取或无限翻页。

### 在 BridGes 中形成的具体职责与调用顺序

| 职责 | 采用的参考方法 | 本项目负责的行为 |
| --- | --- | --- |
| 话题规划与调度 | MediaCrawler 的逐级编排，aiotieba 的按吧搜索契约。 | 复用已有服务与节点内核，维护查询、候选、采集任务、预算和版本。话题、同义词与子问题来自当前有效用户条件；模型不自行扩大来源或权限。 |
| 浏览器会话与请求 | MediaCrawler 的浏览器 `fetch` 和会话生命周期。 | 自动认证检测与登录续接、同账户登录入口复用、固定只读请求、会话复用、请求级取消和失败分类；采集器不直接驱动聊天展示。 |
| 响应解析与边界转换 | MediaCrawler 的搜索、详情、楼层及楼中楼解析；aiotieba 的场景专用数据类。 | 校验外部字段，区分候选、首楼、普通楼层和楼中楼，输出本项目的不可混淆证据；协议对象与第三方类型不穿透到领域和界面。 |
| 采集与证据保存 | MediaCrawler 的按页 callback；aiotieba 的身份、父楼层和分页信息。 | 每页保存成功证据和实际范围，按真实 ID 去重，保留发现路径和必要上下文；事务、幂等性、租约和任务版本由已有仓储及节点收据保障。 |
| 语义筛选、总结与展示 | 参考项目提供可定位的原始材料，本票补齐话题理解与语义总结。 | 经现有模型网关筛选、分批归纳和汇总，绑定证据并核验支持程度；交付一段总结及少量引用，失败与未读范围清楚可见。两个参考项目的这些采集方法本身不能代替总结能力。 |

一个典型运行按以下数据流执行：

1. 把“宿舍条件”规划为宿舍、寝室及相关子问题的吧内查询，保留用户的校区和时间条件。
2. 在已复验的浏览器会话中分页取得候选；每个命中保留查询、帖子身份及上游能提供的命中发言定位，合并同一帖的不同发现路径。
3. 先读候选详情与必要正文，确认吧名和话题；即使帖子标题是“开学杂谈”，回复确实涉及宿舍，也可进入相关讨论范围。
4. 给不同相关帖子读取机会，以普通楼层为入口发现相关讨论串，再按父楼层独立读取楼中楼。取得预览只标预览；出现“这个情况今年已改变”等补充时，保留其所回应的上下文并核对发言时间。
5. 每页成功后保存真实证据与范围，更新本运行进度。停止、页面失败或预算不足时，保留有效部分并停止后续请求。
6. 将相关发言及必要上下文交给模型，生成带证据绑定的观点，再汇总成一段文字。引用定位到实际发言；不能用“谁回复了谁”这一不确定关系推导作者立场。
7. 核验观点支持、引用、时间和实际范围，通过后交付。用户点击引用看到已采集片段与时间，并能跳到原帖；未读范围在详情中如实说明。

以上“宿舍条件”“开学杂谈”及纠正说法只是说明流程的示例，不是本轮真实采集结果。
