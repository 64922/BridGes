# 科教智能体成熟项目规划路线图

Type: wayfinder:map
Status: active

## Destination

产出一份成熟、功能全面、技术含量高且能直接指导开发的《科教智能体项目规划书》，完整定义产品、智能体、科学可信体系、多模态能力、系统架构、前端、技术栈、数据治理、评测与工程演进，不以时间、人员或算力为由裁剪为 MVP。

## Notes

- 以 `C:\Users\33755\Desktop\项目要求.txt` 为比赛硬约束。
- 研究时必须参考 `C:\Users\33755\Desktop\参考资料\灵感\` 下的全部材料，并区分“直接采用、调整采用、不采用”。
- 每次工作前读取根目录 `CONTEXT.md` 和 `docs/agents/` 下的项目规则。
- 需要外部事实时使用高可信一手资料，技术版本、Qwen 能力、模型价格和接口限制必须注明核验日期。
- 使用 `research`、`domain-modeling`、`grilling`、`prototype` 等与任务类型匹配的技能。
- 项目主轴是“长期科学学习与表达伙伴”，核心用户为大学生、研究生、青年科研人员及深度科学爱好者。
- 产品采用科学成长循环、全局科学伙伴与科学项目空间、本地优先混合架构、领域包、证据化画像、可审计工作流和持续评测。
- 产品支持多用户注册与登录；所有功能页面需要认证，每个用户独立拥有画像、学习路径、项目、材料、索引、记忆与评测结果。
- 学习实验室参考 `mattpocock/skills` 的 `teach`：使命驱动、可信资源、短课、最近发展区、检索练习、间隔/交错练习、即时反馈与证据化学习记录。
- 本地项目开发使用 Conda 环境 `agent`；它不是生产部署方式。生产独立支持手动分进程部署、一个 CLI 命令统一启动前后端、Docker 和 Podman，并共享配置、迁移、健康检查与数据语义。
- 本路线图只做规划研究，不进入产品代码实现。

## Decisions so far

<!-- 已解决任务会在这里留下摘要与链接；详细结论只保存在对应任务中。 -->

- [提炼比赛约束与参考项目的可迁移设计](issues/01-competition-and-reference-synthesis.md) — 以证据、画像和类型化工作流为统一内核，八条项目原则约束后续全部产品与架构决策。
- [定义成熟产品的能力体系与边界](issues/02-product-capability-system.md) — 以项目工作台为产品主结构、科学成长循环为业务闭环、四条主链为内部能力模型，并加入认证入口、九类一级能力和逐用户教学体系。
- [设计科学证据、RAG 与领域包体系](issues/03-scientific-trust-system.md) — 以 claim 级证据验证、版本化出处链、多维证据画像、领域包映射和确定性发布门构成科学可信内核，证据不足、冲突或安全失败时显式降级或闭锁。
- [细化证据化画像、长期记忆与授权治理](issues/04-profile-memory-governance.md) — 分离学习证据、画像断言和记忆使用链，以版本化派生、最小授权切片、逐账户隔离、删除级联和诚实降级形成可信长期陪伴闭环。
- [设计有人味且不越过事实边界的表达引擎](issues/05-human-scientific-expression.md) — 以表达任务契约、事实锁、论证图和体裁契约驱动双通道质量流水线，使个性化中文表达服从 claim、证据强度、引用和风险边界。
- [规划多模态科学理解与创作体系](issues/06-multimodal-science-studio.md) — 以统一科学媒体对象和分级创作链连接多模态摄入、结构化分镜、可编辑源、沙箱渲染、跨媒体事实绑定、无障碍与科学验证。
- [核验 Qwen 能力并形成候选技术栈](issues/07-qwen-and-technology-research.md) — 以版本化能力注册表和模型网关承载时效性能力，以 Next.js、Python 模块化单体、PostgreSQL、自有协议与可替换适配器形成候选栈，并用十二类验证 spike 决定最终架构。
- [定义智能体拓扑、工作流协议与质量门](issues/08-agent-orchestration-contracts.md) — 采用薄监督器、专业工作节点、确定性控制平面和类型化产物，以双状态机、作用域信封、有限重试、人工门和失败闭锁形成动态但可审计的智能体编排合同。
- [形成前端信息架构与关键交互原型](issues/09-frontend-information-architecture.md) — 以项目工作台承载认证后主壳，以伙伴对话和结构化任务舞台分离轻重交互，以科学出处图和统一检查器渐进呈现证据、画像、风险与版本。
- [建立持续评测、基线对比与消融体系](issues/10-continuous-evaluation.md) — 以版本化评测套件、可重放案例、运行锁和结果包贯通确定性、离线、端到端、纵向、人工及线上六层证据，用不可平均的安全科学硬门与配对非劣门共同约束发布，并要求所有升级在四种部署路径下可复现双跑。
- [收敛系统架构、数据治理与工程质量方案](issues/11-system-architecture-and-governance.md) — 采用设备侧个人保险库、领域模块化单体、Temporal、PostgreSQL/RLS/FTS/pgvector、S3、非权威 Redis 与独立沙箱，按风险拆进程而非按菜单拆微服务；Conda `agent` 仅用于本地开发，四种生产路径共享运行合同。
- [定义首批科学领域包与专家治理](issues/12-initial-domain-pack-governance.md) — 将八类领域包收敛为带学科规则、确定性校验、措辞门和评测夹具的签名资产，以职责分离复核、失效传播和不可放宽的平台下限保证可验证升级。
- [定义协作空间、机构租户与跨设备同步边界](issues/13-collaboration-organization-sync-boundaries.md) — 以个人保险库、显式共享项目和机构管理域分离归属与管理权，并用对象级授权、版本化同步、密钥撤销和删除墓碑支撑不越过个人边界的成熟协作。
- [设计领域包专家工作台与发布流程](issues/15-domain-pack-expert-workbench.md) — 采用阶段控制台、语义 Diff 主画布、责任泳道和失效影响带的组合式工作台，以三类独立签名、平台安全下限及可审计撤销链约束领域包发行。
- [制定成熟项目开发路线、团队并行计划与阶段验收](issues/14-development-roadmap-and-stage-acceptance.md) — 以八阶段成熟度门、十二个长期责任域和 G0—G5 发布证据门组织全量开发，成熟发行前必须完成迁移、安全、容量恢复、文档和四种生产部署等价验证。
- [确定最终规划书的章节编排、图表与附录结构](issues/16-final-plan-document-structure.md) — 采用五部二十二章的决策蓝图正文，以六条黄金路径贯穿产品体验，并用需求—章节—证据矩阵、25 张必备图和 13 项附录保证覆盖、去重与可复现。
- [汇编并校验最终《科教智能体项目规划书》](issues/17-assemble-and-validate-final-plan.md) — 已将全部研究和决策汇编为五部二十二章、25 幅图和 13 项附录的成熟产品规划书，并完成结构、约束、术语和链接校验。
