# 设计领域包专家工作台与发布流程

Type: prototype
Status: resolved
Blocked by: 12, 13

## Question

领域专家、独立复核者、平台发行者和安全管理员应如何在同一工作台中完成来源注册、规则与措辞策略编辑、确定性校验器配置、夹具构建、判定差异审查、依赖影响分析、资质与利益冲突声明、职责分离签名、灰度验证、正式发行、失效传播、紧急撤销和回滚？请形成角色权限矩阵、信息架构、关键交互原型、异常与拒绝流程，确保一个按钮、单人身份或领域包自身都无法绕过双人复核、平台安全下限和审计链。

## Answer

采用“阶段控制台 + 语义 Diff 主画布 + 责任泳道与失效影响带”的组合式领域包专家工作台。内容维护者、独立复核者、平台发行者和安全管理员分别受职责分离权限约束；内容签名、独立验证签名和发行签名绑定同一规范化包摘要，任何内容变化都会使旧签名失效。安全管理员可以暂停、隔离或紧急撤销，但不能编辑规则、代替独立复核或发布版本。

完整角色权限矩阵、三类状态机、信息架构、关键交互、异常与拒绝流程及验收标准见[领域包专家工作台与发布流程决策](../decisions/15-domain-pack-expert-workbench.md)。经用户确认的 A/B/C 交互材料见[领域包专家工作台 UI 原型](../prototypes/domain-pack-expert-workbench/README.md)。
