# 成熟产品能力体系与边界

确认日期：2026-07-24

## 结论

产品采用三层互补结构：

1. **用户产品结构采用“全局科学伙伴 + 科学项目空间”**：这是注册用户日常看到和操作的主结构。
2. **跨模块业务采用“科学成长循环”**：它定义任务如何从目标、画像、证据、解释、创作和校验走向反馈演进。
3. **内部规划采用“四条主链能力地图”**：它用于架构分层、团队边界、质量门和完整性检查。

三层不是三个独立产品。用户只面对统一的产品空间；业务工作流和内部能力地图分别解释“任务怎样流动”和“平台怎样支撑”。

## 认证入口与多用户边界

注册、登录、凭据恢复和会话退出属于产品公共入口。除这些入口和必要的公开说明外，所有功能页面均需要登录。

每个用户独立拥有：

- 账户设置与授权；
- 证据化画像和候选画像；
- 学习使命、知识掌握度、学习记录和学习路径；
- 科学项目空间、材料、证据、索引、中间产物与版本；
- 会话记忆、反馈、评测结果和个性化模型状态。

任何检索、画像召回、后台任务、缓存、索引、日志和导出都必须携带明确的用户归属。禁止跨用户召回、合并画像、共享私人索引或通过缓存泄露内容。未来若增加协作，必须通过用户显式授权的共享空间实现，不能破坏个人数据边界。

## 一级能力与二级功能

### 1. 身份、访问与账户

- 注册、登录、退出、凭据恢复、会话管理；
- 用户级数据隔离、设备与登录记录；
- 隐私授权、数据导出、账户注销与删除；
- 功能页面认证守卫和越权审计。

### 2. 全局科学伙伴

- 自然对话、意图识别和任务分流；
- 跨项目提醒、待办、学习回顾和长期目标跟踪；
- 只召回当前任务所需的画像、记忆和项目上下文；
- 把复杂任务送入结构化工作台，而不是在聊天窗口隐藏状态。

### 3. 科学项目空间

- 围绕学习主题、研究问题或创作任务建立独立上下文；
- 管理材料、证据、claim、学习产物、多模态产物和版本；
- 展示智能体工作流、运行状态、人工确认点和失败恢复；
- 支持项目内检索、版本对比、归档和导出。

### 4. 学习实验室

- 学习使命、成功标准、约束和范围；
- 先备知识诊断、知识掌握度和最近发展区估计；
- 可信资源策展、知识图谱和概念依赖；
- 短小自包含课程、交互练习、即时反馈；
- 检索练习、间隔复习和交错练习；
- 由学习证据更新学习记录与个性化学习路径；
- 参考资料、术语表、公式表和可复用模拟器。

教学机制参考 [mattpocock/skills 的 `teach`](https://github.com/mattpocock/skills/blob/main/skills/productivity/teach/SKILL.md)，但调整为多用户数据库模型：`MISSION.md` 对应用户或项目级学习使命，`RESOURCES.md` 对应可信资源集合，`learning-records` 对应带证据的学习记录，HTML lesson 对应版本化课程产物。学习记录只在用户展示了理解、纠正了误区或明确说明既有能力时更新；“看过内容”不等于“已经学会”。

### 5. 科学表达工坊

- 科普文案、课程讲稿、科研汇报和论文辅助；
- 场景、受众、体裁、术语和表达目标建模；
- 事实锚点冻结、证据—措辞强度映射；
- 论证结构重组、中文人味复查和个性化风格适配；
- 多受众版本、差异比较、评论与局部修订。

### 6. 多模态科学实验室

- PDF、图片、公式、图表、音频和视频理解；
- OCR/ASR 中间结果查看与人工纠正；
- 静态科学图、数据图表、交互式 HTML 和科学动画；
- 教学设计稿、storyboard、代码生成、静态检查、沙箱运行和有限修复；
- TTS 朗读、字幕和可访问性输出。

### 7. 证据与校验台

- 来源管理、claim—evidence—wording 关系；
- 支持、反驳、限制和证据冲突展示；
- 引用正确性、数字、单位、公式和结论强度检查；
- 领域包规则、风险信号和高风险边界；
- 发布质量门、失败闭锁和人工裁决。

### 8. 画像与记忆中心

- 稳定画像、候选画像、项目记忆和会话记忆分层；
- 来源、置信度、适用场景、授权、有效期和版本；
- 查看某次回答调用的画像切片；
- 逐条确认、修改、冻结、删除、回滚和导出；
- 画像反馈与回答反馈分别处理。

### 9. 评测与运行中心

- 科学准确、学习增益、画像质量、人味表达和多模态质量评测；
- 纵向测试、基线对比、消融、对抗测试和用户盲测；
- 智能体运行轨迹、模型路由、工具调用、成本、延迟与错误；
- 数据集、提示词、Schema、阈值和结果版本化。

## 跨模块闭环

### 长期教学闭环

学习使命 → 可信资源 → 先备诊断 → 单一学习胜利的短课 → 练习与即时反馈 → 学习记录 → 最近发展区更新 → 间隔/交错复习 → 学习路径调整。

### 科学表达闭环

目标与受众 → 画像最小切片 → 证据组织 → 事实锚定 → 内容生成 → 人味复查 → 事实复核 → 用户修订 → 表达偏好或产物版本更新。

### 多模态创作闭环

教学目标 → 媒体选择 → 设计中间件 → 生成 → 静态检查 → 沙箱运行 → 科学校验 → 人工确认 → 版本保存。

### 画像闭环

对话或行为信号 → 候选画像 → 证据与授权检查 → 稳定画像 → 任务内最小调用 → 用户反馈 → 晋升、降级、修订或删除。

### 持续质量闭环

线上运行记录 → 失败与用户反馈 → 版本化评测 → 基线/消融 → 模型、规则或工作流调整 → 回归测试 → 受控发布。

## 明确非目标

- 不是无边界的通用聊天助手；
- 不提供临床诊断、处方或替代专业决策；
- 不模仿名人，也不未经授权替用户发声；
- 不允许无证据的高置信科学结论；
- 不以自由群聊式多智能体或智能体数量代表技术深度；
- 不以规避 AI 检测器作为“有人味”的目标；
- 不默认上传完整画像和私人材料；
- 不把未通过运行或科学校验的产物标记为完成；
- 不用统一课程列表代替逐用户学习路径。

## 开发与部署硬约束

- 项目后续在 Conda 环境 `agent` 中构建和运行开发工具链；
- 支持 Docker 与 Podman 容器部署；
- 支持非容器的手动部署；
- 提供统一 CLI 命令，同时启动前端与后端；
- 容器部署与手动部署必须使用同一配置模型、健康检查和数据迁移规则，避免形成两套产品。
