# 智能体拓扑、工作流协议与质量门

确认日期：2026-07-24

## 1. 决策摘要

成熟产品采用：

> **薄监督器 + 专业工作节点 + 确定性控制平面 + 类型化产物**

不采用多个智能体自由群聊、通过自然语言互相转述状态或无限自主循环。

- **薄监督器**只负责识别任务类型、选择并编译工作流、调度节点和判断收敛；
- **专业工作节点**负责需要语义判断或生成能力的检索、科学推理、教学设计、
  科学表达、多模态设计、画像候选和评测；
- **确定性控制平面**负责身份授权、作用域、Schema、工具注册、证据规则、
  风险策略、人工确认、运行账本和终止判定；
- 智能体之间不共享隐式“脑内状态”，只交换版本化的类型化产物；
- 工作流运行状态与科学产物可信状态分开保存；
- 只有瞬时且可修复的错误可以有限重试；
- 证据冲突、越权、安全拒绝、删除和人工否决必须失败闭锁；
- 工作流可以动态选择已注册能力，但不能在运行时临时扩权、删除质量门或调用
  未注册工具。

用户已通过一次性状态机原型确认此方案。原型覆盖正常教学、证据冲突、授权撤回、
工具 Schema 失败、多模态沙箱失败、协作撤权、画像晋升和并行检索八个难例。

## 2. 拓扑与职责

### 2.1 入口与薄监督器

全局科学伙伴是用户入口，不是无边界的万能智能体。它把任务整理成
`WorkOrder`，交给工作流编译器。

监督器由三个逻辑职责组成：

1. **任务路由**：识别教学、证据核验、表达、多模态、画像治理或复合任务；
2. **工作流编译**：选择版本化模板，冻结节点、依赖、Schema、质量门、预算、
   作用域和人工确认点；
3. **执行协调**：调度可运行节点、处理等待与取消、收集终止信号。

监督器不能直接改写科学结论、绕过专业节点或把一个节点的失败解释成成功。
规划器输出只是候选执行图；通过编译校验后才成为可运行工作流。

### 2.2 专业工作节点

| 节点族 | 核心职责 | 明确禁止 |
| --- | --- | --- |
| 上下文与画像切片 | 按任务编译最小、已授权的画像与记忆切片 | 读取完整个人保险库、写入稳定画像 |
| 来源发现与检索 | 发现、解析、去重和定位版本化来源 | 把相关性分数当证据强度 |
| 科学推理 | 构造 claim、限定条件、证据关系和不确定性 | 编造引用、越过事实锁 |
| 教学设计 | 根据学习使命、先备知识和最近发展区设计短课与练习 | 把浏览或完成度当掌握证据 |
| 科学表达 | 依据表达任务契约、事实锁和体裁契约生成内容 | 为“人味”改变科学判断 |
| 多模态设计 | 生成结构化分镜、可编辑源和渲染计划 | 直接发布未经过沙箱与科学复核的媒体 |
| 画像候选 | 从明确证据生成可解释的候选画像 | 静默晋升或推断敏感身份 |
| 评测 | 生成版本化评测请求和辅助判断 | 用单次模型自评替代确定性规则或专家门 |

事实校验、风险识别和评测可包含模型辅助节点，但最终权限、Schema、单位公式、
证据状态、发布资格和终止状态由确定性服务或具名人工节点裁决。

### 2.3 确定性控制平面

控制平面至少包含：

- 身份、会话、租户、项目和对象级授权服务；
- 工作流编译器和 Schema 注册表；
- 能力与工具注册表、模型网关和模型运行锁；
- 证据协议、领域包规则和事实锁校验器；
- 风险与安全策略引擎；
- 人工任务与审批服务；
- 幂等、预算、取消、补偿和终止控制器；
- 追加式运行账本、产物出处图和评测事件流。

控制平面规则优先于监督器与模型输出。模型不能通过提示、工具返回值或外部文档
修改这些规则。

## 3. 运行上下文信封

每次运行和每个节点都携带最小化、不可变的运行上下文信封：

- `run_id`、`workflow_version`、父运行和因果事件；
- `actor_id`、`user_id`、可选 `tenant_id`、`project_id`；
- 允许访问的对象集合与读写范围；
- 授权快照、策略版本、密钥时期和有效期限；
- 任务所需的记忆切片引用，不携带完整画像；
- 事实锁、领域包、证据协议和风险等级；
- 能力版本、模型运行锁、工具 Schema 哈希；
- 节点与运行级时间、Token、成本和重试预算；
- 幂等键、追踪 ID 和审计分级。

共享项目只能召回项目对象。需要个性化时，由用户本人编译一次性记忆切片，
不得把个人画像写入项目公共状态。

授权、撤权、删除墓碑、来源状态或密钥时期未知时失败闭锁。授权撤回后不能用旧
快照恢复原运行；如需继续，必须基于新授权创建新的派生运行。

## 4. 类型化产物协议

跨节点交换的主要产物包括：

- `WorkOrder`：任务目标、成功标准、风险与允许范围；
- `ContextSlice`：一次任务所需的最小上下文及授权说明；
- `EvidenceSet`：版本化来源、定位、状态和证据画像；
- `ClaimGraph`：claim、支持、反驳、限制和措辞强度；
- `TeachingPlan`：学习胜利、先备要求、讲解、练习和验证任务；
- `ExpressionDraft`：事实锁绑定的体裁化表达版本；
- `MediaStoryboard`：教学目标、场景、状态、旁白和科学判断绑定；
- `ValidationReport`：规则、模型或人工检查的逐项结果；
- `ProfileCandidate`：证据、置信度、范围、有效期和待确认项；
- `HumanDecision`：具名决定、理由、范围、时间和责任；
- `RunSummary`：终态、输出引用、失败、补偿和资源使用。

所有产物必须带 Schema 版本、所有者、对象域、创建活动、输入引用、模型或规则
版本、状态和内容哈希。修改创建新版本，不覆盖历史。

自由文本可以是产物字段，但不能代替状态、权限、出处、证据关系或质量门结果。

## 5. 工作流 DSL

每个版本化工作流至少声明：

- 输入、输出和中间产物 Schema；
- 节点依赖、条件执行、稳定输入和读写集合；
- 用户、租户、项目、对象范围与授权要求；
- 逻辑能力名、工具版本约束、模型运行锁和领域包版本；
- 超时、幂等键、节点级与运行级重试预算；
- 前置门、后置门、人工门和发布门；
- 失败闭锁、取消、补偿和终止信号。

示意合同：

```yaml
workflow: personalized_science_lesson@3
input: WorkOrder@2
scope: [user, project, object_set, authorization_snapshot, key_epoch]
nodes:
  - id: retrieve_sources
    capability: scientific_source_discovery
    output: EvidenceSet@3
    reads: [project_sources]
    writes: [run_artifacts]
    retry: {max: 2, only: [timeout, rate_limit]}
  - id: design_lesson
    depends_on: [retrieve_sources, compile_context_slice]
    output: TeachingPlan@2
    gates: [evidence_bound, pedagogy_rules, schema_valid]
human_gates: [learning_path_change]
terminal: [SUCCEEDED, BLOCKED, CANCELLED]
```

DSL 是受版本控制的产品合同，不允许模型在运行中生成任意代码作为执行计划。
模型可以在模板允许的参数和分支中作选择，编译器负责验证和冻结。

## 6. 双状态机

### 6.1 工作流运行状态

`DRAFT → COMPILED → RUNNING`

运行中可以进入：

- `WAITING_HUMAN`：等待具名人工决定；
- `RETRYING`：可修复失败且仍有预算；
- `SUCCEEDED`：合同内节点已经正确收敛；
- `BLOCKED`：不能安全或可信地继续；
- `CANCELLED`：用户、权限、删除或上游取消导致终止。

`SUCCEEDED` 只表示流程成功结束，不等于产物已批准、已发布或科学上无争议。

### 6.2 产物可信状态

正常路径：

`NOT_CREATED → DRAFT → EVIDENCE_BOUND → QUALIFIED → APPROVED`

异常状态：

- `CONFLICTED`：有效证据或科学语义存在未裁决冲突；
- `QUARANTINED`：Schema、安全、沙箱或完整性检查失败；
- `INVALIDATED`：授权、来源、事实锁或上游对象失效。

发布需要运行处于允许终态、产物达到相应可信状态、发布门通过且没有未解决的
撤权、冲突或删除事件。

## 7. 质量门与结果协议

质量门返回以下结构化结果之一：

- `PASS`：允许进入下一节点；
- `WAIT_HUMAN`：暂停并创建人工任务；
- `RETRYABLE_FAIL`：在原合同和剩余预算内修复；
- `FAIL_CLOSED`：阻断后续写入或发布；
- `INVALIDATE`：撤销当前或下游产物资格。

主要门：

1. **编译门**：DAG、Schema、能力、预算、读写集合和终止条件完整；
2. **授权门**：当前主体、作用域、对象权限、密钥时期和目的有效；
3. **输入门**：来源、版本、完整性和提示注入隔离通过；
4. **节点输出门**：Schema、出处和模型运行锁完整；
5. **科学门**：claim、证据、数字、单位、公式、限定条件和领域规则通过；
6. **教学门**：学习使命、先备知识、练习和学习记录证据规则通过；
7. **表达门**：事实锁、体裁契约、引用和人味表达边界通过；
8. **多模态门**：可编辑源、沙箱、跨媒体事实一致性和无障碍通过；
9. **发布门**：全部必需门、人工批准、授权和状态仍然有效。

## 8. 事件 Hook

事件包括运行编译与启动、节点开始与结束、产物生成、质量门失败、人工任务创建、
授权撤回、删除请求、来源失效、模型路由改变、重试、补偿和终止。

Hook 可以：

- 追加审计事件；
- 更新可观测指标；
- 触发重新校验、取消或人工任务；
- 使下游产物失效。

Hook 不能：

- 扩大权限或对象范围；
- 修改 Schema、事实锁、质量门和重试预算；
- 直接把产物标记为批准；
- 在失败后切换为无合同自由文本兜底。

## 9. 工具和能力注册

工具使用稳定的逻辑能力名，不在工作流中硬编码供应商型号。注册项至少记录：

- 输入输出 Schema 与前后置条件；
- 所需账户、项目、对象和外部操作权限；
- 网络、文件、代码执行与沙箱隔离级别；
- 版本、区域、可用状态和验证证据；
- 延迟、成本、限流与并发约束；
- 幂等性、可取消性、补偿能力和数据保留；
- 可接受的替代能力与禁止降级条件。

Qwen 等实际模型由模型网关解析，并在运行开始时形成模型运行锁。替换能力必须
重新通过兼容性和质量门，不能仅因 API 形状相同自动替换。

## 10. 并行和汇合

仅当以下条件同时满足时允许并行：

- 分支输入已经冻结；
- 写集不相交或只写各自运行产物；
- 不依赖尚未完成的人工决定；
- 取消、超时和预算能够独立控制；
- 汇合规则是确定性的。

汇合器按 Schema、来源版本、精确定位、领域规则优先级和出处关系归并。相同
科学判断、事实锁、对象归属或删除状态发生冲突时保留分支并进入人工门，禁止
最后写入者获胜或用模型多数票压平冲突。

## 11. 重试、取消与补偿

可以有限重试：

- 瞬时网络失败、限流、超时；
- 明确可修复且不改变语义的格式或 Schema 错误；
- 在事实锁不变前提下的受限代码修复。

不得自动重试：

- 身份或权限拒绝、角色移除、密钥时期失效；
- 证据冲突、关键来源状态未知、事实锁冲突；
- 安全策略、删除墓碑或人工否决；
- 会改变科学语义、画像结论或共享范围的修复。

重试同时受节点预算和运行预算约束，沿用原输入、Schema、范围、模型锁和事实锁。
预算耗尽进入 `BLOCKED`，不能取消 Schema 或换成自由文本。

取消时立即停止新调度、撤销工具票据、传播取消信号、阻止提交，并执行已声明的
补偿。已产生的审计元数据保留；正文和中间产物按对象域、授权与保留策略处理。

## 12. 人工确认矩阵

默认需要人工确认：

- 高风险科学、医学或可能影响现实安全的结论；
- 证据冲突、事实锁变化或措辞强度升级；
- 稳定画像晋升、修改、删除和跨域共享；
- 共享项目审批、公开发布和外部写操作；
- 自动修复可能改变科学语义；
- 同一科学判断、归属、授权或删除的并发冲突。

人工决定必须记录责任人、角色、授权、输入版本、决定、理由、范围和时间。
人工 override 不能改写历史，也不能授予其角色本来不拥有的权限。

## 13. 标准工作流骨架

### 个性化教学

学习使命 → 最小画像切片 → 来源与先备诊断并行 → 确定性汇合 → 科学解释 →
教学设计 → 练习与反馈 → 科学/教学质量门 → 用户确认学习路径 → 学习记录候选。

### 科学表达

表达任务契约 → 证据与事实锁 → 论证结构 → 草稿 → 人味复查 → 事实复核 →
用户修订 → 发布门。

### 多模态创作

教学目标 → 媒体选择 → 结构化分镜 → 可编辑源 → 静态检查 → 沙箱运行 →
跨媒体科学复核 → 人工确认 → 版本保存。

### 画像治理

画像观察 → 候选画像 → 证据和授权门 → 用户逐条确认 → 稳定画像 →
可回滚版本。任何教学或对话工作流都不能绕过此链直接写入稳定画像。

## 14. 审计与可观测

运行账本以追加事件记录：

- 谁在何种角色和设备上发起；
- 使用了哪个工作流、能力、模型、工具、Schema、领域包和策略版本；
- 哪些输入生成了哪些产物；
- 每个质量门、重试、人工决定、取消与补偿结果；
- 延迟、成本、Token、工具错误和终止原因。

审计日志保存必要元数据、引用和内容哈希，不复制完整画像、私人材料、提示上下文、
模型输出或密钥。正文审阅通过受控产物访问完成，不通过日志旁路完成。

## 15. 验收标准

1. 任一运行都能重建 DAG、版本、授权、事件和产物出处；
2. 未注册能力、Schema 不匹配或作用域不完整的工作流无法开始；
3. 运行 `SUCCEEDED` 时，未批准产物仍不能发布；
4. 证据冲突不会被模型投票、重试或最后写入自动消除；
5. 权限或角色撤回后不再产生新工具调用或提交；
6. 重试次数有节点级和运行级硬上限，且不能通过降级绕过 Schema；
7. 并行分支只在稳定输入和不相交写集上执行，汇合可复现；
8. 稳定画像只能由具名用户确认或已定义治理流程晋升；
9. 多模态运行失败时可保留可审查源文件，但成品不能发布；
10. 人工决定可审计且不能突破账户、租户和对象权限；
11. Docker、Podman、手动和统一 CLI 运行共享同一编排合同；
12. Windows Conda 环境 `agent` 中也执行完整多用户、权限和失败闭锁测试。

## 16. 后续规划硬约束

### 系统架构

- 编排引擎必须支持持久运行、等待人工、取消、有限重试、补偿和事件回放；
- 自有领域协议位于具体智能体框架之上，不把框架私有对象当长期数据模型；
- 所有后台任务、队列、缓存、索引和工具调用携带同一作用域信封；
- 调度器可以替换，但双状态机、类型化产物和质量门语义不能改变。

### 数据模型

- 分离工作流定义、工作流版本、运行、节点尝试、事件、产物版本、质量门、
  人工任务、授权快照、工具调用和补偿记录；
- 状态转换使用乐观并发或等价机制，不能由多个节点任意覆盖；
- 产物出处图与删除、撤权、来源失效传播相连。

### 前端

- 科学项目空间展示结构化运行，而不是隐藏在聊天消息中；
- 分开显示运行状态、产物可信状态、当前节点、质量门和人工待办；
- 提供证据冲突、有限重试、取消补偿、版本差异和为何阻塞的可解释视图；
- 用户能看见本次使用的画像切片、模型能力和授权范围。

### 评测

- 建立正常、冲突、越权、撤权、删除、Schema、沙箱、并发和画像晋升场景集；
- 统计非法转换率、越权工具调用率、重试越界率、错误发布率和出处完整率；
- 对监督器、专业节点、质量门和人工节点做消融，证明技术深度来自合同而非数量。
