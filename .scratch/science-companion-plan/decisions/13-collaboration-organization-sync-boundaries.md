# 协作空间、机构租户与跨设备同步边界

确认日期：2026-07-24

## 1. 决策摘要

成熟产品采用彼此不自动继承权限的三域模型：

1. **个人保险库**：个人画像、学习记录、全局记忆、私人材料和个人索引的唯一默认归属域；
2. **显式共享项目**：用户主动选择对象后形成的协作域，按项目角色和对象权限开放；
3. **机构管理域**：机构身份、席位、策略、机构自有项目和必要审计的治理域。

跨设备副本不是第四个所有权域。它只是绑定用户、设备、对象域、授权版本和密钥时期的加密副本，不能成为绕过服务器撤权、删除墓碑或对象归属的独立真相。

用户确认采用以下产品结构：

- 普通用户以“空间边界地图”为协作主心智模型；
- 角色×对象权限矩阵进入权限与机构治理详情；
- 离线编辑、冲突、设备撤销和删除传播进入设备与同步中心；
- 机构管理员默认不能查看成员的个人画像、学习记录、私人材料、私人索引或全局记忆；
- 个人对象进入协作时默认创建独立的项目对象，不自动同步后续私人修改；
- 设备撤销承诺阻止未来访问、撤销会话并轮换密钥，不承诺远程擦除已被用户合法导出的明文。

## 2. 身份、租户与归属

### 2.1 用户账户

用户账户是人的长期身份和个人数据归属边界。一个账户可以不属于任何机构，也可以同时加入多个机构。加入、退出或被移出机构，不会转移个人保险库的所有权，也不会令机构自动获得历史个人数据。

### 2.2 机构租户

机构租户是组织管理成员、席位、机构策略、组织自有项目、域名登录和必要安全审计的边界。机构租户不是用户账户的上级数据容器；“管理员”也不是能读取所有成员内容的全局超级用户。

机构可以拥有明确标记为“机构所有”的项目和对象。创建时必须显示所有权、数据保留、密钥恢复、管理员可见性和退出后的处理方式，不能事后把个人项目改判为机构资产。

### 2.3 对象归属

每个对象必须同时记录：

- 所有者：个人、共享项目共同体或机构；
- 所在域：个人保险库、显式共享项目或机构管理域；
- 当前可见主体和角色；
- 创建、复制、引用、修改、导出和删除的出处链；
- 授权目的、期限、策略版本和撤回状态；
- 加密范围、密钥时期和同步状态。

对象的“存放位置”“所有者”“谁能查看”是三个独立维度，不能用一个 `tenant_id` 或 `visibility=shared` 粗略代替。

## 3. 三域边界

### 3.1 个人保险库

个人保险库默认包含：

- 证据化画像、候选画像和画像观察；
- 学习使命、学习记录、知识状态和学习路径；
- 全局会话记忆、用户置顶事实和表达偏好；
- 私人材料、个人批注、个人索引和未公开草稿；
- 个人设备、授权、导出与删除记录。

只有本人可以浏览正文。导师、项目负责人、机构管理员和安全管理员都不因角色而自动获得权限。

用户可以主动分享某条学习证明、某份材料或某个草稿，但系统必须创建范围明确的共享项目对象；不得把完整学习记录、画像切片或私人索引挂载到项目供成员搜索。

### 3.2 显式共享项目

显式共享项目只包含用户明确加入项目的对象：

- 项目材料、数据和出处；
- claim、Evidence、事实锁和冲突记录；
- 项目记忆、决策、任务与工作流运行；
- 共享表达产物、多模态产物、评论、审批和版本；
- 项目成员、角色、邀请、密钥与审计事件。

个人对象共享时默认执行“复制为项目对象”：

1. 展示将复制的字段、接收方、目的和权限；
2. 去除画像、学习记录、私人批注和无关元数据；
3. 创建具有新对象 ID、项目归属和出处关系的副本；
4. 原对象继续留在个人保险库；
5. 两者后续修改不自动双向同步；
6. 用户可再次发起受审查的更新，但不能由系统静默覆盖项目版本。

项目之间可以在后续架构中支持可撤销引用，但个人保险库对象不得用引用方式绕过上述复制与最小化门。

### 3.3 机构管理域

机构管理域可以包含：

- 成员身份、席位、组织角色和邀请状态；
- SSO/OIDC、域名、MFA 和会话安全策略；
- 机构自有项目及其保留、发布和审批策略；
- 聚合使用量、容量、计费和服务健康；
- 登录、授权、共享、导出、撤权和安全事件的必要审计元数据；
- 机构领域包、评测基线和合规配置。

机构管理域默认不包含：

- 成员个人画像、学习记录、全局记忆和私人材料正文；
- 个人项目的聊天记录、提示词、检索内容和模型输出正文；
- 为“效率分析”而收集的个人学习细节；
- 未经逐对象授权的共享项目内容。

安全管理员处理真实安全事件时，仍遵守目的限定、最小披露、双人批准、时限和完整审计。紧急权限不能变成日常内容浏览入口。

## 5. 邀请、协作与退出

### 5.1 邀请

邀请必须包含机构/项目身份、邀请人、目标角色、可见对象范围、到期时间、数据处理说明和是否需要 MFA。用户接受前可以预览权限，不因点击邀请链接而自动加入或上传个人数据。

外部访客默认使用到期角色，不能邀请他人、导出完整项目、修改成员权限或访问机构内部目录。高敏感项目可以要求设备合规与再次确认。

### 5.2 评论与审批

- 评论是独立对象，不直接修改正文；
- 建议修改产生可审查差异；
- 编辑者可创建新版本，但不能自行通过需要审阅的发布门；
- 导师/审阅者可以批准指定质量门，不因此获得个人学习记录；
- 最终发布由项目负责人或明确授权的发布者完成；
- 所有人工 override 记录理由、范围和责任人，不能改写历史。

### 5.3 退出与移除

成员主动退出或被移除后：

1. 立即停止新访问并撤销活跃会话；
2. 移除成员角色与对象授权；
3. 对需要前向保密的项目轮换密钥时期；
4. 停止向该成员设备同步新事件；
5. 保留其合法贡献、署名和不可变审计关系；
6. 显示尚未确认撤权的离线设备；
7. 不触及该成员个人保险库；
8. 不虚假声称已擦除其曾合法导出的明文。

项目负责人离开前必须转移负责人角色或进入机构/成员共同决定的冻结状态，不能产生无人负责但仍可修改的项目。

## 6. 跨设备同步合同

### 6.1 权威状态

同步以版本化对象、操作记录、授权快照、设备身份和删除墓碑为基础。设备缓存是可丢弃副本，不是权威数据库。所有上传操作都要再次通过账户、租户、项目、对象和当前授权检查。

### 6.2 离线编辑

- 设备离线时追加本地操作，不覆盖未知的远端新版本；
- 每项操作携带设备、用户、对象、基础版本和因果关系；
- 恢复联网后先同步授权、撤权和删除墓碑，再提交内容操作；
- 已撤权设备提交的旧离线操作进入隔离区，不自动重获项目访问；
- 离线状态下不得执行需要新云端推理、最新来源状态或新权限判断的动作。

### 6.3 冲突合并

可确定性合并：

- 不同对象或不重叠结构字段；
- 评论追加、标签集合和无语义顺序的成员操作；
- 能由 Schema、版本和事实锁证明等价的机械变化。

必须人工选择：

- 同一科学判断、数字、单位、公式或措辞强度的不同修改；
- 一方修改事实锁、证据关系或发布状态；
- 删除与编辑并发；
- 对象归属、授权和可见性冲突；
- 自动合并会丢失任一有效分支的情况。

系统保留两个分支、共同祖先和差异理由，禁止用“最后写入者获胜”覆盖科学语义冲突。

### 6.4 加密与计算

- 个人保险库默认按用户和设备密钥加密；
- 共享项目使用项目密钥，并按成员和设备包装；
- 成员撤权或设备撤销触发新密钥时期；
- 机构自有项目若启用机构恢复密钥，必须在创建和加入前显著披露；
- 云端 Qwen 只接收一次任务所需、经授权解密的最小上下文；
- 存储加密、共享授权和模型计算授权是三个不同许可，不能合并为一个开关；
- 服务端日志不得记录解密正文、密钥或完整提示上下文。

## 7. 设备撤销

设备撤销顺序：

1. 撤销设备证书、刷新令牌和活跃会话；
2. 标记设备为 `REVOKED`，拒绝新的同步和密钥包装；
3. 对敏感项目轮换密钥时期；
4. 向其他设备传播撤销事件；
5. 被撤销设备重新联网时先接收撤销与删除指令，不上传普通离线操作；
6. 跟踪“已确认撤销”“尚未联网”“已丢失”状态；
7. 向用户准确说明可控范围。

系统不承诺远程擦除用户已导出的明文、截图或脱离受控存储的副本。对于仍受设备密钥保护的本地缓存，可以通过密钥撤销和加密删除使其不可读，并记录验证结果。

## 8. 删除、撤权与保留

### 8.1 个人对象删除

个人删除请求先冻结新召回和新派生，再沿出处图传播至主记录、项目更新候选、索引、向量、缓存、任务队列、设备副本和备份清理计划。个人对象此前复制出的项目对象具有独立归属，不会被静默删除；系统必须显示复制关系，并允许用户按其项目权限另行申请删除或撤回。

### 8.2 共享项目删除

共享对象删除需要对象所有者或项目策略授权。删除与编辑并发时进入人工冲突。删除墓碑先阻止备份恢复后“复活”，再追踪各存储和设备确认。

项目整体删除要处理：

- 成员通知和可撤销等待期；
- 法定或机构保留与其明确依据；
- 导出、引用和下游派生关系；
- 项目密钥销毁；
- 备份到期和恢复后的墓碑重放；
- 最终删除凭证。

### 8.3 法定保留

法定保留只适用于明确范围的机构对象或必要审计，不能把个人画像和私人材料默认纳入。保留对象与产品个性化、检索和模型上下文隔离，并向受影响用户显示依据、范围和期限。

## 9. 审计与管理员可见性

审计事件至少记录 actor、角色、设备、对象 ID、对象域、操作、策略版本、授权/拒绝结果、时间、理由和关联事件。普通运维与机构管理员默认只看必要元数据和聚合指标。

任何正文访问都需要：

- 明确的对象权限或安全事件授权；
- 可说明的目的与时限；
- 对高敏感对象的双人批准；
- 不可修改的访问记录；
- 向对象所有者提供适当通知和事后查询能力；
- 访问结束后的权限自动收回。

不得在审计日志中复制个人画像正文、学习答案、完整提示、私人材料或模型输出。

## 10. 产品信息架构

### 普通用户：空间边界地图

在项目和共享入口始终并排展示：

- 个人保险库：仅本人；
- 显式共享项目：按项目角色；
- 机构管理域：机构策略和机构对象。

对象检查器显示所有者、所在域、默认可见性、同步范围、硬规则和共享后变化。共享动作必须先经过最小化预览。

### 权限与机构治理：权限矩阵

权限详情提供角色×对象矩阵、对象级例外、邀请和到期策略，并能运行“导师申请查看学生草稿”“管理员导出成员画像”“成员退出共享项目”“安全事件最小披露”等异常场景。

### 设备与同步中心：事件时间线

设备中心显示：

- 受信、离线、待确认撤权和已撤销设备；
- 密钥时期和最近同步证明；
- 离线操作、冲突分支和人工裁决；
- 删除墓碑传播和备份清理进度；
- 产品能保证与不能保证的边界。

## 11. 异常场景裁决

1. **导师想查看学生全部学习记录**：拒绝。学生可以分享一条独立学习证明或把指定草稿复制到项目。
2. **机构管理员要导出成员画像做统计**：拒绝。只能使用自愿、去标识、目的明确且与个人保险库隔离的数据产品。
3. **成员退出但笔记本离线**：立即拒绝服务器新访问并轮换密钥；设备标为待确认撤权，不宣称已擦除。
4. **离线设备修改了已删除对象**：删除墓碑优先，离线修改进入隔离区，可供原作者手动导出但不能复活项目对象。
5. **两个成员同时改变科学结论强度**：保留双分支，由事实锁和人工审阅裁决。
6. **项目引用个人材料后用户修改原件**：项目副本不自动变化；用户可提交新的项目版本供审查。
7. **机构要求保留个人聊天记录**：不允许用通用租户策略扩张个人域；只有明确适用的法律依据和最小范围才可另行处理。
8. **安全管理员发现疑似数据外泄**：先限制会话和对象访问；正文访问需事件范围、双人批准、时限和审计。
9. **成员截图或导出项目内容后被移除**：撤销未来访问，但不作无法兑现的远程删除承诺；敏感项目通过水印、导出限制和责任协议降低风险。
10. **一个用户加入两个机构**：两个机构域互不可见，个人保险库保持同一账户独立归属，跨机构共享必须创建明确项目和对象授权。

## 12. 后续规划硬约束

### 智能体编排

- 每次运行携带 user、tenant、project、object scope、authorization snapshot 和 key epoch；
- 共享项目只能召回项目对象，不能自动调用成员个人画像；
- 需要个性化时，由用户本人编译一次性记忆切片，不写回项目公共状态；
- 权限、撤权、删除或同步状态未知时失败闭锁；
- 评论、审批、冲突裁决和发布是类型化人工节点。

### 前端

- 协作主界面保留三域边界；
- 分享前显示字段、接收方、目的、期限和共享后的独立性；
- 管理员界面明确区分“管理成员”与“读取内容”；
- 同步中心显示撤销与删除的真实传播状态；
- 所有功能页面仍需认证，邀请预览除外。

### 系统架构

- 数据模型分离账户、租户、成员关系、项目、对象归属、角色、对象授权、设备、密钥时期、同步操作、冲突、墓碑和审计事件；
- 关系库、对象存储、索引、缓存、队列和观测都执行相同的作用域约束；
- RLS/ACL 不能只在 API 层实现；
- Conda `agent` 只用于本地开发；生产的手动分进程、统一 CLI、Docker 和 Podman 共享同一授权、迁移、密钥、同步和删除合同；
- Windows 开发环境不得以“本地单机”为由跳过多用户隔离测试。

### 评测

- 跨账户、跨机构、跨项目召回与缓存泄漏率必须为零；
- 覆盖管理员越权、邀请劫持、离线撤权、删除复活、密钥时期回退、冲突覆盖和审计正文泄漏；
- 测量撤权和删除在各层传播的完成率、时延与未确认设备数；
- 用纵向用户测试验证三域模型和分享预览能否被准确理解。

## 13. 验收标准

1. 用户加入机构后，管理员仍无法读取其个人保险库；
2. 个人对象只有经过最小化预览才能复制到共享项目；
3. 项目成员权限同时受角色、对象授权和风险策略约束；
4. 导师只能查看用户主动分享的独立证明或项目对象；
5. 机构自有项目在创建前清楚声明所有权、保留和恢复密钥；
6. 离线编辑不覆盖未知远端版本；
7. 科学语义冲突不会被最后写入者自动覆盖；
8. 退出、移除和设备撤销立即阻止服务器新访问；
9. 删除墓碑能阻止备份恢复后复活对象；
10. 系统能区分已撤销、待设备确认和无法控制的外部明文；
11. 一个账户加入多个机构时数据不串联；
12. 普通用户、项目负责人和机构管理员都能解释自己为何能或不能执行某项操作。
