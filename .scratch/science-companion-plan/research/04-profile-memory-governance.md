# 证据化画像、长期记忆与授权治理研究

核验日期：2026-07-24

## 1. 结论

本项目不能建设一个把聊天摘要、用户标签、学习进度和项目上下文全部塞进同一张“长期记忆表”的系统。成熟方案应采用三条相互关联但不可混写的链：

1. **学习证据链**：用户做了什么、在什么条件下表现如何、反馈和延迟复测结果是什么；
2. **画像断言链**：哪些原子观察在何种授权和场景下，支持了哪一条可撤销的用户画像；
3. **记忆使用链**：某次任务为何召回哪些最小信息、如何影响输出、何时失效。

核心决策：

- 原始观察和学习证据是版本化事件；证据化画像、知识状态和学习路径是可重算的派生判断。
- “候选画像”不是低分版稳定画像。它默认不可用于高影响个性化，只有满足授权、证据、场景和冲突检查后才能晋升。
- 会话记忆、项目记忆、用户置顶事实、偏好、知识状态和画像断言是不同对象，具有不同归属、保存期和召回规则。
- 画像必须“薄而准确”。未知、矛盾和已过期都是合法状态；不得用模型猜测填满空白。
- 画像只可改变解释层级、表达方式、例子、任务顺序和学习挑战度，不能改变科学事实、证据强度、安全规则或访问权限。
- 任何个性化都先编译为一次性**记忆切片**。Qwen 不直接浏览完整画像库，也不能自行写入稳定画像。
- 删除必须沿出处图使派生画像、知识状态、向量、缓存和同步副本失效；“界面看不见”不等于删除完成。
- 登录账户是最小归属边界。跨用户召回、缓存命中、向量近邻、后台任务串线和共享项目隐式暴露画像的容忍度均为零。

## 2. 一手依据及其适用边界

### 2.1 隐私与用户权利

《中华人民共和国个人信息保护法》确立了明确、合理目的，直接相关、最小范围、公开透明、保存期限最短必要，以及知情、决定、限制/拒绝、查阅复制、更正补充、删除等要求；敏感个人信息需要更严格的目的、必要性和保护措施。[中国政府网法律全文](https://www.gov.cn/xinwen/2021-08/20/content_5632486.htm)

欧盟 GDPR 的目的限制、数据最小化、准确性、存储限制、透明度、访问、更正、删除、限制处理、可携带、隐私保护默认设置等原则，可作为产品能力的高标准参考，但不能把 GDPR 合规声明直接套用于所有地区。[EUR-Lex GDPR 正文](https://eur-lex.europa.eu/eli/reg/2016/679/oj)

[NIST Privacy Framework](https://www.nist.gov/privacy-framework) 将隐私风险治理组织为识别、治理、控制、沟通和保护；[NIST AI RMF](https://www.nist.gov/itl/ai-risk-management-framework) 强调 AI 风险的治理、测量和持续管理。项目采用其“可识别、可治理、可测量”的思想，不把任何框架名称当作自动合规证明。

删除介质和备份时参考 [NIST SP 800-88 Rev.2](https://csrc.nist.gov/pubs/sp/800/88/r2/final) 的介质清理与验证思想。具体法规适用、法定保留、跨境传输、未成年人和敏感信息处理，必须在上线地区由法务及安全负责人再次核验。

### 2.2 出处和学习事件

[W3C PROV-O](https://www.w3.org/TR/prov-o/) 的 Entity—Activity—Agent 与派生、修订、失效关系适合表示“某观察经何次抽取和确认形成哪条画像”，但出处完整不等于推断正确。

[xAPI 规范](https://github.com/adlnet/xAPI-Spec) 和 [1EdTech Caliper Analytics](https://www.imsglobal.org/spec/caliper/v1p2) 可借鉴主体—动作—对象、结果、上下文和时间等学习事件结构。项目不把“打开课程”“看完视频”自动解释为掌握，只把这些事件作为活动记录或练习调度依据。

`teach` skill 明确区分即时流畅感与长期储存强度，并以学习使命、可信资源、短课、检索练习、间隔、交错、即时反馈和学习记录确定最近发展区。本项目直接采用这些教学约束，但将 Markdown 文件模型调整为逐账户、版本化、可授权的数据模型。

### 2.3 智能体记忆与安全

长期记忆研究和实现可提供“情节、语义、程序性记忆”“分层记忆”“时间关系”等启发，但不能直接成为产品权限模型。外部文本、用户上传、工具结果和被召回记忆都属于不可信数据面。[OWASP Prompt Injection](https://genai.owasp.org/llmrisk/llm01-prompt-injection/) 指出，间接提示注入不能仅靠 RAG 或微调消除；因此记忆内容永远不能改变系统指令、权限和工具策略。

## 3. 领域对象：不能混成一个 `memory`

| 对象 | 定义 | 能否直接个性化 | 默认作用域 |
| --- | --- | --- | --- |
| `ProfileObservation` 画像观察 | 带原始来源和情境的原子信号，例如明确偏好、纠正或行为表现 | 否 | 会话/项目/账户 |
| `CandidateProfile` 候选画像 | 从一个或多个观察提出、尚未满足晋升门的可验证假设 | 仅可用于请求确认或低风险实验 | 账户 + 场景 |
| `ProfileAssertion` 画像断言 | 经授权和证据门确认的稳定、版本化画像条目 | 是，但必须经记忆切片 | 账户 + 适用场景 |
| `KnowledgeState` 知识状态 | 对某知识点当前掌握程度和不确定性的可撤销判断 | 仅用于教学 | 用户 + 学习使命 |
| `LearningRecord` 学习记录 | 用户已经展示理解、技能、纠错或迁移的证据化记录 | 不直接；用于更新知识状态 | 用户 + 学习使命/项目 |
| `SessionMemory` 会话记忆 | 当前对话连续性所需的短期内容和未完成状态 | 是，仅当前会话 | 用户 + 会话 |
| `ProjectMemory` 项目记忆 | 科学项目空间内的决策、约束、术语、开放问题和产物关系 | 是，仅该项目 | 用户/显式共享空间 + 项目 |
| `PinnedFact` 用户置顶事实 | 用户明确要求保存的事实、边界或默认设置 | 是，按用户指定范围 | 账户/项目 |
| `Preference` 偏好 | 影响呈现和交互但不改变事实的场景化选择 | 是 | 账户 + 场景 |
| `TransientSignal` 情境信号 | 当前紧迫度、困惑、疲劳或可能情绪等短时、低置信信号 | 仅当前交互适配 | 会话，短期到期 |
| `AuthorizationGrant` 授权记录 | 谁允许系统为哪个目的处理哪些对象、进行哪些操作、持续多久 | 它决定其他对象能否使用 | 用户 + 目的 |
| `MemorySlice` 记忆切片 | 为一次运行编译的最小、授权、可解释信息集合 | 是，仅绑定运行 | 单次 run |
| `DeletionRecord` 删除记录 | 删除范围、级联状态和验证结果，不保留被删内容本身 | 否 | 账户审计域 |

重要边界：

- `ProfileObservation` 是证据，`ProfileAssertion` 是判断；删除或失效证据可能使判断降级。
- `LearningRecord` 是已观察表现，`KnowledgeState` 是对掌握度的估计；二者都不是课程完成率。
- `PinnedFact` 来自用户明确保存，不因“证据不足”被模型否决，但仍受作用域、期限和安全规则约束。
- `ProjectMemory` 不得被提升为全局用户特征；共享项目内容也不意味着共享成员个人画像。
- `TransientSignal` 不得自动晋升为人格、心理健康或稳定情绪画像，不用于诊断。

## 4. 最小数据契约

所有对象共有：

```text
id, tenant_id, owner_user_id, project_id?,
schema_version, created_at, updated_at,
status, visibility, provenance_ref,
authorization_ref, valid_from, expires_at?,
supersedes_id?, invalidated_at?, invalidation_reason?
```

### 4.1 画像观察

```text
observation_id
source_type: explicit_statement | correction | choice | task_behavior |
             assessment | imported | system_inference
source_ref, source_span_or_event
scene, purpose
observed_content
signal_kind
extractor_and_version
model_rationale
user_confirmed: yes | no | rejected | not_asked
reliability_factors[]
sensitivity_class
retention_policy
```

禁止只保存“用户喜欢简短回答，confidence=0.82”。必须保留发生在什么任务、用户原话或行为是什么、该观察允许影响什么。

### 4.2 候选画像与画像断言

```text
candidate/assertion_id
canonical_dimension
value_or_rule
applicable_scenes[]
non_applicable_scenes[]
supporting_observation_ids[]
contradicting_observation_ids[]
evidence_summary
authorization_scope
promotion_policy_id/version
review_status
stability_state
last_used_at, last_confirmed_at
next_review_at
```

不能把可解释状态压缩成单一浮点数。内部可保留模型分数用于评测，但产品判定必须由证据类型、独立场景、冲突、用户确认和时效等维度解释。

### 4.3 学习记录与知识状态

`LearningRecord` 至少包含：学习使命、知识点/技能、任务版本、先备条件、作答或产物、提示使用、正确性、解释质量、迁移距离、反馈、延迟、来源、评审者和时间。

`KnowledgeState` 至少包含：知识点、状态（unknown/emerging/supported/robust/stale）、支持与反驳记录、最近直接证据、不同情境表现、模型/规则版本、不确定性、下一次最佳检验，而非笼统“掌握 87%”。

### 4.4 记忆切片

```text
slice_id, run_id, task_purpose
included_item_ids[]
inclusion_reason_per_item[]
excluded_sensitive_categories[]
authorization_snapshot
compiled_by_policy_version
token/content budget
expires_at
use_receipt
```

切片是唯一允许发送给云端 Qwen 的长期信息载体；默认不包含原始会话全文、完整画像、未确认候选和无关私人材料。

## 5. 画像生命周期与状态机

```text
OBSERVED
  ├─ 无保存授权/不相关/敏感推断 ─→ DISCARDED
  └─ 满足最小质量门 ───────────→ CANDIDATE
       ├─ 用户拒绝 ─────────────→ REJECTED
       ├─ 冲突未决 ─────────────→ CONFLICTED
       ├─ 到期或长期未验证 ─────→ STALE
       ├─ 明确确认或多情境证据 ─→ ACTIVE
       └─ 仅当次任务 ───────────→ SESSION_ONLY

ACTIVE
  ├─ 新证据修正 ───────────────→ 新版本 ACTIVE
  ├─ 反例/不再适用 ────────────→ CONFLICTED 或 STALE
  ├─ 用户冻结 ─────────────────→ FROZEN
  ├─ 撤回授权 ─────────────────→ RESTRICTED
  └─ 删除 ─────────────────────→ DELETION_PENDING → DELETED
```

### 5.1 晋升门

画像条目必须同时满足：

1. 与后续回答或教学确有可说明的用途；
2. 来源可追溯，情境和限定条件完整；
3. 具有相应目的和保存授权；
4. 非被禁止的敏感推断；
5. 没有未解决的实质冲突；
6. 满足该维度策略：用户明确确认，或多个真实任务中出现独立、一致信号；
7. 通过确定性 Schema、权限和期限检查。

以下永不自动晋升：

- 一次性情绪、反讽、角色扮演、假设示例；
- 用户引用他人的经历；
- 模型推断的人格、政治、宗教、健康、性取向、精确位置等敏感属性；
- 当次任务的格式要求；
- 仅由点击、停留或“看过课程”推断出的掌握度；
- 与回答质量无关、只是让系统显得“更懂用户”的标签。

### 5.2 冲突、合并与衰减

- 场景不同的相反偏好拆成两条场景化断言，不强行平均；
- 新观察先形成新版本，不覆盖历史；
- 用户纠正优先作用于所指条目，不能无理由重写其他维度；
- 稳定事实、表达偏好、阶段目标、情境信号使用不同复核周期；
- 衰减的是“可用性状态”，不是悄悄修改内容或降低一个黑箱分数；
- 到期条目变为 `STALE`，只能用于请求再确认，不能按事实使用；
- 回滚生成新版本并保留变更理由，不能删除审计链。

## 6. 知识掌握与学习路径

学习系统必须区分：

- **接触事件**：打开、浏览、播放、停留，只说明可能接触；
- **即时表现**：刚学习后的正确回答，可能受工作记忆和提示影响；
- **检索证据**：不看材料从记忆中提取；
- **延迟保持**：经过间隔后仍能回忆或应用；
- **迁移证据**：能在新题型、真实任务或不同表征中运用；
- **纠错证据**：能解释错误、修正误区并避免重复；
- **元认知证据**：能说明不确定处和需要查证的部分。

更新规则：

1. 浏览行为永不直接生成 `LearningRecord`；
2. 有提示的正确与无提示检索分开记录；
3. 即时表现最多进入 `emerging`，延迟复测和迁移才支持 `robust`；
4. 单次失败不立即判定“不会”，要区分题目、表达、注意力和先备知识；
5. `KnowledgeState` 始终允许 `unknown`，并记录最值得验证的下一步；
6. 最近发展区由学习使命、先备知识、近期证据和挑战成功率共同决定；
7. 学习路径使用检索、间隔和交错调度，但不给所有用户套同一固定课程；
8. 用户可纠正系统对其基础的判断，系统以新版本和后续任务验证，而非争辩。

## 7. 写入、召回和使用闭环

### 7.1 写入门

```text
事件进入
→ 租户/权限/目的检查
→ 敏感与注入检测
→ 结构化为观察或学习事件
→ 确定性字段校验
→ Qwen 提出候选及理由
→ 晋升策略/必要用户确认
→ 版本化写入
→ 记录 provenance 和授权快照
```

普通对话不默认启动深度画像分析。优先响应“记住”“以后默认”“这不像我”“不要记录”“删除/查看/导出”等明确信号。

### 7.2 召回门

```text
任务目的与风险分类
→ 登录、租户、项目和授权检查
→ 只查询 ACTIVE 且场景适用的条目
→ 排除敏感、冲突、过期和无关内容
→ 生成最小记忆切片
→ 策略层验证
→ Qwen 使用
→ 输出后记录使用凭证
→ 用户反馈分别路由到“回答修正”或“画像修正”
```

### 7.3 职责矩阵

| 环节 | 确定性程序 | Qwen | 用户/人工 |
| --- | --- | --- | --- |
| 身份与权限 | 会话、RLS/ACL、租户和项目边界 | 无决定权 | 管理授权与共享 |
| 信号抽取 | Schema、来源、时间、敏感类别 | 提出观察候选和情境 | 可确认、拒绝、纠正 |
| 画像晋升 | 状态机、必填证据、期限、冲突门 | 给结构化理由，不自行晋升 | 敏感或高影响条目必须确认 |
| 知识状态 | 汇总学习记录、规则和版本 | 评估开放题表现并给理由 | 教师/专家处理高影响争议 |
| 记忆切片 | 目的、授权、最小化、预算和过期 | 不得扩大切片 | 用户可查看本次使用 |
| 个性化生成 | 事实锁、安全和措辞边界 | 调整解释、例子、顺序和语气 | 可评价回答或画像 |
| 删除 | 级联任务、索引/缓存/备份追踪 | 无权保留或恢复 | 发起、撤回未执行请求、查看凭证 |
| override | 权限与审计 | 只能建议 | 授权责任人留理由和范围 |

## 8. 授权与用户控制

授权不是一个全局布尔开关。`AuthorizationGrant` 至少记录：

- 数据类别；
- 处理目的；
- 允许操作：收集、推断、保存、召回、上云、共享、导出；
- 账户/项目/会话作用域；
- 生效、到期和撤回时间；
- 授权文本版本和获取方式；
- 法律依据/产品许可记录（两者不可混为一谈）。

画像与记忆中心必须支持：

- 查看“系统记住了什么”及自然语言说明；
- 展开来源、证据、场景、授权、版本和最后使用；
- 逐条确认、修改、拒绝、冻结、删除；
- 查看某次回答实际使用的记忆切片和影响；
- 比较版本、回滚、导出结构化数据；
- 撤回某目的或某类数据的授权；
- 注销账户并跟踪删除进度。

敏感信息默认不推断、不保存、不用于推荐。用户主动提供也不代表允许长期保存；必须验证必要性和明确授权。比赛提到的“情绪变化识别”仅形成短期 `TransientSignal`，默认会话结束或短期窗口到期，不生成心理诊断、人格结论或稳定标签。

## 9. 删除语义

### 9.1 删除级联

```text
DeletionRequested
→ 冻结该对象的新召回与新派生
→ 解析 provenance 依赖图
→ 主记录删除/不可逆去标识
→ 画像断言、知识状态和学习路径失效或重算
→ embedding、词法/关系索引、缓存和队列消息删除
→ 对象存储及本地同步副本传播
→ 日志内容最小化；保留无内容的合规审计
→ 备份登记到期清除，恢复时重新应用 tombstone
→ 删除验证
→ DeletionCompleted
```

### 9.2 软删、tombstone、硬删与加密删除

- **软删**仅用于短暂可撤销窗口，期间对象绝不可召回；
- **tombstone**只保留不可反推出内容的标识、范围、时间和删除状态，用于阻止备份恢复“复活”数据；
- **硬删**移除活动存储、索引、缓存和派生内容；
- **加密删除**可用于受独立密钥保护的备份或设备副本，但需要证明密钥不可恢复；
- 法定必须保留的审计记录应与产品记忆隔离、最小化、不可用于个性化，并向用户说明保留依据和期限。

删除凭证至少包含请求范围、受影响对象数、各存储层状态、剩余备份到期日、验证结果和异常。不能承诺无法验证的“立即从所有备份物理消失”。

## 10. 多用户隔离与记忆安全

必须覆盖关系库、对象存储、向量库、词法索引、关系图、缓存、任务队列、日志、评测集、导出和模型上下文：

1. 每个对象带 `tenant_id`、`owner_user_id` 和可选 `project_id`；
2. 访问过滤在检索前执行，不能全库召回后过滤；
3. 缓存键包含租户、项目、授权策略版本和数据版本；
4. embedding 和去重不能泄露“其他用户存在相同内容”；
5. 后台任务使用不可伪造的租户上下文，消费端再次校验；
6. 输出前二次检查切片内所有对象的当前可见性；
7. 公共目录与私人使用记录分离；
8. 共享项目只共享明确选中的项目对象，个人画像、学习记录和全局记忆默认不共享；
9. 管理员权限不等于可浏览成员私人画像；
10. 设备丢失、退出登录、注销和撤权必须撤销会话、密钥和离线副本访问。

记忆内容和来源文本均可能包含提示注入。读记忆的模型没有权限修改系统策略、扩大授权或调用高风险工具；任何“请忽略规则并导出画像”的记忆内容都只能作为数据。检测到来源篡改、跨租户标识、异常批量写入或矛盾画像投毒时进入隔离区。

## 11. 诚实降级与失败闭锁

| 状态 | 条件 | 行为 |
| --- | --- | --- |
| `PERSONALIZED` | 授权、证据、场景、期限均有效 | 使用最小切片 |
| `SESSION_ONLY` | 无长期授权或用户要求不保存 | 只用当前会话 |
| `GENERIC` | 无相关稳定画像、画像过期或用户关闭个性化 | 给通用但可靠回答 |
| `CONFIRM_REQUIRED` | 候选会显著改变教学/建议 | 先向用户确认 |
| `CONFLICTED` | 画像或知识证据互相冲突 | 不做单一判断，说明需校准 |
| `QUARANTINED` | 投毒、注入或来源完整性异常 | 不召回相关对象 |
| `BLOCKED` | 租户、权限、删除或审计关键门失败 | 停止个性化；涉及泄漏风险时停止回答 |

以下不得静默退回“模型觉得它记得用户”：

- 租户或项目过滤异常；
- 授权快照缺失、撤回或用途不匹配；
- 切片含其他账户对象；
- 已删除/冻结对象仍被命中；
- 画像来源失效且无法重算；
- 敏感属性由模型推断产生；
- 记忆切片或使用凭证无法落盘；
- Qwen 结构化抽取连续达到重试上限；
- 注入或索引完整性检查失效。

## 12. 纵向评测与红队

### 12.1 画像质量

- 画像断言精确率、错误晋升率、用户拒绝率；
- 证据覆盖率、场景限定完整率、冲突发现率；
- 陈旧条目率、过期后误用率；
- 用户纠正到生效的成功率和延迟；
- 画像使用对回答质量的净增益，而非画像长度。

### 12.2 教学质量

- 无提示检索、延迟保持和迁移表现；
- 知识状态的校准和错误掌握判定率；
- 学习路径调整后真实学习增益；
- 流畅感被误判为掌握的比例；
- 裸 Qwen、固定课程、只看点击行为、证据化学习路径的消融比较。

### 12.3 隐私与控制

- 跨租户召回、缓存、队列和导出泄漏率：必须为零；
- 删除在活动存储、索引、缓存、同步副本和备份的 SLA；
- 撤权后继续使用率：必须为零；
- 用户是否能找到、理解和完成查看/纠正/冻结/删除/导出；
- 最小切片相对完整画像的内容减少率与任务效用。

### 12.4 对抗样本

- 角色扮演、反讽、一次性情绪、第三方故事被错误晋升；
- 同一偏好在赶任务和研究讨论中相反；
- 用户纠正后旧缓存继续影响回答；
- 删除源对话后派生画像、embedding 仍存在；
- 恶意文档要求导出画像或改变授权；
- 两个账户上传同名材料或使用同一设备；
- 共享项目成员试图召回他人个人画像；
- 利用批量反馈污染知识状态或学习路径。

## 13. 对后续规划的硬约束

### 智能体编排

- 观察抽取、敏感分类、候选生成、晋升、知识状态更新、切片编译、使用审计和删除级联是独立节点；
- 节点交换版本化 Schema，不传自然语言画像摘要充当状态；
- Qwen 不能自行晋升、解除冻结、恢复删除或扩大授权；
- 画像反馈与回答反馈分流，避免“回答不好”直接改写人格画像。

### 前端

- 注册登录后才能进入功能页面；
- 提供画像与记忆中心、学习证据视图、逐条控制、版本差异、切片使用说明和删除进度；
- 普通回答不机械宣称“根据你的画像”，但用户必须能主动查看本次用了什么；
- 对候选、稳定、冲突、过期、冻结和删除中状态使用不同且可理解的提示。

### 技术架构

- 领域主键、出处图、授权和删除状态由平台掌握，不绑定 Qwen 或某个向量库；
- 本地优先保存完整私人数据，云端只接收一次性最小切片；
- Conda `agent` 只用于本地开发；生产的手动分进程、统一 CLI、Docker 和 Podman 使用同一 Schema 迁移、密钥、删除作业和健康检查；
- 跨设备同步不能绕过 tombstone、授权版本和冲突规则。

### 教学

- 学习使命是所有教学记录和路径的目的锚点；
- 课程短小、单次获得一个可观察胜利；
- 可信资源支持知识获得，检索/间隔/交错和即时反馈建立长期储存强度；
- 最近发展区只由可追溯学习证据更新。

## 14. 采用、调整与舍弃

### 直接采用

- `cognitive-profile` 的“有信号才采集、薄而准确、原话—观察—影响、场景化偏好、用户纠正优先、不能替用户说、用户可删除”；
- `teach` 的学习使命、可信资源、短课、最近发展区、检索、间隔、交错、即时反馈和学习记录；
- W3C PROV 的派生与修订出处；
- PIPL/GDPR/NIST 的目的限定、最小化、准确性、保存限制、用户控制和风险治理原则；
- xAPI/Caliper 的结构化学习事件思想。

### 调整采用

- 将 Markdown 整体画像改为原子观察、候选和版本化画像断言；
- 将人工“低/中/高把握”改为多维证据和显式状态，保留可解释原因；
- 将定时复盘改为“信号触发 + 到期复核 + 使用效果反馈”；
- 将学习事件标准用于记录活动，不把完成事件当掌握；
- 将智能体长期记忆论文的分类用于启发，不照搬其无账户、无删除和无授权的实验设置。

### 明确舍弃

- 自动总结整段对话并覆盖用户画像；
- 一张 `memory` 表容纳所有长期状态；
- 从一次情绪、反讽、角色扮演或点击行为生成稳定标签；
- MBTI、人格、心理健康和敏感身份的主动推断；
- 用不可解释 confidence 分数决定高影响个性化；
- 向 Qwen 上传完整画像或让模型直接查询全库；
- 跨用户共享 embedding、缓存或画像去重；
- 删除界面记录但保留派生画像、向量和缓存；
- 删除或授权服务失败时继续个性化；
- 用“越来越懂用户”的主观感受替代纵向基线与消融。

## 15. 边界场景与验收标准

### 场景裁决

1. 用户说“我数学很差”：形成自述观察；不等于知识状态，需任务证据。
2. 用户在赶截止日期时要求短答、研究讨论时要求完整依据：形成两条场景偏好，不合并成“喜欢短答”。
3. 用户角色扮演“我是某疾病患者”：不写入健康画像。
4. 用户显式说“以后都用 SI 单位”：可形成置顶偏好；仍需场景范围和修改入口。
5. 用户删除一段对话：由该对话唯一支持的画像失效；其他独立证据仍可支持新版本，但必须可解释。
6. 用户退出共享项目：项目访问被撤回，其个人画像从未进入共享空间。
7. 用户关闭长期记忆：系统进入 `SESSION_ONLY`，不得用 Qwen 参数记忆伪装个性化。

### 实施验收

1. 每类对象拥有独立 Schema、状态和作用域；
2. 同一观察能追踪到来源、抽取运行、候选和画像版本；
3. 候选无法绕过授权、敏感、冲突和用户确认门；
4. 课程浏览不会更新知识掌握，延迟检索与迁移能更新；
5. 每次个性化都有可查看的最小记忆切片和使用凭证；
6. 撤权后所有新运行不再使用相关数据；
7. 删除能覆盖主记录、派生物、向量、缓存、队列、同步副本和备份计划；
8. 两个账户同名同内容数据不存在召回或侧信道泄漏；
9. 画像冲突、过期或抽取失败时可退回通用回答；
10. 纵向评测证明个性化净增益，同时错误晋升、敏感推断和跨租户泄漏满足质量门。

## 16. 研究置信度和后续复核

- **高置信度**：对象分层、原始证据与派生判断分离、最小记忆切片、用户逐条控制、删除级联、逐账户隔离和失败闭锁是必要架构。
- **高置信度**：浏览完成和即时流畅感不能等同长期掌握；学习记录必须包含检索、反馈、延迟或迁移证据。
- **中高置信度**：xAPI/Caliper、W3C PROV、智能体记忆研究可为事件和出处结构提供参考，但项目需自建权限、授权和删除协议。
- **需法务复核**：地区适用、未成年人、敏感个人信息、跨境、法定保留、自动化决策和删除例外。
- **需技术票据核验**：本地加密、跨设备同步、向量删除、备份清理、密钥轮换及选定数据库的 RLS/ACL 能力。
- **需持续实验**：不同画像维度的晋升证据数量、复核周期、学习状态阈值和切片预算，必须由纵向评测确定，不在本研究中凭经验写死。
