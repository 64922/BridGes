# 比赛约束与参考项目的可迁移设计研究

核验日期：2026-07-24

## 1. 研究问题与结论

本研究回答：

> 比赛要求和十份灵感材料共同限定了哪些必须能力、加分能力、质量门槛、可迁移架构模式、潜在冲突与差异化机会？哪些设计应直接采用、调整采用或明确舍弃，才能形成一套一致而非堆砌的项目原则？

结论是：项目不应被定义成“带画像的 RAG 聊天机器人”，也不应把十个参考项目分别变成十个功能模块。最一致的产品内核是：

> **以可追溯证据约束科学内容，以证据化画像决定解释和表达方式，以类型化工作流生产、校验并持续修正多模态科学产物。**

所有参考模式只允许进入以下四条主链之一：

1. **理解用户**：候选画像提取、授权确认、最小切片召回、反馈校准；
2. **理解科学问题**：材料接入、证据检索、证据强度判断、矛盾与不确定性呈现；
3. **生成科学产物**：个性化解释、写作、图表、动画、语音等；
4. **保证长期可信**：事实与风险校验、运行审计、版本化评测、画像或产物修正。

不能进入这四条主链、不能提高评分项、又会扩大风险面的参考能力，应当舍弃。

## 3. 比赛约束

### 3.1 必须能力

| 必须能力 | 具体含义 | 规划时必须留下的可验证产物 |
| --- | --- | --- |
| 数字分身与人味表达融合 | 画像不能是独立设置页，人味不能是回答末端的滤镜；两者必须共同影响科学理解和表达 | 同一用户跨轮次的画像证据、调用记录、回答差异和修正历史 |
| 长期陪伴与画像更新 | 记录基本情况、目标、兴趣、表达习惯、重要经历、当前问题和授权范围，并说明何时记录、更新和调用 | 候选画像、稳定画像、来源证据、置信度、适用场景、授权、版本和删除记录 |
| 科学内容转化 | 将专业内容转为适合不同受众和难度的文本、语音、图像、视频或交互体验 | 受众模型、解释策略、事实锚点和多模态产物 |
| 中文自然表达 | 在科普文案、课程讲稿、科研汇报、论文写作等场景减少模板腔、机翻感和不合场景的“AI 味” | 场景化风格规则、改写前后对照、人评与盲测 |
| 科学事实准确 | 不因个性化、简化或润色改变数字、单位、条件、引用关系和结论强度 | claim 级证据绑定、事实一致性检查、引用与不确定性展示 |
| 多轮反馈改进 | 用户反馈必须能修正当前回答，也能在授权条件下影响后续表现 | 反馈分类、局部修订、画像晋升/降级规则和纵向评测 |
| Qwen 基座 | 推理与生成必须基于 Qwen 系列模型 | 带版本的模型路由、调用日志、可复现配置与降级记录 |
| 完整工程交付 | 智能体、技能、多模态、校验、反馈、稳定性、交互入口、代码和流程都要完整 | 架构、状态模型、测试矩阵、可观察性、部署和复现实验说明 |

这里的“作品演示”不进入开发路线；但评分中的“交互入口与交付完整度”仍是产品开发要求，因此前端工作台、可审查中间产物、运行状态和错误恢复仍是必须规划的工程能力。

### 3.2 加分能力

1. **画像闭环**：记录画像 → 任务内最小召回 → 个性化生成 → 用户反馈 → 修正回答或画像，并展示多轮改进；
2. **可复现低幻觉**：不仅“有 RAG”，还需证明检索覆盖、引用支持、结论强度校准、冲突处理和失败闭锁有效；
3. **风险信号识别**：将安全、证据不足、领域高风险和画像越权分别识别，避免用统一免责声明代替具体控制；
4. **开源基线对比**：与裸 Qwen、仅 RAG、仅画像、Humanizer-zh 类规则改写等基线比较，并做画像、RAG、人味复查、事实校验的消融实验；
5. **多模态闭环**：图片、公式、图表、语音、动画或交互式 HTML 不只可生成，还能保留来源、经过校验、失败可修复；
6. **用户可控性**：能查看本次回答使用了哪些画像和证据，能冻结、删除、回滚、导出；
7. **长期成长证据**：能以纵向任务而非单轮偏好打分证明“越来越懂用户”和“真的帮助理解或表达”。

### 3.3 评分质量门槛

比赛权重给出的优先顺序是：科学价值 40%，技术深度 30%，应用潜力 30%。因此质量门槛必须按下面顺序闭锁，而不能把视觉效果或智能体数量放在科学可靠性之前。

| 门槛 | 对应评分点 | 最低通过条件 | 失败行为 |
| --- | --- | --- | --- |
| G1 事实与证据门 | 事实准确性 15 分 | 关键 claim 有证据；数字、单位、条件、引用和因果强度未越界 | 阻止高置信发布，展示缺口并请求补充或降级措辞 |
| G2 解释与受众门 | 清晰度 15 分 | 解释难度、先备知识、例子和媒体形态与用户和场景相符 | 改用更适合的解释策略，不篡改事实 |
| G3 主题一致门 | 完整性与一致性 10 分 | 产品、页面和智能体均服务“科学成长循环” | 不纳入无法回到总闭环的孤立功能 |
| G4 编排与技能门 | 模型/智能体/技能 10 分 | 每步输入输出、权限、重试、终止和质量门可审计 | 禁止无界群聊和无法复现的自由转交 |
| G5 多模态门 | 多模态 10 分 | 媒体输入有来源，生成物可运行或可查看，内容与科学 claim 一致 | 保留原始输入；失败产物不冒充成功 |
| G6 稳定性门 | 校验/反馈/稳定性 10 分 | 有确定性检查、模型审查、人工确认、恢复和回归测试 | 高风险写入和状态更新失败闭锁 |
| G7 真实价值门 | 场景价值 10 分 | 覆盖真实学习与表达任务，并有完成质量或学习增益指标 | 不以功能数量代替任务结果 |
| G8 产品交付门 | 入口与交付 10 分 | 全局科学伙伴、科学项目空间和结构化工作台形成完整入口 | 不用单一聊天窗隐藏复杂状态 |
| G9 复现门 | 代码/结果/流程 10 分 | 固定数据集、模型版本、提示词、Schema、阈值、随机种子和运行记录 | 不接受只展示精选成功案例 |

## 4. 十份参考材料的可迁移模式

### 4.1 AutoAgent：从自然语言到受验证工作流

可迁移模式：

- 用结构化中间表示连接“用户意图”和“可执行工作流”；
- 组件注册表统一管理智能体、工具和工作流；
- 阶段式生成、Schema 验证、有限重试和明确终止信号；
- 运行环境隔离。

调整点：

- 本项目采用 JSON/Pydantic 一类易被前后端共同消费的类型化协议即可，不因参考项目使用 XML 就照搬 XML；
- “元智能体自动写代码并热加载”会扩大供应链、安全和复现风险，只能作为隔离的高级扩展实验，不能进入科学回答主链；
- API Key 绝不能写入动态工具代码。

### 4.2 Claude Code：生命周期 Hook 与审查—验证分离

可迁移模式：

- 在任务开始、模型调用、工具调用前后、状态写入、产物完成等节点挂接 Hook；
- 将候选问题的发现与真伪验证分离；
- 专业智能体只获得最小工具白名单；
- 同一阶段可并行做独立检索、审查或评测。

调整点：

- 完成条件必须由结构化状态和质量门共同决定，不能仅凭模型输出“DONE”；
- Stop-loop 只允许有限次、可观测、可取消的恢复循环；
- 人工确认只放在授权、证据冲突、高风险发布、画像晋升等真正需要用户判断的节点。

### 4.3 cognitive-profile：薄而准确的长期画像

可迁移模式：

- 有信号才采集，不为“显得懂用户”而强行画像；
- 区分用户原话、观察、对未来回答的影响和把握度；
- 用户纠错优先于自述和模型推断；
- 按场景拆分可能相反的偏好；
- 删除、暂停、冻结与不能替用户说的边界是核心功能。

调整点：

- Markdown 画像升级为加密、版本化、可查询的证据记录；
- 候选画像进入稳定画像需满足授权与证据规则；
- 普通回答不暴露内部评分，但画像中心必须能用日常语言解释记录和调用。

### 4.4 Humanizer-zh：可操作的中文痕迹复查

可迁移模式：

- 将模板腔拆成具体、可诊断、可举例的模式；
- 粗筛与精查分层；
- 用直接性、节奏、信任度、真实性、精炼度等连续维度做评测；
- 区分“去除痕迹”和“形成真实、合场景表达”。

调整点：

- 规则只能是候选诊断器，不能成为机械替换器；
- 三段式、连接词、破折号等并非天然错误，必须结合体裁、用户偏好和语义功能；
- “像不像 AI”不是主目标，事实、清晰、受众适配和用户声音优先。

### 4.5 LlamaIndex：可组合、可追溯的知识流水线

可迁移模式：

- 文档 → 节点 → 变换 → 索引 → 检索 → 后处理 → 合成的分层；
- 元数据在嵌入与推理阶段采用不同暴露策略；
- 保留来源、父子、前后、字符偏移等结构关系；
- 摄入缓存、文档哈希、增量索引、多查询融合、重排与引用；
- 存储、检索器和合成策略可插拔。

调整点：

- 不照搬“大而全 RAG 框架”作为业务架构；只吸收接口与数据模型；
- 科学检索必须增加来源层级、发布时间、证据类型、研究设计、结论强度和冲突关系；
- 检索相关不等于证据支持，最终以 claim—evidence 支持关系而非相似度决定可发布性。

### 4.6 ManimCat：可视化先设计、后生成、再验证

可迁移模式：

- 将教学意图与代码生成分开，中间产生可审查 storyboard；
- 静态图、动画和交互式 HTML 按教学目标路由，而不是全部动画化；
- API 白名单、静态检查、沙箱渲染、错误驱动最小修补；
- 常见高价值场景使用专家模板，开放问题使用生成能力。

调整点：

- 渲染检查失败不能继续把产物当成成功结果；
- 代码修补有严格轮次上限，且每次只做最小 patch；
- 视觉吸引力不能覆盖公式、尺度、单位、坐标、标签或因果关系错误。

### 4.7 nanobot：小内核、状态机与通道解耦

可迁移模式：

- 会话编排和模型工具循环分层；
- Turn 使用显式状态机，可恢复、可测试、可追踪；
- 消息总线解耦界面通道和智能体内核；
- 组合式上下文构建与工具注册；
- 每个 turn 锁定不可变的模型运行时。

调整点：

- 文件式会话和 Markdown 长期记忆适合原型，不满足成熟产品的加密、细粒度授权、可删除和并发一致性；
- 自动“Dream”总结只能生成候选记忆，不能直接覆盖稳定画像；
- “轻量”应体现为深模块和窄接口，而不是缺少治理与校验能力。

### 4.8 nuwa-skill：材料蒸馏的证据纪律

可迁移模式：

- 本地材料优先，先找证据缺口，再定向补充一手来源；
- 多维采集、阶段检查点、矛盾保留、来源等级与独立验证；
- 提炼结果必须具有跨场景复现、对新问题的生成力和区别性；
- 诚实边界必须与能力一起交付。

调整点：

- 不构建“名人数字替身”，而是把方法迁移到用户的表达偏好和科学认知策略；
- 禁止未经授权的人格模仿与心理推断；
- “像某个人”不能取代科学证据或用户自己的声音。

### 4.9 百炼 Qwen 能力路由：按能力与风险选择模型

可迁移模式：

- 对话/推理、低风险结构化任务、视觉、OCR、ASR、TTS、Embedding、Rerank、评测裁判分开路由；
- 同一任务运行期间锁定模型版本与参数；
- 记录实际路由、usage、延迟、失败和降级；
- Embedding 模型或维度变化必须重建索引；
- 高风险状态写入、评测和事实门控禁止静默降级。

调整点：

- 模型名、价格、限流和接口能力都是带日期的部署事实，进入技术方案前必须再次查询官方文档；
- 本地材料中的具体路由是候选方案，不是不可更改的架构常量；
- 禁用会绕过本项目证据协议、隐私边界和审计链的供应商内置工具。

### 4.10 scientific-humanization：事实锁定与措辞强度校准

可迁移模式：

- 改写前冻结数字、单位、对象、条件、术语、图表与引用关系；
- 先修论证顺序，再修句子；
- 将证据类型映射到允许的结论措辞；
- 按论文、课程讲稿、科研汇报、科普等场景调整表达；
- 将改写正文与仍需确认的事实风险分开。

调整点：

- 通用证据—措辞规则进入公共层，具体领域规则进入领域包；
- 事实一致性既要有确定性 diff，也要有 claim 级语义校验；
- “有人味”不得放大证据强度、删掉必要限制或用故事感掩盖不确定性。

## 5. 决策矩阵

“直接采用”表示方法可原样成为项目原则；“调整采用”表示只吸收机制并重建其数据、权限或质量边界；“明确舍弃”表示不进入主产品。

| 来源 | 设计项 | 决策 | 项目化落点 | 舍弃或限制的部分 |
| --- | --- | --- | --- | --- |
| AutoAgent | 结构化中间表示、Schema 校验、有限重试、组件注册表 | 直接采用 | 工作流定义、智能体/工具注册、类型化产物 | 不绑定 XML |
| AutoAgent | 元智能体动态写代码、热加载并自我演进 | 明确舍弃 | 无 | 科学主链不允许未审查代码进入运行时 |
| Claude Code | 生命周期 Hook、工具前后拦截、审计事件 | 直接采用 | 安全、证据、画像、运行日志的横切控制 | Hook 不替代核心状态机 |
| Claude Code | 审查—验证分离、多视角并行 | 直接采用 | 事实候选审查、风险复核、离线评测 | 不为增加“智能体数量”而冗余运行 |
| Claude Code | 反复喂相同提示直至自报完成 | 明确舍弃 | 无 | 改为结构化完成条件和有限恢复 |
| cognitive-profile | 有信号才采集、纠错优先、场景化偏好、删除即删除 | 直接采用 | 证据化画像规则 | 无 |
| cognitive-profile | Markdown 薄画像 | 调整采用 | 加密记录、候选/稳定分层、版本与授权 | 不以自由文本作为唯一事实源 |
| Humanizer-zh | 模式库、前后示例、粗筛/精查、量化评分 | 调整采用 | 中文表达诊断器和评测集 | 规则不直接机械改写 |
| Humanizer-zh | 以规避 AI 检测为目标 | 明确舍弃 | 无 | 目标改为清晰、自然、合场景且事实不变 |
| LlamaIndex | 分层 RAG、节点关系、增量索引、多路检索与重排 | 直接采用 | 可信知识流水线的接口和数据契约 | 不要求绑定某一框架实现 |
| LlamaIndex | 只凭相似度让生成模型合成答案 | 明确舍弃 | 无 | 必须增加来源层级、claim 支持和冲突门 |
| ManimCat | 教学设计 → 代码生成 → 静态检查 → 沙箱渲染 → 最小修补 | 直接采用 | 可视化实验室 | 无 |
| ManimCat | 检查失败仍继续渲染或交付 | 明确舍弃 | 无 | 未通过门槛的产物只能标为失败草稿 |
| ManimCat | 所有主题都生成动画 | 明确舍弃 | 无 | 按教学目标选择图、动画或交互 |
| nanobot | 小内核、状态机、消息通道、组合上下文 | 直接采用 | 编排运行时基础 | 无 |
| nanobot | JSONL 会话 + Markdown 长期记忆作为正式存储 | 调整采用 | 可导出格式可保留，正式存储改为加密数据库 | 不满足治理要求时不得充当权威画像库 |
| nanobot | 后台自动总结直接写长期记忆 | 明确舍弃 | 无 | 只能写候选画像，需证据和授权晋升 |

| nuwa-skill | 名人式角色扮演和替用户发声 | 明确舍弃 | 无 | 与证据化画像、人格边界冲突 |

| scientific-humanization | 事实锚点、论证优先、证据—措辞映射、场景改写 | 直接采用 | 科学表达工坊与事实门 | 无 |
| scientific-humanization | 为自然感删去关键限制或不确定性 | 明确舍弃 | 无 | 事实边界高于风格目标 |

## 6. 潜在冲突与裁决

| 冲突 | 风险 | 裁决 |
| --- | --- | --- |
| 个性化 vs 科学事实 | 为迎合用户而选择性呈现或加强结论 | 画像只能改变解释策略、信息顺序、例子和语气，不能改变事实锚点和证据强度 |
| 人味改写 vs 证据边界 | 去模板腔时删掉限定词、样本条件或不确定性 | 先冻结 claim 与事实字段，改写后做确定性和语义双重一致性校验 |
| 长期记忆 vs 隐私/可撤回 | 自动总结将敏感、临时或错误推断写入长期画像 | 模型只能提出候选；稳定画像需授权/重复证据；删除是真删除并产生最小审计记录 |
| 动态自治 vs 可复现 | 自生成工具、自由转交、无限重试使运行不可审计 | 使用类型化 DAG/状态机、组件白名单、固定上限和结构化完成条件 |
| 轻量内核 vs 成熟功能 | 把“成熟”误解为堆框架，或把“轻量”误解为缺能力 | 保持编排内核小而稳定，将领域包、技能、多模态和评测作为边缘深模块 |
| 通用 RAG vs 学科差异 | 相同来源等级与结论规则误用于不同学科 | 公共证据协议 + 独立领域包；领域包定义来源、单位、公式、证据等级和误区 |
| 多智能体并行 vs 成本与不一致 | 多个智能体给出互相冲突的隐式结论 | 仅对可独立工作并行；通过共享结构化产物汇合；冲突显式保留并进入裁决节点 |
| 模板稳定性 vs 个性化与创造性 | 专家模板让所有回答同质化 | 模板只固定事实结构、检查项和媒体约束，不固定用户最终措辞 |
| 云端 Qwen 能力 vs 本地优先 | 私人材料或整份画像被无差别上传 | 云端只接收任务所需最小切片；原文、长期画像和索引默认本地加密 |
| 模型裁判 vs 评测可信度 | Qwen 既生成又自评，结果偏向自身 | 规则指标优先，固定版本裁判只做补充，并加入专家、人类盲测和对照实验 |
| 视觉表现 vs 科学正确 | 动画好看但图形、单位、比例或因果错误 | 视觉代码、渲染成功与科学内容分别过门；任何一门失败都不能发布为完成品 |

## 7. 差异化机会

### 7.1 证据约束的人味表达

现有“去 AI 味”方案多关注语言表面，RAG 方案多关注检索。项目可将两者合成一项更强的能力：每次改写都携带不可修改的事实锚点和可调节的表达变量，最终展示“哪些事实保持不变、哪些表达因用户和场景而变化”。

### 7.2 可解释的长期个性化增益

不是只宣称“越用越懂你”，而是为每次个性化建立因果链：

> 使用了哪条画像 → 改变了哪个解释或表达决策 → 用户是否接受 → 画像置信度怎样变化。

这使画像更新准确性、帮助效果和越权率都可以测量。

### 7.3 claim—evidence—wording 三层科学图谱

在普通向量检索之上增加三层关联：

- claim：系统准备表达的科学判断；
- evidence：支持、反驳或限制该判断的材料；
- wording：在当前证据强度下允许使用的措辞。

它能同时服务低幻觉、引用透明、冲突检测和自然表达，是比“加一个事实核查智能体”更深的结构差异。

### 7.4 从一次回答到可演进的科学项目

科学项目空间保留问题、材料、证据、解释版本、多模态产物、反馈和运行轨迹，使用户的学习或创作能跨会话演进。全局科学伙伴只负责入口与协调，复杂内容在工作台中可见、可审查。

### 7.5 面向科学任务的多模态验证

不是“模型支持图片/音频/视频”就算多模态，而是：

- 输入媒体保留来源与原件；
- OCR/ASR 是可纠正的中间证据；
- 图表、动画和 HTML 有教学设计稿；
- 代码在沙箱运行；
- 公式、坐标、单位、图例和叙事 claim 分别校验。

### 7.6 领域包驱动的跨学科扩展

公共平台保持统一的证据、画像、编排和评测协议；物理、化学、生物、天文、计算机等领域包只增加本体、来源、工具、规则和评测集。这样既能跨学科，又不会用一个通用提示词冒充专业性。

### 7.7 评测即产品能力

把纵向用户任务、事实支持率、措辞校准、引用正确率、画像误写率、画像调用增益、人味盲测、工具成功率和恢复率做成版本化评测资产。评测结果不仅用于比赛，也反向控制模型路由、规则阈值和发布门槛。

## 8. 统一项目原则

十份材料最终只保留为八条项目原则：

1. **证据先于表达**：任何个性化、简化和人味改写都在事实锚点与证据强度之后发生；
2. **用户控制高于“懂用户”**：少记、准记、按场景记，最小调用，候选与稳定分层，删除与回滚可验证；
3. **工作流先于自由自治**：监督器编译类型化流程，专业智能体交换 Schema 产物，不靠自由群聊传递事实；
4. **设计、生成、审查、验证分离**：复杂科学产物先形成可审查设计，再生成；候选问题由独立步骤验证；
5. **确定性规则优先，模型判断补充**：数字、单位、Schema、权限、来源和运行状态先用规则检查，语义与表达再由模型审查；
6. **公共平台 + 领域包**：统一证据、画像、编排和评测协议，学科差异在领域包中显式建模；
7. **本地优先、最小上云、失败可见**：私人数据本地加密，云端只得最小上下文；高风险流程失败闭锁且保留可恢复状态；
8. **每项能力都必须可复现地证明价值**：基线、消融、纵向评测、专家评审与用户盲测共同回答“更准、更懂、更自然、更稳定了吗”。

这八条原则共同排除了三种功能堆砌：

- 用更多智能体数量代替工作流深度；
- 用更多媒体类型代替科学可验证性；
- 用更长画像代替个性化实际增益。

## 9. 对后续规划任务的约束

后续产品、架构、前端和技术选型必须满足：

1. 任一功能都能标注它属于“理解用户、理解科学问题、生成科学产物、保证长期可信”中的哪一条主链；
2. 任一智能体都有明确输入、输出、工具、权限、终止条件和质量门；
3. 任一画像字段都有来源、场景、授权、置信度、版本和删除语义；
4. 任一科学 claim 能连接到支持/反驳/限制证据，并按证据强度约束措辞；
5. 任一多模态产物都有设计中间件、来源、验证和失败状态；
6. 任一 Qwen 路由都有版本、区域、参数、降级和复现记录；
7. 任一“更懂用户”“更有人味”“更低幻觉”的主张都有基线、指标和可重复实验。
