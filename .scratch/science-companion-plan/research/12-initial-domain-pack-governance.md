# 首批科学领域包与专家治理研究

核验日期：2026-07-24

## 1. 总体结论

首批领域包不应是八套提示词，也不应是八个复制公共检索、账户、工作流和安全逻辑的“小应用”。它们应当是八组**可签名、可机器校验、可迁移、可撤销的学科规则与评测资产**：公共平台负责身份、权限、来源快照、证据图、运行审计、失败闭锁和发布状态；领域包只回答该学科特有的“什么问题算同一问题、什么来源对该问题有权威、什么证据足以支持何种措辞、哪些确定性规则必须过门、哪些冲突必须交给人”。

八类包的共同发布原则是：

1. **包不能降低平台下限。** 平台权限、安全、租户隔离、来源完整性、事实锁和高风险公共策略优先于包内规则；包只能收紧，不能放宽。
2. **来源名录不是领域包。** 每个包必须同时交付问题分类、证据映射、状态解析、确定性校验、冲突规则、措辞约束、人工门和评测夹具；仅列数据库或机构名称不具备可执行性。
3. **证据强度按问题类型解释。** 数学证明看形式链和假设，测量看计量溯源与不确定度，生命科学看设计与偏倚，医学还要增加指南和风险门，地球/气候看观测产品与处理链，天文看时标、参考系和历表，软件文档看规范/版本/可复现运行，标准数据集看标识、许可、模式和版本关系。不存在一套跨八类通用证据金字塔。
4. **确定性程序先于模型判断。** Schema、签名、哈希、版本范围、单位量纲、公式语法、标识符、时间尺度、坐标系、数据模式、依赖闭包等先由程序检查；模型只补充语义分类、解释和候选冲突，不能把 `unknown` 改成“已验证”。
5. **双人复核是职责分离，不是两个同质模型投票。** 每次正式发布至少由内容维护者和独立复核者完成不同检查；高风险医学包还需相应资质的临床/循证专家承担最终人工门。签名表示“谁对哪一版本、哪一范围和哪组评测负责”，不表示内容永久正确。
6. **版本变化会使旧判定失效，但不抹除历史。** 包升级、来源勘误、撤回、数据产品重处理、标准取代、术语变更或工具验证失败，都应把受影响的 EvidenceAssessment 标为 stale，创建新运行并保留旧链。
7. **工具只注册逻辑能力，不冻结具体实现。** 本文出现的证明检查器、单位库、轨道历表、模式校验器、沙箱执行器等均是候选能力或接口要求；后续技术选型必须通过兼容性、安全性、许可和评测后，才能写入能力注册表。
8. **包的最小可信单元是“规则 + 夹具 + 责任”。** 没有可重放夹具的规则无法证明生效；没有责任人的签名无法处理失效；没有迁移和撤销语义的包无法安全升级。

## 2. 平台公共能力与领域包边界

### 2.1 公共平台必须唯一实现的能力

| 公共能力 | 平台责任 | 领域包不得做的事 |
| --- | --- | --- |
| 账户、租户与项目隔离 | ACL、行级安全、对象归属、缓存与索引命名空间、输出后二次可见性检查 | 自行查询其他租户、用学科理由绕过权限 |
| 来源与内容快照 | Source/Document/Chunk、哈希、许可、抓取时间、解析版本、隔离区 | 直接把实时网页或工具返回当作不可变事实 |
| claim—evidence—wording 协议 | 原子 claim、支持/反驳/限制关系、精确 locator、事实锁、引用渲染 | 自由生成 DOI、页码、引用编号或改变 Claim |
| 生命周期状态机 | `VERIFIED`、`QUALIFIED`、`PARTIAL`、`CONFLICTED`、`STALE_OR_UPDATED`、`QUARANTINED`、`BLOCKED` | 自创更宽松的“基本可用”状态解除闭锁 |
| 工作流与模型运行锁 | 类型化节点、有限重试、工具白名单、模型/参数/提示/降级快照 | 动态写代码热加载、无限自治、静默更换模型 |
| 通用安全下限 | 不可信内容隔离、提示注入防线、最小权限、秘密管理、资源限额、失败闭锁 | 将文档文字视为命令，或在安全服务失败后回退模型记忆 |
| 供应链与发布账本 | 构建来源、依赖锁、摘要、签名、透明记录、撤销、回滚和审计事件 | 包内自签后绕过平台验证，或覆盖历史发布记录 |
| 持续评测框架 | 夹具格式、运行隔离、基线/消融、指标汇总、回归门 | 只报告挑选成功案例，或由生成模型单独自评 |

### 2.2 领域包必须拥有的学科差异

每个包只增加以下内容：学科范围与排除项；问题类型；来源层级与适用范围；来源适配器的规范化映射和状态刷新策略；术语、本体、标识、单位、公式或数据模式规则；多维证据画像到 certainty/wording 的映射；学科冲突、过期和人工门；专用能力接口；正例、反例、边界例与失效例夹具。

领域包可以声明“需要某种逻辑能力”，例如 `formal_proof_check`、`unit_dimension_check`、`sequence_identifier_resolve`、`ephemeris_query`、`schema_validate`，但不能将某个库名、服务名或供应商型号变成领域概念。能力注册表负责把逻辑能力映射到经验证的实现版本，模型运行锁记录一次任务实际使用了什么。

来源注册也必须区分“机构权威”与“内容适用”。标准组织对其正式标准有权威，不代表它发布的新闻页能证明实验 Claim；数据库对 accession、版本和注释状态可能最接近一手记录，不代表数据库注释能替代机制研究；论文作者最了解自己的实验，却不能自行决定研究无偏倚。因而每个 `source_policy` 必须写明权威对象、适用问题、可承担的 evidence role、内容接近度要求、状态检查入口和不可承担的结论。系统按当前问题选择来源，而不是维护一张从高到低的永久网站榜单。

同一来源可在不同问题中处于不同层级。例如 ClinicalTrials.gov 对注册字段与历史版本是直接来源，对治疗效果则只是注册/结果记录入口；JPL Horizons 对特定配置的历表计算是直接工具来源，对天体形成机制不是；软件源码对该提交的实际行为很接近，对标准承诺仍须回到规范。这个“按 Claim 角色授权”的模型必须进入机器规则和夹具，不能只写在专家说明中。

### 2.3 冲突时的固定优先级

```text
平台权限与安全不变量
  > 医学等高风险公共策略
  > 已签名且未撤销的领域包规则
  > 当前项目的来源偏好
  > 用户的表达与教学偏好
```

“用户希望更肯定”“项目更信某个作者”“领域包维护者认为可放宽”都不能越过上层。跨包问题由监督器组合规则，但合成结果采用最严格的风险门和所有相关事实锁；若两个包对同一 claim 的语义或证据要求实质冲突，状态进入 `CONFLICTED`，不得按包优先级静默覆盖。

## 3. 可机器校验的 Manifest、Schema 与迁移

### 3.1 Manifest 最小契约

以下是字段语义示例，不冻结 YAML、JSON 或具体校验库：

```yaml
manifest_schema: "domain-pack-manifest/v1"
id: "astronomy.observation"
version: "1.3.0"
platform_api: ">=1.2,<2.0"
pack_api: "domain-pack/v1"
languages: ["zh-CN", "en"]
disciplines: ["astronomy"]
risk_tiers: ["general_education", "research_support"]
question_types: []
source_policies: []
source_adapters: []
status_resolvers: []
claim_schemas: []
evidence_mappings: []
wording_policies: []
ontologies: []
validators: []
tools: []
conflict_rules: []
evaluation_sets: []
dependencies: []
migrations: []
maintainers: []
reviewers: []
build_provenance: {}
signatures: []
```

机器校验至少检查：`id` 全局唯一且不可在同一主版本中改义；版本满足语义版本格式；`platform_api` 与运行平台相交；所有文件路径均在包根目录内且无路径穿越；每项规则、工具、来源、夹具都有稳定 ID；引用的 ID 必须存在；依赖图无环且满足版本范围；同一问题类型至少有来源策略、证据映射、措辞策略和夹具；高风险类型必须声明人工门；哈希覆盖所有被发布文件；签名覆盖规范化 Manifest、依赖锁和构建出处摘要。

### 3.2 规则 Schema

规则不能只有自然语言说明。每条可执行规则至少包含：

- `rule_id`、`rule_schema_version`、`applies_to`、`priority`；
- 明确输入类型、必填字段和 `unknown` 处理；
- 条件、输出、拒绝码与用户可理解说明；
- `effective_from`、可选 `expires_at`、替代规则关系；
- 规则依据的来源版本和定位；
- 对应正例、反例、边界例、恶意例夹具；
- 自动、模型辅助或必须人工的执行类别；
- 维护者、复核者、最后复核时间和变更理由。

所有枚举采用“未知值拒绝或保留 unknown”的开放世界策略，不能把 API 缺字段解释成 `false`。自然语言说明用于专家审查，结构字段用于程序执行；两者不一致时发布失败。

### 3.3 依赖、兼容与迁移

- **patch**：修正文案、定位或不改变判定语义的实现缺陷；必须运行本包全量确定性夹具和受影响集。
- **minor**：增加兼容来源、问题类型、术语或校验能力，不改变既有有效输入的判定；必须运行依赖闭包回归和下游组合测试。
- **major**：改变 Claim Schema、证据等级、措辞映射、默认状态或删除接口；必须提供显式迁移、双版本对照和回滚窗口。

依赖声明必须区分：平台 API、其他领域包、共享本体/标准资产、逻辑能力与评测资产。运行时只解析锁文件中的确定版本；范围依赖仅用于求解，求解结果写入不可变锁。可选依赖必须给出“缺失时降级到何状态”，不得静默跳过质量门。

迁移是纯函数式、可重放的 `old_record -> new_record + migration_report`。它不能删除旧 Assessment、签名或 provenance；不确定映射必须标 `needs_review`。迁移前后运行同一金样集并输出判定差异，任何高风险规则放宽、旧 `BLOCKED` 变可发布或关键措辞增强都需独立人工批准。

## 4. 专家与发布治理

### 4.1 双人复核、资质与利益冲突

正式版本至少包含两个独立角色：

1. **内容维护者**：提出来源、规则、Schema、迁移和夹具，提交逐项依据与变更影响；
2. **独立复核者**：不得仅复述维护者说明，必须重跑夹具、抽查来源定位、检查冲突/过期规则和安全下限，签署接受或拒绝意见。

同一人不得在同一版本同时承担两种签名。复核者需具备与包范围匹配的可核验经历，例如相关学位、研究/工程实践、标准组织工作或公开专业成果；平台保存资质类型、核验者、有效期和适用范围，不公开不必要的身份证件。医学高风险教育包的临床诊断/治疗规则必须由相应执业或循证方法资质者至少一人终审；形式证明包的形式化规则需有对应证明助理或逻辑系统实践；数据/软件包需有版本、标准或可复现工程经验。

每名参与者每版声明利益冲突：雇佣、资助、顾问、持股、专利、作者/维护者关系、与被评价产品或数据集的竞争关系。存在直接利益不自动否定专业知识，但不能作为唯一复核人；重大未披露冲突触发签名撤销、影响分析和重新复核。声明本身也版本化，不能用一句“无冲突”永久覆盖。

### 4.2 签名发布与供应链

发布流水线应产生：

- 规范化 Manifest、内容树摘要、依赖锁和夹具摘要；
- 构建环境、源码提交、构建步骤和产物摘要的 provenance；
- 维护者与复核者分别对待发布摘要签名；
- 平台发布服务在验证双签、资质、利益冲突、兼容性和评测后追加发行签名；
- 可查询的透明发布记录、时间戳、撤销和取代关系。

[The Update Framework（TUF）元数据](https://theupdateframework.io/docs/metadata/)提供角色分离、版本、过期和目标摘要的可迁移思路；[Sigstore bundle](https://docs.sigstore.dev/about/bundle/)提供将签名验证所需材料装入可验证 bundle 的思路；[SLSA provenance v1.2](https://slsa.dev/spec/v1.2/provenance)提供构建出处语义。项目应采用这些安全目标和数据语义，但是否直接使用相应实现由后续技术选型与离线部署约束决定。

第三方包默认不可信：先进入隔离仓，验证摘要、签名、来源、许可、依赖、恶意内容与权限声明，再运行沙箱夹具。包不得携带任意安装脚本、秘密、网络凭据或运行时自更新器；工具依赖只通过能力注册表解析。依赖或签名服务不可用时保持已验证旧版并标记状态，不允许下载“差不多”的替代包。

### 4.3 变更、失效、撤销与责任追踪

变更请求必须列出：动机、一手依据、受影响问题类型、规则差异、数据迁移、评测差异、安全影响、回滚方法、责任人。状态刷新器发现来源勘误/撤回、标准替代、数据重处理、接口语义变化、专家资质失效、签名密钥泄漏、严重评测回归或供应链异常时，创建失效事件并计算受影响的包版本、运行、Claim、Evidence 和 Wording。

响应级别：

- **收紧/隔离**：签名无效、恶意依赖、跨租户或高风险安全问题，立即停止新运行并撤销；
- **暂停高置信发布**：关键来源状态未知、重大规则争议、医学指南变化，进入 `STALE_OR_UPDATED` 或 `BLOCKED`；
- **计划更新**：非实质性勘误、兼容接口新增，保留旧版并在到期前发布修订；
- **历史保留**：撤销只改变可用性，不能删除旧产物、评测或责任链。

每次发布、安装、运行、人工 override、撤销和迁移都记录 actor、角色、包摘要、输入/输出摘要、时间、理由和关联事件。责任追踪回答“谁在什么资质和利益状态下，基于哪些来源与夹具，批准了哪条规则；哪些用户产物受其影响”，而不是用签名替代科学正确性。

### 4.4 共同运行状态与人工门分级

包的治理状态与一次科学回答的验证状态必须分开。包本身至少经历 `DRAFT`、`IN_REVIEW`、`SIGNED`、`ACTIVE`、`DEPRECATED`、`SUSPENDED`、`REVOKED` 和 `EXPIRED`：草案不能进入生产；已签名但尚未通过平台发行门的包不能激活；弃用包允许锁定的旧项目在过渡期重放但不得成为新项目默认；暂停用于可恢复的状态未知或评测回归；撤销用于签名、供应链、安全或严重科学缺陷；过期表示复核时限已到而非内容必然错误。状态改变必须来自平台状态机和授权角色，包内文件不能把自己重新设为有效。

人工门分为四级：

| 等级 | 触发条件 | 人工责任 | 自动化边界 |
| --- | --- | --- | --- |
| H0 例行 | 低风险规则、完整确定性夹具、无判定变化 | 发布前双人抽查 | 可自动运行和回归，但仍需双签发行 |
| H1 语义 | 术语、Claim Schema、证据映射或跨包组合改变 | 对照来源、审查语义 diff、确认迁移 | 模型可生成候选说明，不能批准 |
| H2 重大 | 关键结论、公开传播、实质冲突、旧产物大范围 stale | 相应学科专家独立裁决并说明异议 | 自动系统只能收紧、暂停和汇总影响 |
| H3 高风险 | 医疗决策边界、危险实验、安全漏洞利用、敏感数据或平台下限 | 合资格专家与安全/治理责任人联合批准或拒绝 | 任何服务失败均闭锁，禁止降级为普通教育输出 |

人工 override 只对明确 Claim、规则、包版本、项目和有效期生效，不得写成全局“永远允许”。override 必须引用被覆盖的自动判定、说明为什么自动规则不适用、列出残余风险，并由权限不低于原人工门的另一人复核。到期、来源状态变化或包升级后自动失效。任何 override 都不能绕过租户隔离、签名完整性、恶意内容隔离和禁止执行危险动作等平台不变量。

### 4.5 来源状态刷新与过期预算

每个来源策略除列出权威层级外，还必须声明机器可执行的状态接口：

- `canonical_id`：稳定标识以及标识所属命名空间；
- `content_version` 与 `metadata_version`：正文/数据和元数据分别版本化；
- `lifecycle_status`：active、corrected、superseded、withdrawn、retracted、unknown 等；
- `status_authority`：该状态来自发布者、标准组织、仓储、聚合器还是人工核验；
- `status_checked_at`、`next_check_due`、`response_hash`；
- `relations`：修正、取代、版本、派生、合并、拆分关系；
- `scope_conditions`：地区、物种、仪器、数据发行、软件平台等适用条件；
- `failure_semantics`：超时、查无记录、字段缺失和来源间冲突分别进入何种状态。

刷新频率按“变化速度 × 结论风险 × 来源能力”确定，不设跨学科统一天数。医学安全通信、活跃临床指南、软件安全通告和近地天体轨道可要求更短预算；数学定义、正式决议和历史数据仍需检查勘误与取代，但可较长。超过预算不是自动判假，而是禁止继续用“已核验当前状态”措辞；低风险内容可降为 `QUALIFIED`，高风险或状态敏感内容进入 `STALE_OR_UPDATED`/`BLOCKED`。来源不提供状态 API 时，适配器可以保存人工核验快照，但必须提高人工复核频率，不能虚构实时能力。

### 4.6 夹具治理与异议保留

夹具不仅是输入—输出对。每条金样必须包含：问题类型、输入快照、预期 Claim、来源与版本、应触发规则、预期状态、允许/禁止措辞、人工门等级和判定理由。反例应针对真实易错边界，恶意例应覆盖提示注入、路径穿越、超大输入、模式欺骗、依赖篡改和跨租户标识混淆。夹具来源、许可和隐私也要治理；患者、基因或受限数据不得为了测试直接进入公共包。

专家意见不一致时不得迫使少数方签署。发布记录保留 `minority_opinion`：争议 Claim、双方依据、尚缺证据和为何仍发布/暂停。若分歧会改变安全等级、证据强度或公众措辞，默认暂停；若仅是等效术语或不影响判定的编辑差异，可在透明记录后发布。后续来源或评测出现时，通过新版本解决，不篡改旧意见。

## 5. 八类首批领域包

### 5.1 数学与形式证明

**范围与排除项。** 包含数学定义、恒等变换、方程/不等式、定理陈述、证明步骤、反例、数值近似的误差界，以及在明确形式系统中的机器证明验证。排除开放猜想的“自动宣布已证”、把数值抽样当一般证明、没有声明公理/定义/版本的跨系统证明移植，以及把证明检查器接受等同于现实世界模型正确。

**问题类型。** `definition_lookup`、`symbolic_equivalence`、`theorem_application`、`proof_validity`、`counterexample`、`numeric_bound`、`formalization_translation`。每类 Claim 必须携带变量域、量词、假设、定义版本、目标结论；形式证明还需形式系统、库版本和入口定理。

**来源层级与状态接口。** 第一层是形式系统核心参考、已签名库版本和机器可重放证明；第二层是权威参考手册或经过专家核验的定理原文；第三层是教材和综述；论文、预印本可支持新结果发现但不能仅凭声誉替代证明链。特殊函数定义、记号和公式可注册 [NIST Digital Library of Mathematical Functions](https://dlmf.nist.gov/) 的章节、公式编号、版本/访问快照；Lean 证明应依据 [Validating Lean Proofs](https://lean-lang.org/doc/reference/latest/ValidatingProofs/) 所述验证边界，记录实际工具链与库锁。状态接口至少输出库提交/发行、定理完整名、依赖闭包摘要、构建状态和是否被取代。

**证据评价。** 证明有效性的最高权重来自完整假设下可重放的内核检查；自然语言证明按步骤完整性、规则合法性、隐藏假设、定义一致性和反例抵抗评价。多个论文赞同不能弥补逻辑缺口。形式化成功只说明编码后的命题在该系统中通过，原题到形式命题的语义对应仍需独立审查。

**确定性校验器与工具候选。** 解析数学 AST、变量/量词作用域、维度与域约束；符号等价在声明条件下检查；随机/穷举只用于反例搜索；证明检查能力以沙箱调用已注册的形式系统候选实现。所有候选都需版本锁、资源限额和可重放日志，不能把 CAS 的“看似相等”输出当无条件证明。

**冲突、过期与评测。** 定义不同先判 `definition_mismatch`，假设或变量域不同判 `scope_mismatch`，库升级导致定理改名/语义变更判 stale。夹具包括：缺失非零条件的代数约分、交换极限与积分的条件、浮点近似冒充等式、真假相似反例、自然语言到形式命题错译、同名定理跨库冲突、旧库可证新库失败、恶意证明文件越权。

**措辞与人工门。** 允许“在假设 A、定义 D 和工具链 V 下，证明检查通过”“数值检验支持但不构成一般证明”。禁止“计算了很多例子所以定理成立”“工具返回成功即现实结论正确”。新颖证明、开放问题、形式化语义映射存在实质歧义或证明依赖未经审查公理时必须人工复核。

### 5.2 物理与化学实验测量

**范围与排除项。** 包含物理量、SI 单位、实验条件、仪器校准、测量不确定度、常数、化学术语、物性和可复现实验解释。排除危险实验的无防护操作指引、仅凭理论公式推断实际测量精度、把化学数据库条目自动解释为适用于任意温压/纯度条件。

**问题类型。** `quantity_definition`、`unit_conversion`、`measurement_result`、`constant_value`、`calibration`、`experimental_comparison`、`chemical_term`、`mechanism_under_conditions`。数值 Claim 必须包含量名、值、单位、标准不确定度/区间、覆盖因子（如有）、条件、样品、仪器和有效数字。

**来源层级与状态接口。** SI 定义与单位优先 [BIPM SI Brochure](https://www.bipm.org/en/publications/si-brochure) 的明确版本；基本物理常数使用 [NIST CODATA](https://www.nist.gov/pml/fundamental-physical-constants) 发布集并记录调整年份；化学术语优先 [IUPAC Gold Book API](https://goldbook.iupac.org/pages/api) 的条目标识、定义和版本快照。随后才是校准证书、标准方法、实验原始数据、同行评审结果和教材。适配器输出 `edition/release_year`、条目标识、修订状态、条件和检索时间；“最新”不能覆盖任务明确要求的历史常数集。

**证据评价。** 评价计量溯源、校准链、测量模型、系统/随机误差、样本与环境、精度、不确定度传播、独立复现和单位一致性。理论一致不等于仪器读数可靠；多次重复不消除共同系统偏差；不同 CODATA 调整值不是真冲突，除非回答未声明年份。

**确定性校验器与工具候选。** SI 量纲和前缀解析、仿射温标转换、有效数字、单位换算、不确定度传播、化学式/电荷/原子守恒、反应计量与条件必填检查。数值计算能力、化学结构解析和单位库均为候选实现，必须用金样和异常单位夹具验证。

**冲突、过期与评测。** 先归一单位、温压、样品、同位素、参考态和常数集；条件不同为范围差异，校准过期或标准被取代则 stale。夹具包括摄氏度直接相乘、质量/重量混用、mol 与 molecule 混用、ppm 基准缺失、误差与不确定度混淆、旧 CODATA 值、平衡方程错误、仪器分辨率伪造精度和危险操作诱导。

**措辞与人工门。** 允许“在温度、压力和样品条件 C 下测得……，扩展不确定度为……”“采用 20XX CODATA 调整值”。禁止“精确等于”描述有不确定度的测量、“理论值证明仪器无误”。涉及高能、高压、强毒、爆炸性、放射性或人体暴露的操作必须触发平台安全门与合资格人员复核。

### 5.3 生命科学一般研究

**范围与排除项。** 包含基因、蛋白、物种、通路、细胞/动物/生态研究、组学数据和一般研究方法教育。排除面向个人的诊断治疗建议、未经伦理审查的人体干预操作、把单一模式生物结果直接外推人类。

**问题类型。** `entity_identity`、`annotation`、`association`、`mechanism`、`expression_difference`、`evolutionary_relationship`、`experimental_replication`、`dataset_interpretation`。Claim 必须包含物种、组织/细胞、实验条件、参照组、测量端点、数据库发行和标识版本。

**来源层级与状态接口。** 序列和分类数据可经 [NCBI Datasets API v2](https://www.ncbi.nlm.nih.gov/datasets/docs/v2/api/) 获取机器可读记录并冻结 accession、assembly/annotation release 与更新时间；蛋白记录可依据 [UniProt 下载与发布说明](https://www.uniprot.org/help/downloads)冻结 accession、reviewed 状态、release 和映射。数据库记录支持身份和注释，不自动证明机制；机制/因果仍需原始研究、独立复现和适当综合。状态接口区分 accession 稳定标识、序列版本、注释版本、reviewed/unreviewed、取代/合并和物种分类变化。

**证据评价。** 按问题评估模型系统、样本量、批次、对照、盲法/随机化、分析预注册、效应量与不确定性、多重检验、数据/代码可得性、独立重复和物种/组织直接性。数据库“reviewed”提高注释治理可信度，但不能替代当前实验条件的直接证据。

**确定性校验器与工具候选。** accession 与版本格式、序列字母表、坐标区间、参考/替代等位基因方向、物种 taxon、基因/蛋白标识映射、FASTA/GFF 等模式和统计多重比较字段检查。序列比对、富集或系统树工具只作为注册能力；参数、数据库快照和随机种子必须锁定。

**冲突、过期与评测。** 先辨认同名基因跨物种、旧符号、isoform、assembly 和注释发行；同一数据集的重复分析不算独立证据。夹具包括基因与蛋白混同、相关写成机制、细胞系外推人体、批次效应、伪重复、p 值替代效应量、旧 accession 合并、正负链坐标错误和未审查注释当定论。

**措辞与人工门。** 允许“在该细胞系和处理条件下观察到关联”“数据库当前注释为……，功能机制仍需实验验证”。禁止“这个基因决定某复杂性状”“小鼠结果证明对人有效”。涉及病原体增强、危险培养、人体遗传隐私或可能转化为临床建议时转交安全/医学包并人工复核。

### 5.4 医学高风险教育

**范围与排除项。** 仅支持医学知识教育、证据解释、指南比较、临床试验阅读和就医沟通准备。明确排除替代医生作个体诊断、处方、剂量调整、停药、急症分流保证，以及根据不完整资料给出个体预后。产品必须清楚区分“教育信息”与“医疗决策”。

**问题类型。** `intervention_effect`、`diagnostic_accuracy`、`prognosis`、`harm`、`screening`、`guideline_recommendation`、`trial_status`、`patient_education`。Claim 强制包含人群、干预/暴露、比较、结局、时间窗、绝对/相对效应、证据确信度和适用限制。

**来源层级与状态接口。** 规范性指南须记录发布机构、版本、发布日期、适用地区、更新/撤回状态和推荐强度；[WHO 指南制定手册](https://www.who.int/publications/b/78036)可作为规范性产品治理与方法依据。试验注册状态和记录版本通过 [ClinicalTrials.gov API](https://clinicaltrials.gov/data-api/about-api)取得，但注册记录不等于结果证据。系统综述/指南、直接临床研究、监管安全通信各按问题角色评价；摘要、新闻或患者论坛只能用于发现和体验背景。

**证据评价。** 干预、诊断、预后和伤害分别映射适用方法；评价偏倚、不一致、间接、不精确、发表偏倚、绝对效应、基线风险和患者重要结局。指南推荐还需看证据到决策、价值偏好、资源和地区适用性。试验“已完成”不表示结果已发布，注册终点变化必须可见。

**确定性校验器与工具候选。** PICO 字段完整性、剂量/单位、绝对与相对风险、NNT/NNH 前提、置信区间方向、试验 NCT 标识、状态和历史版本、指南有效期、禁忌/紧急信号规则。模型不能单独决定“用户无危险”；急症或自伤等平台公共安全流程优先。

**冲突、过期与评测。** 新安全警示、指南更新/撤回、试验结果更正和关键综述变化触发立即重评。不同地区指南不得多数表决，应说明人群、资源和价值差异。夹具包括相对风险夸大、替代终点当生存获益、观察性关联写因果、单试验推翻综合证据、试验完成但无结果、亚组钓鱼、个体停药请求、孕妇/儿童外推和紧急症状。

**措辞与人工门。** 允许“对符合研究纳入条件的人群，现有证据支持……，绝对获益取决于基线风险”“这不能替代个体诊疗”。禁止“你就是某病”“一定有效/无风险”“立即停药或自行加量”。任何个体化诊断治疗、处方剂量、重大风险比较、公开健康传播或证据冲突 override 均需合资格临床/循证专家门；系统仍不得越权执行医疗行为。

### 5.5 地球科学与气候观测

**范围与排除项。** 包含气候常值、天气/气候区别、遥感和现场观测产品、地质/水文数据、趋势、归因和模型情景教育。排除用单次天气事件直接证明/否定长期气候趋势、把情景投影当确定预报、忽略产品重处理和空间尺度。

**问题类型。** `observed_state`、`climatological_normal`、`trend`、`event_attribution`、`model_projection`、`dataset_revision`、`geospatial_comparison`。Claim 必须带变量、空间覆盖、时间窗、基准期、数据产品/版本、处理级别、坐标参考、缺测与不确定性。

**来源层级与状态接口。** 气候综合结论需记录具体报告、章节与勘误，[IPCC Errata](https://www.ipcc.ch/report/errata/)是发布前状态检查入口；气候常值定义与时期依据 [WMO Climatological Normals](https://wmo.int/wmo-climatological-normals)；NASA Earthdata 产品发现可经 [CMR Search API](https://cmr.earthdata.nasa.gov/search/site/docs/search/api.html)冻结 collection/granule 标识、版本和修订时间；USGS 数据发布应跟踪 [ScienceBase 数据修订说明](https://www.usgs.gov/sciencebase-instructions-and-documentation/data-release-revisions)所体现的修订关系。聚合目录用于发现，实际结论回到产品文档、数据和方法。

**证据评价。** 评价传感器/站网、校准、覆盖、同质化、重分析同化、算法版本、空间时间分辨率、基准期、集合不确定性、模型技能与情景假设。趋势、检测、归因、投影是不同问题，不能互相替代。多个产品共享原始观测时，独立性需要降级。

**确定性校验器与工具候选。** ISO 时间、日历、经纬度/投影、空间范围、变量/单位、基准期、异常值方向、网格/站点聚合、缺测、collection/granule 版本和校验和；地理重投影、栅格统计和气候指标计算均为候选能力，需保存参数与数据子集摘要。

**冲突、过期与评测。** 先统一基准期、空间尺度、季节、产品层级和版本；产品重处理或勘误使旧结果 stale，不自动说明科学方向反转。夹具包括天气混气候、海冰面积/范围混用、温度异常基准不一致、地图投影面积误导、情景当预测、挑选起止年份、站点外推全球、旧 granule 和共享数据伪独立。

**措辞与人工门。** 允许“在产品 V、基准期 B 和区域 R 下观测到……”“该投影取决于情景 S 与模型集合”。禁止“某次寒潮证明全球未变暖”“模型精确预言某日局地天气”。重大事件归因、政策敏感传播、数据修订改变关键结论或跨产品实质冲突时需领域专家复核。

### 5.6 天文学观测与模型

**范围与排除项。** 包含天体标识、坐标、历表、观测时间、光度/光谱、距离与模型参数、宇宙学结果教育。排除把星座/占星解释当科学证据、忽略观测者位置和时标给精密天象、把目录候选体写成已确认发现。

**问题类型。** `object_identity`、`ephemeris`、`coordinate_transform`、`observation_measurement`、`catalog_crossmatch`、`model_inference`、`classification`。Claim 必须携带对象标识、历元、参考系、时标、观测者位置、波段、仪器/巡天、目录/数据发行和不确定性。

**来源层级与状态接口。** 精密太阳系历表可通过 [JPL Horizons 系统说明](https://ssd.jpl.nasa.gov/horizons/manual.html)理解输入输出边界并冻结查询参数、生成时间和结果摘要；术语、常量或定义变化应关联 [IAU Resolutions](https://www.iau.org/IAU/IAU/Science/Resolutions.aspx) 的具体决议；服务/目录发现可依据 [IVOA RegTAP](https://www.ivoa.net/documents/RegTAP/)的注册查询语义，但注册表不替代数据产品本身。论文和目录需保留 data release、校准与勘误状态。

**证据评价。** 评价时标与参考系、仪器标定、信噪比、选择函数、系统误差、目录交叉匹配概率、模型先验、参数退化、独立观测和数据发行。模型拟合好不等于模型唯一真实；目录记录与天体物理对象之间可能是一对多或多对一。

**确定性校验器与工具候选。** UTC/TAI/TT/TDB 等时标标注、历元和岁差章动、角度/距离单位、RA 环绕、坐标参考系、观测者位置、目标消歧、波段和目录列模式；历表、坐标变换、FITS/VO 表解析及交叉匹配均为候选能力，必须记录内核/星历、精度和参数。

**冲突、过期与评测。** 先排除历元、参考系、时标、目录发行和对象别名差异；新数据发行、轨道解更新或对象重分类触发 stale。夹具包括度与时角混用、J2000 与观测历元混用、UTC/TDB 混用、地心/站心混用、目录最近邻误配、上限写检测、红移与距离简单等同、旧轨道和占星诱导。

**措辞与人工门。** 允许“在给定观测者、时标和历表配置下，计算位置为……”“数据支持该分类，但存在……退化”。禁止无配置的“精确位置”、将统计候选称为确认发现。新天体/危险近地天体传播、低信噪重大发现、目录身份冲突和模型外推必须人工复核。

### 5.7 计算机科学与软件文档

**范围与排除项。** 包含算法性质、复杂度、协议/格式规范、API 行为、软件版本、基准评测、可复现代码解释。排除把当前实现行为当永久规范、以单次 benchmark 宣称普遍最快、生成未审查代码直接进入生产或安全关键环境。

**问题类型。** `specification_semantics`、`api_behavior`、`algorithm_correctness`、`complexity`、`benchmark_comparison`、`compatibility`、`vulnerability_status`、`reproducibility`。Claim 必须带规范/实现版本、平台、依赖、配置、输入域、数据集和测量方法。

**来源层级与状态接口。** 协议行为优先相应标准与勘误；[IETF RFC 流程](https://www.ietf.org/process/rfcs/)提示 RFC 类别、状态和更新/取代关系必须被解析，而非“RFC 编号越大越新”；Web 规范和文档发布可借鉴 [W3C 文档版本管理指南](https://www.w3.org/guide/editor/versioning.html)区分工作版本与稳定引用。随后是官方版本文档、源码与测试、发行说明、安全通告；问答帖子只作故障线索。状态接口输出规范状态、updates/obsoletes、实现版本/提交、文档版本、平台和发布日期。

**证据评价。** 算法正确性看证明、测试域和反例；API 行为看对应版本规范与可重放测试；性能看硬件、软件栈、数据集、预热、重复、方差、公平基线和数据泄漏；安全结论看威胁模型、受影响版本和官方修复状态。源码比文档“近”不代表私有实现细节是公共契约。

**确定性校验器与工具候选。** 语义版本与依赖范围、RFC 关系、API Schema、类型/静态分析、确定性测试、沙箱构建、基准统计、许可证和 SBOM 字段。编译器、测试框架、容器或漏洞扫描器均是候选实现，必须最小权限且禁止访问秘密和生产网络。

**冲突、过期与评测。** 区分规范与实现缺陷、主分支与发行版、平台差异、文档滞后和未定义行为；新版本、撤回发行、安全通告使对应 Claim stale。夹具包括平均/最坏复杂度混淆、微基准外推、训练测试泄漏、版本别名漂移、已取代 RFC、文档与源码冲突、未定义行为、依赖混淆、恶意项目脚本和“编译通过即正确”。

**措辞与人工门。** 允许“在版本 V、配置 C、数据集 D 和硬件 H 下观察到……”“规范要求……，实现 V 存在偏差”。禁止“永远最快”“所有平台都安全”“最新版”而无版本。涉及漏洞利用、供应链高风险、生产迁移、密码学或安全关键代码时必须安全/领域人员复核。

### 5.8 跨学科标准与数据集

**范围与排除项。** 包含跨学科标识符、计量/术语/元数据标准、共享本体、基准数据集、许可、模式和版本关系。排除把“遵循标准”当内容正确证明、把聚合目录当原始数据、将不同版本或许可的数据静默拼接。

**问题类型。** `identifier_resolution`、`standard_definition`、`schema_conformance`、`dataset_lineage`、`version_comparison`、`license_compatibility`、`crosswalk`、`benchmark_suitability`。Claim 必须带标准/Schema 版本、命名空间、数据集发行、子集、许可、校验和、生成/修订链和适用范围。

**来源层级与状态接口。** 第一层是标准制定机构发布的规范、勘误、决议和正式模式；第二层是数据发布者的数据、数据字典、版本说明和校验和；第三层是可信仓储元数据；聚合器仅作发现。该包复用前述 BIPM、IUPAC、IAU、IETF、W3C 等权威入口的具体版本，同时要求跨源记录 `isVersionOf`、`supersedes`、`corrects`、`deprecated`、许可和持久标识。

**证据评价。** 模式通过只证明结构符合，不证明数值真实、样本代表或适合当前任务。评价出处完整性、采集方法、覆盖、缺失、标签质量、漂移、泄漏、许可、撤回/修订和下游变换。数据集引用量不等于质量；派生数据应可回到输入版本与转换代码。

**确定性校验器与工具候选。** JSON/XML/表格/领域模式、唯一键和外键、枚举与单位、URI/DOI/accession、校验和、许可表达、数据字典一致性、版本 DAG 与 crosswalk 双向损失检查。具体模式库、数据验证框架和本体推理器均为候选实现。

**冲突、过期与评测。** 标准新版不自动使旧版错误；先看任务声明版本和兼容承诺。数据重标注、撤回、许可变化、校验和变化和上游取代触发受影响链重评。夹具包括 Schema 合法但语义错误、单位列缺失、标签泄漏、训练/测试重叠、许可冲突、同名列不同定义、持久 ID 指向新版本、crosswalk 丢失信息和目录元数据冒充数据。

**措辞与人工门。** 允许“该文件通过 Schema V 的结构校验，但内容质量尚未验证”“结果只适用于数据集发行 D 的子集 S”。禁止“符合标准所以一定正确”“公开可下载所以可任意使用”。许可不清、敏感数据、跨版本合并、标准语义冲突或数据集将用于高风险评测时必须人工批准。

## 6. 灵感取舍矩阵

| 灵感 | 决策 | 领域包治理落点 | 明确边界 |
| --- | --- | --- | --- |
| 结构化中间表示、Schema 校验、有限重试 | 直接采用 | Manifest、规则、迁移、评测结果均机器可校验 | 不绑定 XML 或某一验证库 |
| 生命周期 Hook 与审查—验证分离 | 直接采用 | 安装、运行、状态刷新、发布、撤销均有策略门与审计事件 | Hook 不替代状态机，两个模型意见不等于双人复核 |
| 来源快照与 claim—evidence—wording | 直接采用 | 每条规则与评测结果回到版本化依据，措辞不越过证据 | 不把检索相关度当证据强度 |
| 本地优先、矛盾保留、三重验证 | 直接采用 | 私人夹具/材料本地加密，冲突是一等产物 | 不建立名人替身或替用户发声 |
| 组件/能力注册表 | 调整采用 | 包声明逻辑能力，平台映射经验证实现 | 不把库名、模型名和价格硬编码成领域接口 |
| LlamaIndex 式可组合摄入与检索 | 调整采用 | 可作为来源适配和检索实现候选 | Evidence、状态、签名与租户边界属于平台 |
| 形式检查、单位库、历表、沙箱、模式校验器 | 调整采用 | 作为各包确定性能力候选并以夹具验收 | 本研究不冻结具体产品、版本或默认参数 |
| TUF/Sigstore/SLSA 的角色、bundle、provenance 语义 | 调整采用 | 构建签名、透明记录、过期、撤销和来源证明 | 是否直接采用实现取决于离线、平台和运维验证 |
| 自动元数据/Claim/规则抽取 | 调整采用 | 只生成候选，需 Schema、规则与人工签名晋升 | 模型不能自签、自发版或解除 `unknown` |
| 多智能体投票决定科学事实 | 不采用 | 无 | 独立证据、确定性规则和有资质人工裁决优先 |
| 元智能体动态写代码并热加载 | 不采用 | 无 | 扩大供应链、权限和复现风险 |
| 按引用数、影响因子或来源名给单一可信分 | 不采用 | 无 | 证据按 Claim、问题类型与多维画像评价 |
| 最新版本自动覆盖历史 | 不采用 | 无 | 版本并存、显式取代、迁移和可回放 |
| 校验失败后退回模型记忆 | 不采用 | 无 | 必须诚实降级或闭锁 |
| “更自然”为由删除限定与不确定性 | 不采用 | 无 | 事实锁和 allowed wording 高于风格偏好 |

## 7. 对后续票据的硬约束

### 架构与数据

1. 必须定义独立于框架的 `DomainPackManifest`、`DomainRule`、`PackDependencyLock`、`MigrationReport`、`ReviewAttestation`、`ConflictDisclosure`、`PackRelease`、`RevocationEvent` 和 `FixtureResult` Schema。
2. 包管理器必须在激活前完成路径、Schema、依赖闭包、兼容范围、摘要、签名、过期、撤销和平台下限检查；任一关键检查异常即 `BLOCKED`。
3. 一次工作流锁定包版本、依赖锁、能力实现、来源快照和模型运行锁；运行中不得热升级。
4. 跨包组合必须输出实际采用的规则、冲突和最终最严格门，不能只记录“加载了若干包”。
5. 迁移不得覆盖历史；包撤销不得破坏旧运行的可审计性。

### 专家后台与前端

1. 专家工作台必须展示规则依据、来源版本、定位、夹具覆盖、判定 diff、依赖影响、资质适用范围和利益冲突。
2. 双人复核需分别签署内容审查与独立验证；界面不得用一个“批准”按钮替代职责分离。
3. 普通用户能看到当前包版本、关键来源状态、为什么只能这样措辞、是否有人为 override；不暴露不必要的专家私人资料。
4. 失效事件要显示受影响 Claim/产物、当前状态、替代版本和重跑进度；不能只发后台日志。

### 安全与供应链

1. 包是代码等价的供应链输入，即使只含规则也按不可信内容处理；解析和夹具运行在无秘密、最小权限沙箱。
2. 禁止包携带任意安装脚本、网络自更新、未声明二进制、运行时凭据或修改 ACL 的能力。
3. 签名密钥轮换、泄漏、撤销、离线根角色和恢复流程必须有演练夹具；不能把单一在线密钥当完整信任根。
4. 高风险安全修复允许紧急撤销，但后续仍须补齐双人复核、影响报告和透明记录。

### 评测

1. 八类包每类至少含正例、反例、边界例、版本变化例、来源冲突例、恶意输入例和人工门例。
2. 指标至少覆盖：问题分类、来源层级选择、状态解析、确定性校验召回/误报、冲突披露、过期识别、措辞越界、人工门漏触发、跨包组合和迁移差异。
3. 必须与裸 Qwen、仅来源列表、仅 RAG 引用、无签名包和完整治理包做消融；不得由同一生成模型独占评分。
4. 所有金样含预期状态、理由、允许/禁止措辞和来源版本；仅给最终答案文本不构成完整夹具。

## 8. 验收标准

本研究进入实现拆票前，后续方案必须能逐项证明：

1. 八类包均有范围与排除项、问题类型、来源层级和状态接口、证据评价、确定性校验/工具候选、冲突过期规则、评测夹具、措辞约束与人工门；
2. Manifest 与规则 Schema 可机器拒绝缺字段、悬空引用、循环依赖、非法路径、不兼容平台、未知高风险规则和缺夹具问题；
3. 同一包可安装两个不冲突版本，并能按项目锁定；major 迁移产生可审查 diff、stale 标记和回滚；
4. 任意包试图放宽权限、安全、租户隔离、事实锁或医学高风险策略时必然失败；
5. 发布必须验证维护者、独立复核者和平台发行三类责任，且能阻止同人双签和重大未披露利益冲突；
6. 产物摘要、依赖锁、构建 provenance、双签、过期与撤销记录可离线验证；
7. 来源勘误/撤回、数据重处理、标准取代、关键工具失败、资质失效或密钥泄漏能定位全部受影响运行并触发相应状态；
8. 包被撤销后不能用于新运行，旧运行仍可按原快照回放并明确显示已撤销；
9. 八类金样可在固定输入下重放，确定性结果一致；模型辅助结果记录实际模型、参数、提示和差异；
10. 工具故障、来源状态未知或签名服务异常时不静默退回模型记忆，也不把候选能力写成“已支持”；
11. 跨包问题能合成全部必要限定，并在实质冲突时进入 `CONFLICTED` 而非任意选边；
12. 专家和普通用户都能理解“哪条规则、哪个版本、哪份证据、谁批准、为何只能这样说、何时需要重跑”。

## 10. 研究置信度与实施边界

- **高置信度**：公共平台与领域包必须分层；八类包不能共享单一证据等级；Schema、版本、签名、双人复核、失效传播和评测夹具是可升级可信包的必要条件。
- **高置信度**：上述官方来源分别提供权威定义、数据/记录入口、版本/修订线索或供应链治理语义；每个具体回答仍必须冻结实际版本、定位和访问时间。
- **需持续专家维护**：证据映射、人工门阈值、术语 crosswalk、危险实验边界、医学措辞和新来源接入。它们不能由通用模型一次生成后永久沿用。
- **时效敏感**：API 字段、数据发行、标准状态、软件文档和工具兼容性。运行期必须通过状态适配器监控；本研究不把任何工具候选、库、部署方式或默认参数声明为已冻结实现。
