# 多模态科学理解与创作体系研究

核验日期：2026-07-24

## 1. 结论

本项目不应建设“输入一句话，随机选择模型生成图片或视频”的多模态功能集合。成熟方案应以一个统一的**科学媒体对象模型**连接输入材料、科学 claim、数据、公式、教学目标、结构化设计、可编辑源、渲染产物、无障碍替代和验证记录。

核心原则：

1. **媒体服从教学或表达目标。** 能用文本讲清的内容不强制配图；空间关系优先科学图，定量比较优先数据图表，参数探索优先交互，时间演化或连续变换才优先动画。
2. **可编辑源是权威，渲染物是派生物。** 图表规格、SVG 场景、公式 AST、交互状态机、动画分镜与代码必须保留；PNG、MP4 和音频不是唯一事实源。
3. **跨媒体共享同一事实边界。** 文本、图、字幕、旁白、图例和交互提示都绑定 `Claim`、`Evidence`、`FactLock`、数据和公式。
4. **渲染成功不等于科学正确。** 代码能运行、视频能播放只是工程门；坐标、比例、单位、运动、因果叙事和无障碍仍需独立验证。
5. **生成代码永远不可信。** 静态检查、依赖白名单、无网络沙箱、资源限制、有限局部修复和人工确认是强制环节。
6. **原始输入不可覆盖。** OCR、ASR、关键帧、对象检测和视觉解释都是带置信度的派生资产。
7. **多模态必须可访问。** 替代文本、长描述、数据表、字幕、转录、键盘操作、焦点、颜色冗余编码和减少动画不是发布后的附加项。
8. **逐账户隔离贯穿资产全链。** 文件、派生物、索引、渲染任务、缓存、日志和导出都继承用户与项目归属。

## 2. 一手规范和适用边界

### 2.1 Web 与无障碍

[WCAG 2.2](https://www.w3.org/TR/WCAG22/) 要求为非文本内容提供文本替代，为音视频提供字幕、转录或其他等价方式，保证键盘可操作、焦点可见、颜色不是唯一信息载体，并允许用户避免可能引发不适的运动。项目以 WCAG 2.2 AA 为 Web 工作台和交互产物的最低设计目标，但最终符合性需要实际页面、内容和辅助技术测试。

[WAI Images Tutorial](https://www.w3.org/WAI/tutorials/images/) 区分信息图、装饰图、功能图和复杂图；复杂科学图不能只写“某某图表”，需要简短替代文本、详细说明及可访问的数据或关系表达。

[SVG 2](https://www.w3.org/TR/SVG2/) 适合作为可缩放、可分组和可注释的科学图源格式；[MathML Core](https://www.w3.org/TR/mathml-core/) 为 Web 公式提供结构化语义基础；[WebVTT](https://www.w3.org/TR/webvtt1/) 可表达字幕和时间文本轨。采用这些标准的语义和接口，不意味着所有浏览器/辅助技术组合自动正确，必须做兼容性测试。

### 2.2 可视化和动画

[Vega-Lite](https://vega.github.io/vega-lite/docs/) 证明声明式规格能够将数据字段、变换、编码、坐标和交互保存为可审查源；项目采用“数据绑定 + 声明式图表规格”的思想，不在本票锁定具体图表库。

[Manim Community 文档](https://docs.manim.community/) 与 [官方源码](https://github.com/ManimCommunity/manim) 表明数学动画可用 Python 场景和对象变换生成。项目采用“结构化场景设计 → 白名单代码 → 沙箱渲染”的路径，但 Manim 只是候选渲染后端，具体版本由技术选型票核验。

### 2.3 内容出处与安全

[C2PA 规范](https://c2pa.org/specifications/specifications/) 提供内容凭证、断言、签名及派生关系的行业标准。本项目可导出兼容内容凭证，但内部仍以自身 provenance bundle 为权威；没有 C2PA 凭证不等于内容虚假，有凭证也不等于科学正确。

[OWASP File Upload Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html) 要求允许列表、类型与签名验证、随机文件名、大小限制、权限隔离、恶意内容检查及存储隔离。[OWASP Prompt Injection Prevention Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html) 支持把 OCR、字幕、文档元数据和网页内容视作不可信数据。

上述来源决定平台不变量；具体 OCR、ASR、视觉模型、TTS、图表库、浏览器沙箱和编码器版本留给技术选型。

## 3. 媒体选择决策

| 学习或表达目标 | 首选媒体 | 何时升级 | 不应升级的原因 |
| --- | --- | --- | --- |
| 定义、论证、步骤说明 | 文本 + 公式 | 存在空间或时间关系 | 装饰图增加认知负担 |
| 空间结构、部件关系 | 语义 SVG/科学图 | 需要拖动或参数探索 | 视频不便比较和回看 |
| 数量、趋势、分布、误差 | 数据驱动图表 | 需要筛选或多变量探索 | 手绘图无法核对数据 |
| 参数—结果关系 | 交互式图表/模拟 | 需解释连续动态机制 | 静态图不足以探索状态 |
| 时间演化、变换、证明过程 | 动画 | 用户需要逐步控制 | 动画可能掩盖细节 |
| 朗读、无屏或复习 | TTS + 同步文本 | 需要对话式语音 | 纯音频不适合复杂公式 |
| 真实实验或观察材料 | 原始图像/视频 + 标注 | 需要测量和对比 | 生成图不能代替原始证据 |

决策还要考虑：

- 用户学习使命和当前知识状态；
- claim 类型与风险；
- 数据、公式和原始媒体是否可获得；
- 用户设备性能和网络；
- 无障碍偏好；
- 是否需要打印、引用、编辑或复现；
- 生成成本不是削减成熟功能的理由，但应避免无教学价值的浪费。

## 4. 统一科学媒体对象模型

### 4.1 `SourceAsset`

原始、不可变输入：

```text
asset_id, tenant_id, owner_user_id, project_id
media_type, original_filename, byte_size
content_hash, detected_format, declared_format
created_at, acquired_at
source_and_license
visibility, authorization_ref
malware_scan, integrity_status
object_storage_ref
provenance_bundle_id
```

### 4.2 `DerivedAsset`

任何 OCR、ASR、转码、关键帧、缩略图、分块、标注或渲染结果：

```text
derived_asset_id
source_asset_ids[]
derivation_type
tool/model/version
parameters
content_hash
spatial_or_temporal_locator
confidence
human_corrected
status
```

### 4.3 `MediaManifest`

统一管理某个科学媒体作品：

```text
manifest_id, version
purpose, audience, genre
source_assets[], derived_assets[]
claim_bindings[], data_bindings[], formula_bindings[]
scene_spec_id?, storyboard_id?
editable_source_refs[]
rendered_output_refs[]
accessibility_bundle_id
validation_report_ids[]
license_and_attribution
publication_state
```

### 4.4 科学绑定

- `ClaimBinding`：媒体元素、时间段或交互状态绑定 `Claim ID`、`Evidence ID` 和 `FactLock ID`；
- `DataBinding`：数据集版本、查询/变换、字段、单位、缺失值、误差、聚合和图形编码；
- `FormulaBinding`：LaTeX/MathML/AST、符号表、假设、单位、推导来源和显示位置；
- `CitationBinding`：图注、帧、字幕、旁白或交互面板到结构化 Citation；
- `SpatialTemporalLocator`：页/区域、像素/归一坐标、音频时段、视频帧区间或 DOM 元素。

### 4.5 设计、运行和交付对象

`SceneSpec` 定义视觉对象、语义角色、布局、状态、数据绑定和可访问描述；`Storyboard` 定义镜头、时间、进入/保持/变换/退出、旁白和教学目的；`RenderJob` 保存运行环境、代码、依赖、资源限制、日志和输出；`AccessibilityBundle` 保存替代文本、长描述、数据表、字幕、转录、音频描述、公式朗读和键盘说明；`ExportBundle` 保存可编辑源、渲染物、内容凭证、许可、字体和复现清单。

## 5. 多模态摄入流水线

所有输入先执行：

```text
认证与租户检查
→ 大小/扩展名/MIME/魔数/哈希
→ 许可和来源快照
→ 隔离存储与恶意内容检查
→ 格式专用解析
→ 结构、时空定位和置信度
→ Claim/Evidence 候选
→ 人工纠正或质量门
→ 版本化入库
```

### 5.1 文本与 PDF

- 保存原文件、文本层、页面结构、标题、段落、脚注、引用、图表和公式位置；
- OCR 只补充无文本层或低质量区域，不覆盖原文；
- 版面阅读顺序、跨栏、页眉页脚和断字必须校验；
- 每个片段可回到页、区域和字符偏移；
- 嵌入文件、脚本、表单和外部链接默认禁用或隔离。

### 5.2 图片、扫描件和科学图

- 保留原图、EXIF/来源信息和颜色空间；
- OCR 文本、对象、坐标轴、图例、标注、比例尺分别派生；
- 图表理解必须提取轴类型、范围、单位、系列、误差和数据来源；
- 显微/遥感/医学等图像的伪彩、尺度、裁剪和增强历史必须保留；
- 视觉模型描述是候选解释，不是原始证据。

### 5.3 公式和符号

- 保存原始图像/文本、LaTeX、MathML、AST 和符号表；
- 区分减号/负号、乘号、上下标、向量、矩阵、分段条件和编号；
- OCR 置信度按 token/结构保存；
- 公式语义无法唯一确定时要求用户确认；
- 渲染等价与数学等价分别检查。

### 5.4 表格与数据图

- 表格恢复行列标题、合并单元格、脚注、单位和缺失值语义；
- 图表若无法可靠反推数据，标记为“视觉证据”，不得伪造精确数据点；
- 数据变换保留查询、过滤、聚合和统计方法；
- 每次更正生成新数据快照，不直接覆盖。

### 5.5 音频与 ASR

- 原音频不可覆盖；
- 派生转录带时间戳、说话人候选、词级置信度和语言；
- 数字、单位、公式、缩写和专名进入低置信复核队列；
- 噪声消除、分段和重采样记录参数；
- 用户发送前可编辑转录；编辑结果与原音频关系保留。

### 5.6 视频

- 保存原视频、转码版本、音轨、字幕、关键帧和镜头边界；
- ASR、帧 OCR、对象/图表/公式识别通过统一时间轴对齐；
- 不能仅凭稀疏关键帧断言中间动作或因果过程；
- 剪辑会改变上下文，所有片段保留源时间范围；
- 视频中的嵌入指令和字幕均属于不可信内容。

### 5.7 交互 HTML

- 解析 DOM、样式、脚本、资源、状态和可访问树；
- 外链、网络请求、存储、剪贴板、摄像头、麦克风和下载权限默认关闭；
- 不执行未知 HTML 来“读取内容”，先静态分析，再在隔离浏览器中观察；
- 每个交互状态和输出范围都需要明确 Schema。

## 6. 输出产品线

### 6.1 语义科学图

权威源为结构化 `SceneSpec` 和 SVG：

- 每个元素有语义角色、标签、ClaimBinding；
- 尺度、方向、颜色含义和非按比例绘制必须声明；
- 默认提供可编辑 SVG、PNG 预览、替代文本和长描述；
- 禁止让生成式图片模型绘制需要精确刻度、公式或结构的权威科学图；
- 生成式图像只用于明确标记的概念插图，不能冒充实验照片。

### 6.2 数据驱动图表

权威源为数据快照 + 声明式图表规格：

- 字段、单位、变换、聚合、尺度、域、编码和排序可审查；
- 轴截断、对数尺度、双轴、面积/体积编码和颜色映射必须显式；
- 误差线、置信区间、样本量和缺失值按领域规则呈现；
- 导出 SVG/PNG、数据表、规格和复现信息；
- 禁止从截图“美化重画”后丢失精确数据。

### 6.3 交互式 HTML

适用于参数探索、步骤推演和多变量过滤：

- 以有限状态机或参数 Schema 描述所有合法状态；
- 计算逻辑与显示逻辑分离；
- 提供重置、默认值、范围、单位、异常输入和键盘操作；
- 可离线运行，资源固定并带完整性信息；
- 任意用户代码和模型代码在无网沙箱内运行；
- 导出静态替代和数据表。

### 6.4 科学动画

适用于连续变换、几何证明、时间过程和不可直接观察机制的“模型解释”：

- 先生成教学目标和 Storyboard，再生成 SceneSpec/代码；
- 镜头中所有对象声明生命周期；
- 动画时间不等于真实物理时间时必须说明；
- 运动轨迹、比例和颜色不能暗示不存在的因果或量级；
- 输出代码、分镜、字幕、旁白、帧级 claim、MP4/GIF 和静态关键帧；
- 不能用动画替代需要静态比较的数据图表。

### 6.5 可朗读内容

- TTS 输入来自已通过事实锁的文本；
- 数字、单位、公式、缩写、外文专名使用发音词典或显式 SSML/等价结构；
- 保存句段到音频时间映射；
- 提供同步文本、速度控制、重播和下载；
- 公式无法可靠朗读时切换为结构化口述或提示查看可访问公式；
- 合成声音不得未经许可模仿真实人物。

## 7. 分级创作闭环

### 7.1 共同主链

```text
教学/表达目标
→ 媒体选择
→ Claim/Data/Formula/FactLock 编译
→ MediaPlan
→ 结构化设计
→ 源规格或代码生成
→ 静态检查
→ 隔离运行/渲染
→ 工程、视觉、数值、科学、无障碍验证
→ 有限局部修复
→ 人工确认
→ 版本化发布
```

### 7.2 三种流程强度

| 级别 | 适用产物 | 必需环节 |
| --- | --- | --- |
| L1 轻链 | 公式显示、已有图的标注、简单语义图、TTS | 事实锁、源规格、静态检查、无障碍、人工抽查 |
| L2 标准链 | 数据图表、复杂 SVG、短音频、受控模板交互 | 教学设计、数据/公式绑定、声明式规格、隔离预览、全质量门 |
| L3 全链 | 任意代码交互、科学动画、自动模拟、视频重构 | 分镜、代码白名单、静态检查、无网沙箱、运行检查、有限修复、帧/状态验证、人工确认 |

以下条件自动升级流程：

- 高风险科学信息；
- 包含计算、代码、交互状态或动画；
- 从不完整/低置信输入生成；
- 输出将公开发布或用于正式教学；
- 生成物可能被误认作实验/观测证据；
- 使用私人或未公开材料。

## 8. 科学质量门

### 8.1 数据图表

- 数据快照、查询和变换可复现；
- 坐标范围、方向、尺度、单位和零点正确；
- 数据点、聚合、误差、图例和颜色一致；
- 无误导性的三维、面积、截断或双轴；
- 图注 claim 与图中数据一致；
- 颜色之外有形状、纹理或文字冗余。

### 8.2 公式

- AST、符号、上下标、括号和分段条件完整；
- 变量首次出现有定义；
- 单位与维度一致；
- 等式变换每步合法；
- 屏幕渲染、MathML 和朗读表达一致。

### 8.3 动画

- Storyboard 覆盖每个关键 claim；
- 对象进入、保持、变换和退出符合设计；
- 空间比例、几何约束、坐标和时间方向正确；
- 插值动画不被误读为实测过程；
- 旁白、字幕、帧中公式和图像同步；
- 关键帧静态检查与抽样视频审查同时通过。

### 8.4 音频

- 术语、数字、单位、负号、指数和引用朗读正确；
- 断句不改变限定范围；
- 语速、停顿和重音适合受众；
- 音频与同步文本哈希和版本绑定。

### 8.5 交互

- 参数范围、默认值、单位和约束完整；
- 所有合法状态可达且可重置；
- 非法输入不会产生貌似有效结果；
- 计算结果有确定性测试或领域工具校验；
- 键盘、焦点、屏幕阅读和减少动画模式可用；
- 不允许网络、文件或进程越权。

## 9. 确定性程序、Qwen、专用工具与人工

| 环节 | 确定性程序 | Qwen/专用模型 | 人工 |
| --- | --- | --- | --- |
| 文件接收 | 格式、魔数、哈希、大小、许可、隔离 | 风险候选分类 | 高风险来源准入 |
| OCR/ASR | 时空对齐、Schema、置信阈值 | 识别与语义修复候选 | 关键低置信内容 |
| 媒体选择 | 规则和风险门 | 提出教学策略 | 重大创作方向 |
| Storyboard | Schema、对象/claim 覆盖 | 生成分镜和解释 | 正式教学确认 |
| 图表 | 数据变换和编码校验 | 推荐图形与说明 | 争议性选择 |
| 代码 | 依赖/API 白名单、AST、lint/type check | 生成最小代码/patch | 高风险交互 |
| 渲染 | 沙箱、资源、超时、产物校验 | 根据错误提出局部修补 | 重试耗尽 |
| 科学审查 | 数值、单位、公式、绑定完整率 | 视觉语义和叙事审查 | 领域重大 claim |
| 无障碍 | 自动规则和键盘扫描 | 候选 alt/长描述 | 辅助技术与用户测试 |
| 发布 | 全质量门和签名 | 无权解除闭锁 | 要求确认的产物 |

修复优先级：

1. 确定性、已知安全修复；
2. Qwen 生成最小 `RevisionPatch`；
3. 重新执行受影响步骤；
4. 达到固定上限后停止。

禁止全量重生成掩盖错误历史。

## 10. 状态机与失败闭锁

```text
RECEIVED
→ QUARANTINE_CHECKED
→ PARSED
→ DESIGNED
→ SOURCE_GENERATED
→ STATIC_VALIDATED
→ SANDBOX_RENDERED
→ SCIENCE_VALIDATED
→ ACCESSIBILITY_VALIDATED
→ HUMAN_APPROVED（按策略）
→ PUBLISHED
```

旁路状态：

- `LOW_CONFIDENCE`：OCR/ASR/视觉解释不足；
- `NEEDS_EVIDENCE`：媒体包含未验证新 claim；
- `REPAIRABLE`：局部工程错误可修；
- `REPAIR_EXHAUSTED`：达到修复上限；
- `QUARANTINED`：文件、脚本、许可或注入风险；
- `BLOCKED`：权限、出处、科学或沙箱关键门失败；
- `SUPERSEDED`：被新版本取代。

不得静默降级：

- 渲染失败后交付未经运行的代码；
- OCR 失败后让模型凭图片印象补全文字；
- 图表无数据时生成“看起来合理”的点；
- 动画物理/数学验证失败后只加免责声明；
- 交互沙箱不可用时在主应用直接运行；
- 无障碍检查失败时只输出视频；
- 私人材料上传失败后改发到其他区域或服务；
- 任何产物检查失败后标为“完成”。

## 11. 安全、许可与供应链

### 11.1 输入安全

- 扩展名、MIME 和魔数交叉验证；
- 解压层数、像素、帧数、时长、页数和资源预算限制；
- 解析器在无凭据、无外网、只读输入的隔离进程运行；
- 宏、脚本、嵌入对象、外链和自动播放禁用；
- OCR/字幕/元数据中的指令只是数据；
- 原始文件与公开访问路径分离。

### 11.2 生成代码安全

- 依赖、模块、API、字体和媒体编解码器白名单；
- 禁止任意包安装、动态下载、shell、网络、宿主文件系统和设备；
- 临时工作目录、非特权用户、CPU/GPU/内存/磁盘/进程/时间限制；
- HTML 使用隔离 origin、严格 CSP 和 iframe sandbox，禁用持久存储和跨窗访问；
- SVG 清除脚本、事件处理器、外部资源、危险 URL 和嵌入 HTML；
- 运行日志脱敏，不回显密钥或私人内容。

容器/沙箱只是多层防御的一部分，不把“运行在 Docker/Podman”自动视为安全。

### 11.3 许可与真实性

- 摄入时保存许可快照、作者、来源和允许用途；
- 生成资产记录使用的原始数据、参考媒体、模型和人工修改；
- 生成式概念图明确标为生成内容；
- 实验照片、测量图和研究数据不得用生成内容替换；
- 公开导出包含 attribution、许可和可选 C2PA/内容凭证；
- 不生成未经授权的真实人物声音或肖像模仿。

## 12. 多用户和本地优先

- SourceAsset、DerivedAsset、索引、MediaManifest、RenderJob、缓存和导出均带租户、用户和项目；
- 检索和对象读取前置租户过滤，输出前再次校验；
- 内容哈希去重不跨租户泄露“其他用户已有此文件”；
- 私人原文、索引、可编辑源和 provenance 默认本地加密；
- 云端 Qwen 只接收当前步骤所需的压缩资产、片段和最小记忆切片；
- 渲染队列消息携带不可伪造租户上下文；
- 共享科学项目只共享用户显式选择的媒体对象和版本；
- 删除源资产时，派生物、缩略图、字幕、向量、缓存和导出按出处图级联。

## 13. 无障碍交付

每个发布包至少评估：

- 信息图有简短 alt 和必要长描述；
- 复杂图提供可访问数据表或关系说明；
- 公式同时具有可视表达、MathML/结构表达和可理解朗读；
- 音频有转录，视频有同步字幕，必要时有音频描述；
- 交互可键盘完成，焦点顺序和状态变化可感知；
- 颜色不作为唯一编码，对比度满足目标；
- 动画支持暂停、逐步、速度控制和减少动画；
- 自动播放默认关闭；
- 时间限制可延长或取消；
- 静态替代仍能传达核心 claim。

自动检测只能覆盖部分要求，必须加入屏幕阅读器、键盘、低视力和目标用户测试。

## 14. 前端多模态工作台

工作台不只显示最终预览，还应包含：

- 媒体选择理由和可切换方案；
- 原始资产、解析层、OCR/ASR 置信区域；
- claim/data/formula/事实锁绑定；
- SceneSpec、Storyboard、图表规格或交互状态；
- 生成代码与依赖白名单；
- 任务状态、日志、资源、重试和失败原因；
- 关键帧、版本 diff 和局部 patch；
- 科学、工程、安全、无障碍四类检查报告；
- 人工确认和发布历史；
- 可编辑源、渲染物和完整导出包。

用户可以重做某一步，而不是每次整项重生成；错误产物保留为失败版本，不污染已发布版本。

## 15. 评测体系

### 15.1 摄入

- 文本阅读顺序、表格、公式、OCR/ASR、关键帧和时空定位准确率；
- 低置信区域召回率；
- 原始资产—派生资产出处完整率；
- 恶意、异常和注入样本隔离率。

### 15.2 科学和视觉

- claim 覆盖率和事实锁保持率；
- 图表数据点、轴、单位、误差和图例准确率；
- 公式解析和等价率；
- 动画关键对象、顺序、几何/物理约束正确率；
- 音频数字、单位、术语和公式朗读准确率；
- 交互状态覆盖、数值正确和非法输入拒绝率。

### 15.3 工程与无障碍

- 首次运行成功率、有限修复成功率、平均重试和重现率；
- 沙箱逃逸、网络/文件越权和资源耗尽必须为零；
- WCAG 自动规则、键盘、屏幕阅读和字幕/转录覆盖；
- 跨租户资产、缓存和任务泄漏必须为零。

### 15.4 教学价值

- 静态图、动画、交互和纯文本在同一学习目标下的理解、保持和迁移；
- 媒体选择正确率；
- 认知负担和完成时间；
- “增加媒体但无增益”的比例；
- 目标用户盲测和专家科学审查。

基线/消融：

- 裸 Qwen 直接生成；
- 只有生成 + 渲染；
- 加 Storyboard；
- 加事实锁/数据绑定；
- 加沙箱与有限修复；
- 完整流水线；
- 去掉无障碍或人工确认的消融。

## 16. 灵感材料取舍

### 16.1 ManimCat

**直接采用：**

- 问题规划、设计与代码生成分离；
- Storyboard 中间产物；
- API 白名单；
- 静态检查、运行错误反馈和最小 patch；
- 静态图与动画按任务选择；
- 有上限的自动修复。

**调整采用：**

- 模板从“知识点关键词匹配”升级为领域包注册的已验证媒体模板；
- Storyboard 加入 Claim/Data/Formula/FactLock 和无障碍字段；
- 渲染环境改为无网、最小权限和逐账户隔离；
- 工作流/智能体双模式统一为同一可审计运行协议。

**明确舍弃：**

- 静态检查失败后仍继续渲染并交付；
- 渲染成功即视为完成；
- 全量重生成代替局部修补；
- 所有主题优先动画。

### 16.2 LlamaIndex 灵感

- 采用原始 Document/Node 与派生结构、可组合变换、内容哈希缓存和关系追踪；
- 调整为跨媒体 SourceAsset/DerivedAsset/Locator 模型；
- 不把多模态模型回答直接视为 Evidence；
- 不让框架私有对象成为长期媒体领域模型。

### 16.3 Qwen 路由灵感

- 采用按能力和风险路由、严格 Schema、显式降级、原始输入保留和运行记录；
- OCR/ASR/视觉/TTS 结果都是派生候选；
- 模型版本、区域、价格、限流和具体 API 由下一张技术选型票重新核验；
- 禁止供应商内置工具绕过本地证据、权限和沙箱协议。

### 16.4 其他灵感

- 采用小型可审计内核、类型化工作流、有限循环和中间产物；
- 采用事实锁与人味表达双重复核；
- 画像只通过最小记忆切片改变呈现；
- 舍弃自由群聊式多智能体、无限自动循环和未审查代码热加载。

## 17. 对后续票据的硬约束

### 智能体编排

- 摄入、解析、教学设计、媒体选择、分镜、规格/代码生成、静态检查、沙箱、渲染、科学验证、无障碍、人工确认和发布为独立节点；
- 节点交换版本化 Schema；
- 读外部媒体的节点无高风险工具权限；
- 修复循环有固定次数、范围和停止状态。

### 技术选型

- 必须核验 Qwen 文本/视觉/OCR/ASR/TTS 能力及区域；
- 选择声明式图表、SVG/公式、动画、浏览器沙箱、媒体处理和对象存储组件；
- Conda `agent` 只锁定本地开发工具链；生产的手动分进程、统一 CLI、Docker 和 Podman 使用同一应用依赖锁、字体、编解码器、沙箱和健康检查；
- GPU 充足不能成为取消资源配额和隔离的理由。

### 系统架构

- 媒体数据模型独立于模型与渲染库；
- 对象存储、任务队列、关系库、日志和本地缓存共享租户与删除语义；
- 可编辑源、渲染物、验证和 provenance 分层保存。

## 18. 验收标准

1. 所有输入保存原件、派生层、哈希、许可和时空定位；
2. 文本、PDF、图像、公式、表格、音频、视频和 HTML 各有隔离解析路径；
3. 五类输出均有机器可读权威源，而非只有像素或音频；
4. 任一媒体中的科学陈述可回到 Claim/Evidence/FactLock；
5. 简单产物走轻链，代码交互和动画强制走全链；
6. 生成代码无法访问网络、宿主文件、密钥或其他租户；
7. 图表、公式、动画、音频和交互分别通过专用科学质量门；
8. 自动修复达到上限后停止，失败产物不标记完成；
9. 每个发布包具有可访问替代和可编辑源；
10. 两个用户使用同名同内容媒体时无跨账户召回、缓存和侧信道；
11. 删除原始资产能追踪并处理全部派生物；
12. 评测证明所选媒体相对纯文本带来学习或表达增益。

## 19. 研究置信度与待核验项

- **高置信度**：媒体目标选择、原始/派生分离、结构化可编辑源、跨媒体科学绑定、渲染与科学双门、沙箱、无障碍和租户隔离是必要设计。
- **高置信度**：动画和交互必须使用比静态图更严格的分镜、代码、运行和状态验证。
- **中高置信度**：SVG、MathML、WebVTT、声明式图表、Manim 和 C2PA 能提供合适的标准/实现基础，但具体组合需验证。
- **待技术票核验**：Qwen 型号与接口、OCR/ASR/TTS、图表/动画库、浏览器隔离、GPU 沙箱、字体和编解码器版本。
- **待领域专家核验**：不同科学领域的图表误导规则、公式等价、模拟真实性、动画叙事和高风险图像要求。
- **待真实用户核验**：媒体选择对理解、保持、迁移和认知负担的实际影响。
