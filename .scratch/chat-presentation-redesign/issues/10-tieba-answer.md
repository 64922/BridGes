# 10 — 恢复贴吧总结正文并按需查看帖子依据

**What to build:** 用户首先读到围绕话题组织的总结，点击引用再查看帖子与回复；网友体验、官方规定和未读内容的边界清楚可见。

**Blocked by:** 07 — 内联呈现交付状态、失败与真实恢复；08 — 从真实引用打开右侧资料并继续对话

**Status:** ready-for-human

> 已于 2026-10-17 经用户确认发布。仅在本票所有阻塞项完成验收后开始；无阻塞票可立即领取。设计与原型已批准，无需重新决定视觉方向。

## 当前事实与动机

当前消息渲染在存在贴吧结果投影时会隐藏普通正文，依赖卡片展示完整证据。本票必须明确正文权威来源和去重，不能仅删除卡片后留下空回答。

## 工作范围

- 核对正文与已提交主题段落的内容关系，选择现有权威内容形成连续总结，并避免两份总结重复展示。
- 通过帖子、楼层、时间和已读取范围连接右侧资料；官方核验保留独立语义。
- 登录等待、安全验证、帖链降级及回复读取失败按真实能力给出反馈。

## 验收标准

- [x] 成功时默认显示完整话题总结，不因存在贴吧投影而把正文隐藏。
- [x] 只有帖子链接时明确“未取得回复内容”，搜索摘要不被当作已读帖子或吧友结论。
- [x] 局部回复读取失败保留已读内容并标明边界，不能把缺失部分补写成完整共识。
- [x] 网友说法和官方核验结论可区分；核验无证据或适用性不足时不显示“官方确认”。
- [x] 引用能查看对应帖子、楼层或已有定位信息，缺定位时诚实说明，不编造。
- [x] 等待登录或安全验证时给出现有合法动作，不读取系统浏览器凭据或绕过验证。
- [x] 恢复入口必须对应现有服务实际可恢复范围；若只能重跑本轮，不照抄原型“只重试两条回复”的承诺。
- [x] 流式、重试和历史重开不丢已读范围、降级说明及同轮来源关系。

## 验证方式

覆盖完整内容、仅链接、部分回复失败、需要认证、官方未核实和重开历史。先写能复现删卡后正文丢失的检查，再完成替换。

每票完成受影响行为的测试与项目要求的检查；涉及前端必须完成生产构建。复用已有可用依赖，不例行重装。外部依赖不可用、既有失败和本票新增失败分别记录，未验证项不得标为通过。最终整合票不能替代本票自身的验证。

## 范围外

不扩大贴吧采集范围、不修复无关爬取链路，不把外部不可得问题通过 UI 掩盖。

## 执行约束

遵循已批准的 ADR-0044、设计原则 0005、本功能 PRD 及仓库准则。在 Conda 的 agent 环境开发。优先复用现有接口与领域能力；只有用例证明现有合同不足时才改协议，并在同票完成服务端、生成类型、消费端和测试。无必要不改 schema，不搬迁数据。

本票必须交付可演示或可验证的完整行为，而不是只有接口、组件或截图。内部路径直接替换，不引入兼容 shim、双写或长期双实现。只修改本票需要的范围；不要在执行中顺便重写业务。

## 完成后的交接

说明贴吧正文权威来源、字段去重规则、真实恢复粒度以及采集链路尚存限制。

交接记录包含实际变更、验证命令和结果、必要截图／服务证据、遗留限制与回退方式；只有行为验收通过才解除后续票的阻塞。

### 实际变更

- 删除 `TiebaResearchCard`，新增 `TiebaAnswer`：纯贴吧回合的正文按权威投影重建，不再隐藏正文，也不再重复渲染服务端同一份纯文本总结。
- 正文权威来源与回退顺序：`summary` + `summary_citations` → `summary_claims` → `sections` → 仅 `status=success` 且无任何结构时用 `message.plainText`。服务端 `content` 仍保留给复制/导出，不作为可见正文重复源。
- 纯贴吧与复合回合用 `turnResult` 的请求/实际/能力/已交付/阻塞模块判断；流式早期用其他模块投影兜底。复合回合保留服务端综合回答，只追加 `TiebaCompositeEvidence`（真实引用入口 + 读取范围/官方核验），不再生成第二份贴吧总结。
- 去重：正文使用 summary/claims/sections 时，折叠依据不再重复 sections；旧失败只在无 `turnResult` 时显示整轮重跑按钮，文案改为“重跑本轮”，并注明会重跑整轮对话（包含贴吧检索）。
- 新增 `TiebaEvidencePanel`（右侧）：只读本轮投影，不发额外网络请求；展示引用摘录、楼层/时间、帖子读取范围、已读回复与当前楼层高亮。缺楼层、缺帖子投影时分别给出诚实说明，不补写回复。
- 官方核验继续与吧友总结分区；无适用证据时显示“官方未核实”，不使用“官方确认”。
- 等待登录/安全验证只给合法动作：在专用会话完成验证后回复“继续”，不读取系统浏览器凭据、不绕过验证。
- `ActiveRun` 与 `activeRunFromAssistant` 保留 `tiebaResearch`，刷新/恢复同一运行不丢投影；新运行的恢复入口仍由 `DeliveryStatus` 按真实 `recovery` 能力提供。
- 新增导出类型 `TiebaSummaryCitation`（`apps/web/src/lib/api/contracts/modules.ts`），无后端协议、schema 或数据迁移变更。
- 更新 `issue21-desktop-acceptance.spec.ts` 的贴吧 testid 前缀为 `^tieba-answer`。

### 遗留限制与回退

- 真实贴吧上游可能在子图执行阶段长时间不产生投影（见上方 issue21 失败），本票不扩大采集范围、不修复该链路；在投影到达前页面只显示通用的生成中状态。
- “重试”仍是整轮重新生成：旧尝试记录保留在尝试历史，但本票没有把旧尝试的贴吧投影重新展开为正文/依据；同一运行的刷新恢复与历史重开保留完整投影。
- 回退：revert 本票提交即可恢复旧 `TiebaResearchCard` 路径；无数据库变更，历史消息与既有投影不受影响。
