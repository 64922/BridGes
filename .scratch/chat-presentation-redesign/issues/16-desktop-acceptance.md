## 当前事实与动机

各功能票必须已经自行通过验证；本票承担跨场景组合、视觉一致性与最终运行门禁，不把前序票的测试拖到最后。

## 工作范围

- 以批准原型核对正式页面的首页、连续正文、单行过程、右侧资料与异常恢复，逐条核销设计原则。
- 把普通多轮、论文、贴吧、通勤、学习、附件、媒体和旧历史串成跨场景旅程。
- 完成项目检查、构建、真实链路证据及文档状态更新，移除只为调试或迁移留下的本次临时路径。

## 验收标准

- [ ] 1280×720、1440×900、1920×1080 以及常见桌面缩放下布局可读，侧栏／面板／输入不互相遮挡；不扩张移动端支持承诺。
- [ ] 所有核心结论默认可读，详情默认关闭，生成不会自动展开过程或抢占面板。
- [ ] 账户切换、会话切换、历史重开、资料读取失败、断流、停止及重试组合不串状态或泄漏信息。
- [ ] 键盘顺序、焦点归还、中文输入法、减少动态效果和必要状态播报经过实际操作检查。
- [ ] 正式 UI、API、执行器、SSE 与持久化共同参与验收；替代外部模型或来源的范围明确标注。
- [ ] 真实供应商不可用时记录阻塞与部分结果，不报告该能力真实验证通过，不用固定成功回调顶替。
- [ ] 项目定义的检查与前端生产构建通过；既有失败若存在需给出基线与本次差异，不能默默跳过。
- [ ] 原型体验菜单、示例账户、硬编码回答、模拟时序和内存演示笔记没有进入生产路径。
- [ ] 已实施部分更新上下文和 ADR 实施说明；仍有关键未验收项时不得宣布整项交付完成。

## 验证方式

交付可重放的验收步骤、测试命令与结果、正式 UI 截图、变更前后行为差异、外部依赖限制和回退验证。复用已有测试服务隔离，不用真实个人数据制作公开夹具。

每票完成受影响行为的测试与项目要求的检查；涉及前端必须完成生产构建。复用已有可用依赖，不例行重装。外部依赖不可用、既有失败和本票新增失败分别记录，未验证项不得标为通过。最终整合票不能替代本票自身的验证。

## 范围外

不进行无关清理、不合并或发布未经授权的部署，不以原型测试结果替代生产验收。

## 执行约束

遵循已批准的 ADR-0044、设计原则 0005、本功能 PRD 及仓库准则。在 Conda 的 agent 环境开发。优先复用现有接口与领域能力；只有用例证明现有合同不足时才改协议，并在同票完成服务端、生成类型、消费端和测试。无必要不改 schema，不搬迁数据。

本票必须交付可演示或可验证的完整行为，而不是只有接口、组件或截图。内部路径直接替换，不引入兼容 shim、双写或长期双实现。只修改本票需要的范围；不要在执行中顺便重写业务。

## 完成后的交接

形成最终验收记录，给出通过／失败／未验证的明确清单、真实服务边界及保留数据的回退方式。

交接记录包含实际变更、验证命令和结果、必要截图／服务证据、遗留限制与回退方式；只有行为验收通过才解除后续票的阻塞。
