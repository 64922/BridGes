## 验收标准

- [x] 1280×720、1440×900、1920×1080 以及常见桌面缩放下布局可读，侧栏／面板／输入不互相遮挡；不扩张移动端支持承诺。
- [x] 所有核心结论默认可读，详情默认关闭，生成不会自动展开过程或抢占面板。

- [ ] 真实供应商不可用时记录阻塞与部分结果，不报告该能力真实验证通过，不用固定成功回调顶替。
- [x] 项目定义的检查与前端生产构建通过；既有失败若存在需给出基线与本次差异，不能默默跳过。
- [x] 原型体验菜单、示例账户、硬编码回答、模拟时序和内存演示笔记没有进入生产路径。

## 验证方式

交付可重放的验收步骤、测试命令与结果、正式 UI 截图、变更前后行为差异、外部依赖限制和回退验证。复用已有测试服务隔离，不用真实个人数据制作公开夹具。

每票完成受影响行为的测试与项目要求的检查；涉及前端必须完成生产构建。复用已有可用依赖，不例行重装。外部依赖不可用、既有失败和本票新增失败分别记录，未验证项不得标为通过。最终整合票不能替代本票自身的验证。

## 范围外

不进行无关清理、不合并或发布未经授权的部署，不以原型测试结果替代生产验收。

## 执行约束

遵循已批准的 ADR-0044、设计原则 0005、本功能 PRD 及仓库准则。在 Conda 的 agent 环境开发。优先复用现有接口与领域能力；只有用例证明现有合同不足时才改协议，并在同票完成服务端、生成类型、消费端和测试。无必要不改 schema，不搬迁数据。

本票必须交付可演示或可验证的完整行为，而不是只有接口、组件或截图。内部路径直接替换，不引入兼容 shim、双写或长期双实现。只修改本票需要的范围；不要在执行中顺便重写业务。
