# 05 — 让普通回答形成连续可阅读正文

**What to build:** 用户在真实流式回答和历史回答中连续阅读段落、标题、列表及已有富内容，用户消息保留气泡，助手正文不被外层卡片包裹。

**Blocked by:** 02 — 整理消息呈现职责，保留全部结果投影

**Status:** ready-for-agent

> 已于 2026-10-17 经用户确认发布。仅在本票所有阻塞项完成验收后开始；无阻塞票可立即领取。设计与原型已批准，无需重新决定视觉方向。

## 当前事实与动机

当前历史组装主要将内容作为保留换行的文本段落，需确认现有富文本能力与依赖，避免只为原型做静态排版。

## 工作范围

- 为普通对话建立真实内容到连续正文的渲染路径，并与历史读取共用。
- 保留文本原文及复制、朗读所需语义；支持设计需要的标题、列表、代码、表格及现有公式能力。
- 在协议与视图边界处理不可信内容。新增成熟渲染依赖前先核查现有依赖、类型定义及许可，不手写通用 Markdown 解析器。

## 验收标准

- [ ] 同一回答在流式结束、刷新和重新打开后内容一致，不重复段落，不丢换行或标点。
- [ ] 助手正文无统一大卡片；通过标题、段落和留白组织阅读，用户消息保留轻量气泡。
- [ ] 流式片段尚未闭合的标记不会导致页面崩溃或把后续整段吞入错误容器。
- [ ] 代码、表格与长链接在自身范围内滚动或换行，不撑破主阅读列。
- [ ] 用户文本按文本处理；助手内容中的脚本、危险 URL 和原始 HTML 不成为可执行内容。
- [ ] 复制与朗读取得完整可读回答，不混入工具标签或隐藏的流程日志。
- [ ] 不擅自把用户上滚位置拉回底部，流式更新不抢焦点、不逐 token 播报。
- [ ] 普通对话可独立演示；尚未迁移的模块投影仍可读，不在本票一刀切删除。

## 验证方式

使用真实保存的多段回答回放流式与历史两条路径，覆盖长文本、未闭合标记、代码与表格、恶意内容、滚动位置和复制。新增缺陷先复现再修复。

每票完成受影响行为的测试与项目要求的检查；涉及前端必须完成生产构建。复用已有可用依赖，不例行重装。外部依赖不可用、既有失败和本票新增失败分别记录，未验证项不得标为通过。最终整合票不能替代本票自身的验证。

## 范围外

不重写模型输出策略、引用生成协议或各业务模块，不把模拟示例当真实回答。

## 执行约束

遵循已批准的 ADR-0044、设计原则 0005、本功能 PRD 及仓库准则。在 Conda 的 agent 环境开发。优先复用现有接口与领域能力；只有用例证明现有合同不足时才改协议，并在同票完成服务端、生成类型、消费端和测试。无必要不改 schema，不搬迁数据。

本票必须交付可演示或可验证的完整行为，而不是只有接口、组件或截图。内部路径直接替换，不引入兼容 shim、双写或长期双实现。只修改本票需要的范围；不要在执行中顺便重写业务。

说明已支持的正文格式、内容清理边界、纯文本提取与剩余业务容器归属。

交接记录包含实际变更、验证命令和结果、必要截图／服务证据、遗留限制与回退方式；只有行为验收通过才解除后续票的阻塞。
