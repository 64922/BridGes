# 09 — 把论文发现结果融入正文与资料阅读

**What to build:** 用户直接读到围绕研究问题组织的论文推荐与阅读顺序，按需查看论文依据、摘要和真实读取范围，检索过程不再占据整块功能卡片。

**Blocked by:** 07 — 内联呈现交付状态、失败与真实恢复；08 — 从真实引用打开右侧资料并继续对话

**Status:** ready-for-agent

> 已于 2026-10-17 经用户确认发布。仅在本票所有阻塞项完成验收后开始；无阻塞票可立即领取。设计与原型已批准，无需重新决定视觉方向。

## 当前事实与动机

现有论文能力包含条件来源、候选筛选、关联依据、摘要／部分正文／全文读取范围和引用扩展，不能仅保留原型中的三篇静态论文。

## 工作范围

- 将已有推荐、适用理由、阅读角色与顺序转换为正文中的自然段落或清晰列表。
- 把候选详情、检索记录和引用扩展放进可追溯的资料／过程入口，保留必要限制在正文。
- 复用论文查询和投影，不从浏览器重新执行第二套检索。

## 验收标准

- [ ] 按用户问题组织推荐，不再显示独立“论文搜索结果卡”或与正文重复的推荐清单。
- [ ] 论文身份、年份、来源、链接与读取范围来自同轮真实投影。
- [ ] 仅摘要时明确说明，不能把摘要预览称为全文已读；不可得全文有准确反馈。
- [ ] 澄清、检索中、无结果、来源受限、部分成功、失败、停止各有可见状态与合法操作。
- [ ] 用户选择某篇查看详情后继续追问，面板维持该论文，不被下一轮候选列表替换。
- [ ] 条件来自用户表达还是推断的现有区分保留，筛选剔除依据能按需找到。
- [ ] 现有引用图或等价关系信息仍可按需查看，不因默认隐藏卡片被删除。
- [ ] 流式交付与历史重开保持推荐顺序、引用和证据限制一致。

## 验证方式

以问题驱动的真实论文流程验证有结果、零结果、只取得摘要及部分来源失败；外部来源夹具明确标注，另记真实供应商可得性，不能混称真实检索通过。

每票完成受影响行为的测试与项目要求的检查；涉及前端必须完成生产构建。复用已有可用依赖，不例行重装。外部依赖不可用、既有失败和本票新增失败分别记录，未验证项不得标为通过。最终整合票不能替代本票自身的验证。

## 范围外

不改变排序策略、检索源、查询合同和全文获取能力，不复制原型硬编码论文数据。

## 执行约束

遵循已批准的 ADR-0044、设计原则 0005、本功能 PRD 及仓库准则。在 Conda 的 agent 环境开发。优先复用现有接口与领域能力；只有用例证明现有合同不足时才改协议，并在同票完成服务端、生成类型、消费端和测试。无必要不改 schema，不搬迁数据。

本票必须交付可演示或可验证的完整行为，而不是只有接口、组件或截图。内部路径直接替换，不引入兼容 shim、双写或长期双实现。只修改本票需要的范围；不要在执行中顺便重写业务。

## 完成后的交接

交付原论文卡信息去向核对表及三类主要状态的正文／详情截图。

交接记录包含实际变更、验证命令和结果、必要截图／服务证据、遗留限制与回退方式；只有行为验收通过才解除后续票的阻塞。
