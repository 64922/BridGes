# 14 — 在正文中交付图片与视频并保留生成状态

**What to build:** 用户在相关解释旁看到真实生成的图片或视频，能够预览、播放或下载，并清楚知道尚在生成、失败或产物不可用。

**Blocked by:** 07 — 内联呈现交付状态、失败与真实恢复；08 — 从真实引用打开右侧资料并继续对话

**Status:** ready-for-agent

> 已于 2026-10-17 经用户确认发布。仅在本票所有阻塞项完成验收后开始；无阻塞票可立即领取。设计与原型已批准，无需重新决定视觉方向。

## 当前事实与动机

图片与视频任务有独立状态和资产落库时机。允许媒体容器，但不能把生成状态、正文和产物成功混为同一个结果卡。

## 工作范围

- 复用现有媒体任务投影和授权资产读取，把可用媒体嵌入相关正文附近。
- 过程进入统一进度入口，失败与必要恢复操作保持就近可见；完整媒体或详情按需在右侧打开。
- 保持媒体完成后刷新权威消息的既有逻辑，避免重复轮询与重复插入。

## 验收标准

- [ ] 任务生成成功但资产未可访问时，不显示可下载的假链接或成功缩略图。
- [ ] 图片、视频和文字说明属于同一任务及消息，重复完成事件不插入重复产物。
- [ ] 排队、处理中、失败、停止和成功真实呈现；恢复动作按实际能力决定。
- [ ] 媒体加载失败不删除说明正文，用户能返回对话并获取准确反馈。
- [ ] 视频不自动播放；已有播放控制、图片替代文字和下载权限保留。
- [ ] 切换会话、关闭预览或账户变化释放对象 URL、播放器与轮询资源。
- [ ] 历史产物仍可读，资产已删除或无权限时明确说明，不泄漏旧缓存。
- [ ] 媒体容器随窗口变化保持比例，不阻塞文本阅读或撑破页面。

## 验证方式

覆盖图片和视频各一条成功路径、生成失败、资产读取失败、历史重开和跨账户拒绝；外部模型或渲染器可用性单独注明。

每票完成受影响行为的测试与项目要求的检查；涉及前端必须完成生产构建。复用已有可用依赖，不例行重装。外部依赖不可用、既有失败和本票新增失败分别记录，未验证项不得标为通过。最终整合票不能替代本票自身的验证。

## 范围外

不新增生图／视频模型、不改变计费或后台生成管线，不默认自动播放。

## 执行约束

遵循已批准的 ADR-0044、设计原则 0005、本功能 PRD 及仓库准则。在 Conda 的 agent 环境开发。优先复用现有接口与领域能力；只有用例证明现有合同不足时才改协议，并在同票完成服务端、生成类型、消费端和测试。无必要不改 schema，不搬迁数据。

本票必须交付可演示或可验证的完整行为，而不是只有接口、组件或截图。内部路径直接替换，不引入兼容 shim、双写或长期双实现。只修改本票需要的范围；不要在执行中顺便重写业务。

## 完成后的交接

交接记录包含实际变更、验证命令和结果、必要截图／服务证据、遗留限制与回退方式；只有行为验收通过才解除后续票的阻塞。
