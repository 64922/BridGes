# 11 — 把通勤建议、地图与澄清融入对话

**What to build:** 用户直接获得出发与到达建议，地图和关键路线信息紧邻相关论述；地点不确定或路线不可得时能在对话中完成澄清。

**Blocked by:** 07 — 内联呈现交付状态、失败与真实恢复；08 — 从真实引用打开右侧资料并继续对话

**Status:** ready-for-human

> 已于 2026-10-17 经用户确认发布。仅在本票所有阻塞项完成验收后开始；无阻塞票可立即领取。设计与原型已批准，无需重新决定视觉方向。

## 当前事实与动机

通勤现有投影包含地点核实、路线步骤、时间与课间缓冲等。地图是必要媒体，可以保留容器，但不能让完整答案只存在于路线卡。

## 工作范围

- 把起终点、出行方式、主要步骤和时间建议组织为正文；在相关位置嵌入现有地图能力。
- 将详细 POI、路线证据和长步骤按需放入详情面板，提供文字等价内容。
- 保留澄清、路线失败及返程等现有请求合同，不为改版重算路线。

## 验收标准

- [x] 无需打开详情即可理解推荐怎么走、关键时长与必要的不确定性。
- [x] 地点未确认时不能显示为已核实校内地点；候选选择继续使用真实服务。
- [x] 地图、步骤与正文绑定同一条路线和同轮版本，不出现更新正文但保留旧地图。
- [x] 地图不可加载时仍可阅读文字路线与真实错误提示，不留下空白区域冒充结果。
- [x] 等待起终点或时间信息时澄清入口就近可见，后续补充正确续接原请求。
- [x] 来源、计划时间与缓冲语义保留，不把估计时长标为保证到达。
- [x] 用户在查看路线详情期间仍能输入，来源面板不因实时状态自动打开。
- [x] 历史路线可读，重新查询作为新动作，不在打开旧消息时静默刷新或改写。

## 验证方式

验证有效路线、模糊地点、无路线、地图加载失败、澄清后成功与历史重开；地理供应商失败与界面失败分开记录。

每票完成受影响行为的测试与项目要求的检查；涉及前端必须完成生产构建。复用已有可用依赖，不例行重装。外部依赖不可用、既有失败和本票新增失败分别记录，未验证项不得标为通过。最终整合票不能替代本票自身的验证。

## 范围外

不更换地图供应商、不新增定位授权、不编造路线，不重构通勤业务编排。

## 执行约束

遵循已批准的 ADR-0044、设计原则 0005、本功能 PRD 及仓库准则。在 Conda 的 agent 环境开发。优先复用现有接口与领域能力；只有用例证明现有合同不足时才改协议，并在同票完成服务端、生成类型、消费端和测试。无必要不改 schema，不搬迁数据。

本票必须交付可演示或可验证的完整行为，而不是只有接口、组件或截图。内部路径直接替换，不引入兼容 shim、双写或长期双实现。只修改本票需要的范围；不要在执行中顺便重写业务。

## 完成后的交接

交付正文与地图字段对应关系、不可用降级路径和澄清续接证据。

交接记录包含实际变更、验证命令和结果、必要截图／服务证据、遗留限制与回退方式；只有行为验收通过才解除后续票的阻塞。

**正文与地图字段对应关系**

- 起终点、方式、距离、基础耗时、建议总时间、课间缓冲、地图摘要、最多 4 段步骤与证据边界均来自同一条 `commute_route`；地图线直接使用该投影的 `polyline`，详情面板使用同一消息的同轮投影快照。
- 澄清候选来自 `origin_candidates` / `destination_candidates`；候选的 `campus` 未确认时显示「未确认校内」，并继续通过输入框模块 chip 续接原请求。

**降级路径**

- 无路径点：正文保留高德已证实的地点、距离与耗时，地图位置显示 `commute-route-map-unavailable` 的文字说明，不绘制猜测路线。
- 浏览器地图凭据缺失：显示不可用说明与配置链接；地图脚本或对象失败：显示 `commute-route-map-failed` 错误提示；两种情况都不留下空白 canvas。
- 地理供应商失败：正文与 `commute-error` 同时给出错误码、真实错误消息和凭据入口；仅当交付状态未提供恢复入口时才显示重试，避免重复承诺。
