# 04 — 交付新对话布局与真实首轮发送

**What to build:** 用户进入新的简洁桌面对话页，在输入区选择模式、发送第一条消息，并自然进入同一风格的正式会话。

**Blocked by:** 01 — 整理对话运行职责，保持发送与恢复行为；03 — 整理输入区职责，保持发送、附件与听写能力

**Status:** ready-for-agent

> 已于 2026-10-17 经用户确认发布。仅在本票所有阻塞项完成验收后开始；无阻塞票可立即领取。设计与原型已批准，无需重新决定视觉方向。

## 当前事实与动机

采用已验收原型的侧栏、顶部栏、静态欢迎区与输入列；正式入口必须接入现有认证、最近会话和首轮创建。

## 工作范围

- 调整正式主对话的侧栏、顶部、欢迎区与输入区，正文和输入保持限宽对齐；使用现有 BridGes 品牌。
- 将模式选择放入输入区，静态欢迎替代轮换名言；轻量建议只调用已支持的实际入口。
- 对话开始后输入区沉底，消息区独立滚动；保留搜索、知识库、画像、账户及历史菜单的真实导航。

## 验收标准

- [ ] 未发送时可选择日常陪伴／学习模式，首轮服务端锁定后只能显示固定模式，刷新与重新打开一致。
- [ ] 首轮成功创建后最近会话出现且标题正确；失败时用户仍看到草稿、具体反馈和可用的恢复入口。
- [ ] 无轮换名言、营销横幅、功能卡片网格或原型体验菜单；不复制示例账户和静态历史列表。
- [ ] 侧栏折叠、展开、历史搜索和既有重命名／置顶／删除等入口仍可操作。
- [ ] 知识库、画像、登录及设置等共享外壳页面不因局部样式修改失去导航或布局。
- [ ] 输入区保留附件、模块、已有听写等真实能力，未实现能力不能作为可用按钮展示。
- [ ] 1280×720、1440×900、1920×1080 下输入区可见、阅读列限宽，无页面级横向溢出。
- [ ] 加载、空态、认证过期、历史加载失败和重试可区分；键盘顺序及焦点反馈可用。

## 验证方式

使用正式认证、首轮创建、持久化与会话路由验证两种模式，刷新后核对模式和最近历史；截图比较首页与首轮后的布局，不只测模板页。

每票完成受影响行为的测试与项目要求的检查；涉及前端必须完成生产构建。复用已有可用依赖，不例行重装。外部依赖不可用、既有失败和本票新增失败分别记录，未验证项不得标为通过。最终整合票不能替代本票自身的验证。

## 范围外

不重做知识库或画像业务页面，不增加移动端产品范围，不改变日常能力启动授权。

## 执行约束

遵循已批准的 ADR-0044、设计原则 0005、本功能 PRD 及仓库准则。在 Conda 的 agent 环境开发。优先复用现有接口与领域能力；只有用例证明现有合同不足时才改协议，并在同票完成服务端、生成类型、消费端和测试。无必要不改 schema，不搬迁数据。

本票必须交付可演示或可验证的完整行为，而不是只有接口、组件或截图。内部路径直接替换，不引入兼容 shim、双写或长期双实现。只修改本票需要的范围；不要在执行中顺便重写业务。

## 完成后的交接

交付三种桌面尺寸截图、首轮成功／失败证据和样式影响范围。

交接记录包含实际变更、验证命令和结果、必要截图／服务证据、遗留限制与回退方式；只有行为验收通过才解除后续票的阻塞。
