# 01 — 整理对话运行职责，保持发送与恢复行为

**What to build:** 用户发送、停止、重试、刷新和切换会话时仍得到与改造前一致的结果，为后续布局改版提供稳定的运行边界。

**Blocked by:** None — 可立即开始

**Status:** ready-for-agent

> 已于 2026-10-17 经用户确认发布。仅在本票所有阻塞项完成验收后开始；无阻塞票可立即领取。设计与原型已批准，无需重新决定视觉方向。

## 当前事实与动机

现有正式对话页约 1105 行，混合权威历史加载、首轮创建、SSE 订阅、运行投影、学习操作和页面布局。本票是有回归证据的前置整理，不改变界面或业务策略。

## 工作范围

- 先记录普通发送、重试、刷新恢复与会话切换的基线；复用已有测试，缺失的行为检查在重构前补齐。
- 按现有职责拆开运行控制、流事件到视图状态的转换和页面组合；明确唯一状态所有者，避免多个组件各自订阅同一运行。
- 保持协议投影与视图模型的边界转换；创建、停止和重试命令仍调用现有服务，账户与会话标识随操作传递。

## 验收标准

- [ ] 同一首轮重复提交或网络重发不产生第二个会话、用户消息或运行。
- [ ] 刷新进行中的会话后，已接收正文和后续事件正确衔接，不重复追加已提交结果。
- [ ] 终态交接到权威历史时不闪空白、不重复答案、不丢失停止或错误状态。
- [ ] 切换会话或账户时释放旧订阅，迟到事件不能写入新会话；取消本地订阅不等同于擅自停止后台运行。
- [ ] 现有学习诊断重试、记录纠正和续学操作仍到达原服务，不能在整理时删除。
- [ ] 本票涉及的拆分结果及页面组合文件均不超过 500 行；按真实职责拆分，不引入通用事件平台或兼容转发层。
- [ ] API、数据库和用户可见行为保持不变；无新旧状态双写。

## 验证方式

通过正式创建、订阅、停止、重试和历史读取路径验证；可替换外部模型，但不能 mock 掉整段会话生命周期。重点覆盖断流后恢复、双击发送、停止与终态竞态、切换后迟到事件。

每票完成受影响行为的测试与项目要求的检查；涉及前端必须完成生产构建。复用已有可用依赖，不例行重装。外部依赖不可用、既有失败和本票新增失败分别记录，未验证项不得标为通过。最终整合票不能替代本票自身的验证。

## 范围外

不重写 SSE 协议、运行编排或幂等规则；不改视觉，不新增数据库迁移。

## 执行约束

遵循已批准的 ADR-0044、设计原则 0005、本功能 PRD 及仓库准则。在 Conda 的 agent 环境开发。优先复用现有接口与领域能力；只有用例证明现有合同不足时才改协议，并在同票完成服务端、生成类型、消费端和测试。无必要不改 schema，不搬迁数据。

本票必须交付可演示或可验证的完整行为，而不是只有接口、组件或截图。内部路径直接替换，不引入兼容 shim、双写或长期双实现。只修改本票需要的范围；不要在执行中顺便重写业务。

## 完成后的交接

说明运行状态的唯一所有者、订阅释放时机、现有重试语义和已验证的回归路径。

交接记录包含实际变更、验证命令和结果、必要截图／服务证据、遗留限制与回退方式；只有行为验收通过才解除后续票的阻塞。
