## 目标与已批准依据

将正式 BridGes 对话页改为连续阅读体验：用户保留气泡，助手按问题组织正文，过程默认一行收起，复杂资料由用户主动在右侧打开，失败与依据限制就近显示。侧栏、顶部、输入区和正文共同采用已批准的简洁视觉布局。

权威依据如下，实施者开始前须阅读；发生冲突时，不以旧截图或原型硬编码取代现行领域合同：

## 现状核对与拆分理由

本次只读核对发现：正式对话页、消息列表、输入区分别约 1105、1010、1070 行，均超过仓库单文件 500 行要求。前三票分别整理这些责任，保持已有完整路径可验证；不能把它们合成一张无边界的大重构票。

现有服务已提供会话历史、首轮幂等创建、运行事件、结果投影、引用详情及附件读取等能力。改版以复用为先，不预先假设必须改 schema 或新增通用资料平台。某些旧说明仍写着学习模式未实现，但当前代码已经存在目标、诊断、暂停与记录等分支；学习票需要按实际版本核验，不能凭注释删除已交付路径。

当前贴吧结果投影会触发普通正文隐藏；论文结果具有读取范围和发现依据；通勤有地点核实与路线数据；旧模块仍保留历史投影。因此分别交付对应完整场景，比统一删卡或仅换 CSS 更可验证。

## 所有工单共同遵守的边界

1. **纵向交付。** 每票从用户动作到真实命令／查询、领域结果、界面和验证形成完整路径。前置整理票通过保持既有路径行为证明价值；其他票不能只交组件库、空面板、后端接口或截图。
2. **复用与最小化。** 不为视觉改版创建另一套会话、任务、引用或上传模型。协议确有缺口时，同票覆盖必要的边界校验、服务端、生成类型、客户端及契约测试；先说明已有能力为什么不足。
3. **不推测 schema。** 默认没有数据迁移。若证据证明必须改持久化，按仓库实际命令生成、迁移、验证及回退；涉及存量数据再补数据迁移，不能用本 PRD 推定已获清库或数据搬迁授权。
4. **直接替换内部路径。** 某个场景迁移后，其旧内部渲染退出，禁止新增兼容 shim 或双写。尚未迁移的其他场景保留已有行为；对外 API 和历史读取契约仍需兼容，不能以“删除优于兼容”删除用户历史。
5. **原型不是业务事实。** 不复制示例论文、账户、帖子、固定响应、模拟耗时、重试必成功回调和内存笔记到生产。原型未出现的既有能力也不能未经确认删除。
6. **真实状态。** 来源与时间来自真实事件，生成完成不自动等于交付可信；待补充、部分失败、停止和不可重试有各自说明。仅当服务真实支持局部恢复时才承诺局部重试。
7. **隔离与并发。** 账户、会话、消息、运行、引用和对象身份贯穿读取与操作。切换后的迟到结果不得串页，敏感预览与请求生命周期需释放；不能靠全局可变状态缓存所有账户资料。
8. **领域不扩张。** 保留三个日常模块、固定对话模式、附件与知识库分域、画像授权与学习证据合同。不借呈现改版新增模块组合执行、教学策略、记录类别、来源抓取器或新模型。
9. **桌面范围。** 目标为电脑浏览器的三个标准视口及常见缩放。原型的小视口检查只是布局证据，不新增移动端产品交付承诺。
10. **操作可达。** 加载、空态、失败、重试、焦点、键盘和中文输入法都随所在场景验收。不要把可访问性、状态处理或安全输入留到最后一票才实现。
11. **工程约束。** 在 Conda 的 agent 环境开发，遵守既有风格，变更保持最小。新增或按本票职责拆分的文件不得超过 500 行；不为满足行数机械拆出无业务含义的碎片。
12. **不扩展发布权限。** 本组工单指导开发和验收，不包含部署、对外发布、清理账户数据或修改其他任务状态的授权。

## 验证与证据等级

每票应优先复用已有用例。修复已确认缺陷先形成复现；职责整理先保留行为基线。避免编写只断言实现细节的镜像测试。

验证至少区分：

| 层次 | 能证明什么 | 不能声称什么 |
| --- | --- | --- |
| 组件／投影测试 | 格式、状态映射、可见入口、未知内容处理 | 真实执行器或供应商已通过 |
| 正式链路＋受控外部替身 | 正式 UI、API、事件、持久化、权限与错误恢复路径 | 真实网络来源或模型效果稳定 |
| 真实外部服务验证 | 特定配置与时间下的实际可得性、输出与引用 | 所有环境或未来请求都必然成功 |
| 视觉与交互验收 | 页面布局、阅读顺序、资料并排、键盘操作 | 数据真实性或质量门可被省略 |

后续工单不因已有原型截图或 `verification.json` 就跳过生产验证。未配置服务、供应商失败、既有基线失败和本票回归分别记录；遇到强依赖未实现，应记录实际阻塞，不用模拟业务假装完成。
