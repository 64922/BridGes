# 用户画像与个人记忆重设计定稿

日期：2026-10-14（Asia/Shanghai）

状态：用户已确认定稿，尚未实现。本次仅保存设计，不修改运行代码、数据库、模型配置或用户记录，不执行历史重整。

决策依据：本轮 grilling 逐项选择、用户补充的完整反馈闭环要求，以及对开放主题方案的最终确认「我同意你的方案，定稿吧」。正式决策与替代关系见 [ADR-0043](../../docs/adr/0043-evidence-based-personal-memory-loop.md)。本文是该模块的新目标合同，不能作为能力已经上线的证据。

## 1. 产品目标

让 BridGes 在持续交流中准确了解用户，形成并更新个人记忆，完成「记录画像 → 调用画像 → 生成回答 → 用户反馈 → 修正画像或回答」的闭环。成功标准包含事实准确、更新正确、调用相关、回答改善，以及纠正和删除后错误不再延续，不能仅统计入库条数。

范围覆盖稳定背景与偏好、习惯和约束、经历与重要关系、目标变化、未完成事项及近期交流上下文。保持聊天优先，不增加独立人格服务、心理诊断、提醒调度或新的用户插件平台。

学习掌握程度仍由 ADR-0042 的学习领域依据实际作答管理。个人记忆可以保存用户自述的学习背景，按用途引用学习档案，但不得另行写出一套掌握结论或把提问频率当作能力证据。

## 2. 已确认的产品决策

| 编号 | 定稿合同 |
| --- | --- |
| D01 范围 | 持续了解用户的个人记忆系统，包括稳定画像、经历、重要关系、目标变化、未完成事项和近期上下文。 |
| D02 事实依据 | 长期事实必须有用户明确表达作为依据，支持口语、省略和跨轮理解；行为线索只用于暂时适配，不自动升级为长期事实。 |
| D03 保留策略 | 选择性保留预计有助于后续交流的信息；普通琐事默认留在当前对话，用户明确要求记住时例外。 |
| D04 敏感自述 | 默认不自动长期保存；用户明确要求记住时，保存明确自述及用途，不延伸推断。密码、验证码、访问密钥等凭据不进入记忆。 |
| D05 冲突 | 无法确定的新旧冲突保留不确定性，不作为确定事实使用；相关任务确实依赖它时再自然澄清。 |
| D06 反馈闭环 | 反馈含义和修正方式明确时，直接修正当前回答，并提交有依据的长期记忆变更；一次性要求只改变当前回答。 |
| D07 历史 | 重整现有画像并补提取允许处理的历史聊天；用户修改优先，历史时间语义、删除和禁止记录保护不变。 |
| D08 时机 | 普通信息在回答正常完成后后台整理；明确记住、忘掉和纠正当轮处理，整体摘要可以稍后更新。未提交不得宣称已记住。 |
| D09 页面 | 整体概览＋进行中事项＋可编辑记忆条目，来源和变更记录按需展开，均来自同一套权威事实及领域引用。 |
| D10 来源 | 默认使用聊天和手动编辑；指定文件、图片等材料仅在用户明确要求据此更新画像时参与。材料上传或任务读取本身不是画像授权。 |
| D11 分类 | 取消四分类作为能力硬边界；开放事实记录，主题可扩展、多选，不作为写入门禁，也不要求填满固定档案字段。 |
| D12 验收依据 | 用户没有现成失败片段，使用已复现问题和明确标注的合成连续对话作为初始基线；真实模型和真实使用效果须另行验证。 |

自动记录、已有长期信息使用和本轮不用的独立控制继续遵循 ADR-0032。明确主动管理不被自动记录开关阻止；重新启用不解除删除抑制，不追溯授权禁止记录期间的材料。

## 4. 开放主题与事实模型

### 4.1 主题不是固定槽位

默认浏览主题包括：基本背景与称呼、交流与协作偏好、兴趣与喜好、日常习惯与现实约束、目标与计划、经历与重要事件、重要关系、持续事项、学习背景与学情。

主题是可扩展、多选的组织信息。无现成主题时，合格事实仍可记录并在全部条目中找到；主题不得扩大敏感授权、把主题推断成事实或产生同内容的多个副本。默认主题无需空栏展示，近义主题可归一化，主题调整不得改变事实身份。

记忆性质描述事实、偏好、经历、目标和约束等更新语义，与主题正交；内部类型不重新形成内容范围白名单。每条保存一件可独立更改的完整信息，不把无法独立成立的条件拆散。

例如「我每周三晚上去实验室，那晚别安排学习」保存相关安排与约束及其关系，可关联多个主题；不因多主题复制事实，也不丢失周三晚上的适用范围。

### 4.2 逻辑对象与所有权

| 对象 | 最小职责 |
| --- | --- |
| 来源证据 | 账户、来源对象和版本、角色、精确引用、时间及时区、材料使用目的；优先引用已有来源，不另存无限量完整聊天副本。 |
| 原子记忆 | 稳定 ID、版本、完整正文、主体/关系/对象、极性和条件、主题、性质、适用范围、时间、证据引用、用户权威与生命周期。 |
| 记忆变更提案 | 指定依据和目标版本，提出新增、补充、更正、状态变化或不处理；提案在校验提交前不是事实。 |
| 进行中事项 | 目标、进展、待续问题与活动/暂停/完成状态。已有学习目标等由原领域拥有，本页引用其权威状态，不创建另一套任务执行器。 |
| 整体画像与近期摘要 | 依赖有效条目及其版本的可重建视图；每项陈述可定位依据，不增加新的事实或心理判断。 |
| 本轮采用记录 | 条目及版本、采用用途、排除原因、控制与撤回版本，关联实际回答运行。 |
| 反馈结果 | 指向当前回答及相关记忆，区分事实纠正、状态变化、长期偏好、本次要求、回答质量或待澄清。 |

物理表、接口名和内部字段细节在实施时结合已有合同确定；不建立通用知识图谱或新的模型平台。所有权仍以账户隔离，关系人物仅是用户明确介绍的对象，不创建他人账号画像或跨账户合并。

## 5. 提取、校验与更新

### 5.1 来源与处理时机

普通提取仅在回答正常完成后持久登记；失败和停止轮不自动提取，成功重试幂等处理。任务登记与完成状态一致，进程中断可恢复，不能依赖页面仍打开。

后台以有限的新消息和必要前文理解信息，并读取相关已有记忆。助手问题只用于消歧；助手建议未被用户明确采纳时不成为用户计划。单独的「同意」缺少明确指向时不推断采纳。普通关键词规则不再否决自然自述或代替语义补提取。

显式记住、忘掉和纠正优先处理，目标不明确时澄清，不猜测批量改动。明确事实可用于修正本轮回答；持久化失败须如实告知，不能声称长期更新成功。后台未完成不阻塞普通回答，本轮新自述由当前对话上下文承接，跨会话使用以提交成功为准。

指定材料须有明确的更新目的、仍有效的账户访问权和可定位来源；上传不授权，未读取不假装已读。原有照片草稿禁止入画像保持不变；发送后材料仅在明确指定、可访问且完成实际解析后进入提取。文件正文中的指令不具有授权权威，用户指定材料也不自动授权保存其中全部敏感内容。

### 5.2 证据验证

模型提出规范化事实并引用来源 ID 与原话；服务端解析和核对精确区间，不能依赖模型计算字符位置正确。多处同文且无法定位时暂不提交，需要多个片段支持的结论保留全部引用。

确定性检查涵盖来源存在、角色/账户/版本、授权范围、引用有效、凭据排除、删除抑制和目标版本；语义核验涵盖主体归属、否定、时间、条件、是否明确表达以及原话是否支持规范化含义。引用合法、模型自报置信度或字符串存在均不能独立证明正确。

支持不足的内容暂不作为长期事实，不用规则臆造兜底。纯问候可跳过，混合消息逐项评估。语义核验的调用编排和预算由实际评测确定，不预先承诺每轮调用次数或使用独立新模型。

### 5.3 更新语义

| 情况 | 行为 |
| --- | --- |
| 同一事实的同义表达 | 归并证据，保持事实身份，不重复新增；相似检索仅用于找候选。 |
| 「之前说错了，我是大三」 | 纠正事实，旧错误不作为真实经历；保留必要更正审计。 |
| 「现在升大三了」 | 更新当前状态，保留带时间的历史状态。 |
| 喜欢跑步，又喜欢游泳 | 两项并存，不自动替代。 |
| 准备考研，最近找工作 | 可并存；没有明确取消依据不删除旧目标。 |
| 新旧事实确实矛盾但含义不明 | 保留各自依据，冲突部分不作确定事实使用，相关时澄清。 |
| 用户手动修改后收到旧自动任务 | 拒绝覆盖；普通自动提取不高于用户权威。 |
| 目标完成、暂停、取消或恢复 | 仅更新已明确定位的目标；当前状态与历史经历分开。 |

相对时间锚定来源时间，不按重试日或历史重整日解释。未明示期限不编造日期；无期限目标或约束在制定依赖它的具体计划前按 ADR-0032 确认当前有效性。普通未使用不等于过时，不用访问频次强化事实可信度，也不按统一遗忘曲线删除有效事实。

## 6. 召回、回答与反馈闭环

### 6.1 任务相关召回

先按账户、使用控制、删除、生命周期和用途限定可用范围，再结合语义与关键词召回相关条目，按当前任务筛选和排序。核查并复用已有向量/全文能力，避免为画像另建重复检索底座；向量表示属于派生索引，继承访问和删除规则。

默认交流偏好可以跨主题适用；专业背景、经历、关系和目标需与任务相关。当前明确要求覆盖长期默认，不改变科学事实或用户任务。敏感自述只在明确用途内最小使用，不能因相似检索被注入无关回答。

采用记录冻结条目及版本，说明允许影响的回答决策，例如解释顺序、任务难度起点或时间安排。发送前复查撤回和版本；失效后重编译，不继续发送旧切片。整条保留必要限定，预算不足时舍弃低相关条目，不机械截断关键条件。整体概览不默认整段注入。

### 6.2 反馈路由

| 反馈 | 处理 |
| --- | --- |
| 「你记错了，我不是研究生」 | 定位事实并纠正，修正当前回答中依赖它的部分。 |
| 「今天赶时间，简短一点」 | 调整本次回答，不改长期偏好。 |
| 「以后都先给结论」 | 保存明确长期偏好，并应用于修正回答。 |
| 「身份没错，但解释太难」 | 调整表达，不推断知识水平低。 |
| 「不是这个意思」且无法明确定位 | 先澄清，不猜测长期变更。 |

修正方式明确时直接给出修正后的回答，无需用户再次要求重写。新回答记录关联被修正回答及采用版本；不得静默改写历史证据。记忆提交与回答生成分开报告结果：记忆更新失败不妨碍按用户本轮明确内容改答，回答失败也不能假称已成功重写；重试不得重复修改记忆。

只改受影响内容，不借反馈无关重做工具任务。用户点赞、阅读、停留时间和重复提问不自动证明事实、偏好或掌握程度。

## 7. 用户控制、页面与派生视图

账户中的「关于我的记忆」提供：简短整体概览、进行中事项、可编辑具体条目。默认主题用于筛选已有内容，不展示待填满的固定档案表；没有主题的新事实仍可见。

概览每项陈述关联来源条目，点击可定位并纠正；事项可完成、暂停或纠正，已有领域对象经所属服务更新。条目提供修改、删除和按需展开来源、范围、时间、变更记录。修改保留保存/取消，删除沿用明确确认；不增加逐条自动写入确认。

修改、删除或关闭使用后，受影响概览、近期摘要、缓存和检索索引立即失效；后台重建前可显示更新中或有效剩余内容，不能显示过期错误为当前事实。提供加载、无记忆、整理中、失败及重试状态，操作可键盘完成，状态可被辅助技术识别。

自动记录、长期使用和本轮不用继续分开控制。忘掉的语义覆盖同义事实及旧原文、摘要、缓存、任务派生内容的间接个性化；原聊天可按明确查看历史用途读取，不因此恢复记忆。明确重新记住仅恢复指定事实与范围，不批量重放旧证据。已经发送的模型请求无法撤回，不宣称外部内容已被收回。

## 8. 持久化、并发与可观测性

复用现有账户、个人数据存储、模型网关、共享执行内核、持久队列和审计机制。模型调用在写事务外；提交原子核对账户控制、证据版本、目标版本、用户修改和撤回状态，再写入事实变更、处理进度和派生视图失效记录。

采用有界来源窗口、可恢复处理进度和幂等标识；标识覆盖账户、来源版本及处理合同版本。失败不消费未完成窗口；没有合格事实与提取失败分开记录。并发冲突重新读取后有限重试，不能盲目覆盖或无限调用模型。取消、账户删除和权限撤回使迟到任务失效。

审计保留操作、版本、来源引用、结果和拒绝原因；普通日志不输出聊天正文、敏感事实或凭据。记录提取耗时、积压、失败、跳过原因、召回采用、纠正后复发和调用成本。完整检查点、重试队列、派生索引及备份/导出范围必须纳入账户生命周期设计。

逻辑职责分别为来源与提取、记忆更新、任务召回、反馈处理、视图投影；在现有模块边界内实现，不按表创建远程服务。新增或重构文件遵循项目单文件 500 行上限。

## 9. 四分类退出与历史重整

新权威写入路径使用开放原子记忆，移除四维必填枚举、按维度限制的模型提示与召回门禁，以及四维记录和原子镜像的内部双写。旧字段仅作为迁移解释依据，不新增长期兼容层。外部 API 契约、历史展示、导出和数据库迁移另作显式兼容评估。

实施前核对权威库和写入者，备份并验证恢复，执行只读迁移预览。沿用现有安全回放机制中可用的进度、幂等和删除保护能力，但不得直接把旧 `profile-auto-v2` 回放命令视为支持本合同的新迁移。

历史重整遵守：

1. 用户主动编辑、明确纠正和删除的权威优先；旧材料不得覆盖。
2. 旧自动记录回到可访问原始依据核验，错误拆分、重复和过时状态重新整理；证据不足暂不采用，不凭旧标签补事实。
3. 只补提取允许处理的历史；禁止记录期间的内容、已删除来源和撤回范围不重放。指定材料与敏感信息须有对应明确授权依据。
4. 使用原始发生时间、来源关系和当前状态，历史计划不得被当作今天的新目标。
5. 分批处理，记录重整范围、版本、结果和跳过原因；并发期间的新修改和删除优先，失败可恢复。
6. 对账事实数、来源关系、用户编辑、撤回、导出和跨账户隔离，核验后切换唯一权威写入路径。

回滚方案必须先验证；停用新写入并保存新数据及撤回记录，不能将新事实强塞回四维或静默丢失。旧执行器、检查点和重试不得在切换后重新启动旧写入，历史只读解释不构成旧业务兼容运行。

## 10. 验收合同

以下为合成场景；其中 T01–T03 的当前入口表现已做内存探针，其他均是待实现的验收要求。没有生产模型成功率或效果结论。

| 编号 | 场景 | 必须验证的行为 |
| --- | --- | --- |
| T01 | 「我叫小林」「周末一般去爬山」「我养了一只猫叫团子」 | 明确个人事实和习惯可被提取，不受四分类或固定句式限制。 |
| T02 | 「我喜欢心理学」 | 正确区分学科兴趣与敏感心理推断。 |
| T03 | 学线性代数，每晚只能半小时 | 学习内容与时间约束均保留，安排同时遵守。 |
| T04 | 助手问专业，用户答计算机；之后说这个专业 | 正确理解跨轮指代，使用正确历史范围，不能读取当前消息之后的内容。 |
| T05 | 转述朋友经历、小说、他人简历、材料内指令 | 不误归属用户，不把材料指令当作授权。 |
| T06 | 助手建议计划，用户没有采纳；孤立「同意」 | 不自动形成用户计划，缺指向时保持不确定。 |
| T07 | 纠正年级、升年级、增加爱好、并行考研求职 | 分别执行纠错、状态变化、并存和保留不确定性。 |
| T08 | 同一事实换说法重复出现 | 合并证据而非重复新增，关系不同的事实不误合并。 |
| T09 | 仅今天简短；以后先给结论；解释太难 | 分别修改本次回答、长期偏好、表达方式，不推断全局能力。 |
| T10 | 用户手改后旧提取完成；两个后台任务竞争 | 用户修改不被覆盖，重复处理幂等，冲突不会丢失更新。 |
| T11 | 删除后同义提及、历史重整、摘要或缓存召回 | 不复活，不间接用于个性化；明确恢复只覆盖指定范围。 |
| T12 | 新会话继续未完成事项，之后暂停或完成 | 找到相关进展，状态正确，不夹带无关记忆，不创建重复学习目标。 |
| T13 | 明确要求记住过敏信息；普通情绪表达；凭据 | 依用途处理敏感自述，情绪不默认长期化，凭据不入库。 |
| T14 | 普通上传与明确指定本人简历更新背景 | 前者不提取个人记忆，后者有访问、解析、授权和证据检查。 |
| T15 | 模型超时、合同错误、提交失败、进程重启 | 失败与无信息区分，有限重试与进度恢复，不虚报保存成功。 |
| T16 | 用户纠正后生成失败；保存失败但回答修正成功 | 各结果诚实独立反馈，重试不重复写入，后续不使用已失效事实。 |
| T17 | 关闭记录、关闭使用、本轮不用、切换账户 | 控制按合同生效，无间接个性化泄漏，无跨账户来源或召回。 |
| T18 | 用户编辑条目，概览尚未重建 | 旧概览立即失效，条目、事项和摘要不互相矛盾。 |
| T19 | 来源被编辑/删除，历史相对时间重整 | 拒绝迟到旧版本，日期按原时间锚，历史不变为当前状态。 |
| T20 | 主题外的新事实、多主题事实 | 不因主题缺失被丢弃，多主题不造成重复事实。 |

### 验证层次

1. 确定性行为测试：来源、控制、事务、并发、撤回、迁移、界面操作与完整闭环必须通过。
2. 真实模型评测：同一模型与固定多轮语料比较当前基线和新链路，记录事实准确/遗漏/误归属、修订正确率、去重和证据支持；增加措辞变化、长对话、混合主体、时间变化及留出的独立场景，避免只适配固定例句。
3. 回答效果评测：配对比较无画像、正确画像、错误/过期画像、纠正后画像的回答，核验实际适配、无关干扰、错误复发、时延和成本。人工复核关键案例，不能只让模型自评。

账户、凭据、撤回、授权、用户权威等关键场景不得出现已知违规通过；平均回答收益不能抵消这些失败。所有关键旅程通过后才可验收。质量数值门槛与预算在取得基线后、正式评测前冻结，不捏造达成率，也不在结果出来后放宽门槛。

## 11. 实施顺序与完成定义

1. 建立当前基线、合成语料及来源链复现，核查现有依赖、索引、接口和外部兼容义务。
2. 落地开放原子记忆、证据提取与更新语义，完成并发、撤回和恢复保障。
3. 接通用途召回、回答采用记录和反馈修正，验证多轮闭环。
4. 更新概览、事项与条目页面及其失效机制，验收完整交互状态。
5. 在备份和只读预览后受控重整历史，完成对账、旧写入退出、导出及回滚验证。

每阶段都交付对应验证；实施前再拆本地任务，本次不创建虚假已完成工单。实现提交前运行项目完整检查；前端变化另做构建，schema 变化执行对应生成/迁移及必要数据迁移。

完成意味着上述链路与关键验收均成立，有真实模型结果和历史迁移证据；文档定稿、增加分类、写入成功或单次演示均不等于完成。本次交付仅为设计定稿。
