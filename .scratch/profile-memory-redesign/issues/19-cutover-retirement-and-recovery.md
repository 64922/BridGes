# 19 — 验证四维路径退出、受控切换与回滚

**What to build:** 维护者能够将已验收候选切换到新画像能力，确认旧四维路径退出，并在故障演练中恢复服务而不丢失切换后新增的修改或删除约束。

**Blocked by:** [18 — 真实模型闭环验收](18-real-model-loop-evaluation.md)。

**Status:** ready-for-agent

**发布状态：** 2026-10-15 用户已确认拆分与依赖，正式发布；尚未实施。

**对应合同：** D07、D08、D11、D12；T10、T11、T15、T17、T19。参见[定稿](../PRD.md)、[共同执行约束](../README.md)。

## 用户演示

在隔离环境完成启动、切换和中断恢复，验证未知主题能够保存和使用；随后模拟回滚，核对切换后新建事实、人工修订及删除屏障，最后再次升级并验证一致。

## 依赖与实施范围

各前序票随能力替换删除对应过时内部实现，本票做最终退出审计和运行演练，不承担积压的所有旧代码清理。

- 审计活跃入口、提示词、校验、持久化、检索与前端均不再将四维当写入门槛；排除镜像双写和隐蔽旧后台路径。
- 明确切换时正在处理的提取、检查点、租约和重试归属，旧任务不能在新状态上恢复旧事实。
- 对外稳定接口、数据库版本及必要历史读取按合同处理；内部不建立兼容 shim、双写或永久双模式。
- 在隔离环境执行 schema/数据迁移、启动、故障恢复、回滚及再次升级，验证一致性和可观测性。
- 恢复方案覆盖备份之后的有效新增、人工修订、控制变更及删除屏障；旧备份不得直接覆盖并丢失这些变化。
- 更新运行手册和能力状态，明确代码已交付、数据已迁移、部署已执行分别需要什么证据。

## 验收标准

- [ ] 活跃调用链没有封闭四分类门槛、旧镜像写入或绕过新校验的入口；保留的历史读取有明确合同和用途。
- [ ] 旧任务、恢复队列及重试不会重新引入已删事实或覆盖人工修改；切换与停止步骤可验证。
- [ ] 同一候选版本完成全检查及构建，18 后的修复按影响范围补做真实闭环验证。
- [ ] 回滚/重升级演练保留切换后事实和撤回约束；不能仅证明旧备份启动成功。
- [ ] 不将新主题强制投影回四类以迁就旧程序；无法支持的回滚范围及恢复方式在执行前明确。
- [ ] 运行手册包含实际命令、前置状态、校验、失败定位和恢复步骤，不使用臆造的通用迁移命令。
- [ ] 实际用户实例的停启、迁移和部署遵守既有授权与操作流程；文档、实现完成不等于已生产发布。

## 验证与交付

交付旧路径退出清单、受控切换手册、故障/回滚/重升级演练证据及最终候选版本。对无法达到恢复目标的方案保留阻塞，不宣称可回滚。

## 明确不做

不顺手清理无关模块，不引入内部兼容层，不在工单编写或审核阶段操作真实用户数据库。
