# 06 — 区分重复、纠错、变化与事实冲突

**What to build:** 用户重复表达、补充或纠正后，记忆不会重复或误覆盖，也不会把错误保留成真实经历；不确定冲突只在相关任务需要时澄清。

## 用户演示

先说喜欢跑步，再换句话重复，随后增加游泳；前两次归并依据，游泳独立保留。「之前说错年级」纠正错误，「现在升年级」保留真实历史。

## 依赖与实施范围

05 提供可信多轮证据；变更需要同时读取相关旧条目和原话。

- 定位稳定事实和属性槽，区分新增、合并证据、纠错、状态变化、并存及不处理；相似检索仅用于找候选。
- 明确更正操作针对指定条目或属性，禁止按大类批量覆盖；普通自动信息不能覆盖手动编辑。
- 冲突保存各自依据与受影响属性，争议部分不作为确定事实采用；无关问题不主动打断。
- 变更落库并更新条目详情；事务内核对来源、目标版本与用户权威，冲突后先重读再有限重试。

## 验收标准

- [ ] 同一事实换说法只增加依据；「喜欢 Python」与「正在学 Python」关系不同，不误合并。
- [ ] 「说错了」与「现在变了」具有不同历史语义，不统一按最新覆盖。
- [ ] 多个爱好或可并行目标并存，没有明确取消依据不删旧目标。
- [ ] 手动编辑不被更高模型置信度或更晚自动消息覆盖。
- [ ] 冲突未解决时不作确定判断，仅当前回答实际依赖该属性时澄清。
- [ ] 并发用户修改、重复提交及错误目标均有真实存储测试，不丢版本和依据。
- [ ] 页面状态、采用结果与存储一致，新增冲突数据支持迁移、导出、删除和恢复。

## 验证与交付

通过聊天和页面验证重复、关系不同、纠错、变化和冲突；在 worker 提交前插入用户修改，证明权威与版本守卫有效。交付事实身份、变更结果、冲突状态及更正接口供后续复用。

## 明确不做

不做通用关系图推理，不以相似度决定删除恢复，不产生全局人格评价。
