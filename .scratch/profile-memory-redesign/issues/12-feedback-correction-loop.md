# 12 — 根据反馈纠正当前回答与必要记忆

**What to build:** 用户指出问题后直接获得修正回答；只有明确长期事实或偏好发生变化才更新记忆，后续不重复同一错误。

**Blocked by:** [11 — 任务召回与实际采用记录](11-hybrid-purpose-recall.md)。

**Status:** ready-for-agent

**发布状态：** 2026-10-15 用户已确认拆分与依赖，正式发布；尚未实施。

**对应合同：** D05、D06、D08；T07、T09、T16。参见[定稿](../PRD.md)、[共同执行约束](../README.md)。

## 用户演示

用户说「你记错了，我不是研究生」，系统纠正对应事实并重写受影响解释，新会话不再重复错误。「今天简短一点」只改本次，「以后先给结论」更新默认偏好。

## 依赖与实施范围

11 提供回答实际采用对象与版本，其传递依赖提供受控纠正操作和并发保护。

- 结合原回答及采用记录识别事实纠错、状态变化、长期偏好、本轮要求、表达质量或不明确反馈。
- 明确反馈完成必要记忆操作并直接改答，不要求再说重新回答；指向不明只澄清需要的信息。
- 修正回答关联原回答与实际采用版本，不静默修改旧消息或把修正输出当成用户事实依据。
- 持久化与回答生成独立报告结果，操作幂等；复用原任务和有效工具结果，不因改答重做无关外部副作用。

## 验收标准

- [ ] 明确身份纠错定位对应事实，当前与后续回答均不沿用旧结论。
- [ ] 「今天简短」不改变长期偏好，「以后先给结论」正确持久化。
- [ ] 「解释太难」调整表达，不自动产生能力低或掌握不足标签。
- [ ] 「不是这个意思」无法定位时不猜测批量修改，不扩大敏感授权。
- [ ] 保存失败仍可依据本轮明确事实改答并诚实反馈；改答失败不回滚已成功纠正或假称完成。
- [ ] 重复反馈与生成重试不重复写记忆或执行工具副作用，删除竞态受相同守卫约束。
- [ ] 反馈与运行关系支持重启、读取、导出和账号删除，聊天状态与错误反馈完整。

## 验证与交付

跑反馈→条目状态→修正回答→新会话复问；分别注入保存失败、生成失败和删除竞态。交付反馈路由、幂等结果及修正运行关系，记录错误复发评测样本。

## 明确不做

不将点赞、停留或含糊回应当长期事实，不新增第二套全文改写平台。
