# 09 — 按明确要求和用途保存敏感自述

**What to build:** 普通知识兴趣不被敏感词误拦截；用户明确要求记住过敏等自述时，可查看保存内容和用途，只有相关回答采用。

**Blocked by:** [08 — 撤回与使用控制](08-semantic-forgetting-and-controls.md)。

**Status:** ready-for-agent

**发布状态：** 2026-10-15 用户已确认拆分与依赖，正式发布；尚未实施。

**对应合同：** D04、D08；T02、T13、T17。参见[定稿](../PRD.md)、[共同执行约束](../README.md)。

## 用户演示

「我喜欢心理学」作为普通兴趣保存；「记住我有花粉过敏，户外建议要注意」按用途保存；普通焦虑表达不形成长期档案，密码即使请求也不保存。

## 依赖与实施范围

08 及其传递依赖已提供多证据核验、范围撤回和使用控制。

- 语义区分学科兴趣、短期情境、明确敏感自述和禁止凭据，不仅按关键词拒绝或放行。
- 明确请求的目标和用途进入证据化提交；用途无法从请求明确时澄清，不默认用于任意场景。
- 详情显示用途并支持修改、删除；基础采用入口立即强制用途检查，后续混合召回复用相同边界。
- 自动敏感候选不持久化；拒绝结果不回显敏感原文，凭据不得进入候选记录、摘要、索引或日志。

## 验收标准

- [x] 心理学兴趣可记录，答辩焦虑默认仅用于会话，不生成长期心理/情绪标签。
- [x] 明确要求记住的过敏信息用于户外建议，其他问题不携带该内容。
- [x] 授权某一项不扩大为全部敏感信息；材料授权也不自动成为敏感授权。
- [x] 密码、验证码和访问密钥不进入记忆及派生存储，即使用户明确要求。
- [x] 删除或缩小用途后，旧采用及迟到提交均失效，恢复不能扩大范围。
- [x] 失败不声明已保存，不新增自动记录默认逐条确认流程。

## 验证与交付

敏感/非敏感最小对照、用途越界、并发撤回和日志审查；实际用户入口与真实模型结果分开验证。交付明确授权依据、用途和拒绝合同供材料、检索和重整使用。

## 明确不做

不推断人格、心理或敏感身份，不建设逐类授权设置中心。
