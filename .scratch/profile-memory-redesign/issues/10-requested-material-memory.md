# 10 — 从明确指定的材料更新个人记忆

**What to build:** 用户明确要求据本人简历等材料更新背景后，系统读取实际内容、形成有来源事实并展示结果；普通上传不触发画像更新。

**Blocked by:** [09 — 明确敏感自述与用途](09-explicit-sensitive-memory.md)。

**Status:** ready-for-agent

**发布状态：** 2026-10-15 用户已确认拆分与依赖，正式发布；实施已完成，待合并。

**对应合同：** D02、D04、D10；T05、T14、T19。参见[定稿](../PRD.md)、[共同执行约束](../README.md)。

## 用户演示

上传简历不会自动产生个人记忆；随后明确要求「这是我的简历，请更新我的背景」，处理完成后能查看事实与对应材料片段，未读部分不宣称已处理。

## 依赖与实施范围

09 及其传递依赖提供多证据、授权、敏感用途和撤回规则，材料沿用同一提案与提交入口。

- 从明确请求定位材料、主体和目的，绑定当前账户与现有附件/知识库权限，复用解析、视觉和 OCR。
- 解析完成后再提取，覆盖解析中、不支持、不可读、失败及部分处理状态；草稿不参与。
- 来源保留页码、片段或可定位图片区域及版本；详情支持追溯，材料访问不因记录生成而永久扩大。
- 多人材料和身份不明时不猜测归属；文件内伪造授权或系统提示无权改变提取规则。

## 验收标准

- [ ] 普通上传、阅读和任务分析不新增个人记忆；明确指定后才启动受控处理。
- [ ] 本人可读材料形成有依据事实，不把他人简历或多人内容归给用户。
- [ ] 指定材料不自动授权其中全部敏感内容，凭据继续禁止保存。
- [ ] 未完成解析或只读取部分时，结果如实说明，不伪造页码或引用。
- [ ] 跨账户拒绝，跨会话附件遵循原访问边界，草稿不成为来源。
- [ ] 材料编辑、删除、撤回或权限失效后，旧候选和派生采用失效。
- [ ] 当前支持的文本文件和图片路径均有实际端到端证明及错误恢复。

## 验证与交付

文本材料与图片解析各验证完整路径，覆盖恶意指令、未解析、多人归属和权限竞态。交付指定材料授权与引用合同，供历史重整判断旧材料是否允许处理。

## 明确不做

不自动迁移附件到知识库，不新增材料格式，不做无边界后台扫描。
