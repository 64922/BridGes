# 13 — 跨会话接续事项并管理暂停和完成

**What to build:** 用户在新对话可继续之前未完成的事项，查看进展和待续问题；完成或暂停后系统不再把它当当前目标。

**Blocked by:** [11 — 相关召回与采用](11-hybrid-purpose-recall.md)。

**Status:** ready-for-agent

**发布状态：** 2026-10-15 用户已确认拆分与依赖，正式发布；尚未实施。

**对应合同：** D01、D03、D09；T07、T12、T18。参见[定稿](../PRD.md)、[共同执行约束](../README.md)。

## 用户演示

跨两次对话准备申请，第二次说「继续上次的申请」能接续已有进展；页面显示进行中事项，暂停或完成后状态和后续回答同步变化。

## 依赖与实施范围

11 及前置提供时间、状态、相关召回与撤回。反馈改答不是本票的阻塞条件。

- 以明确事实建立最小事项投影，关联目标、实际进展与待续问题，不把助手建议自动解释为用户承诺。
- 提供事项区和来源详情，以及暂停、完成和纠正操作；歧义时定位正确事项，不按主题批量更新。
- 维护带事实依赖和版本的近期工作上下文，修改、来源删除或控制变化立即失效，后台重建守卫新版本。
- 其他领域目标只使用所属领域引用，不能复制状态；学习专门对接由 14 完成，未接通不得伪造学习状态。

## 验收标准

- [ ] 新会话接续正确事项及进展，不要求重复全部背景或携带无关事项。
- [ ] 并行事项独立，暂停/完成/恢复不误覆盖其他目标。
- [ ] 待续问题有真实交流依据，摘要不成为新增用户事实来源。
- [ ] 删除依赖事实、关使用、源消息变化使近期上下文及时失效，迟到重建不能覆盖新状态。
- [ ] 页面加载、空态、失败重试、保存结果和键盘访问完整。
- [ ] 新状态在本票完成迁移、并发更新、重启恢复、导出和账户删除验证。

## 验证与交付

两会话接续、多个事项、暂停后恢复、来源删除和摘要竞态的端到端旅程。交付事项投影、领域引用管理接缝及近期上下文失效规则。

## 明确不做

不创建提醒调度、任务执行器或第二份学习目标，不新增无授权主动消息。
