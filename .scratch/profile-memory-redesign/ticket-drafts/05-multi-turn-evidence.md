# 05 — 理解跨轮省略并展示可核验依据

**What to build:** 用户用简短回答或「这个专业」等回指时，系统理解必要前文，条目详情能展示真正支持结论的原话，不误认助手或他人内容。

**Blocked by:** [04 — 可恢复语义提取](04-durable-semantic-extraction.md)。

**Status:** needs-triage

**发布状态：** 待审核草稿，尚未发布或实施。

**对应合同：** D02、D10；T04、T05、T06、T19。参见[定稿](../PRD.md)、[共同执行约束](../README.md)。

## 用户演示

助手询问专业，用户答「计算机」，之后说「这个专业我想继续读研」；页面显示正确专业和计划，各自依据可定位，助手单方建议不变成用户承诺。

## 依赖与实施范围

04 已有后台提案和核验提交，本票扩展其有限证据窗口。

- 修复邻近消息方向与当前消息截断，以来源位置选择必要前文，包括消歧所需助手问题，禁止读取未来消息。
- 支持多个原话片段、角色、来源版本和时间；模型引用原话，服务端确定 Unicode 区间，重复文本无法定位时暂缓。
- 规范化正文与证据分离，检查主体归属、关系、否定、条件与时间确被支持，而非仅检查引用 ID 合法。
- 页面展示跨轮来源及不可用状态；编辑/删除来源时使陈旧候选失效，并重新核验已有依赖事实。

## 验收标准

- [ ] 空邻近消息缺陷有先失败后通过的复现，正确读取当前消息之前的必要内容。
- [ ] 省略专业可正确承接，孤立「同意」缺少明确对象时不保存计划。
- [ ] 转述、引用、假设、第三人经历及助手文本不被误归属为用户事实。
- [ ] 规范化事实可不同于原文字面，但关键含义逐项有证据，多片段引用完整。
- [ ] 重复原话、无效区间或伪造片段不会随意定位或通过写入。
- [ ] 来源版本变化、删除、跨账户读取与迟到结果被检查，详情不会泄露不可访问正文。

## 验证与交付

通过实际聊天及依据详情验证多轮省略、重复片段、Unicode、混合主体、未来消息及删除竞态；真实模型使用留出措辞。交付统一窗口、引用定位与多证据合同供材料、反馈和历史使用。

## 明确不做

不扩大为全量聊天上传，不把引用存在当作语义正确，不实现材料导入。
