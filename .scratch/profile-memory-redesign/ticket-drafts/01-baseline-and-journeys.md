# 01 — 建立画像闭环基线与可复现验收旅程

**What to build:** 从当前聊天、记忆页面和回答入口复现已知问题，建立能重复执行的多轮基线，明确新实现如何证明记准、用对、纠正有效。

**Blocked by:** 无；拆分批准并正式发布后可开始。

**Status:** needs-triage

**发布状态：** 2026-10-15 待审核草稿，尚未发布或实施。

**对应合同：** D02、D11、D12；为 T01–T20 建立语料，重点复现 T01–T04。参见[定稿](../PRD.md)、[共同执行约束](../README.md)。

## 用户演示

输入姓名、宠物、爬山习惯、心理学兴趣、学习内容与时间限制，并进行一次跨轮回指；记录当前实际提取、保存、采用和回答结果，能从相同输入重跑。

## 实施范围

- 采用明确标注的合成数据，为每个场景写明说话者、来源时间、预期事实、预期变更和回答表现；加入否定、混合主体、同义表达和独立留出变体。
- 经实际服务入口复现漏提取、敏感词误拦截和空邻近消息问题。内存探针只用于定位，不能代替入口证明。
- 核查已有模型、持久队列、索引、外部 API 和所有旧画像写入消费者，记录真实能力和兼容义务。
- 使用实际配置记录真实模型基线及成本、时延；配置不可用时保留明确缺口，不伪造数据。确定性基线可先交付，18 的真实质量验收必须补齐真实基线。
- 在正式对比前冻结评测方法、数值门槛和预算及其依据，区分开发语料与留出语料。

## 验收标准

- [ ] T01–T20 均有固定输入、预期结果与后续负责票，未支持的新功能不冒称现有缺陷。
- [ ] 姓名、宠物、习惯、心理学、时间限制、邻近消息六类问题有可重现的实际结果。
- [ ] 固定代码、模型、提示、输入合同和运行版本，真实响应与替身响应分开标记。
- [ ] 已知失败单独记录，不通过无条件跳过、改预期或让整个回归长期标红处理。
- [ ] 指标分别覆盖准确、遗漏、误归属、修订、召回、回答收益、错误复发、成本和延迟，不能只报告记忆条数。
- [ ] 不将真实私人原文、凭据或生产数据库写入仓库。

## 验证与交付

重跑一个已通过和一个已知失败的完整旅程，验证结果可以追溯到输入与版本。交付语料、基线报告、测量方法、能力/消费者清单及真实模型缺口；为后续票保留同一对照。遵守共同约束的完整检查与证据记录要求。

## 明确不做

不修复业务、不调阈值美化结果、不扫描真实账户或执行历史迁移。
