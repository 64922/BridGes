# 02 — 分离记忆提交与旧画像读取边界

**What to build:** 保持当前记住、编辑、删除、自动写入和历史读取行为不变，整理唯一提交边界，让开放事实替换不必复制事务和用户权威逻辑。

**Blocked by:** [01 — 基线与验收旅程](01-baseline-and-journeys.md)。

**Status:** needs-triage

**发布状态：** 待审核草稿，尚未发布或实施。

**对应合同：** D07、D11；T10、T11。参见[定稿](../PRD.md)、[共同执行约束](../README.md)。

## 用户演示

重构前后执行记住、手动编辑、删除、后台写入失败和历史导出，相同输入得到相同可见行为。历史读取不启动提取任务。

## 依赖与实施范围

01 的固定基线和实际消费者清单用于证明行为不变。本票是先行准备重构，限于后续必须改动的提交、用户权威和历史只读接缝。

- 整理当前事务参与、提交结果和异常传播；保留原有回滚与撤回语义，不创建第二套仓库。
- 查清四维与原子镜像的全部活动写入入口，明确内部调用与真正外部契约。
- 分离历史只读和新写入职责，保持来源查询、导出、条目管理完整。
- 只抽出必要的内聚职责，不增加转发 shim、通用框架或无关清理。提取与召回的业务替换由各纵向票负责。

## 验收标准

- [ ] 原有正常操作和错误反馈与基线一致，没有新模型调用、新状态或新产品行为。
- [ ] 提交中途失败仍完整回滚，没有半份来源或镜像；此票保持当前事务，03 才移除双写。
- [ ] 读取、恢复检查和导出不启动业务执行或自动写入。
- [ ] 用户编辑优先、删除抑制、账户隔离和恢复测试不退化。
- [ ] 新拆出的代码文件不超过 500 行，职责与接口清楚，不把超长文件简单机械切碎。
- [ ] 03 可以通过明确的唯一提交接缝替换写模型，消费者清单有实际引用核对。

## 验证与交付

运行提交、故障回滚、治理、用户编辑、API 与历史读取回归；比较重构前后可见结果。交付事务和写入所有权说明、活动消费者清单、外部兼容义务及真实检查结果。

## 明确不做

不改变四分类能力，不新增持久化模型，不做全仓重构，不为后续实现预建多余抽象。
