# 修复贴吧搜索范围与结果展示

Status: ready-for-human

用户原句：我想了解国庆节假期的讨论。

根因：域名仅作为普通搜索词；备用查询放开站点；停用词删除把“了解”拆成“解”；“讨论”未识别为体验意图；官方首次词命中来自标题与导航；结果卡片和正文重复展示。

修复：固定贴吧入口及官方域名，两个检索轮次都限站；提供方 API 与读取前 URL 门共同落实来源约束；保留国庆主题并正确识别混合问题；官方正文段落摘录；单一结果卡片及折叠审计。来源合同见 ADR-0037。

- 贴吧/搜索最终测试 246 项通过、2 项跳过；另外 2 项旧路由断言已在修改前 HEAD 基线复现失败，最终针对性回归中单独排除，未计为通过。
- 仓库全量类型检查存在职业规划、学习资料及评测等未改动代码的问题；本次后端源文件局部 mypy/ruff 检查通过。
- 用户原句经过真实聊天入口、后台执行器、限站备用查询与实际回复投影的测试通过。官方正文额外覆盖“标题不能单独证明有正文”以及“国庆问题不能采用其他假期段落”。
- 全仓 Python 测试执行至 2925 项通过、63 项失败、3 项跳过后，按失败上限停止；失败涉及旧路由、MCP、职业规划、摄取及发布门等路径，不据此声称整个仓库检查通过。
- 首轮仅执行请求合同测试，不能当作真实国庆讨论的召回验收。第二轮通过应用凭据解析器找到真实 Tavily 凭据并执行检索（密钥未打印、未导出）；国庆／十一的限站查询只返回无关帖子或零命中，自然中文查询加域名限制也未改善。

## 第二次反馈与当前阻塞

- 用户已登录 Edge，提供截图确认可以正常浏览贴吧。后端 HTTP 没有这份会话，固定入口真实 GET 返回 403 百度安全验证；不能把索引缺失报告为吧内没有讨论。
- Codex 已检测到 Edge 扩展，但刷新连接、列出标签页、新建标签页、按目标 URL 连接页面均失败，错误为 `nodeRepl.fetch request failed`。用户确认页面已打开、扩展已连接，未反复要求用户检查。
- 用户进一步改用 Chrome，确认扩展侧栏正常使用，并发送真实 `@Chrome` 关联。工具检测到 Chrome，但会话命名、直接读取标签页、按固定目标 URL 连接均仍失败。详见 [连接诊断](../connection-diagnostic.md)；不能认为换浏览器或重装贴吧登录可以解决当前控制连接故障。
- 第二轮时生产模块仍使用公开搜索与公开 HTTP，未接入浏览器会话；此阻塞现已通过下述用户授权的专用 Chrome 路径解决。此前回归只证明范围和官方通知取证，不能当作讨论召回验收。
- 已修复：通知只摘录“安排如下”而丢失列表；2018 年通知误标当前适用；官方证据被整体空态吞掉；同吧但主题无关的帖子被确认为结果；固定入口标点粘入链接。通用备用检索使用常见“国庆”措辞，但不声称关键词能解决索引缺失。

- 第二轮最终相关后端测试 268 项通过、2 项跳过、2 项旧路由断言单独排除；前端全量 245 项通过，lint 和生产构建通过；局部 mypy/ruff 通过。前端全量 typecheck 仍有未修改的职业规划、学习资料、论文及通用夹具类型问题。

## Comments

贴吧公开索引的覆盖与页面可访问性仍影响是否能取得讨论；范围约束不能承诺一定有结果。空结果应如实说明，不扩大到视频或其他社区。无需数据库迁移；重新启动使用这份源代码的后端进程后，再从固定来源范围检索。

- 用户明确授权 Playwright 专用会话，并提供当前账户用于目录绑定。人工完成滑块和登录后，重开同一隔离目录仍可进入目标吧。没有导出 Cookie，也未使用个人 Chrome 配置。

- 新生产装配使用原生搜索优先、公开索引后备且两路记录不丢失；官方域名查询独立。阅读器按账户工厂构造，不使用可变的全局账户上下文。窗口 API 由认证主体绑定账户，CSRF 防护沿用现有中间件。
