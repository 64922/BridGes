# BridGes 智能体工作流与编排设计

日期：2026-09-30。状态：**已确认定稿**。D01—D17 已在讨论中逐项确认，用户随后以「定稿」确认完整方案，包括技术合同、预算初值方案与迁移顺序。本目录描述目标设计，当前实现状态仍以代码和 V2 已交付记录为准。

## 核心方案

采用一个主智能体统一理解与规划、按需调用专业智能体和确定性服务。共享执行内核负责权限、状态、预算、检查点与交付；日常陪伴允许受约束的动态能力组合，学习模式保留教材小节与教学阶段约束。

普通闲聊保持轻量。专业智能体只在需要语义匹配、综合分析或教学判断的步骤参与；它们通过带证据的结构化产物协作。模型提出计划和调整建议，代码验证并执行。

## 延续的边界

- 首条消息后会话模式固定；一个学习会话仍对应教材的一个小节，首轮书页照片输入要求保留。
- 账户隔离、会话附件与全局知识库分域、原子画像编辑权威及删除墓碑继续有效。
- 日常陪伴不会自动创建教学计划；学习外部补充不会自动扩大复盘考查范围。
- 六个日常模块的来源范围继续有效，包括校内通勤、目标贴吧、公开可访问材料。
- 新编排不恢复旧项目工作台、提醒任务、退役创作或媒体生成入口。
- 开发和验证使用 conda `agent` 环境。
