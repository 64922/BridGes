# 当前工作流的批判性审查

日期：2026-09-30。状态：已确认定稿。范围：V2 日常陪伴、六个模块、学习模式及其执行底座。结论来自静态阅读，未通过故障注入或用户任务实测证明所有风险已实际发生。

## 应保留的优点

当前系统已经具备账户作用域、会话模式锁定、消息与附件幂等绑定、SQLite 检查点、带游标的 SSE、停止和终态守卫、真实来源投影及模块局部降级。教学题目和书页引用可持久化，用户画像也有原话来源、编辑优先与删除墓碑。

这些底座比智能体数量更重要。改进应增强任务理解、证据使用和执行恢复，继续复用有效工具适配器与运行服务。

## 公共编排问题

| 问题 | 当前证据 | 影响与改进 |
| --- | --- | --- |
| 子图恢复粒度过粗 | [日常父图](../../src/bridges/chat/graph.py)在 `invoke_subgraph_or_chat` 内整体调用模块的 `service.run`；六个模块主要由顺序 Python 调用及节点事件包装组成 | 父图检查点不等于每个检索、读取和分析步骤都可恢复。应将必要步骤注册为持久节点，保存类型化产物与完成收据 |
| 公共核验节点检查消息终态 | 父图 `_node_verify_output` 判断消息是否为 `DONE`；模块已自行完成消息 | 终态检查不能独立证明内容可信。改为先产生待交付产物，再核验和统一提交 |
| 上下文存在多套入口 | 父图编译上下文；[论文](../../src/bridges/paper/service.py)和[资料](../../src/bridges/resources/service.py)分别取近期用户原文；[GitHub](../../src/bridges/github/service.py)自行抽取历史锚点 | 任务条件、画像和证据选择难保持一致。编译共同任务快照，再为各工作节点选择最小切片 |
| 澄清由模块回扫消息寻找 | 各模块 `_pending_wait` 查找最近尚未被结果取代的等待投影 | 等待缺少统一任务归属、版本与失效规则，换话题后存在误接旧问题的风险。改为绑定任务版本的等待记录 |
| 单模块派发与复合需求脱节 | 请求中的 `module_id` 固定派发；普通聊天模块建议按固定优先级选一个 | 用户目标可能包含多个能力与依赖。增加主智能体提出的有限计划，由代码校验后执行 |
| 模块分别起计时 | [聊天预算](../../src/bridges/chat/budget.py)有 120 秒预算基础，模块服务还建立独立阶段截止时间，父图调用未统一传递该预算合同 | 需要将每个模块和修复分支纳入同一运行预算，预留最终核验与提交时间 |
| 版本标识较粗 | 父图以图名称/版本记录运行，多种模块实现共用父图版本；运行还展示单一模型锁关联 | 不能仅用父图版本说明节点配方、提示词与多次模型调用。需逐节点记录实际能力与版本，复用前核对 |
| 旧编排合同容易被误用 | [旧 WorkOrder 合同](../../src/bridges/contracts/workflows.py)仍有项目归属及执行前人工确认语义 | 不能把旧工作台审批引入新混合启动流程。新设计复用基础设施，使用当前会话和账户合同 |

最后两项属于可审计性与迁移风险，不代表当前历史记录一定丢失，也不代表旧接口应被直接删除。

## 各模块问题

| 模块 | 薄弱点 | 目标改进 |
| --- | --- | --- |
| 论文 | [排序](../../src/bridges/paper/ranking.py)依赖原词覆盖和综述/教程标记；词义匹配不足以证明研究问题相关性或入门适配性 | 保留原始需求；候选相关性逐项绑定摘要/全文证据，读取深度由结论需要决定 |
| 通勤 | 地点收集、消歧、路线请求和缓冲仍在一个服务运行中；重新问询和计算难以作为独立恢复边界 | 主智能体处理自然语言与歧义，代码完成定位、方式校验、请求和计算；保存已确认地点，只重算受影响步骤 |
| 学习资料 | [排序](../../src/bridges/resources/ranking.py)用标题阶段标记、视频时长等弱信号；[规划](../../src/bridges/resources/planning.py)固定 2 本书和 3 条视频；书与视频搜索顺序执行 | 学习目标驱动的精简路径；独立检索并行；用目录、简介等实际内容证据评价先修与覆盖 |
| 贴吧 | 固定搜帖、读帖、整理后再按需核对官方；不同问题的取证优先级相同 | 问题类型决定流程；规定与经历分别取证，冲突保留，阅读范围明确 |
| 职业规划 | [建议](../../src/bridges/career_plan/advising.py)主要从岗位样本中的技能组合生成，当前模块不接入完整的个人能力差距分析输入 | 区分岗位情报与个人规划；未知能力保持待确认，个人建议基于最小明确背景 |
| GitHub | [排序](../../src/bridges/github/ranking.py)按关键词覆盖计数，并以比例区分整体与组件 | 用必要功能及场景证据矩阵判断覆盖；区分 README 自述与已核对实现，关键必要功能缺失不能被大量可选项抵消 |

上述规则具备确定性和易调试的优点，但应作为初筛信号，而非高层结论的充分依据。

## 学习模式问题

| 问题 | 当前证据 | 改进方向 |
| --- | --- | --- |
| 评分依据在作答后生成 | [复盘题合同](../../src/bridges/contracts/study.py)没有预先评分要点；[批改](../../src/bridges/study/review.py)收到答案后生成判定和标准答案 | 题目与评分要点一起核验，判定依据在提问前冻结 |
| 阶段意图识别较窄 | `review_intent` 以正则和短语匹配开始、暂停与再讲 | 主智能体提出有原话依据的阶段事件，代码按当前状态验证；否定、引用和普通回答不触发迁移 |
| 引用覆盖与内容正确性混淆 | 识别后映射检查片段 ID 及每页引用，预习/复盘检查知识点覆盖；辅导检查来源类型和引用合法性 | 保留结构门，再增加关键定义、公式、关系及评分要点的证据支持核验 |
| 辅导补证缺少问题级充分性门 | [辅导](../../src/bridges/study/tutoring.py)使用 `ChatMode.COMPANION` 规划联网；联网异常可直接中断 | 先判断书页是否足够，必要时逐层补证，可选来源失败不阻断书页能够支持的回答 |
| 教学状态与运行检查点职责需明确 | [学习服务](../../src/bridges/study/service.py)同时更新领域状态并运行持久图，节点体使用闭包里的状态 | 权威教学状态保存在领域仓库；运行图保存版本和产物引用；用完成收据与版本检查消除恢复时的歧义 |
| 一次回答难证明长期掌握 | 总结有 `mastered` 类别，并通过题目判定关系核验 | 用户选择保持一次覆盖复盘。总结限定为本次表现，保留未作答与缺口，不自动追加教学循环 |

教学状态的恢复一致性需要专项故障测试，静态阅读不足以将它定性为已经复现的数据错误。

## 设计取舍

新增主智能体会增加理解与规划成本，语义匹配也引入模型误判可能。因此采用轻量直答、稳定模块配方、按需专业调用、有证据的匹配、按风险复核和有限补证。模块节点不会全部升级为自主智能体。

具体目标合同见 [公共编排](orchestration.md)、[日常流程](daily-workflows.md)、[学习流程](study-workflow.md)。效果需通过 [迁移与验收](delivery-and-validation.md)中的场景和配对评测确认。
