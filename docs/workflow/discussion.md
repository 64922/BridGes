# 智能体工作流设计讨论记录

## 范围与现状依据

本轮覆盖日常陪伴、论文搜索、校园通勤、学习资料推荐、华东交通大学吧信息搜集、职业规划、GitHub 项目推荐，以及学习模式的识别、预习、辅导、复盘和总结。

现状以 [V2 工作流](../v2/workflows.md)、[V2 产品契约](../v2/product-contract.md)、[ADR-0030](../adr/0030-v2-campus-assistant-and-approved-desktop-interaction.md) 和当前实现共同核对。现状审查属于静态审查，尚未通过实测确定性能或回答质量。

## 已确认决策

### D01：日常陪伴采用混合启动

用户确认选项 B：保留模块菜单；用户通过自然语言明确要求查论文、找资料等任务时，可以直接启动对应模块；复合任务可以组合相关模块。有歧义时追问，执行过程可见、可停止。

这项选择修改 ADR-0030 与 V2 产品契约中的显式启动合同：未选模块时不再仅提供一键建议。现有代码仍遵循原合同，后续实施需要同步更新相关合同与验收依据。

当时待展开：自动组合范围、计划调整的具体限制，以及澄清答案与任务的绑定规则。

### D02：主智能体统一规划，按需委派专业智能体

用户确认选项 A：一个主智能体统一理解任务并提出执行计划，专业智能体按需参与；代码控制权限、预算、检查点、重试和终止。

确定性工作直接调用工具或服务，复杂分析才调用专业智能体。不要求每个节点都成为智能体，也不采用各模块自由协商、互相无限调用的结构。

当时待展开：专业智能体输入输出合同、核验策略的具体触发条件，以及日常陪伴和学习模式如何共享编排底座。

### D03：跨模块动态规划，模块内部受约束调整

用户确认选项 A：主智能体可依据任务组合已经登记的能力，安排顺序、依赖和并行关系。模块内部保留稳定流程，只允许明确登记的补证、改查和重排分支。

例如，论文与学习资料可以独立检索；查找选定论文的实现需要先取得论文结果，再调用 GitHub 模块。结果不足时可以依据真实缺口调整查询或补充来源，但保留用户原始条件。通勤必须先确认地点，再请求路线，不能由模型跳过必要步骤。

当时待展开：计划与任务状态的具体合同、调整触发条件、执行预算、重试上限，以及新增或修改条件时的失效和恢复范围。

### D04：保存独立的跨轮任务状态

用户确认选项 A：会话承载聊天历史，可以包含多个任务；任务保存目标、已确认条件、计划、结果和待回答的问题，可以跨多轮持续；单次运行只执行本轮必要步骤，具有自己的检查点和失败状态。

系统需要明确识别继续、修改、暂停和新任务；指代不清时追问，避免串用条件。普通闲聊保持轻量，不为每条消息创建复杂任务。

例如，岗位搜索中的「换成杭州」修改原任务的城市；「根据这些要求推荐练手项目」复用岗位证据并接入 GitHub 模块；「先不找了，聊点别的」暂停原任务，后续闲聊不作为旧澄清请求的答案。

当时待展开：任务状态迁移、条件修改后的产物失效范围，以及多个可延续任务之间的定位规则。

### D05：分层核验，按任务类型和风险启用独立复核

用户确认选项 A：代码执行确定性检查，覆盖权限、结构、引用定位、数值计算和用户条件；对生成的关键结论执行证据核验，检查证据是否支持结论、是否夸大以及是否存在冲突。

复杂综合判断、存在争议的解释或不确定的学习判定，按任务类型和风险交给独立核验角色复核。证据不足时补证、缩小结论或明确缺口。普通闲聊和纯工具计算不强制增加整套模型复核。

引用存在不等于结论受到支持；模型复核也不作为正确性的保证。各模块仍须明确它实际取得并读取了哪些证据，以及尚未核实哪些内容。

当时待展开：各模块必须通过的质量门、独立复核触发条件，以及流式正文与最终核验状态的呈现关系。

### D06：局部恢复，交付有效部分，必要步骤失败则阻塞

用户确认选项 A：以节点为单位保存已完成且仍有效的产物和执行状态；失败后从受影响步骤恢复，不重复执行有效的已完成工作。

临时超时允许有限重试；结果不足或核验不通过，允许在执行预算内补证或调整查询。可选步骤失败时交付已经核实的部分，明确未完成项；必要步骤失败时阻止依赖它的结论或状态推进。

例如，视频检索失败可以先交付已核实书目；论文尚未确定时不能声称某仓库是对应实现；学习批改失败时保留当前题，不跳题、不更新掌握判断。

当时待展开：各模块必要和可选步骤的划分、重试与补证预算、产物有效性规则，以及失败原因与恢复操作的用户投影。

### D07：学习模式保留一次覆盖式复盘

用户选择选项 B：保持一次覆盖式复盘。每题判定后给正确答案和简短解释，随后进入下一题；理解漏洞记录在总结中，用户主动要求时再辅导。

不自动追加补救题或迁移验证题，也不要求用户补答原题。题量仍随本节知识密度变化，并覆盖本节已上传书页内容。批改或必要核验失败时沿用 D06，保留当前题，不推进题号或掌握判断。

该选择保持现有 V2 复盘的核心产品合同。后续改进聚焦题目质量、答案判定、证据支持、总结表述和状态恢复，不引入系统主动追加的教学循环。

当时待展开：知识范围和题目覆盖核验的具体合同，以及评分与总结的具体核验规则。

### D08：学习辅导教材优先，证据不足时自动补证

用户确认选项 A：先取得与问题相关的书页证据，判断其是否充分；不足时按用户设置检索已启用的知识库，仍不足时自动联网补证。补证围绕具体缺口展开，不对每次辅导强制联网。

书页充分时直接讲解；教材内容与补充解释分开标注来源。补充来源失败时可交付已有书页能够支持的部分，并说明剩余缺口，依赖缺失证据的结论保持阻塞。

复盘范围仍限定为本节上传书页内容，外部补充不自动成为考查范围。数据使用继续遵守账户与会话作用域和用户设置。

当时待展开：证据充分性的具体判据与来源冲突处理。

### D09：先建立并核验评分要点，再提问和判定

用户确认选项 A：复盘出题时同时建立核心评分要点、对应书页依据、可接受的不同表述或等价推导，以及关键误解和不完整判定条件。评分依据通过核验后再向用户提问，内部依据不提前展示答案。

收到作答后按已保存要点核对，表达方式不同不作为扣分理由；有争议的判定按 D05 进入复核，必要核验失败按 D06 保留当前题。评分依据不因学生回答而临时变更。

总结描述本次答对内容与实际暴露的漏洞，避免将单次答对直接解释为长期掌握；仍遵守 D07，不自动追加补救题。

当时待展开：评分要点与知识范围的版本绑定、核验触发细则，以及追加书页后的未问题重排规则。

### D10：证据约束的语义匹配，加确定性条件过滤

用户确认选项 A：候选匹配保留用户原话和明确条件，使用受约束查询获取候选证据；专业智能体判断需求与证据的语义对应关系，并给出支持各项需求的具体片段。代码继续检查年份、城市、出行方式等明确条件。

关键词作为检索线索，不再要求每个相关候选都字面命中原词。不能证明相关性的候选标为未确认或排除；查询扩展和候选选择不得改变用户目标。原始请求与实际查询词仍可供用户检查。

这项选择修改 V2 工作流中原词硬覆盖的部分规则，主要影响论文、学习资料和 GitHub 推荐。职责、对象范围等明确过滤条件继续有效，语义匹配不能用于绕过这些条件。

当时待展开：各模块匹配量表、语义核验预算，以及整体项目和组件等分类的具体判据。

### D11：先筛选，再按结论需要逐级深入读取

用户确认选项 A：推荐任务先取得可访问的候选材料并筛选，再根据准备给出的结论加深读取。简单推荐保持轻量，重点候选和复杂判断投入更多读取与核验。

论文可先按标题、摘要、作者和年份筛选；比较具体方法、解释实验或给复现建议时需要相应的深入证据。GitHub 可先读取元数据和 README；判断关键功能实现或可借鉴架构时需要相关实现证据。学习资料可先读取书目、简介、目录或可访问的视频介绍；判断先修要求、内容覆盖或具体学习路径时需要相应内容证据。

每项结果标明实际读取范围；没有取得全文或实现文件时，结论停在已有证据能够支持的层次。必要证据缺失时补证或按 D06 交付有效部分，不能凭模型记忆冒充已经读取。

当时待展开：各模块必读证据、分层读取的执行预算，以及重点候选选择规则。

### D12：学习资料按目标组织精简学习路径

用户确认选项 A：先明确学习目标、已有基础与时间约束，再选择资料与组织顺序。说明每份资料的用途、顺序和适用基础；数量及书、视频的组合随目标、内容互补性和实际可得证据变化。

快速理解概念使用少量直接相关材料；备考围绕课程范围和薄弱知识点；系统学习确定主线教材与补充讲解，并说明先修要求。书与视频可以并行检索，缺少会影响选择的信息时才追问。

这项选择修改 V2 默认「2 本书 + 3 条视频」的数量合同。用户明确提出的数量或媒介要求仍需遵守；不足时如实说明，不以未经核实条目补足。

当时待展开：学习路径的匹配量表、目录或视频介绍等证据不足时的降级形式，以及跨模块结果的整合格式。

### D13：职业规划按目标支持岗位分析与个人差距规划

用户确认选项 A：用户只要求查询岗位时直接完成岗位分析；用户要求个人准备建议时，在岗位证据基础上结合最小相关背景，给出差距判断和行动优先级。

流程为核实目标岗位与样本、提炼岗位要求、获取最小相关用户背景、区分已确认差距与待确认项，再给出有依据的行动优先级。背景取自当前陈述、允许使用的画像或简历材料，明确区分证据与推断。

背景不足时先交付岗位分析，再追问一个会影响建议的关键问题。岗位要求不直接等同于用户能力差距，未知能力不判为薄弱项。

当时待展开：个人差距的判定量表、行动建议与论文/资料/GitHub 模块的组合边界，以及岗位样本分析的质量门。

### D14：贴吧模块按问题类型安排来源顺序和核验

用户确认选项 A：规定类问题优先核对适用的官方来源及日期，贴吧提供实际办理经历；个人体验类问题以实际读取的帖子和回复为主，保留时间、场景与不同意见；混合问题分开取得并呈现两类证据。

官方公告与吧友经历可能对应不同时间或场景，不直接合并为同一结论。保留冲突和缺口；只有搜索摘要时只输出帖子线索，不能概括未读取的回复或声称普遍共识。

该选择调整 V2 统一贴吧检索主线后再补官方核验的执行顺序，仍限定在华东交通大学吧的公开帖子及任务相关官方补证范围。

当时待展开：来源冲突的具体裁决规则、证据日期有效性与取证预算。

### D15：明确正文优先，模块选择作为路由提示

用户确认选项 A：正文表达明确时按正文处理，自动调整本轮路由；模块选择用于辅助理解，有歧义时追问。复合请求可依据正文组合相关模块。

用户明确说「只查论文」「不要联网」等限制属于必须遵守的约束，不因模块提示或模型计划而放宽。实际调用模块在本轮进度和结果中可见，历史消息标识不重写。

本决策只调整日常陪伴的能力路由，不改变首条消息后固定的会话模式，也不自动将学习会话转换为日常陪伴。

这项选择修改 V2 将逐消息 module_id 作为固定派发依据的合同。后续实现需要分别保留请求中的模块提示与实际执行决定，避免在持久化消息或重试中混淆两者。

当时待展开：歧义与跨轮任务定位规则、自动组合的执行预算，以及本轮路由的简洁呈现方式。

### D16：默认及时交付可信结果，必要时自动补证一轮

用户确认选项 A：普通查找保持精简，必要时最多自动补证一轮。用户明确要求比较、精读或深入分析时，由代码按任务类型分配更高预算；仍有缺口时说明限制，由用户决定是否继续。

所有节点共用本次运行的总预算，为必要核验和结果交付预留时间；重试、并行分支和进程恢复都不能重置预算。主智能体不能自行延长预算，耗尽时交付已核实部分或说明阻塞原因。

具体时间与调用上限在正式设计中区分建议值和待实测项，不将尚未验证的性能当作承诺。当前聊天预算已有 120 秒硬上限基础，各日常模块还使用自己的阶段计时，需要在后续实现中统一约束。

当时待展开：两种模式如何共享内核；预算建议值、节点重试和重点候选上限需在具体方案中明确并经代表性任务实测。

### D17：共享执行内核，模式策略与领域状态分别管理

用户确认选项 A：日常陪伴和学习模式共享任务与运行管理、上下文编译、能力注册、节点恢复、预算、证据核验和进度事件，模式策略及领域状态分别管理。

日常策略按明确意图规划并组合六个模块；学习策略在当前教材小节和教学阶段内组织讲解、取证与反馈，代码检查阶段迁移，复盘遵守 D07 的一次覆盖规则。

会话模式仍在首条消息后固定。普通聊天不自动创建教学流程，学习流程不被无关的日常任务替换。共享内核统一公共规则，同时保留教学领域的独立约束。
