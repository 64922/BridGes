# 迁移与验收

状态：已确认定稿。本轮仅完成设计；本文件是已确认的后续实施顺序与验证要求，不表示测试已经运行或外部能力已上线。开发与验证使用 conda `agent`。

## 1. 合同与兼容

进入实施时，在正式 ADR 和 V2 产品/API/交互合同中记录替代关系，不静默覆盖历史设计。任务通过本仓库 `.scratch/` 本地 Markdown 跟踪，沿用 [任务约定](../agents/issue-tracker.md)与 [分诊状态](../agents/triage-labels.md)。

| 当前合同 | 变更 | 兼容要求 |
| --- | --- | --- |
| 逐消息 module_id 固定派发 | 保留原请求提示，另记实际路由与来源 | 旧消息模块标识不重写，新旧投影按版本解释 |
| 无模块只建议启动 | 明确意图可直接执行，歧义仍澄清 | 点击建议绑定任务版本，不靠改原文重复提交 |
| 模块自行结束消息 | 返回产物，由共享内核核验并统一收敛 | 历史结果结构可只读展示，终态服务继续承担守卫 |
| 模块内串行黑盒 | 显式持久节点与完成收据 | 安全恢复旧运行；不把新版本节点套到旧谱系 |
| 原词硬覆盖 | 语义证据匹配加硬条件过滤 | 原话/查询可追溯，旧防止改主题的验收目标保留 |
| 固定 2 本书 + 3 条视频 | 目标驱动的精简路径 | 用户明确数量/媒介要求仍是条件，旧清单可读 |
| 作答后即时生成评分标准 | 出题前保存私有评分要点 | 旧题保留原判定，不能宣称曾按新标准判过 |
| 日常/学习分别维护执行规则 | 共享内核、模式领域状态分离 | 会话模式与小节边界继续由服务端限制 |

不通过复用旧 WorkOrder 引入项目审批流程，不恢复退役媒体、提醒或工作台能力。原有账户/附件/画像/删除与导出合同继续适用。

## 2. 实施顺序

每个切片均交付一条可验证的纵向路径，不先建立巨大通用智能体平台。以下是建议拆分，需在进入实现时生成本地任务。

| 切片 | 实施内容 | 验收结果 |
| --- | --- | --- |
| S01：任务与产物合同 | 任务版本、等待绑定、产物引用、节点收据、计划与模式校验；复用现有运行/事件/终态存储 | 同一请求幂等、跨账户拒绝、旧消息可读、等待不占运行资源 |
| S02：确定性节点恢复 | 先将通勤拆为真实节点，验证阶段产物与停止守卫 | 定位已完成而路线失败时只重试路线；取消后迟到结果不推进状态 |
| S03：混合入口与任务延续 | 主智能体结构化理解、模块提示/实际路由区分、硬条件与跨轮关系 | 自然语言直启、旧模块提示冲突、暂停/换话题/条件修改均符合合同 |
| S04：论文/资料/GitHub | 逐模块接入语义匹配、分层读取、证据矩阵及质量门 | 不同表述相关候选可命中；关键词假阳性被排除；未读内容不作断言 |
| S05：贴吧/职业 | 来源类型规划、样本统计、最小背景与差距合同 | 规定/经历分开，职位分析不冒充个人能力诊断 |
| S06：学习领域迁移 | 版本化书页、范围覆盖、预习门、问题级补证、出题前评分、判定/总结提交 | 一次复盘、不自动追加题，补页/中断/最后一题总结失败可正确恢复 |
| S07：统一预算与界面投影 | 全节点共同截止/调用计数、有限调整、实际进度、有效部分和阻塞呈现 | 预算不重置、不发布未核验事实块、刷新后结果与状态一致 |
| S08：配对评测与外部上线门 | 保持相同任务数据比较现状和目标流程，真实服务最小探针 | 质量、成本、延迟有证据；未通过外部门的能力继续如实降级 |

预算与权限守卫从 S01 就进入骨架，S07 是覆盖所有模块和前端的完整接线，不是允许前面切片先无限调用。公共语义策略可复用，模块量表和来源规则分别维护，不为了统一而抹平领域差异。

现有 `chat/graph.py`、`service.py`、`turn.py`、`run_executor.py`、检查点、终态和模块服务是主要接缝。按切片抽出职责，复用有效解析、请求、渲染和投影；不一次性重写庞大的聊天服务或改无关格式。

## 3. 必须成立的场景

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| A01 | 普通问候/陪伴 | 轻量回答，无不必要专业调用和复杂任务 |
| A02 | 保留论文提示，正文明确问校内通勤 | 按通勤路由；只问真正缺少的地点/方式，历史标识不改 |
| A03 | 孤立歧义主题，前文无法消歧 | 问一个必要问题，不替换主题、不先查猜测领域 |
| A04 | 查入门论文和学习资料 | 共享目标，独立部分可并行；一个总预算 |
| A05 | 查选中论文的对应实现 | 以论文标识为依赖；身份未确认时不声称仓库对应 |
| A06 | 求职城市从上海改杭州 | 新版本使旧城市样本/统计失效，背景和无关有效产物复用 |
| A07 | 澄清未答时用户换话题，稍后说“好的” | 不把新消息填进旧澄清；需要唯一任务归属 |
| A08 | 多个历史任务都可能被“继续那个”指代 | 澄清一次，不仅凭最近模块强行恢复 |
| A09 | 资料视频来源失败，书目仍可核验 | 交付有效书目及范围；不凑视频、不整体抹掉书目 |
| A10 | 候选使用不同术语，但证据支持需求；另一个只命中词 | 前者可通过语义匹配，后者因无覆盖证据被排除 |
| A11 | 用户限定年份/城市/不联网 | 语义扩展和补证不放宽这些条件 |
| A12 | 通勤某方式无真实路线 | 不用其他方式耗时替代，不生成猜测地图 |
| A13 | 高峰前后 10 分钟边界 | 按 Asia/Shanghai 一致计算，5 分钟缓冲标为规则 |
| A14 | 贴吧只有标题/搜索摘要 | 只交付线索，未读回复不总结，不称普遍共识 |
| A15 | 官方规定与帖子经历冲突 | 按日期/范围核对，仍冲突时分别呈现 |
| A16 | 无用户技能背景的岗位查询 | 正常交付岗位分析，未知技能不判为不足 |
| A17 | GitHub 可选功能很多，必要功能未支持 | 不因覆盖比例或 stars 判为整体适配 |
| A18 | README 有架构说明但未读实现、未运行 | 区分文档自述、静态证据与运行未验证 |
| L01 | 书页关键负号/上标不清 | 定位补拍/补录，依赖该符号的出题被阻塞 |
| L02 | 不同知识点同名、多个页含不同公式 | 用稳定 ID 与片段定位，不串题或评分依据 |
| L03 | 书页足以回答 | 不自动联网；必要上下文保留 |
| L04 | 书页不足，知识库/公网其中一路失败 | 交付能支持的部分，缺口真实；不伪装外部来源 |
| L05 | “还没学完”或引用“开始复盘” | 不触发复盘；语义动作仍通过代码阶段门 |
| L06 | 学生使用等价表述/推导 | 按预先要点判定；争议复核，不因措辞不同判错 |
| L07 | 批改调用失败或判定结构不合法 | 不推进题号、不将系统失败记为学生错误 |
| L08 | 暂停复盘后要求讲解，随后继续 | 讲解不作为答案；已问题保留，默认继续未问题 |
| L09 | 本节追加书页识别失败后重试 | 原有效范围保留，复用未变页；有效更新后只重排未问题 |
| L10 | 最后一题判定已提交，总结失败 | 判定/反馈保留，只重试总结，未完成总结不称全流程完成 |
| L11 | 原题已判错后继续复盘 | 给反馈后继续基础计划，不自动追加补救题 |
| L12 | 直接读取会话/重放事件 | 未来题和未到反馈阶段的评分要点/标准答案不泄露 |
| L13 | 总结存在未答题或未判定题 | 单独描述，不能计为掌握或错答 |
| R01 | 同一请求重试、刷新/SSE 断线 | 不重复消息、附件或判定；事件按游标可重放 |
| R02 | 节点产物已提交，图检查点尚未保存时进程失败 | 从完成收据恢复，已完成本地效果不重复 |
| R03 | 旧租约执行者晚返回，或用户已经停止 | 拒绝旧尝试/取消后的提交，不覆盖新版本 |
| R04 | 工具限流或多节点重试 | 预算/计数不重置，有限重试，真实恢复时刻才展示 |
| R05 | 材料/画像撤回后恢复旧运行 | 重新检查访问与依赖有效性，不重新召回被撤回切片 |
| R06 | 不兼容配方版本的历史运行 | 安全结束或迁移到明确新运行，不盲目套新图继续 |
| R07 | 用户停止、稍后明确继续 | 停止不自动续跑；继续创建新运行并复用有效产物 |
| R08 | 模型建议调用未登记/退役能力或切换模式 | 代码拒绝，不能绕过 API/模式/能力边界 |

这些是行为断言，不以“节点名出现”或最终正文包含关键词代替真实验证。

## 4. 验证方法

先以固定工具/模型响应验证确定性状态、预算、版本和恢复不变量，再以真实模型评估语义匹配、教学与核验。针对节点收据、检查点、判定和最终提交之间的边界做故障注入，覆盖重复请求、旧租约与取消竞争。

接口和桌面验收同时验证实际模块、简短进度、有效部分、等待和阻塞可理解；直接 API 请求也必须守住会话模式和对象权限。复用已有 V2 账户、附件、画像墓碑、终态与恢复测试，仅修改和新决策冲突的预期，不删掉仍有效的防错目标。

模型语义案例包含同义表达、跨语种术语、关键词假阳性、稀疏来源、争议答案和错误书页。记录代码/配方/模型/提示词/Schema/来源快照与时钟；真实模型结果不假设完全确定，必要时多次运行并报告波动。

## 5. 质量、成本与延迟

| 维度 | 记录与比较 |
| --- | --- |
| 路由/任务延续 | 正确能力、任务归属、硬条件违反、错误自动启动、澄清次数 |
| 证据 | 关键结论有支持的比例、引用可定位、读取范围诚实性、未支持断言 |
| 推荐 | 语义相关性、必要需求覆盖、学习基础适配、重复/无效条目 |
| 教学 | 关键识别错误、范围覆盖、评分要点正确性、等价答案误判、总结夸大 |
| 稳定性 | 本地重复效果、错误状态推进、恢复复用、迟到覆盖、取消后的新调用 |
| 成本 | 模型/工具调用数、输入输出 token、实际读取量、重试与补证次数 |
| 延迟 | 首个真实进度、首个可用结果、完整结果的 P50/P95，按任务类型分组 |

对同一组任务配对比较旧 V2 和新编排。新增模型核验的成本应换来可观测质量收益；轻量对话不应增加规划/裁判调用。语义正确率和延迟阈值在取得基线后确定，不用未测数字宣称改进。

账户越权、硬条件绕过、系统失败推进题号、重复判定和取消后的非法写入属于阻止发布的不变量。外部结果不全可以降级，不支持的关键断言不能因为“回答完整”而通过门。

## 6. 外部能力上线门

继续执行 [V2 可行性门](../v2/feasibility.md)，本轮设计不替代真实服务验证。学术全文可得性、高德校内覆盖、贴吧回复、公开岗位和视频内容均按实际取得范围处理；用户配置模型的结构化、多模态和上下文能力仍须真实探测。

新读取或语义节点未通过实测时，只开放已经验证的层次，不宣称深读、代码运行或全部回复总结已经可用。试测只使用获授权配置与最小必要查询，测试结果记录状态与脱敏指标，密钥不进入输出。

上线顺序以纵向切片为准。回滚停用新写路径并保留新旧历史、事件和产物，不通过清数据库、丢弃新任务或恢复退役入口实现回滚。

## 7. 本轮文档验证范围

本轮检查文档路径、相对链接、D01—D17 覆盖、模块数量和关键约束的一致性。尚未实施业务改动，因此没有将这些验收场景宣称为已通过；预算初值、模型效果和外部服务门留待实施验证。
