# 文章按需定向二次修订（至多两次写作调用）

> 状态：accepted（2026-08-12）
>
> 本 ADR 正式取代 [ADR-0011](0011-clean-room-humanizer-and-license-boundary.md) 中「自然语言文章路径只做一次结构化生成」的条款。普通聊天仍然只沿唯一主模型调用注入轻量策略，一次调用不变。

## 决策

带版本化表达任务契约的文章任务允许至多一次首稿生成和一次定向修订，两者合计的写作模型调用上限为 2。首稿完成后先执行来源保真硬门、任务契约检查与表达审稿；只有存在明确、可修复的问题时才追加一次定向修订。修订调用只接收原任务、必要原文与保护项、首稿正文和带位置的问题清单（code/位置/证据/目标），只修指定问题；不重新注入全量规则、不扩张事实、不循环调用。修订后重新执行同一版本保真硬门、契约检查与表达审稿，再决定交付、带警告交付或停止交付。

本决策不改变以下既有合同：

- 普通聊天仍沿唯一主模型调用注入轻量策略，不获得第二次写作调用（[ADR-0026](0026-frozen-product-contracts-and-migration-gates.md)、Issue 07）。
- 文章最终结果仍跳过全局轻量策略二次改写（ADR-0026、Issue 07 增量决策）。
- 模型提供方重试、协议重试（`RetryPolicy`/`ModelCallStatus.RETRYABLE_FAIL`）与风格修订各自独立计数：只有进入正文生成语义的调用计入 2 次写作上限。
- 修订不授予新的事实来源：修订稿不得包含来源账本之外的事实、经历、例子或新论点；保护 span（精确引语、用户指定措辞、原文保留项）与来源哈希必须保持。

## 触发条件（版本化触发裁决）

触发裁决是版本化确定性逻辑（`revision-policy-v1`），至少区分以下类别：

| 类别 | 是否触发修订 | 说明 |
| --- | --- | --- |
| 可修复保真问题 | 是 | 保护项被破坏、事实/专名/数字/日期/方向被篡改等可定向恢复的问题。 |
| 无来源新增 claim | 是 | 修订删除该 claim 即可恢复硬门，不新增任何材料。 |
| 任务契约遗漏 | 是 | 硬约束未包含、体裁任务目标未达成等契约层面缺口。 |
| 高置信表达问题 | 达到预注册阈值才触发 | warning 级表达审稿发现；按 code 预注册最低命中数（默认 1，弱信号 code 可注册更高阈值）。 |
| 低置信软信号 | 否 | suggestion/info 级发现与 `no_change_recommended` 不触发修订。 |
| 模型/协议错误 | 否 | 错误按既有失败语义终态，不是修订触发条件。 |
| 无需修改 | 否 | 首稿已自然时只调用一次，不触发。 |

高置信阈值与 code 清单随策略版本预注册，不随单次任务输入漂移。

## 修订调用预算与截止时间

- 修订调用有独立的第二阶段预算与截止时间：预算不足、用户已停止或全局前台截止时间不足时不启动修订，直接返回首稿的真实硬门/软审稿状态。
- 写作调用计数在持久运行状态中原子记录（单条消息更新的 SQLite 事务，消息级运行锁保证同一消息无并发 run）：重试与恢复沿用计数，服务重启不能重新获得修订额度；任何路径都不会发生第三次写作调用。
- 修订有独立超时语义；超时、预算不足或用户停止后按首稿的真实检查状态终态，不把未通过的稿子标为成功。

## Issue 01 第八轮：用户手动重试视为新一轮写作预算

本增补修订「修订调用预算与截止时间」中「任何路径都不会发生第三次写作调用」的范围：**单轮（单次任务尝试）内**写作调用仍至多 2 次、任何路径都不超过本轮 2 次上限；但**用户手动重试（任务输入已保留）视为新一轮写作预算**——重试创建的新尝试重置持久化的写作调用计数（`bridges.chat.service.RETRY_RESETS_WRITING_BUDGET`，默认开启，可关闭回滚），新一轮内首稿 + 定向修订仍至多 2 次。

- 恢复路径语义不变：服务重启后同一条消息的 queued run 重新执行时仍沿用计数与已产出正文（不重新获得修订额度）；只有用户通过消息级「重试」按钮创建的新尝试才重置计数。
- 驱动原因：保真失败且 2 次写作调用已用尽时，旧语义下用户点「重试」直接撞 `writing_call_limit_reached` 死胡同，与「重试（输入已保留）」的恢复文案承诺不符（生产观测 2026-08-15）。把手动重试定义为新一轮预算后，用户可真实再生成；单轮上限数值不变，不引入第三轮修订。
- 实现位置：`src/bridges/chat/service.py::ChatService.retry_generation`（新尝试的 humanizer 检查点不再沿用旧计数）；开关关闭时恢复旧语义（沿用计数，用尽稳定拒绝），供灰度回滚。

## 终态语义

- 首稿通过：只调用一次，按既有语义交付。
- 触发修订：恰好增加一次调用；修订后重跑同版本来源硬门、任务契约检查与表达审稿。
- 修订后仍有关键保真失败：停止交付（错误终态），展示具体冲突与恢复方式。
- 修订后只剩非关键风格警告：按现有 WARN 语义交付并展示具体风险。
- 修订后已通过：交付修订稿。
- 修订未执行（预算/停止/截止/开关关闭/模型失败）：返回首稿的真实硬门/软审稿状态与原因，正文与警告照常交付。

## 观测与审计

- 运行结果记录：是否触发、触发 code、首稿/修订稿检查摘要、问题解决数、额外 token、额外延迟与终态；正文不进入普通日志与遥测（正文仍按既有受控结果存储）。
- 指标：修订触发率、按 code 触发分布、问题解决率、修订后硬门失败率、额外 token、p50/p95 额外延迟、预算拒绝数与停止数。
- 审计只记录哈希、检查摘要与必要审计 ID，不保存正文或系统提示词。

## 回滚

定向修订由独立能力开关控制：关闭即恢复一次调用，不改变来源硬门行为，也不把未通过首稿标为成功。通过能力开关与策略版本灰度发布；回滚只关闭修订调用，新 ADR 与历史审计不删除。

## Issue 02 第八次改进增补：机械违规确定性句子级剔除交付

第八次改进 Issue 02 在「终态语义」上追加一层确定性救援：定向修订后重跑
同一版本检查仍 blocking、且全部 blocking findings 属于**机械可剔除集合**
（`unattributed_claim` / `assumption_not_allowed` / `assumption_carries_fact`
/ 无来源新增亲历形态的 `first_person_unbound`）时，对最新候选正文按
finding 位置定位违规条目所在**句子**并整句剔除（零模型调用，不占用写作
调用额度），对剔除稿重跑同一版本全套检查（保真硬门 + 硬约束包含 + 表达
审稿），通过则以「已剔除交付」终态交付成品并如实标注移除清单；真正破坏
原文事实（引语/URL/公式/代码/引用被破坏、因果方向反转、否定删除、结论
强度升级、亲历丢失等）时维持拦截。

- 剔除粒度整句，不做 span 级（词级）剔除；同一句子命中的多条 finding
  只剔除一次，移除清单仍逐条记录。
- 安全护栏（任一命中即停止交付、不交付残稿）：剔除后正文为空；剔除
  句数占比超过单一常量（默认 40%，`EXCISION_SENTENCE_RATIO_LIMIT`）；
  剔除稿重检仍不通过（如违规句同时承载保留事实）。破坏事实类码与保留
  检查形态（无位置）永不剔除。
- 终态与审计：表达契约路径的 `revision_audit.final_state` 新增取值
  `excised_delivery`；`delivery_note` 如实写明「已移除 N 处无来源/未授权
  内容」；审计记录 `excision_attempted`、移除条数、剔除句数、句数占比与
  `excision_blocked`（尝试剔除但仍未交付，即「剔除后仍拦截次数」的计数
  来源），全部为脱敏计数、不含正文。已剔除交付是完整交付（`delivered`），
  不是部分交付。旧显式 SKILL 路径没有修订审计（`revision` 恒为 None），
  其剔除交付通过投影 `article.excision` 与遥测审计记录同样的移除条数/
  类别与 `excision_blocked`，交付语义与新路径一致。
- 新旧路径一致：表达契约流程在「定向修订后仍 blocking」时剔除；旧显式
  SKILL 流程在终态判定前对机械可剔除类 blocking 同样剔除（两路径共享
  同一剔除模块、同一 `_excise_candidate` 编排与护栏）。剔除是终态前的
  确定性救援，与修订是否执行/跳过原因无关（用户手动停止、预算不足、
  修订开关关闭、模型失败等场景下，只要最终候选仅含机械可剔除类 blocking
  且护栏通过即剔除交付；不触发额外模型调用）。前提不满足（含任一破坏
  事实类码/无位置）时剔除流程不启动，不产生无效尝试记录与过程事件。
- 回滚：`EXCISION_DELIVERY_ENABLED` 能力开关（`service.py` 中
  `FIDELITY_GATE_ENABLED` 旁）关闭即恢复本 ADR 原终态（修订后仍
  blocking → `fidelity_gate_conflict` 停止交付），不改变硬门规则与
  错误码定义。
