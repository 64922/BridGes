# 人性化表达采用原创净室实现

BridGes 将建立原创只读内置 `bridges-humanizer` SKILL，重新编写规则、提示、示例和测试资产，仅从外部参考项目吸收不受版权保护的通用方法。未声明许可证的 `scientific-humanization` 只用于研究，不复制其文本、结构或示例；对 MIT 许可的 `Humanizer-zh` 仍优先不复用，若确需复用任何代码或文本，必须保留许可证、作者署名和可审计来源记录。该 SKILL 同时支持改写已有文本与按主题生成文本，固定输出最终文本、修改明细与理由、事实核查结果和尚未解决的问题；其目标是提高自然度、任务适配度与可读性，不得用于规避 AI 检测、冒充真人或牺牲科学事实。

## Issue 07 增量决策（2026-08-10）

文章改写通过统一聊天入口的 `humanizer-route-v1` 确定性路由进入既有
`bridges-humanizer` 生命周期。路由只编译能力标识、来源、任务合同和版本
快照，不生成最终文章，也不调用模型；旧显式 SKILL 消息仍按旧投影读取和
重试。自然语言改写默认不检索全局知识库；只有消息明确引用当前账户知识库
文档时，才启用现有账户作用域检索，并只把名称精确匹配的材料切片交给人味化
服务。聊天附件不作为新自然语言路由输入，依赖历史聊天附件的自然路由任务
重试必须先迁移到当前账户知识库。自然语言任务还会把“补充/核验外部事实”
保存为路由快照；未明确提出时跳过公网与 arXiv planner。自然语言路径只做
一次结构化生成，质量检查不再二次调用模型；未知路由版本在执行前显式拒绝。

本增量的路由词表、默认值、合同字段、提示文案和测试语料均为 BridGes
原创，参考项目 `Humanizer-zh-main`、`human-writing-main` 与
`scientific-humanization-main` 未贡献任何可复制资产；对应来源清洁记录见
`src/bridges/skills/humanizer/skill/CLEAN_ROOM.md`。

## Issue 17 增量决策（2026-08-10）

- 将原有完整文章人味化任务与普通回复拆开：普通自然语言正文使用 `global-humanized-writing-v1` 轻量策略，沿用现有唯一模型生成调用；Issue 07 文章最终结果跳过全局策略二次改写。
- 全局策略只影响解释深度、例子和称呼等表达层；代码、公式、JSON、引用、链接、确定性错误、工具原始结果、加载/停止状态和协议字段不进入改写范围。模型输出落库前对已知保护区执行确定性恢复，原始事实和机器契约优先。
- 每个运行记录绑定一次策略/模式/最小画像切片快照，重试沿用旧快照；策略资源或画像切片不可用时使用安全基线。审计仅保存版本、模式、切片标识、条目数量和降级原因，不保存画像正文或系统提示词。
- 本次仍执行净室原则：`scientific-humanization`、`cognitive-profile`、`Humanizer-zh`、`human-writing`、`nuwa-skill` 只作为研究/审计对象，未复制代码、提示词、文本、示例、测试、素材或结构；未声明许可的资料不作为实现来源，MIT 资料默认零复用。新增实现、夹具与版本记录均为 BridGes 原创。

## Issue 07 方法体系升级决策（2026-08-11）

- `SKILL.md` 增加合规 frontmatter、检测面、改写面、事实护栏面、三场景档位、个性与分寸，以及人味分档和教学落例两项原创规则；文档明确记录 `DRAFT` 事件、硬门/软门、一次定向修复和 `WARN` 交付语义。
- `method_rules.py` 是方法规则的单一事实源。文章改写与文章生成提示词按路径选择同一规则体系；全局聊天策略使用其聊天档规则，并把版本从 `global-humanized-writing-v1` 升级为 `global-humanized-writing-v2`。保护区、安全基线和文章最终结果跳过全局二次改写保持不变。
- 规则 ID、文档标签与提示词组装由 `tests/humanizer/test_method_rules_consistency.py` 交叉校验；净室整段精确匹配自查结果记录在 `CLEAN_ROOM.md`，参考项目仅贡献通用方法研究方向，不贡献可复制文本或结构。

## Issue 06 证据安全修订增量决策（2026-08-12）

- 文章默认保留原结论：表达任务契约的 `evidence_revision_mode` 默认
  `preserve`，不因体裁是科研/技术就自动打开证据安全修订；只有用户显式
  授权（自然语言授权词或显式选择）才进入 `evidence_safe`，且该选择固化进
  不可变任务快照。
- 默认模式只做确定性 claim 分类与证据风险检测（相关写成因果、无检验写
  显著、拟合/聚类/消融宣称机制、预测等同因果、预测等同真实场景有效），
  风险以独立项呈现，候选正文保持原结论语义，不做静默改动。
- 授权修订最多追加一次模型调用（首稿 + 一次定向修订），更新本 ADR 原
  「质量检查不再二次调用模型」条款：第二次调用只发生在用户显式授权
  证据安全修订且风险非空时；修订后必须重新通过来源保真硬门与受保护项
  一致性检查，否则保持首稿原文并返回稳定 `hold_for_user` 状态，不自动
  添加保守套话，也不进入人工审稿队列。
- 每次结论强度变化记录原文 span、改后 span、变化类型、来源条目、理由与
  是否需要用户确认，由程序在原文与修订文本上确定性重建；数字、单位、
  日期、专名、模型/数据集、样本、图表编号、公式、引语与引用关系保持
  protected，授权改结论不等于授权改这些项。
- 高风险体裁的来源硬门失败仍阻止交付，任何风格评分或系统裁判多数票都
  不能放行。
