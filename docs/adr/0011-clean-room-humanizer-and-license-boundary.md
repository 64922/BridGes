# 人性化表达采用原创净室实现

BridGes 将建立原创只读内置 `bridges-humanizer` SKILL，重新编写规则、提示、示例和测试资产，仅从外部参考项目吸收不受版权保护的通用方法。未声明许可证的 `scientific-humanization` 只用于研究，不复制其文本、结构或示例；对 MIT 许可的 `Humanizer-zh` 仍优先不复用，若确需复用任何代码或文本，必须保留许可证、作者署名和可审计来源记录。该 SKILL 同时支持改写已有文本与按主题生成文本，固定输出最终文本、修改明细与理由、事实核查结果和尚未解决的问题；其目标是提高自然度、任务适配度与可读性，不得用于规避 AI 检测、冒充真人或牺牲科学事实。

## Issue 07 增量决策（2026-08-10）

文章改写通过统一聊天入口的 `humanizer-route-v1` 确定性路由进入既有
`bridges-humanizer` 生命周期。路由只编译能力标识、来源、任务合同和版本
快照，不生成最终文章，也不调用模型；旧显式 SKILL 消息仍按旧投影读取和
重试。自然语言改写默认不检索全局知识库；只有消息明确引用当前账户知识库
文档时，才启用现有账户作用域检索，并只把名称精确匹配的材料切片交给人味化
服务。聊天附件不作为新自然语言路由输入，依赖历史聊天附件的自然路由任务
重试必须先迁移到当前账户知识库。自然语言任务还会把“补充/核验外部事实”
保存为路由快照；未明确提出时跳过公网与 arXiv planner。自然语言路径只做
一次结构化生成，质量检查不再二次调用模型；未知路由版本在执行前显式拒绝。

本增量的路由词表、默认值、合同字段、提示文案和测试语料均为 BridGes
原创，参考项目 `Humanizer-zh-main`、`human-writing-main` 与
`scientific-humanization-main` 未贡献任何可复制资产；对应来源清洁记录见
`src/bridges/skills/humanizer/skill/CLEAN_ROOM.md`。
