# ADR-0040：话题驱动的贴吧讨论采集与自动登录续接

日期：2026-10-11。状态：accepted（用户已确认设计；代码已部分实现，真实端到端验收未完成）。

## 背景

用户希望提出华东交通大学吧的一个话题后，系统搜集相关帖子和回复，交付一段有来源依据的文字总结。现有实现只尝试读取前三个候选，浏览器读取依赖有限次滚动；主题判断主要依靠关键词命中，“归纳”通过标记词分类摘录而不调用模型。这些机制不足以支持多帖、多层回复的语义总结。

本 ADR 记录用户确认的设计边界。实现与验证进度、未完成验收及环境限制见 [贴吧话题研究工单](../../.scratch/tieba/issues/01-topic-driven-tieba-research.md)。

## 已确认的产品边界

- 固定搜集华东交通大学吧的话题讨论。默认覆盖优先，先覆盖更多相关帖子，再深入采集相关回复、楼中楼与必要上下文；不要求先读完整个长帖才能交付。
- 用户没有指定时间时，以近十二个月为主；讨论不足时补充历史信息，明确标注时间并区分近期与历史情况。用户明确时间条件优先。时间依据采用实际发言时间，老帖的近期回复可以纳入，旧内容作为必要上下文；无法确认时间的发言不能标为近期证据。
- 讨论搜集默认只查贴吧。用户要求确认规定或核实真伪时，再追加学校官网核验，分别表达网友说法与已核实规定。
- 允许在原话题内扩展同义词、常用说法和相关子问题，分组检索，再通过实际取得的正文与回复筛选。检索覆盖回复中出现的话题，标题不是唯一入口；不静默放宽用户明确条件。
- 默认交付一段连贯的语义总结，包含主要讨论点、不同意见、不确定信息和必要的时间变化。关键观点后附少量可点击引用，展开后能核对已采集原文、发言时间及原帖链接；完整采集范围和审计详情默认折叠。
- 单次任务默认最多五分钟，包含采集、总结与核验。证据充分时提前结束，达到上限时按实际取得的证据收尾并说明覆盖范围；人工登录或安全验证的等待不消耗这五分钟。

## 自动登录与任务续接

采用本机专用 Chrome 会话，登录态按当前已认证的 BridGes 账户隔离保存。BridGes 登录与贴吧登录是独立状态；日常浏览器的登录状态不能作为专用会话已登录的证据。

调用模块后先检测专用会话。缺少会话或明确检测到未登录时，系统自动打开贴吧官方登录页面，用户自行完成登录。系统检测到成功后，复验认证状态和吧内搜索可用性，再自动继续原话题搜集；正常流程不要求点击“打开登录窗口”或“登录完成”按钮，也不要求重新提交话题。

登录确认与采集可用性分别判断。会话目录存在、窗口打开、Cookie 存在或用户自述完成，都不足以证明认证有效；应采用当前会话的实际已认证响应确认登录，再检查所需采集路径。具体检测接口、响应字段和状态证据必须通过真实环境验证，不能仅凭参考源码宣称可用。

已登录但遇到安全验证时，自动打开验证页面并保留原任务。网络超时或无法判断状态时，给出真实失败与重试说明，不判成未登录。一个登录或验证等待过程只自动打开一次窗口，同一账户的并发请求复用该入口，避免反复弹窗。用户关闭窗口而未完成时，保留任务并说明搜集尚未开始，用户可在聊天中说“继续”恢复；用户明确停止后不得自动续跑。

## 架构与工作流

主流程为：话题理解 → 检索计划 → 吧内召回 → 候选筛选 → 分页采集 → 证据整理 → 语义归纳 → 引用与支持程度核验 → 交付。按意图追加的官网核验遵守同一运行预算与既有来源边界。

采集主路径沿用专用浏览器登录环境，优先取得结构化响应，页面读取作为补充。一次采集运行复用浏览器上下文，减少反复启动开销；请求频率、并发、分页数量、重试和取消由代码控制，所有真实外部调用进入现有账本。

参考项目仅作为架构、工作流、分页与建模思路的研究资料。用户明确要求新增业务代码由 BridGes 独立设计和编写，不复制源码、搬运函数体或代码片段，也不通过改名或逐行转写移植实现；两者的源码和业务客户端不作为本方案的运行时实现引入。外部接口和字段语义经实际验证后作为协议事实使用，源码索引只用于定位设计依据；继续复用 BridGes 已有能力与通用依赖。

参考思路在本项目中的职责分配如下：

- MediaCrawler：借鉴编排、客户端、解析器与存储的职责划分，以及浏览器环境中的结构化请求、逐层采集、分页和请求节奏控制。参考的是本地代码已体现的功能，不能将 README 中的 Pro 功能视为当前源码能力。
- aiotieba：借鉴吧内搜索、回复与楼中楼分页，以及帖子 ID、回复 ID、父级回复、吧名、时间与分页状态的建模。第一版不以 aiotieba 客户端作为主采集路径，避免增加独立的凭据衔接机制。外部响应在适配器边界校验并转换为 BridGes 的领域证据，参考库对象不直接成为内部模型。
- BridGes：复用账户隔离、共享执行内核、任务版本、节点产物、预算账本、取消与恢复、模型网关和已有可信交付机制。采集与总结职责分开，不另建一套运行系统。

帖子、回复与楼中楼按真实身份去重，保留父子关系、原文、时间、发现路径和实际读取范围。搜索摘要只用于发现候选，贴吧归属与主题相关性通过真实取得的内容确认。筛选保留与话题有关的反驳、纠正和后续补充及其上下文；热门或高赞不是唯一采集依据。字段缺失时如实保留未知，不编造楼层、时间、总量或父子关系。

总结通过现有模型网关生成。材料较少时直接归纳，超过输入预算时按帖子或讨论串分批归纳后汇总；各阶段保留观点与证据的关联。外部帖子内容作为不可信材料，不得改变任务、来源或权限。关键观点须绑定已取得的发言，并检查引用身份、引文匹配与语义支持程度；不能将非随机采集样本概括为全体学生的共识。

部分采集失败时，用已经取得的相关证据交付并说明不足；没有可用原文时如实说明本轮未取得讨论，不以搜索摘要或模型记忆补写。模型总结失败时保留真实证据与任务状态，说明总结尚未生成，后续重试可复用仍有效的证据。

## 与现有合同的关系

[ADR-0037](0037-tieba-fixed-source-scope.md) 的固定目标贴吧、账户隔离、真实读取、未读范围声明与历史证据保护继续适用。实施本 ADR 后，替换该区域既有的规定类自动官网优先、按钮引导登录、有限候选读取与确定性原文分类交付路径；当前代码仍按既有实现运行。

五分钟是贴吧任务的专用上限，对现有通用阶段预算形成明确例外，需接入同一本预算账本并为总结、核验和交付留出空间。登录等待、恢复和新执行预算的衔接须遵守运行租约、任务版本和停止守卫，不能仅延长浏览器超时或绕过内核。

新解析、检索、采集和总结语义实施时应升级相应配方与能力版本，使旧语义产物不能在新运行中冒充新合同结果；历史消息按原证据解释。公开投影和前端类型仍保持同源生成，是否需要数据库迁移在实现设计时按实际字段与持久化变更评估。

实现审查须确认参考思路已经转化为适合本项目的职责划分、流程与证据模型，新增代码独立完成；参考项目的许可差异不改变用户明确的“不复制代码”要求。

## 实施前验证与验收

先验证选定浏览器路径的登录检测、吧内搜索、回复分页与楼中楼读取，记录真实成功或失败及可取得的字段；接口成功率、采集规模和耗时尚未实测。采集数量、请求节奏和分批总结规模在五分钟上限内据实测校准，不预先承诺帖子或回复数量。

验收至少覆盖：

- 一个话题使用不同说法、只出现在回复里或跨多个帖子时，能够发现并按实际内容筛选。
- 长帖中的反驳、纠正和楼中楼有必要上下文，重复内容不充作多份独立证据。
- 近期发言、历史内容和未知时间分清；用户明确时间、校区及话题条件保持有效。
- 未登录时自动打开官方页面，认证与访问复验成功后自动续接原任务；过期、验证、网络失败、关闭窗口、并发登录和明确停止各有真实状态。
- 达到预算、部分读取失败或总结失败时能够诚实收尾；关键观点与引用能回溯，未读内容不成为总结依据。

本决策已进入部分实现阶段。自动化回归和协议生成情况记在工单中；在专用浏览器、真实贴吧账户和生产模型完成端到端验收前，不将本决策标记为完整实施。
