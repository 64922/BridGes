# 设置页运行期更换 Qwen 凭据并激活手填主模型

V2 Issue 09 把「运行配置」做成用户可在设置页自行更换的两个部分：全局 Qwen 凭据与主模型 ID。两者都遵循同一协议——先用候选值做只读验证，成功后才原子替换当前生效值，失败保留原值。凭据保存到 CLI 首启使用的同一个凭据库条目（`global-qwen-api-key`，ADR-0024 的全局运行凭据），因此命令行首启、桌面设置页与后台执行器读到的是同一份凭据；主模型配置写入账户库中的运行配置状态行（`application_state` 的 `run_model_config` 命名空间），与凭据库同为跨进程共享来源。

**凭据更换**：输入框始终为空且永不回显旧值（后端只返回"是否已配置 + 末次验证时间"，响应、日志与浏览器存储都不含明文）。候选密钥的验证顺序是"该密钥能查到当前主模型元数据"再"能做一次最小真实调用"：鉴权失败、模型不可见、探测失败分别给出稳定错误码与中文原因，错误信息只含模型 ID、能力名与供应商脱敏摘要。验证通过后写入凭据库并就地轮换本进程内的 Qwen 客户端与 Embedding 端口密钥；**其他进程（后台执行器）在下次启动时读取新凭据**——凭据库不是热更新通道，这一点仍是 ADR-0024 的边界。

**主模型激活**：主模型只有手填 ID，没有预设列表。提交时按 `docs/v2/architecture.md` §7 执行两步证据链：先用当前密钥做百炼「查询模型列表」精确元数据查询（按 `model` 字段精确比对，读 `capabilities`/`features`/`model_info`），核对文本、图片、工具调用、结构化输出与上下文额度；再用候选模型做四项最小真实能力探测。任一不通过都不保存。通过后模型 ID、能力档案、上下文额度、元数据合同版本与验证时间在一次写入中激活为运行配置。

**解析时机**：`ModelGateway` 在每次调用时把「能力名」解析为「实际模型 ID」——优先级为运行锁固定值（进行中的轮次）> 运行配置（仅限可配置能力）> 出厂批准矩阵。注册表本身不被改写，因此生产组合门禁（ADR-0006 的一个能力一个模型快照）仍然成立；`fixed_models.py` 仍是批准矩阵与工厂默认值的单一事实源，非可配置能力（Embedding、语音、图像、视频等）继续只走批准矩阵。

**在途与历史**：运行配置变化只影响之后创建的轮次。每个对话轮次在创建时把当时的模型 ID 写进运行配置（`run_model_id`），本次运行及其重试的所有模型调用都带上这个锁定值，因此正在执行的轮次不会中途换模型；历史消息记录的模型标识不被改写，旧会话的下一轮自然采用新配置。

运行锁的边界是"一个对话轮次"，不是"整个应用"：媒体提取（`media/qwen_extraction.py` 的视觉理解）、知识库录入 OCR（`ingestion/ocr.py`）与图像替代文本生成是各自独立的运行，调用时按能力名解析当时生效的运行配置，因此它们会采用落在本次运行中途的激活结果。这些能力与主对话共用同一份经过验证的配置，属于预期行为（同一次激活即希望全部走新模型），但意味着验收与排障不能假定"激活前后所有调用都严格分成两批"。

**与向量模型的关系**：知识库向量模型与索引版本保持独立固定（ADR-0008），不随主模型手填 ID 或 Qwen 凭据更换改变；更换 Embedding 仍需重建索引而非复用。

## 与旧决策的关系

本 ADR 取代 [ADR-0024](0024-global-qwen-run-credential.md) 中「全局 Key 轮换后必须重启相关服务，首轮整改不引入运行期热更新」对桌面设置页的适用性：桌面 profile 现在允许在设置页验证并替换全局凭据，无需重启 API。该 ADR 的其他约束继续有效——凭据仍只有唯一来源标识、仍写入操作系统凭据库、仍对账户隔离与云端最小披露无影响。

本 ADR 取代 [ADR-0009](0009-fixed-model-and-provider-matrix.md) 与 [ADR-0030](0030-v2-campus-assistant-and-approved-desktop-interaction.md) 中「用户不能更换模型」对主对话、视觉识别与 OCR 的适用性：这三个可交互能力的模型 ID 由用户手填并经元数据核验加真实探测后接管。其余固定项（含 Embedding、语音、图片、视频与公开搜索提供方顺序）不变，且不允许只替换常量而留下隐藏调用走旧模型的实现。

## 实施后果

1. API 与后台执行器通过同一个账户库读取运行配置，因此一次激活对两个进程都生效，无需重启；**凭据**跨进程需要重启后台执行器，运维与验收脚本必须按此预期设计。
2. 元数据查询失败按用户可修正程度分级：鉴权失败、模型不存在、元数据字段缺失按 422 返回具体原因（需用户改输入），网络或供应商不可用按 503 返回（可稍后重试）；无论哪种，当前生效配置不变。
3. 元数据声明与真实探测冲突时按失败处理并指出具体能力；元数据本身拿不到时能力状态是「未核对」，界面不得替用户断言「不支持」。
4. 测试环境继续使用确定性适配器，不做真实网络调用；真实探测只在用户主动提交时发生，且每个候选模型只发固定四项最小请求。
