# V2 校园学习助手与桌面交互方案

> 状态：accepted（产品与交互设计，2026-09-24）；生产实现待按 tickets 验收。
>
> 用户逐项确认 V2 产品行为，并在查看可点击桌面原型后回复「认可」。此 ADR 固化已获批准的设计，不表示当前代码已迁移完成。

## 决策

BridGes V2 面向华东交通大学在读学生的日常学习、校园生活和职业准备，不核验学籍，只交付个人电脑上的桌面浏览器体验。产品仍有「日常陪伴」和「学习模式」，但新聊天右上角才能切换；第一条消息成功创建会话时锁定模式，已有会话仅显示只读模式标识。

日常陪伴的输入框左侧使用 `+` 上拉菜单：先提供照片／文件上传，再列出论文搜索、校园通勤、学习资料推荐、华东交通大学吧信息搜集、职业规划、GitHub 项目推荐六个工作模块。模块选择显示为可移除 chip，发送时作为逐消息的显式 `module_id` 传给服务端。同一日常会话可切换模块，原始消息历史完整保留；普通聊天可以建议用户一键启动合适模块，但不得暗中执行。

学习模式是独立工作模式，不在 `+` 菜单中。一个学习会话对应一本书的一节：上传书页照片并识别 → 提出暂不要求回答的预习问题 → 根据书页通俗辅导 → 学完后逐题复盘 → 总结。错题或不完整回答立即给正确答案，不让用户补答同题；题量随知识密度变化、覆盖本节知识面。复盘可暂停回辅导，再从未问题继续。聊天附件只归属当前会话，不自动进入账户知识库。

画像改为无固定类别的原子记录列表，每行仅提供修改与删除；提取必须有用户原话证据，编辑优先、删除防止从旧消息重建。设置中可更换 Qwen、Tavily 和高德凭据；Qwen 主模型由用户手填精确 ID，元数据核验加真实能力探测成功后才原子保存。全局自然表达保留在主生成链，文章人味化专用模块与其二次编排退出。

实现采用 LangGraph 日常父图加六个显式模块子图、独立学习阶段图；共享有预算和证据追溯的会话上下文编译器。现有账户隔离、SQLite、SSE、知识库混合检索和历史导出可作为底座，旧业务工作流不因名称相同而直接复用。外部检索与地图必须有实际可核验结果和失败降级，不能用模型记忆填补未取得的帖子回复、岗位样本或路线。

详细合同以 [产品契约](../v2/product-contract.md)、[交互规格](../v2/interaction.md)、[工作流](../v2/workflows.md)、[可行性门](../v2/feasibility.md)、[技术架构](../v2/architecture.md)和[交付顺序](../v2/delivery-plan.md)为准；[已认可的桌面原型](../../apps/web/prototypes/v2-desktop/README.md)作为正式 UI 的交互验收参考。

## 与旧决策的关系

本 ADR 取代 [ADR-0026](0026-frozen-product-contracts-and-migration-gates.md) 中与 V2 冲突的产品行为：自然语言自动启动专用能力、聊天禁止附件、四维画像、文章人味化任务、旧教学计划和旧能力入口。旧 ADR 仍记录当前已实现系统的历史合同；它的账户隔离、密钥保护、证据真实性、历史可读、迁移对账与回滚门继续约束 V2 实施。后续实现不得因为本 ADR 已被接受，就将尚未迁移的功能当作已上线。

## 实施后果

1. 先按 [交付顺序](../v2/delivery-plan.md)拆分本地 tickets，逐条完成图状态、附件、上下文、模块、学习、画像和模型配置的纵向切片。
2. 每个模块的外部数据可得性需过实测门；高德校内路线、贴吧回复和公开岗位样本是明确的条件性能力。
3. 生产 UI 按已认可原型接入真实服务时，不展示未实现模块为“可用”。原型本身始终只演示，不存用户数据，不充当生产前端。
4. 旧会话和结果保持可查看、可导出；旧写路径按迁移门逐步关停，不能一次性清掉兼容读能力。
