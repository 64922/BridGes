# 记录已确认工作流合同替代与增量迁移接缝

> 状态：accepted（合同替代说明，2026-09-30）；各实现票负责自己的接口、迁移与验收。
>
> 本 ADR 是「已确认替代」的权威来源，只记录目标行为、旧数据解释、负责票与兼容接缝，不提前实现任何能力。它不代表任何 V2 变化已经上线。用户依据：工作流 D01–D17（[讨论记录](../workflow/discussion.md)、[设计索引](../workflow/README.md)）、上下文九项原则（[改进方案](../上下文工程/改进方案.md)）、人味化六项原则（[讨论记录](../人味化/讨论记录.md)、[实施方案](../人味化/实施方案.md)）、画像 D01–D09 与 R01–R08（[讨论记录](../用户画像/讨论记录.md)、[profile-contract-v1](../用户画像/画像规格与验收合同.md)）与 [ADR-0032](0032-profile-facts-controls-and-history-suppression.md)。

## 背景

工作流、上下文、人味化和画像四份定稿分别修改了若干 V2 合同，而 V2 目录保留 2026-09-24 的设计基线。实施者若只读多份文档，可能执行相反行为。本 ADR 消除这一风险：它逐项记录替代关系与兼容接缝，并保持旧合同、旧消息和旧运行仍可解释。它不静默覆盖历史设计，也不把设计目标当作已实现状态。

## 决策

### 2. 统一任务语义

上下文九项原则、人味化六项原则与工作流 D01–D17 描述同一个任务对象，不各建一套语义。统一后的载体是「跨轮任务 + 任务版本 + 单次运行 + 类型化产物」（逻辑合同见[公共编排与状态合同](../workflow/orchestration.md) §3、§5）。

| 来源 | 关键原则 | 统一到同一任务语义后的含义 |
| --- | --- | --- |
| 上下文决策 1–9 | 同会话连续性、用户明示权威、约束绑定原任务、按需摘要、后台摘要、指代处理、超限处理、旧材料读取、可靠性硬门 | 约束绑定任务版本而非会话；历史摘要只是可重建派生物，相关原文仍是权威；模型推测只作线索，不晋升为硬约束 |
| 人味化 D1–D6 | 有分寸的伙伴、全自然语言覆盖、保留单次生成、记忆相关时自然使用、倾诉不强制建议、任务帮助与分寸不退化 | 表达适配发生在同一次用户可见生成调用内，不新建人格服务或二次全文改写；不改变事实、任务合同与工具状态 |
| 工作流 D01–D17 | 混合启动、主智能体规划、跨模块动态规划、跨轮任务、分层核验、局部恢复、一次覆盖复盘、教材优先补证、评分前置、语义匹配、分层读取、目标驱动路径、职业规划、贴吧取证、正文优先、及时交付、共享内核 | 任务/运行/产物/质量门/预算的统一底座；模式策略与领域状态各自拥有写模型 |

统一语义下的两条硬边界：

- **混合启动替代旧的显式 `module_id` 固定派发限制**：模块选择成为理解提示，实际执行决定另记；历史消息标识不重写。
- **读取已有材料不自动授权刷新外部来源**：材料进入上下文不等于获得新工具执行授权。用户「只查论文」「不要联网」等硬限制是必须遵守的约束，不因模块提示或模型计划放宽（D11、D15，[上下文改进方案](../上下文工程/改进方案.md) §4）。

### 3. 调用目的分类与计量

不同目的的模型调用不能互相冒充。成本与预算报告按目的分组，不得把允许的摘要调用说成人味化二次润色，也不得把原任务固有的多步调用或供应商重试误计为新增人味化调用。

| 调用目的 | 触发 | 计量与边界 | 来源 |
| --- | --- | --- | --- |
| 普通回复生成 | 每条消息的正式用户可见生成 | 一次生成，无额外人味化专属追加调用；表达规则在同一次调用内注入 | 人味化 D3、[ADR-0011](0011-clean-room-humanizer-and-license-boundary.md) Issue 17 |
| 按需历史摘要 | 预算压力或需要压缩较早历史 | 可按需调用模型并缓存；按「摘要」目的计数，是可重建派生物，不写成用户事实 | 上下文决策 4、5；工作流 D17 |
| 普通画像后台提取 | 回答**正常完成**后异步 | 按「画像提取」目的计数；失败/停止不提取，成功重试幂等；不阻塞回答 | 画像 D07、D09、R03 |
| 按风险独立核验 | 多来源冲突、关键数值/公式不一致、复杂比较新结论、岗位差距依据不足、实现断言证据不足、评分等价答案争议 | 按「核验」目的计数；纯工具计算先用代码核对，不强制附加模型裁判 | 工作流 D05、[orchestration](../workflow/orchestration.md) §9 |

### 4. Expand–migrate–contract 增量兼容方案

沿用 [ADR-0026](0026-frozen-product-contracts-and-migration-gates.md) 的 expand–migrate–contract 框架，但**不以全库重写为前置**：先允许新字段与旧投影并存，各模块切片迁移后再收敛写路径。每个切片在自己的票内完成适用的版本化迁移、备份/导出、删除、审计与失败恢复，不留给最终集成票（43）补做。

#### 4.1 消息投影

- **旧投影**：每条用户消息一个 `module_id`（逐消息显式选择），服务端按该值选择工作流。
- **Expand**：保留旧 `module_id` 列；新增请求提示、本轮实际路由来源、能力列表与简短理由（与运行/事件关联）。旧读取路径不变，历史消息仍按旧投影渲染。
- **Migrate**：新消息双写旧投影（供旧渲染与历史一致）与新投影；各模块逐步改读新投影。
- **Contract**：写路径只写新投影；旧 `module_id` 列收缩为只读兼容，继续供历史消息展示。历史消息标识永不重写。
- **门禁**：点击旧建议是绑定任务版本的意图澄清事件，不靠改写原文重复提交。

#### 4.2 任务、运行与产物版本

- **旧投影**：单次生成 run 直接对应一条消息，模块内串行黑盒。
- **Expand**：在现有 run/事件/终态存储旁新增跨轮任务、任务版本、计划版本、节点产物与完成收据；旧 run 仍可读取。
- **Migrate**：模块步骤逐个成为显式持久节点；节点局部事务提交产物、完成收据与待投递事件，图检查点可随后保存；恢复时先查完成收据（R02）。
- **Contract**：收敛到「领域仓库更新领域状态、终态服务统一收敛最终消息」，模块不再自行终结助手消息。
- **门禁**：旧运行按不兼容配方安全结束或迁移到明确新运行（R06），不盲目套新图继续；跨进程恢复保留原运行截止时间与已消耗次数（D16）。

#### 4.3 学习题目与评分要点版本

- **旧投影**：题目与评分标准随作答即时生成。
- **Expand**：出题时同时冻结题目版本与评分要点版本（含书页依据、可接受等价表述、关键误解），并绑定本次知识范围版本。
- **Migrate**：已判定题保留原判定与原始依据；追加书页后只重排未问题（L09、L11）。
- **Contract**：判定只按已冻结要点；总结只描述本次实际表现，不把单次答对解释为长期掌握（L10、L13）。

#### 4.4 阶段门禁与回滚

- **Expand 失败**：保留旧数据与新 staged 结果，修复后继续；旧读路径继续可用。
- **Migrate 失败**：只回滚未发布的目标投影或写路径；已提交的本地效果（消息、附件绑定、题目判定、最终消息）靠唯一键、预期版本与终态守卫确保不重复。
- **Contract 后**：不恢复退役入口；回滚停用新写路径并保留新旧历史、事件与产物，不清库、不丢新任务、不恢复退役入口。

### 5. 保留的不变量与退役边界

以下合同不因本 ADR 改变，实施票必须继续守住：

- **模式固定**：首条用户消息提交时由服务端永久锁定；直接 API 请求也守（[ADR-0022](0022-persisted-conversation-mode.md)、ADR-0030）。
- **单会话单教材小节**：一个学习会话对应教材一节，首轮书页照片输入要求保留。
- **账户/附件分域**：账户隔离；会话附件与全局知识库分域；聊天照片草稿不进入知识库、索引、检索或画像。
- **原子画像编辑权威**：用户编辑优先，普通自动提取无论时间先后都不能覆盖手动编辑；删除墓碑抑制旧证据与普通同义提及，只有明确重新记住才恢复指定范围。
- **历史可读/导出**：历史消息、结果与旧运行保持可查看、可导出。
- **退役能力边界**：不恢复退役创作、媒体生成、提醒、用户插件/MCP 或项目工作台；不引入旧 WorkOrder 的项目审批流程。

## 工单 36 的总结合同落地（2026-10-05）

总结复用既有 21/22 采用与表达策略接缝，发送前撤回复查失败则清除画像和规则并重新核算预算。
