# ADR-0034：可信回合结果与渐进交付

日期：2026-10-06。状态：已实施，独立验收见工单 38 的验收记录。

## 问题

消息生成结束、领域交付可信和跨轮任务等待是不同状态。只以消息 `done`
展示“已完成”会掩盖澄清、证据缺口和总结失败；只在全部模块结束后展示结果，
又让已核验的独立部分无法及时使用。外部异常原文也不能成为新增公共结果字段。

## 决策

复用消息上的 `turn_result` JSON 列（数据库 v69）。普通、单模块及历史消息
从已提交领域状态推导；复合终态在正文、领域投影和终态的同一守卫事务内写入。
历史 `module_id` 不重写，无存量回填。学习派生只按本轮消息标识匹配公开记录，
不把当前会话的学习阶段追溯套到历史回答。

复合步骤通过真实模块质量门后，由调度线程发布 `result` SSE **覆盖式快照**。
公开块只使用核验产物重建的 Claim 文本，不采用草稿、证据原文或自由摘要。
快照、游标事件在同一事务内写入，并检查账户、停止、消息终态、启动租约和
任务版本。同一模块重复发布不产生新块或事件；刷新读取相同快照。
快照的 `outcome=running` 仅说明部分已交付，本轮仍执行，不能代替最终 `done`。
最终 `done`/`error` 沿用既有原子终态协议；停止后不自动派发新运行，已核验块保留。

成功并不自动消除领域的显式证据限制：例如资料 `path_verified=false` 显示
部分交付和证据绑定，不能标为完整核验。等待与恢复取对应运行和登记的真实错误类别，
真实恢复时刻按浏览器用户时区展示；冷却到期更新按钮，不自动调用。外部失败文本
在新公开投影边界转换成登记文案，未知失败只说明未形成可交付结果。

## 合同、迁移与回滚

`turn-result-v1` 增加 `running` 分类与 `result` SSE；正文 `delta` 和原子终态
合同不变。OpenAPI 与 TypeScript 类型同源生成。旧客户端可忽略新增事件，终态
及历史继续可读；新客户端以快照覆盖而非追加结果，避免游标重放重复。
v69 是加列迁移，初始化前使用已有备份机制；账户导出、删除和审计沿用消息表的
账户作用域与通用行处理。没有存量数据搬迁，故无需额外数据迁移。
回滚停用渐进写入并保留消息、事件和新列；需要恢复旧数据库时使用迁移前备份，
不清库，也不丢弃历史结果。

## 验证边界

确定性模型和工具替身仅替换外部边界。正式 HTTP、执行器、现行图、SQLite、SSE
以及桌面浏览器用于验证机制；真实模型质量与公网来源可得性由后续评测票验证。
具体命令、基线失败差异及实际通过数记录在验收目录，不由本 ADR 代替测试证据。
