# 人味化模块审查与改进建议

审查日期：2026-09-30。代码基线：`7818c34`。本次阅读代码、执行只读反例和定点测试，没有修改产品实现，没有调用真实模型，也没有使用真实用户聊天数据。

## 核心判断

当前模块已经能减少部分机械表达，但它主要处理“当前一句话属于什么回答形态”和“注入哪些表达规则”。它尚不足以支撑“每一句回复都像一个理解上下文、有分寸的伙伴”。改进重点应是语境适配、覆盖完整回复路径、事实与流式一致性，以及真实体验评测。

用户已确认：默认交流方式为**有分寸的伙伴**；适配范围为**所有用户可见自然语言**；**保留单次生成**；相关时自然使用明确偏好与背景；倾诉时先具体承接、按语境陪聊或轻问、不强制建议。代码、公式、引用原文、工具数据和状态含义保持准确。各项决策与后续验收取舍以[讨论记录](讨论记录.md)为准。

## 应保留的设计

- 普通聊天在原有生成调用中注入少量规则，避免无条件追加全文润色。
- 表达规则让位于用户当前要求与任务合同；风格不能覆盖科学边界和工具状态。
- 已有策略版本、规则 ID、运行快照和重试复用机制，可用于比较与回滚。
- 已限制画像切片，避免整份个人信息进入表达提示词。
- 策略或画像失败允许降级，不把表达优化变成用户无法完成任务的新阻塞点。
- 不冒充真人、不伪造经历和来源，以及原创净室约束，应继续保留。

## 缺点、证据与影响

### 1. 单轮关键词路由误把话题当成用户状态

位置：`lightweight_policy.py:186`、`:213`、`:428`。

实际执行反例：

| 输入 | 实际形态 | 问题 |
| --- | --- | --- |
| 解释焦虑的生理机制 | `empathy` | 在讨论概念，不能仅因“焦虑”推定用户需要情绪承接 |
| 他说“我很焦虑”，帮我翻译成英文 | `empathy` | 引语中的情绪与用户当前任务混淆 |
| 我今天很难过，不想听建议，只想聊聊 | `advice` | “建议”关键词覆盖了“不想”的明确否定 |
| 我很焦虑，怎么办 | `advice` | 主任务需要建议，但单标签无法同时表达必要的情绪承接 |
| 写一篇两千字的故事 | `compact_default` | 低置信默认“不扩成长文”与显式长度需求形成冲突，虽有优先级声明仍增加理解负担 |
| 继续 | `compact_default` | 分类器没有前文输入，无法知道继续的是讲解、安慰还是未完成任务 |

**边界：**以上证明策略分类与规则选择存在问题，不证明真实模型必然生成错误回复。模型仍可能依据历史和优先级声明自行纠正；当前模块缺少对此的可重复验证。

建议：先识别用户任务、显式限制、引用材料边界和必要前文，再决定如何表达。允许“主要任务 + 可选情绪承接”组合。扩充正则词表无法根治引语、否定、跨轮和混合意图问题。

### 2. “有分寸”仍被固定收尾与强制行动破坏

位置：`lightweight_policy.py:101`、`:108`。

全局规则要求没有真实下一步就结束，但解释档要求“结尾用一句话确认是否解决”。情绪档要求“承接后必须带来具体判断、帮助或下一步”。两者都会把本来完整的回答拖回固定模式。

建议：完成任务后默认停止；只在缺少必要信息、真实教学检查或用户希望延续话题时追问。用户只是倾诉时，允许简短承接、停留与具体回应，不强制解决问题。不要求每句增加温暖、称呼、幽默或口语词。

### 3. 当前原子画像被旧维度过滤器丢弃，并产生矛盾提示

位置：`profiles/atomic.py:1180`、`lightweight_policy.py:53`、`:351`、`:510`、`turn.py:5212`。

原子画像输出 `dimension=""`；表达策略仍只允许 `basic_information`、`academic_status`、`expression_habit`。复核输入一条无类别偏好“回答喜欢简短直接”，表达策略采用 **0 条**，并写出“本轮没有可用画像信息”。与此同时，另行传入的 `profile_context` 仍然存在。

**边界：**不是所有个性化都失效；独立画像上下文仍可能让模型采用偏好。具体问题是表达策略与画像上下文自相矛盾，以及表达元数据不能准确描述采用情况。

建议：沿用无类别原子画像的产品合同，在内部将用户明确表达的称呼、篇幅、专业程度与交流偏好编译为少量用途明确的约束。不要为了适配表达模块重新增加用户可见画像分类，也不要简单把所有无类别条目放行。

相关但不同的缺口：原子画像相关性主要按当前问题的词面判断（`atomic.py:202`），通用“偏好短答”未必与学科问题匹配。应区分可跨任务生效的明确表达偏好与只在特定问题中需要的背景信息。

### 4. 工具结果、工具错误和拒答信号没有进入普通编译调用

位置：`lightweight_policy.py:213`；`turn.py:5360`、`:5383`。

分类器支持 `tool_error`、`tool_result`、`refusal`，但普通 `_compile_writing_policy` 的调用只传入 `lesson`，没有对应三项参数。因此编译器单元测试中可用的系统信号形态，不等于真实调用链已采用。

建议：让调用方传入实际工具状态和任务结果；单元测试之外，验证真实运行如何选择形态。拒答含义需要明确策略来源，不能靠用户文本猜测，也不能承诺在生成前知道尚未发生的模型拒答。

### 5. 覆盖率低于“每一句回复”的目标

当前普通聊天和部分旧生涯路径有策略，当前学习辅导单独编译；其他学习阶段和模块存在独立提示词或模板。修改一个策略文件不会自动改变这些回复。

建议：建立用户可见回复路径清单。模型生成的自然语言在现有调用中加入共用适配规则；固定文案调整模板；结构化结果的证据、数字、链接和状态由原服务保留。每条正式路径必须有接入检查，不能以普通聊天通过代替全部模式通过。

### 6. 正则恢复器可主动损坏正确内容

位置：`global_writing_policy.py:138`、`:158`、`:178`。

该函数遍历源片段，但每次都重新寻找候选中的第一个同类匹配，没有绑定对象或位置，也没有消费已配对目标。

| 原始输入/来源 | 候选 | 实际恢复结果 |
| --- | --- | --- |
| 甲 10 ms；乙 20 ms | 甲 11 ms；乙 21 ms | 甲 20 ms；乙 21 ms |
| 样本量为30，未发现显著差异 | 样本量为300，发现显著差异 | 完全不变，未保护纯数字及否定关系 |
| 这行 `x = 1` 不对，请把数值改为 2 | 改为 `x = 2` | 改为 `x = 1`，覆盖用户授权的纠错 |
| 两个可用来源 URL：a、b | 正确引用 a | 可被替换为 b，见复核脚本 |

建议：优先移除“按同类第一个片段盲替换”的行为。区分用户要求保留的片段、允许纠正的片段、来源中的可引用字段和模型需要计算的新值。对可精确绑定的片段使用 ID/位置与哈希检查；无法可靠定位时不要猜测替换。科学关系、否定与结论强度的保真另列评测，不能宣传正则已保证全部事实正确。

### 7. 流式修复违反前端追加语义

位置：`turn.py:3481`、`:3487`；`apps/web/src/app/(app)/chat/[conversationId]/page.tsx:374`。

后端修复结果不再以已发内容为前缀时，把整段修复正文作为 `delta` 发出；前端始终把 `delta` 追加到已有内容。

只读逻辑模拟：原片段为 `` `x = 1` ``，模型两次输出 `值 \`x = 0` 和 `` `。 ``。落库正文是 `值 \`x = 1\`。`，前端累加成 `值 \`x = 0值 \`x = 1\`。`。

**边界：**该例模拟当前后端与前端算法，未执行真实浏览器验收。真实界面可能在终态重新取消息后恢复，但已显示的增量仍违反追加语义，需要链路验收。

建议：若保留流式修复，受保护片段在完整边界确认前暂缓发送；确实需要修订已发送正文时使用明确的替换事件并让前端、重放和存储一致处理。不要把完整正文伪装成增量。具体方案在实施时选一种最小可行方式。

### 8. 当前指标不能证明“更有人味”

位置：`evaluation/metrics.py:110`、`:121`、`:129`；退役记录中明确删除专用人味评测框架。

剩余画像指标的自然度按套话出现次数扣分；个性化收益按“根据你的目标”等措辞是否出现打分。这样的指标无法区分：是否理解了用户、是否尊重“不想听建议”、是否有跨轮连续性、是否多说了废话，以及是否自然地用了用户背景。

它们还可能奖励刻意插入“根据你的目标”，惩罚恰当的“首先”。这只是评分规则的推论，尚未证明当前模型因此发生了优化偏移。

建议：将词表保留为诊断信号；用真实模型、多轮任务和用户盲评比较旧策略、新策略与简洁基线。自然度、任务帮助、分寸、连续性分别评分，事实错误与用户边界违规单独设门，不平均进“人味总分”。

### 9. 表达复杂度与输出预算没有联动

位置：`turn.py:1865`。

普通载荷固定 `max_tokens=1024`，紧凑默认又偏向最短回答。对于用户明确要求较长内容，路由和长度预算都需要核查。实际网关是否进一步限制或覆盖预算，应在实施时联同模型能力配置验证；本次没有用真实模型证明截断。

建议：根据已有任务长度与模型预算设置合理上限；不要把“简短”当作自然表达的唯一尺度，也不要无界提高所有回复的预算。

## 改进的基本方向

将策略目标从“每句润色”落实为“每轮尊重任务、上下文和用户的交流意愿”。一轮回答可以有事实、说明、承接和行动，不必逐句添加所谓人味。

优先级建议：

1. 事实与流式一致性：先修复会改错内容的恢复机制，补齐合法学习路径测试。
2. 统一覆盖与画像适配：接入当前正式路径，消除矛盾提示，明确哪些偏好可用于表达。
3. 语境适配：去除强制行动与固定收尾，处理显式否定、引语和跨轮任务。
4. 真实体验评测：通过盲评和消融决定哪些规则确实有收益，再扩大应用。

不建议在这一步引入独立人格智能体、情绪长期画像、随机温暖度、全局禁词清洗，或恢复完整旧文章编排。这些方案增加复杂度，却没有解决上述可复现问题。
