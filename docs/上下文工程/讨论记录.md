推荐 A：保留“已说过”与“系统推测”的区别，不让摘要或模型回答自行变成用户事实。已明确的内容不重复要求确认。

## 决策 3：约束的有效范围与话题切换（已确认）

问题：用户切换话题后，之前明确提出的任务约束是否自动约束整个会话？

| 选项 | 行为 |
| --- | --- |
| A：默认绑定原任务，明确要求时才扩大范围（推荐） | 任务约束用于原任务和明确续接；无关话题不受约束，回到原任务时恢复仍有效的约束；用户明确“这个聊天都……”时按会话范围保留 |
| B：默认整个会话持续生效 | 约束容易继承，但新任务可能被不相关的旧要求干扰，需要用户主动清除 |

推荐 A。任务依据目标与对象辨认，不能仅凭模块 ID 判断是否换任务：例如论文搜索切换到 GitHub 找同一篇论文的实现，仍可属于原任务。旧任务状态在切换时暂不采用，原文和来源仍可用于后续续接；遇到影响答案的实质歧义才澄清。

示例：推荐笔记本时“预算 5,000 元”仅约束该选购任务；随后问校园通勤不沿用该预算；再说“回到刚才的笔记本推荐”时恢复仍有效的选购条件。

用户答复：**“认可”。**

确认结果：采用 A。约束默认绑定原任务，切换无关话题时不采用，回到原任务时恢复仍有效的条件；用户明示时才扩大到整个会话。模块切换本身不代表换任务，是否续接依据目标和对象判断。后续明确纠正或撤销的内容不因恢复旧任务而复活。

## 决策 4：摘要方式与额外模型调用（已确认）

问题：是否接受为较早对话按需增加模型摘要调用，以保留有来源的背景和状态线索？

| 选项 | 行为与取舍 |
| --- | --- |
| A：按需模型摘要，结合原文和状态（推荐） | 近期对话保留原文；有效任务状态保留来源；历史需要压缩时调用模型生成有界结构化摘要并缓存复用。触发时增加调用成本和等待，但可表达比字面截断更完整的语义 |
| B：仅用确定性提取与原文检索 | 不增加摘要模型调用，可直接审计规则；对自然语言背景、复杂纠正和跨轮语义的覆盖更受规则能力限制 |

推荐 A。摘要内容用于定位与解释背景，不具有用户确认事实的权威；关键约束、数值和纠正须保留原文依据。摘要从覆盖范围内的原始消息生成，不仅依靠不断压缩上一版摘要；记录来源范围与实例版本。已覆盖的历史摘要复用，不每轮重做整段历史。触发与执行策略见决策 5，具体数值按决策 9 的实测方式确定。

摘要生成或校验失败时不把无依据内容写入有效状态，保留预算允许的相关原文与明确缺口；最终输入仍受统一预算硬门约束。

用户答复：**“接受”。**

确认结果：接受按需增加模型调用生成较早对话的结构化摘要，并缓存复用；近期消息保留原文，关键约束和纠正保留来源。摘要用于理解背景和定位原文，不能自行成为用户事实。用户接受触发时增加调用成本和等待的取舍；触发与执行策略见决策 5，具体预算数值尚未确认。

## 决策 5：摘要触发与等待策略（已确认）

问题：摘要优先在回答后后台准备，还是在需要压缩的那一轮发送前同步生成？

| 选项 | 行为与取舍 |
| --- | --- |
| A：后台准备为主，必要时有界补齐（推荐） | 按任务历史预算压力和新增原文量判断需要，优先在回答完成后整理较早片段；下一轮复用仍有效的缓存。缓存未准备好且确需压缩时才同步补齐，并限制等待 |
| B：需要压缩时全部同步生成 | 流程更简单，摘要立即可用于当前轮；触发压缩的轮次会增加发送后的等待 |

推荐 A。不按固定对话轮数触发，也不等到模型硬窗口被填满才开始准备。摘要只覆盖来源明确的已完成历史片段；新请求及最新纠正仍以本轮原文为准，不因后台摘要尚未更新而延迟生效。具体阈值由实现阶段的预算和回归结果决定，不在讨论时猜一个百分比。

同步补齐的次数、超时和总预算应有上限；失败时回退到预算允许的相关原文与明确缺口，仍执行最终预算硬门。必要材料无法容纳时按决策 7 处理。后台任务须按账户与会话隔离，来源发生变更或删除后不复用无效缓存。

用户答复：**“同意”。**

确认结果：采用 A，后台准备为主，必要时限时补齐。按上下文预算压力在回答完成后整理较早历史，下一轮优先复用缓存；确需压缩且缓存未准备好时才同步生成。最新请求和纠正始终直接生效，不等待摘要更新。具体触发阈值、超时和调用次数上限由后续实现与验收确定。

## 决策 6：指代解析与澄清边界（已确认）

问题：遇到“它／第二个／继续”等指代，系统应在什么情况下直接续接，在什么情况下追问？

| 选项 | 行为与取舍 |
| --- | --- |
| A：能明确定位就续接，实质歧义才澄清（推荐） | 先根据近期对话、当前任务和结果列表定位，并按需查原文。明确对应一个对象时直接执行；多个合理对象会改变检索或答案时，问一个简短澄清问题 |
| B：默认选最近的合理对象 | 减少追问，但在多个列表、话题往返和跨模块结果中容易选错，需要用户事后纠正 |

推荐 A。例：刚刚同时讨论论文和 GitHub 仓库，用户说“比较第二个”，若无法确定指向哪张列表，就问“你指第二篇论文，还是第二个仓库？”；只有一个清晰列表时直接续接，不要求用户复述主题。

解析结果要能定位到具体消息、列表版本或结果对象，不仅靠模型声称高置信。解析指代是寻找已存在对象，不允许借此推测并新增用户约束。查找仍未定位时说明“本轮未能定位对应内容”，不把材料缺失误说成用户从未讲过。

用户答复：**“同意”。**

确认结果：采用 A。能从前文明确定位就直接续接；多个合理对象的选择会改变检索或答案时，才简短追问。不能默认把最近对象当作正确对象，也不能把未找到材料说成用户从未讲过。此策略适用于普通聊天和模块续接。

## 决策 7：超限处理与回答完整性（已确认）

问题：必要上下文仍无法容纳时，系统应优先保证本次任务的关键条件完整，还是先交付明确标注缺口的部分回答？

| 选项 | 行为与取舍 |
| --- | --- |
| A：完整条件优先，能拆则分批，不能拆则说明需要缩小范围（推荐） | 先移除不相关和可选材料，再压缩背景；关键条件与必要证据仍放不下时，仅在不改变任务含义且可核验的情况下自动分批，否则明确说明原因和可缩小的范围 |
| B：优先给有缺口的部分回答 | 仍遵守输入硬门，先回答能确认的部分并明确缺失范围；交付更快，但不能保证完成原任务，需要用户自行决定是否继续 |

推荐 A。每次模型调用都执行最终预算硬门，不向供应商发送明知超限的载荷。裁剪优先级按本轮任务必要性判断，不能按来源类别一刀切：某次检索片段、画像中的排除项或历史纠正可能正是必要材料。当前请求、系统与权限规则、已确认有效约束以及支撑当前结论的必要证据不能为节省空间而静默丢弃。

自动分批须有次数和运行预算上限，并保留中间产物的来源；无法证明分批后仍完整满足原请求时，不自行缩小问题或生成冒充完整结果的回答。对用户说明实际受限的材料与具体下一步，不暴露内部提示词和调试细节。总运行耗时、摘要和分批调用量的具体限制仍待工程验证。

用户答复：**“同意”。**

确认结果：采用 A。先删除不相关材料并压缩背景；必要内容仍放不下时，仅在保留任务含义的情况下自动分批，同时限制调用次数和耗时，否则说明原因并给出缩小范围的选择。优先保证关键条件与必要证据完整，不遗漏关键约束后交付看似完成的结果。

## 决策 8：旧材料的按需读取（已确认）

问题：追问旧照片、附件或模块结果的具体细节时，是否允许系统按需重新读取已保存的原始材料？

| 选项 | 行为与取舍 |
| --- | --- |
| A：摘要作定位线索，按问题读取必要原始材料（推荐） | 日常续聊优先使用近期原文、有效状态和摘要；问题需要精确细节时，读取对应原图、原文片段或已保存的模块证据，并计入同一预算。可能增加读取或模型处理成本 |
| B：优先只用既有摘要回答 | 成本更低，但摘要未记录的细节只能说明缺口，不能可靠回答原图局部、原文限定条件等问题 |

推荐 A。例：用户问“上一张图左下角的小字是什么”，应在原图仍可用且本轮预算可容纳时读取对应图片，而非把旧助手描述当作实际看图；问已推荐论文的精确内容时，按实际保存的摘要或全文证据范围回答，不能把未读全文说成已读。

复用材料以具体对象、来源版本与读取范围为依据；文件可用现有已解析原文片段，视觉细节需要原图。照片与聊天附件仍限定账户和会话；全局知识库沿用既有账户作用域。删除、失效或无法读取的材料明确说明缺口，并使相关派生缓存不可继续作为当前依据。

本决策只涉及读取已有材料，不扩大跨会话记忆，也不自动重新执行外部检索或启动新模块。模块结果保持原有来源与时间；确需刷新外部事实时遵循已批准的显式模块选择合同。原文、图片和外部证据作为数据传递，不因重新读取而取得指令权限。

用户答复：**“同意”。**

确认结果：采用 A。摘要用于定位，精确细节依据对应原图、原文片段或已保存证据，按问题需要读取并计入统一预算；材料已经删除或无法读取时明确说明缺口。用户接受可能增加处理成本的取舍，以降低依赖旧回答转述造成的错误。

## 决策 9：验收方式与质量、成本取舍（已确认）

问题：是否以固定多轮案例验证实际连续性，并同时报告额外调用和等待，作为改进完成的依据？

推荐验收规则：

1. **确定性硬门**：固定测试中的最终输入预算、账户／会话隔离、来源有效性、运行模型额度快照检查全部通过；触底后不得发送超限请求。
2. **连续性案例**：覆盖消息末尾约束、后续纠正、话题往返、指代歧义、普通聊天与模块切换、旧图细节和附件限定条件。正确续接或按既定规则澄清、说明缺口才算通过；不把“生成成功”当作正确。
3. **配对比较**：使用相同模型、相同任务、相同输入预算上界与输出额度对比旧版和改进版，记录约束保持、纠正覆盖、对象解析和来源引用结果。必要时重放多次，区分确定性机制与模型输出波动。
4. **成本与等待**：正常短对话不新增不必要的摘要调用；长对话可以在已确认策略内增加摘要、原文读取或分批处理，但要记录输入／输出用量、额外调用量、首字等待和总耗时，并验证超时与调用上限确实有效。具体数值先测基线，再提出可检查的限额，不把未经实测的比例承诺成保证。

推荐采用这些规则：先修复已经复现的边界，再证明固定真实多轮场景的改进效果，最后根据数据校准触发和成本限额。现有 14 项测试通过只代表现有机制基线通过，不能代替新增案例及真实模型效果验证。

用户答复：**“同意”。**

确认结果：采用上述验收规则。可靠性硬门全部通过，固定多轮案例验证连续性；使用相同模型与预算对比前后效果，并记录额外调用和等待。正常短对话不增加无必要的摘要调用，长对话允许已确认策略内的额外处理；具体限额根据实测基线确定。现有测试通过不能代替改进方案验收。
