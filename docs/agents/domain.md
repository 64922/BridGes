# 领域文档

本仓库采用单一上下文布局。工程技能探索代码库前，应按以下规则读取领域文档。

## 探索前读取

- 根目录下的 `CONTEXT.md`
- `docs/adr/` 中与当前工作区域相关的架构决策记录

如果这些文件或目录尚不存在，继续执行即可，不要把缺失本身视为问题，也不要预先建议创建。`domain-modeling` 等技能会在术语或决策真正明确后按需创建它们。

## 文件结构

```text
/
├── CONTEXT.md
├── docs/
│   └── adr/
│       ├── 0001-示例决策.md
│       └── 0002-另一项决策.md
└── src/
```

## 使用词汇表中的术语

在任务标题、重构建议、假设和测试名称中，应使用 `CONTEXT.md` 定义的领域术语，避免改用词汇表明确排除的同义词。

如果所需概念不在词汇表中，应先判断是否引入了项目并未使用的新语言；若确实存在领域模型缺口，再交由 `domain-modeling` 处理。

## 标明与 ADR 的冲突

如果计划或输出与现有 ADR 冲突，应明确指出，不要静默覆盖既有决策。
