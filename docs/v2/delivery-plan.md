# V2 迁移、验收与任务拆分

> 本文是后续写入 `.scratch/` 本地 tickets 的拆分稿。产品共识与桌面原型均已获用户认可；生产改动仍需按纵向切片实施和验收。本轮不修改既有生产路由、数据库或测试。

## 1. 现有做法的审视

| 领域 | 保留的价值 | 当前障碍与 V2 处理 |
| --- | --- | --- |
| 对话与运行 | 账户隔离 SQLite、首轮原子锁、幂等运行、SSE 事件和模型记录已经存在。 | 旧自然语言路由将“识别意图”和“启动能力”混在一起。改为用户选 `module_id` 的确定性派发；旧消息只读兼容。 |
| 旧论文／职业编排 | 已有来源适配、错误处理与消息持久化部件可审计后沿用。 | 不复用旧业务工作流本身；围绕原词提取、真实检索、证据核对和准确角色约束重建子图。 |
| 学习路径 | 旧教学记录、附件／图像能力中可能有可复用的底层件。 | 旧计划不符合“单节照片→预习→辅导→逐题复盘→总结”。新阶段图与旧结果只读解耦。 |
| 文章人味化 | `chat/lightweight_policy.py` 的一次生成轻量表达策略贴近需求。 | 专用 SKILL、全文二次改写与智能体编排增加状态和事实漂移风险，却没有独立用户价值；移除任务入口／运行链，保留轻量表达策略并做事实不变测试。 |
| 知识库 | 当前账户文件管理、异步索引、混合检索和来源片段定位可复用。 | `retrieval/decision.py` 仍有科学名词清单和旧专用路由，`ingestion/ocr.py` 以科学图片为默认；改为任务相关的检索门与通用文档 OCR。聊天附件隔离，文件体积上限用真实材料压测决定。 |
| 用户画像 | 现有显式“记住／忘掉”、证据、撤回、账户隔离是可保留的原则。 | `profiles/four_dimensions.py` 强制四类，`profiles/extraction.py` 的正则类别词会漏掉自然表达并误把具体场景归类；改为原子事实、来源、去重、冲突处理与删除墓碑。自动提取不等于自动保存每句话。 |
| 模型 | 统一网关与运行锁避免多处硬编码，Embedding 版本合同可保留。 | `ai/fixed_models.py` 把主模型、OCR、语音、图像等绑成固定矩阵。按经验证的主模型配置替换可交互能力，同时独立保留向量模型版本。 |

画像设计借鉴开源智能体的**会话状态与跨会话记忆分层**思想：LangGraph 将会话检查点与跨会话存储分开，本项目再把原始聊天历史作为可追溯事实源，画像只存经筛选的长期原子记录。未核实用户所说的“zcode”具体项目与版本，因此不声称复刻其机制；这不影响已确认的画像行为。[LangGraph 持久化与存储说明](https://docs.langchain.com/oss/python/langgraph/persistence)。

## 2. 实施原则与硬门

1. 原型评审门：用户已认可桌面原型。正式接入时按 `interaction.md` 的场景逐项验收；若后续反馈与文档冲突，先更新产品和交互合同。
2. 外部可得性门：高德校内代表路线、百炼手填模型探测、arXiv／GitHub／Bilibili／贴吧／岗位公开页面逐一验证。无法稳定取得的内容按降级合同展示；不以“模型通常能回答”代替证据。
3. 迁移门：每个数据库变更有备份、前后数量对账、旧数据只读渲染和失败恢复；旧入口关闭前检查所有调用方与导出。
4. 账户门：新附件、图检查点、画像、模型配置和 SSE 恢复都做跨账户拒绝测试。密钥不进日志、响应、浏览器存储和截图。
5. 回归门：用户已明确的“模式不能中途切换”“错题直接给答案”“回复不可得只给链接”“模型失败不覆盖旧配置”等反例进入契约测试。

## 4. 横向验收脚本

- **跨模块上下文**：论文模块解释“Transformer”；同一会话切到 GitHub 说“找实现它的项目”，系统用前文语境且可显示关联的原始消息。切回普通聊天后不误启动 GitHub。
- **模式锁**：新聊天切学习并发出照片后，右上角只读；直接调用 API 提交 `companion`／`module_id=paper` 被拒。另开新聊天可选日常。
- **学习纠错**：上传密集的一节后，预习问题暂不要求回答；辅导可问任意难点；学完复盘每题只答一次。错误题立即给标准答案，不出现“再试一次”；总结基于真实作答。
- **隐私和画像**：在聊天上传图片不出现在知识库；画像删除后立即从下一次上下文消失，重新播放旧消息也不复活；用户修改文本不被异步提取覆盖。
- **配置**：无高德 Key 时只有通勤说明缺配置。错误 Qwen Key／不存在的模型 ID 保存失败，原模型下一轮仍可用；正确配置从下一轮生效，历史记录不改。
- **不可得证据**：贴吧回复无法访问、B 站视频只有元信息、论文只有摘要、招聘链接过期、GitHub README 缺失时都呈现实际能证实的内容及缺口。

## 5. 本轮交付的边界

本轮交付是设计文档和[独立桌面原型](../../apps/web/prototypes/v2-desktop/README.md)。原型所有消息、路线、验证结果和用户画像都是内存演示数据，不连接密钥、数据库、地图或外部平台。它为 UI 评审服务，不是任何一个 V2 ticket 的生产实现。
