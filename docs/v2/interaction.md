# V2 桌面交互规格

> 此文档规定页面行为和可验收状态。配套原型在 `apps/web/prototypes/v2-desktop/`，已获用户认可；它只演示交互与布局，不调用真实模型或外部平台。

## 1. 页面与导航

| 页面 ID | 入口 | 内容与约束 |
| --- | --- | --- |
| `CHAT.NEW` | 侧栏「新聊天」 | 右上角模式切换、空白态、输入框；尚无会话 ID。默认日常陪伴。 |
| `CHAT.THREAD` | 发送首条消息或点历史会话 | 顶部标题和只读模式标识、消息流、底部输入框；不显示模式切换按钮。 |
| `KB.HOME` | 侧栏「知识库」 | 当前账户的上传、解析状态、重试／重建、下载、删除；聊天附件不在此列表。 |
| `PROFILE.HOME` | 账户菜单「用户画像」 | 逐条原子信息列表；每条仅编辑、删除；不分固定类别。 |
| `SETTINGS.HOME` | 账户菜单「设置」 | 个人资料、数据与隐私、密钥与模型管理入口。 |
| `SETTINGS.MODELS` | 设置页入口 | Qwen／Tavily／高德凭据状态与更换、手填 Qwen 主模型 ID 与验证结果。 |

全站保持左侧导航、中央限宽聊天区和底部输入区。桌面窗口的首要验收尺寸为 1280×720、1440×900、1920×1080；不把移动端列为首版交付范围。侧栏历史会话标注模式，旧模块消息仍可阅读。

## 2. 新聊天与模式

`CHAT.NEW` 右上角的模式切换显示「日常陪伴」「学习模式」，当前项明确高亮；按键可切换。输入尚未发送时选择可以改变。点击发送时，服务端在创建首轮的同一事务里锁定模式。发送失败时保留模式、文字和附件草稿；未成功创建会话不展示已锁定状态。

进入 `CHAT.THREAD` 后，只在顶栏显示「日常陪伴」或「学习模式」只读标签。历史对话重开后也没有切换控件；不同模式须通过「新聊天」重新选。前端隐藏按钮与服务端拒绝修改构成双重约束。

日常陪伴空白态提示普通提问和从 `+` 菜单选择模块；学习模式空白态提示「上传本节书页照片开始预习」。两种模式拥有同一产品视觉语言，不把学习模式放进 `+` 模块列表。

## 3. 输入框与 `+` 菜单

### 3.1 结构

输入框左侧为带「添加功能或文件」可访问名称的 `+` 按钮。日常陪伴点击后，从输入框上方向上展开菜单：

1. 添加照片和文件。
2. 论文搜索。
3. 校园通勤。
4. 学习资料推荐。
5. 贴吧信息搜集。
6. 职业规划。
7. GitHub 项目推荐。

每行提供一致风格的线性图标、中文模块名和一行功能说明。学习模式菜单仅展示照片／文件上传相关入口；其教学阶段由学习工作流决定。菜单不包含「学习模式」。

选择日常模块后，菜单关闭，输入框文本前显示不可编辑的 `[模块名 ×]` chip；`×` 只移除当前选择，不清除已输入文字。重新打开菜单并选择另一项时直接替换 chip。发送后输入框保留所选模块，方便连续操作；从同一会话选择其他模块时，不新建会话。每条用户消息上方显示当轮模块名，历史消息不因后续切换而改标。

无 chip 时普通聊天直接回答。若用户在普通聊天发送了明显需要专用模块的请求，助手消息内出现「使用某模块」按钮；按钮复用原始请求并明确启动对应模块。候选建议只依据用户原文及已确认上下文，歧义大时不显示自动建议。

### 3.2 文字、附件和发送

输入支持多行，Enter 发送，Shift+Enter 换行；正在生成时发送按钮变为停止。日常模式的纯附件消息可发送并由系统问用途；学习模式首轮必须至少含一张书页照片，允许不写文字。

桌面上传支持点击文件选择器、把文件拖入输入区域、粘贴剪贴板图片。发送前用缩略图列显示文件名、类型、页序和移除按钮。多张书页可拖动排序，同时提供「上移／下移」按钮作为键盘替代；识别顺序以发送时页序为准。发送失败保留全部草稿与顺序；发送成功后附件归属当前会话。附件不会自动进入全局知识库，也不在聊天中弹出添加知识库的建议。

不支持的类型、过大文件、读取失败、重复页和无法识别的模糊页，均在附件旁给出中文原因，不清空其他已选文件。最大文件体积由架构测试确定，不在原型写死新的承诺值。上传和处理状态分别显示；处理未完成不能伪装成「已识别」。

### 3.3 菜单与焦点

`+` 按钮用 `aria-expanded` 表明状态；点击外部或按 Esc 关闭并把焦点还给 `+`。打开后可用上下方向键浏览，Enter 选择，Tab 到正常下一控件。菜单向上展开时不得遮住输入框或当前焦点。chip 的移除按钮、附件排序按钮和发送按钮都有中文可访问名称。焦点轮廓始终可见。

## 4. 消息区与模块结果

用户消息靠右显示文字、模块标识和附件缩略图；助手回答为居中限宽列。来源链接、知识库片段定位、论文元数据与岗位样本各用简洁来源行，不把检索内部日志显示给用户。用户能看见实际用于搜索的关键名词／岗位／地点，并能在下一条消息纠正。

工作流执行中，在助手消息原位依次显示「正在理解请求」「正在检索」「正在核对来源」「正在整理结果」等少量状态。错误时在该消息内说明失败步骤和可重试操作；停止后显示已停止。进度仅代表真实已开始或完成的节点，不展示模型内部推理。长正文、代码、公式和链接在限宽列中保持可读。

### 4.1 校园路线卡

结果先给起点、终点、出行方式、距离、地图基础耗时、课间缓冲和建议总时间，再给可缩放地图及路线文字。课间高峰规则命中时显示「可能人多」及增加的 5 分钟，并写明这是规则估计。地图卡在 1280×720 窗口中仍能完整显示关键信息，适合用户截图保存。地点定位失败时显示可选候选地点或要求用户补充位置，不展示猜测路线。

### 4.2 列表结果

论文、资料、岗位和 GitHub 结果使用可扫描列表，每项有直达链接和简短选择理由；岗位样本单独显示检索日期、样本数和城市范围。贴吧回复无法取得时仅展示帖子标题与链接，并明确「未取得回复内容」。当来源不足时呈现已核实部分和限制，不填充编造内容。

## 5. 学习模式的阶段界面

学习对话顶部用低强调的阶段条显示「书页识别 → 辅助预习 → 辅导 → 复盘 → 总结」，当前阶段高亮；此条是进度提示，不提供绕过学习状态的任意点击跳转。

| 阶段 | 界面行为 |
| --- | --- |
| 书页识别 | 展示照片页序与处理进度。关键处无法辨认时标出页号／位置，并提供继续补拍的入口。 |
| 辅助预习 | 一次展示数个编号预习问题，并注明「阅读时带着这些问题思考，暂不需要作答」。随后输入框变为辅导问答。 |
| 辅导 | 用户自由提问；回答指向本节页码或片段。可追加同节照片；新照片确认后刷新本轮知识范围。 |
| 复盘 | 用户说「学完了」或点击明显的「开始复盘」操作进入。界面一次仅出现一题和对应输入框；每题回答后显示判定与正确答案／必要说明，再进入下一题。可暂停回辅导。 |
| 总结 | 显示「学到了什么」「复盘已掌握」「还需补的点」三段简洁内容；同节追问仍可继续。 |

复盘中回辅导后，已完成题保留判定；继续复盘只出未问的题。追加书页时先更新知识范围，之后重新安排尚未问的题。混入明显不同小节的照片时，请用户新建学习对话或确认同节归属。

## 6. 用户画像、知识库与设置

### 6.1 用户画像

画像页为一列原子记录，每行只显示一条可理解的内容及适当的更新时间。行尾「修改」「删除」操作始终可见，不能依赖悬停。修改在行内编辑，保存与取消清楚分开；删除先确认，然后立即从检索和提示上下文中停止使用该条。空态解释系统会从明确、可长期使用的信息中提炼，而不是每条消息都新增。页面无四类分组、类别筛选或人格标签。

### 6.2 知识库

保留侧栏入口和当前账户文件列表，显示处理／就绪／无法检索／失败状态；上传来源是此页面的主动操作。材料详情可看到文件名、时间、处理状态和可用的定位信息。聊天附件不出现在此列表。对话引用知识库时，只展示本轮确实使用的材料与片段定位。

### 6.3 密钥与模型管理

设置页新增独立入口。Qwen、Tavily 和高德分别展示「已配置／未配置／验证失败」及更换输入框；输入框永不预填旧明文，保存成功后清空。高德凭据按服务端路线规划与浏览器地图展示实际所需字段分组。替换操作有验证进度、明确错误和成功提示，失败时原设置保持有效。

Qwen 模型区域只用一个手填模型 ID 输入框及「验证并保存」按钮，不提供预设模型列表。验证结果显示实际 ID、图片／工具／结构化输出能力、上下文长度和失败原因。通过后提示「从下一条消息起使用」，不会改写历史消息或中途切换正在执行的轮次。若密钥未配置或新密钥与模型不匹配，字段附近指出操作顺序。

## 7. 原型验收脚本

1. 新聊天在日常陪伴下打开 `+`，选择论文搜索，输入「找 Transformer 入门论文」，检查 chip、发送后的模块标识和进度；同一会话再选择贴吧信息搜集，历史论文消息仍在。
2. 新建学习对话，在右上角切换学习模式，上传两张书页并调整顺序，检查预习／辅导／复盘／总结状态；进入会话后确认模式切换按钮消失。
3. 上传前移除附件、粘贴图片、Esc 关闭 `+` 菜单、键盘调整页序，确认文本草稿未丢失。
4. 打开用户画像，编辑一条、删除一条，确认没有四类分组。
5. 打开密钥与模型管理，输入模型 ID，体验验证中、验证失败和成功状态；确认旧 Key 不回显。

原型只模拟上述交互和结果卡，不触发真实 API、写数据库或改变生产路由。用户已批准交互方向；以本规格作为正式组件和 API 的验收依据。
