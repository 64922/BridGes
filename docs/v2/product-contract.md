# V2 产品契约

## 1. 产品目标和边界

BridGes V2 服务华东交通大学在读学生的学习、校内出行与职业准备。身份不做在读核验；「面向本校学生」是内容和使用场景边界，不声称系统已验证学籍。首版只支持个人电脑上的桌面浏览器。账号与数据归属仍由稳定账户 ID 隔离，同一安装实例由一位主要使用者管理 API 凭据。

产品是聊天优先的双模式应用。日常陪伴用于普通交流和六类明确选择的任务；学习模式用于一个教材小节的预习、辅导、复盘、总结。新聊天页面右上角可选模式；第一条消息创建对话后模式永久固定。已存在对话只显示模式名称，不提供切换按钮。另学一个小节或改换模式，需要新建对话。

### 范围表

| 范围 | V2 行为 |
| --- | --- |
| 日常陪伴 | 普通对话；论文搜索、校内通勤、学习资料推荐、贴吧信息搜集、职业规划、GitHub 项目推荐六个任务模块 |
| 学习模式 | 书页照片上传和理解；辅助预习；按上传内容辅导；逐题复盘；学习总结 |
| 共用能力 | 会话历史与上下文编排、聊天附件、账户级私有知识库、逐条用户画像、全局自然回复风格、证据引用、模型与密钥管理 |
| 保留的基础能力 | 注册登录、稳定账户隔离、历史会话、数据导出与备份、删除、审计与安全存储 |
| 退役能力 | 文章人味化任务及其专用 SKILL/编排、图片及视频生成、旧科学文章创作路径、回答朗读和与本轮范围无关的旧工作台入口；依赖经迁移门检查后清退 |

退役不删除旧对话及其已有生成内容。旧结果可查看和导出；旧能力入口、继续执行与重试入口退出。需要只读兼容的解析代码可留在独立兼容层，不能重新暴露旧写路径。

## 2. 日常陪伴与模块选择

输入框左侧 `+` 打开向上展开的列表：先「添加照片和文件」，随后依次列出论文搜索、校园通勤、学习资料推荐、贴吧信息搜集、职业规划、GitHub 项目推荐。每项有图标、名称和一句中文说明。点击模块后，输入框内出现可移除的模块名 chip；用户在 chip 后输入指令。发送消息时将明确的 `module_id` 随消息持久化，服务端按该值选择工作流。模块选择保留到用户切换或移除；同一日常对话可连续使用不同模块，完整对话历史在权限与上下文预算内供后续模块使用。

未选模块时照常聊天。若原文明显需要专用模块，例如「帮我找 Transformer 论文」，系统给出「使用论文搜索」等一键建议；点击后使用原文启动模块，无须重输。建议不是后台自动发起检索。已选模块但请求信息不足或意图含糊时，工作流只问缺少或歧义的一项；不悄悄猜测关键词、路线或岗位。

| 模块 | 输入与结果边界 |
| --- | --- |
| 论文搜索 | 提取并保留原始专业名词，消除歧义；以 arXiv 为主查 3–5 篇适合用户目标的论文，可用学术元数据补充；显示真实查询词、论文链接、选择理由、阅读顺序和未核实项。跨学科覆盖不足时明示其他来源。 |
| 校园通勤 | 解析起点、终点和步行／自行车／电动车；缺项只追问缺项。只支持校内地点及校门与校内地点。用高德路径与交互地图呈现距离、基础耗时和建议时间；约定课间高峰提示并加 5 分钟缓冲。 |
| 学习资料推荐 | 从本轮消息提取想学的技术方向；缺学习层次时可用可靠上下文，仍不清楚则追问。默认 2 本书和 3 条哔哩哔哩视频，标注顺序、适用原因和直达链接。未实际看过的视频不作内容细节断言。 |
| 贴吧信息搜集 | 只将确认为「华东交通大学吧」的公开帖子纳入结果；能取得回复才概括回复，取不到回复则只给帖子链接。校规等事实与学校官方来源交叉核对。 |
| 职业规划 | 准确提取岗位、阶段、城市等意图。公开岗位样本须与目标岗位相符，薪资、技能、地区判断展示来源、日期、样本量与范围；相邻岗位单独列为探索方向。 |
| GitHub 项目推荐 | 优先找与用户完整 idea 功能相近的项目，缺少时补充关键组件项目并说明覆盖范围。默认 2–3 个，按功能匹配优先，再看文档、维护、许可；说明优势、借鉴角度与局限。 |

所有模块如实说明来源、检索时间、样本不足和失败。外部链接是可点开的证据；不能凭搜索摘要声称已阅读不可获取的论文、帖子回复、视频或仓库实现。多步执行在助手消息中显示简短进度和失败位置，不公开模型内部推理。

## 3. 学习模式

一个学习对话对应教材的一个小节，可在开始时上传多张同节照片；图片是首轮必要输入，纯文本或 PDF 不单独启动首版学习流程。桌面端可选取、拖入、粘贴图片，发送前预览、移除和调整页序。照片保存在该对话，绝不自动加入全局知识库，也不弹出加入知识库的引导。

1. **识别与辅助预习**：按页序识别文字、公式、图表及结构，建立可追溯的小节知识范围；关键内容模糊则指出位置，请求补拍或补文字。按知识密度提出几个覆盖重点、有深度但不要求立即回答的预习问题。
2. **辅导**：学生带着问题阅读，哪里不懂就问哪里。系统优先依据本轮书页通俗解释，可适度使用同账户知识库、Tavily 与模型知识，并明确补充来源；不能把补充材料冒充书页原文。
3. **复盘**：学生表示学完后开始。系统按本节知识面生成高质量问题，数量随密度浮动，一次只问一题。每答完立即判断：正确则肯定并给出必要反馈；错误、不完整或不知道则直接给正确答案和简短解释，随后进入下一题，不要求补答同题。复盘仅考本节已上传书页内容。
4. **总结**：概括本节学过的知识、掌握情况与待补的理解点，依据实际问答，不夸大掌握程度。

用户可在预习或辅导阶段追加同节照片。复盘中发现漏拍时先回辅导，更新知识范围并重排尚未问出的题；已判定题不再补答。复盘中也可主动回辅导，再从未问的题继续。总结后可继续追问本节；下一节另开对话。

## 4. 个性化、知识库和上下文

- **会话上下文**：原始消息完整保存，同一对话内各模块可取得相关前文。每次模型调用按所选模型实际上下文窗口编译输入：当前请求、最近消息、较早消息摘要、与当前任务相关的原文片段、当前照片／附件、最小画像切片、相关知识库片段与工具结果。摘要必须可追溯；找不到前文时要承认不确定并询问。
- **聊天附件**：归属当前账户与对话。删除会话时按既有数据导出及删除约束处理。全局知识库只接受用户从侧栏主动添加的材料。
- **知识库**：保留账户隔离、文件管理、后台解析、关键词与向量检索底座。由模式、模块和用户请求判断是否检索，结果以可定位片段进入上下文。首版聚焦讲义、笔记、简历和教材章节，不承诺整本大体积教材；文件上限经解析测试决定。纠正现有图片 OCR 的科学图片预设。
- **画像**：页面为无固定类别的原子信息列表，每行可修改、删除。每轮检查是否出现清晰、可复用的信息，但不是每轮必新增；不自动推断人格或心理标签。普通提取在回答后异步完成，下一轮生效；「记住／忘掉」立即处理。用户修改具有最高权威，删除的旧证据不能让条目自动复活。
- **自然表达**：在各模块最终生成时注入轻量、低优先级的表达规则，遵从用户语气和篇幅要求；引用、数值、代码、公式和工具结果保持准确。不设置独立的人味化智能体或二次全文改写。

## 5. 模型、密钥与界面批准门

个人实例首次启动继续在终端输入 Qwen 和 Tavily Key，安全存入系统凭据库。账户设置新增「密钥与模型管理」：替换 Qwen、Tavily、高德凭据；密钥只显示配置状态及遮罩，绝不回显明文。高德未配置时仅通勤模块提示去设置。

Qwen 主模型由使用者手填模型 ID。保存前按百炼精确模型信息查询文本、图片、工具调用、结构化输出和上下文长度，再用现有 Key 做最小真实能力调用；全部通过才原子替换，失败保留原配置。切换从下一条消息起用于新旧对话；在途轮次用启动时锁定的模型，历史回复不改写。知识库向量模型单独固定并管理索引版本。

涉及聊天界面、模块菜单、附件、画像、设置的生产 UI 必须先出桌面交互原型供用户审查，通过后再进入正式实现。原型借鉴 ChatGPT 的操作逻辑，视觉遵循项目 `DESIGN.md` 与现有设计令牌，不复制第三方标志和界面素材。
